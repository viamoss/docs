이 페이지는 자체 호스팅 설치가 연결하는 모든 곳과, 어느 워크로드가 연결하는지,
어떤 연결을 사설망에 둘 수 있는지 정리합니다. 마지막에는 사용자 브라우저가
설치에서 필요로 하는 것을 다룹니다.

외부로 연결하는 워크로드는 `sdk-backend`, `dashboard-backend`, `worker` 세
가지입니다. 설정하지 않은 대상에는 연결하지 않습니다.

## 한눈에 보기

| 대상 | 워크로드 | 언제 | 사설망에 둘 수 있나요? |
|---|---|---|---|
| PostgreSQL | 두 백엔드, 워커, 마이그레이션 Job, 보존 CronJob | 항상 | 예 |
| Redis | 두 백엔드, 워커 | 항상 | 예 |
| 오브젝트 스토리지(S3 호환) | 두 백엔드, 워커, 보존 CronJob | 스크린샷, 녹화, 지식 베이스 이미지 | 워크로드에는 예. 일부는 브라우저도 필요합니다. [브라우저에 필요한 것](#브라우저에-필요한-것)을 참고하세요. |
| Pinecone | 두 백엔드, 워커 | 지식 베이스 검색과 색인 | 검색과 쓰기는 비공개 엔드포인트로 가능합니다. 인덱스 조회는 계속 `api.pinecone.io`로 갑니다. |
| 채팅 모델 공급자 | 두 백엔드 | 모든 채팅 턴과 대시보드의 AI 기능 | 공급자에 따라 다름 |
| 임베딩 공급자 | 두 백엔드, 워커 | 검색과 색인 | 공급자에 따라 다름 |
| 이미지 주석 모델 공급자 | 워커 | 이미지가 있는 페이지 색인 | 공급자에 따라 다름 |
| 고객사 ID 공급자(OIDC) | 두 백엔드, 대시보드 | 대시보드 로그인 | 예 |
| Google 토큰 서비스 | 두 백엔드, 워커 | `GOOGLE_AUTH_MODE=vertex`일 때 | 자격 증명 유형과 네트워크에 따라 다름 |
| `login.microsoftonline.com` | 두 백엔드 | 워크로드 ID로 Azure OpenAI를 쓸 때 | 네트워크에 따라 다름 |
| Firecrawl, `api.firecrawl.dev` | 워커 | 웹사이트 소스 | 아니요 |
| 소스로 추가한 웹사이트 | 워커 | 웹사이트 소스 | 허용 목록에 넣지 않으면 공개 사이트만 |
| Document360 API | 워커, `dashboard-backend` | Document360 소스 | 아니요 |
| Intercom API | 워커, 두 백엔드 | Intercom 소스와 Intercom 연동. 둘 다 0.17.0부터 | 아니요 |
| Zendesk, `<subdomain>.zendesk.com` | `dashboard-backend`. 직접 생성 방식에서는 `sdk-backend`도 | Zendesk 연동 | 아니요 |
| 고객사 API 액션 호스트와 MCP 서버(0.17.0부터) | `sdk-backend`, `dashboard-backend` | 이를 호출하는 프로시저 | 아니요. 공개 주소만 |
| 고객사 OpenTelemetry 수집기 | 전부 | `OTEL_EXPORTER_OTLP_ENDPOINT`를 설정했을 때 | 예 |
| Slack 수신 웹훅 | 전부 | `SLACK_WEBHOOK_URL`을 설정했을 때 | 아니요 |

파드가 시작되기 전에 마이그레이션 Job에 필요한 데이터베이스를 빼면, 차단되었을 때
워크로드 시작을 막는 대상은 하나뿐입니다. Vertex AI에서 두 백엔드는 시작할 때
Google 액세스 토큰을 받아 오며, 받지 못하면 시작하지 않습니다. 그 밖의 대상은
쓰는 시점에 실패하거나 기능이 줄어듭니다.

## Pinecone 벡터 인덱스

지원하는 벡터 저장소는 Pinecone뿐입니다. 각 워크로드는 `api.pinecone.io`에서
인덱스를 조회한 뒤, 검색, 조회, 쓰기, 삭제 요청을 인덱스 자체의 호스트로
보냅니다.

이 데이터 요청을 사설망에 두려면 비공개 DNS와 함께 Pinecone 비공개
엔드포인트(AWS PrivateLink)를 구성하고 `PINECONE_USE_PRIVATE_ENDPOINT=true`를
설정하세요(0.16.20부터, 기본값은 꺼짐).

- **세 워크로드 모두에 설정하세요.** `sdk-backend`, `dashboard-backend`, 워커에
  대문자 이름과 같은 값으로 설정합니다. 받는 값은 `true`/`false`, `yes`/`no`,
  `on`/`off`, `1`/`0`, `t`/`f`, `y`/`n`이며 대소문자는 구분하지 않습니다. 그 밖의
  값은 백엔드 시작을 막고 모든 색인 작업을 실패시킵니다.
- **`api.pinecone.io`에는 계속 연결할 수 있어야 합니다.** 인덱스 조회는 항상
  그곳으로 갑니다.
- **공개 호스트로 대신 연결하지 않습니다.** 인덱스의 프로젝트에 비공개
  엔드포인트가 없으면 Moss는 연결하지 않습니다. 채팅은 지식 베이스 없이 답하고
  색인은 실패하며, 인덱스와 이 설정을 언급하는 오류가 남습니다.
- **Pinecone을 잠그기 전에 확인하세요.** 각 프로세스는 인덱스를 처음 열 때
  `Pinecone data-plane host: private`을 로그에 남깁니다. 이 줄은 Moss가 고른
  호스트를 보여 줄 뿐, 그 호스트에 연결할 수 있다는 뜻은 아닙니다.
  `sdk-backend`에서는 지식 베이스를 쓰는 질문을 하나 하고
  `Pinecone multi-namespace search completed`의 `results=N/M`에서 N이 0보다 큰지
  확인하세요. 워커에서는 소스 하나를 새로고침하고 Ready로 끝나는지 확인하세요.
  그다음에 Pinecone의 비공개 엔드포인트 전용 제한을 켜세요.

API 키에는 데이터 플레인 읽기와 쓰기 권한이 필요합니다. 인덱스 생성 권한은
Moss가 인덱스를 대신 만들게 할 때만 필요합니다. 인덱스를 직접 만드는 방법은 차트
README의 Vector Store 섹션에 있습니다.

## 오브젝트 스토리지

워크로드는 S3 호환 스토리지 하나(`STORAGE_TYPE=s3`, `S3_ENDPOINT`)를 쓰며, 이
스토리지는 클러스터 안에 있어도 되고 비공개 엔드포인트 뒤에 있어도 됩니다. 여기에
세션 스크린샷, 세션 녹화, 페이지 스냅샷, 워커가 지식 베이스 페이지에서 복사한
이미지가 저장됩니다. `S3_ACCESS_KEY_ID`와 `S3_SECRET_ACCESS_KEY`가 없으면
워크로드는 서비스 계정의 IAM 역할 같은 클라우드 기본 자격 증명을 씁니다.

일부 기능에서는 사용자 브라우저가 스토리지에 직접 연결하므로, 브라우저가 쓰는
주소인 `S3_PUBLIC_ENDPOINT`(설정하지 않았다면 `S3_ENDPOINT`)에 외부에서 연결할 수
있어야 할 수 있습니다. [브라우저에 필요한 것](#브라우저에-필요한-것)을
참고하세요.

## 지식 소스 가져오기

| 소스 유형 | 워커가 가져오는 것과 위치 |
|---|---|
| 웹사이트 | 헤드리스 Chromium 브라우저로 사이트를 열어 `robots.txt`와 사이트맵을 읽고 페이지를 찾은 뒤, 각 페이지 주소를 Firecrawl(`api.firecrawl.dev`, `FIRECRAWL_API_KEY` 사용)에 보냅니다. Firecrawl이 페이지를 가져와 돌려줍니다. Chromium은 사이트 페이지가 불러오는 스크립트나 폰트 같은 것도 함께 불러옵니다. |
| 마크다운 업로드 | 아래 이미지 말고는 없습니다. 파일은 대시보드에서 올라옵니다. |
| Document360 | 고객사 Document360 API 호스트. `apihub.document360.io`처럼 `document360.io`나 `document360.com` 아래에 있어야 합니다. |
| Intercom(0.17.0부터) | 리전에 맞는 Intercom API 호스트: `api.intercom.io`, `api.eu.intercom.io`, `api.au.intercom.io` 중 하나 |
| 모든 유형 | 페이지가 링크한 모든 이미지. 워커가 오브젝트 스토리지로 복사합니다. |

`dashboard-backend`도 관리자가 자격 증명을 저장할 때 확인하고 Intercom 컬렉션
목록을 불러오기 위해 Document360과 Intercom API를 호출합니다. 애플리케이션이
Intercom 연동을 쓰면 `sdk-backend`도 Intercom API를 호출합니다. Intercom 관련
기능은 둘 다 0.17.0에 새로 생겼습니다.

마크다운, Document360, Intercom 소스만 추가하는 설치에는 Firecrawl과
`FIRECRAWL_API_KEY`가 필요 없습니다.

### 사설 주소와 허용 목록

0.16.22부터 콘텐츠에서 나온 주소를 워커가 직접 가져올 때는 공개 주소에만
연결합니다. 이미지, `robots.txt`, 사이트맵, 웹사이트 소스의 시작 주소,
Document360 호스트가 여기에 해당합니다. 사설, 루프백, 링크 로컬 주소는
거부됩니다. 거부된 이미지는 실패로 기록되고 원래 주소를 유지하며, 시작 주소나
Document360 호스트가 거부되면 작업이 실패합니다.

워커가 사내망에 연결하게 하려면 워커의 `WORKER_FETCH_ALLOWLIST`에 호스트와
범위를 넣으세요.

| | |
|---|---|
| 형식 | 쉼표로 구분한 호스트 이름과 CIDR 범위 |
| 기본값 | 비어 있음: 공개 주소만 |
| 예시 | `wiki.corp.example.com,10.20.0.0/16` |

- 호스트 항목은 그 이름과 정확히 일치할 때만 맞습니다. CIDR 항목은 이름이 가리키는
  주소와 비교하며, 이름이 가리키는 모든 주소가 통과해야 합니다.
- `localhost`는 따로 항목이 필요합니다.
- 호스트도 아니고 올바른 CIDR도 아닌 항목이 있으면 워커가 시작하지 않으므로,
  오타가 있어도 열리는 주소는 없습니다.
- 클라우드 메타데이터 주소는 어떤 경우에도 허용할 수 없습니다.
- 사설 `S3_ENDPOINT`에는 항목이 필요 없습니다.

### 프록시

- **프록시를 쓰지 않음**: 위에서 말한 워커의 요청(이미지, `robots.txt`, 사이트맵,
  시작 주소, Document360)은 직접 연결하며 `HTTP_PROXY`와 `HTTPS_PROXY`를
  무시합니다. API 액션과, 0.17.0부터 MCP 연결도 프록시를 쓰지 않습니다. 정방향
  프록시를 거쳐야만 밖으로 나갈 수 있는 워커는 이 요청을 보낼 수 없습니다.
- **`HTTPS_PROXY`를 따름**: Firecrawl 호출, 0.17.0부터 Intercom API 호출, 그리고
  `dashboard-backend`의 Document360 자격 증명 확인은 `HTTPS_PROXY`와 `NO_PROXY`가
  설정되어 있으면 이를 따릅니다.
- **Zendesk**: [Zendesk 헬프데스크](#zendesk-헬프데스크)를 참고하세요.

모델 공급자, Pinecone, 오브젝트 스토리지 같은 그 밖의 외부 연결은 실제로 쓰기
전에 고객사 프록시를 거쳐 시험해 보세요.

## Zendesk 헬프데스크

Zendesk를 호출하는 워크로드는 관리자가 Zendesk 연동에서 고른 생성 방식에 따라
다릅니다.

- **호스트 위임**: Moss는 Zendesk 자격 증명을 갖고 있지 않습니다. 관리자가
  연결하거나 동기화할 때, 그리고 하루에 한 번 `dashboard-backend`가 하위 도메인의
  공개 티켓 양식을 익명으로 읽습니다. 티켓은 고객사 백엔드가 생성합니다.
- **직접**: Moss가 고객사 Zendesk 자격 증명으로 티켓을 생성하므로
  `sdk-backend`도 Zendesk를 호출합니다.

기본으로 꺼져 있는 백엔드 설정 두 가지가 이 호출의 연결 방식을 바꿉니다.
Zendesk를 호출하는 워크로드에 설정하세요.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| `ZENDESK_USE_ENV_PROXY` | `false` | 0.16.24부터. `true`이면 `NO_PROXY`가 Zendesk 호스트와 맞지 않는 한 모든 Zendesk 호출을 `HTTPS_PROXY`에 지정한 `http://` 프록시로 보냅니다. 스킴이 없는 값은 `http://`로 읽습니다. `https://` 프록시는 거부되며, 이때 호출은 직접 연결로 바뀌지 않고 실패합니다. |
| `ZENDESK_ALLOW_PRIVATE_RESOLUTION` | `false` | 0.17.0부터. 프록시 없이 연결할 때 이 서버의 DNS가 공개되지 않은 주소를 돌려주면 Moss는 Zendesk 호스트 호출을 거부하고, 연결 확인 메시지에 이 설정 이름이 나옵니다. 고객사 네트워크가 의도적으로 `zendesk.com`을 내부 게이트웨이로 보낼 때만 켜세요. 루프백, 링크 로컬, 클라우드 메타데이터 주소는 켜도 허용되지 않습니다. |

## API 액션과 MCP 연결

API 액션과, 0.17.0부터 관리자가 연결한 MCP 서버는 공개 주소의 `https`로만
호출합니다. 사설 주소로 해석되는 호스트는 거부됩니다. 이 동작은 설정으로 바꿀 수
없으므로, 고객사 네트워크 안에서만 접근할 수 있는 API는 API 액션으로 호출할 수
없습니다. 0.17.0부터는 일부 VPC가 쓰는 공유 범위 `100.64.0.0/10`도 여기에
포함됩니다.

## 브라우저에 필요한 것

### Moss가 실행되는 페이지에서

| 필요한 것 | 이유 | 세부 사항 |
|---|---|---|
| `sdk-backend`의 공개 주소 | SDK가 시작할 때 불러오는 구성을 포함한 모든 SDK 요청 | SDK의 `apiUrl`이 이 주소를 가리킵니다. [설정](/ko/sdk/configuration)을 참고하세요. |
| 애플리케이션의 허용 도메인에 들어 있는 페이지 호스트 | 모든 SDK 요청을 이 목록과 대조합니다. | 목록에 없는 페이지는 403 `DOMAIN_NOT_ALLOWED`를 받습니다. [대시보드 설정](/ko/configurations/dashboard-settings)을 참고하세요. `SDK_REQUIRE_ORIGIN`(기본값 `false`)을 `true`로 하면 `Origin`이나 `Referer`가 없는 요청과, 목록이 비어 있는 애플리케이션에 대한 모든 요청이 403 `ORIGIN_REQUIRED`를 받습니다. 모든 애플리케이션의 목록을 채운 뒤에 켜세요. |
| 턴 예산보다 긴 프록시 타임아웃 | 채팅 턴은 답변을 보내기 전까지 `LLM_TOTAL_TIMEOUT_SECONDS`(기본 240초)만큼 걸릴 수 있습니다. | 그보다 먼저 요청을 닫는 프록시는 긴 턴을 끊습니다. |
| `S3_PUBLIC_ENDPOINT`(또는 `S3_ENDPOINT`)의 오브젝트 스토리지 | 스크린샷을 캡처할 때, 그리고 파일 첨부를 켰을 때, 브라우저가 백엔드가 서명한 링크로 파일을 스토리지에 올립니다. | 스토리지가 고객사 페이지에서 오는 교차 출처 `PUT`을 받아야 합니다. |
| 워커의 `S3_ENDPOINT`에 있는 오브젝트 스토리지 | 답변 속 지식 베이스 이미지는 서명 없이 버킷과 경로로 스토리지에서 불러옵니다. | 그 주소에서 해당 객체를 읽을 수 있어야 합니다. |
| 모든 프록시를 통과하는 Server-Sent Events | SDK에 `streamActivity: true`와 `appearance.chrome.loader: 'steps'`가 있을 때만 | [로더의 실시간 단계](#로더의-실시간-단계)를 참고하세요. |

0.17.0부터 답변은 허용된 호스트에서만 이미지를 불러옵니다. 허용 도메인, 지식
베이스의 호스트, 오브젝트 스토리지, 그리고 SDK의 `replyLinks.allowedHosts`에
추가한 호스트입니다. `https://s3.<region>.amazonaws.com`이나 Google Cloud
Storage 같은 공유 S3 호스트에서는 지식 베이스 이미지 버킷에서만 불러옵니다. 이
버킷은 `global.storageBuckets.kbImages`, 또는 `worker.env`에 있는 워커의
`STORAGE_BUCKET`, 또는 `sdk-backend`의 `KB_IMAGES_BUCKET`입니다. 셋 다 없으면 그
이미지는 대체 텍스트로 표시되고, `sdk-backend`가 시작할 때 경고를 로그에
남깁니다.

### 대시보드에서

관리자의 브라우저에는 대시보드 호스트, 로그인을 위한 ID 공급자, 그리고 세션
녹화를 서명된 링크로 재생하는 `S3_PUBLIC_ENDPOINT`(또는 `S3_ENDPOINT`)의
오브젝트 스토리지가 필요합니다. 대시보드는 API 호출을 클러스터 안의
`DASHBOARD_API_URL`에 있는 `dashboard-backend`로 전달하므로, 외부에서
`dashboard-backend`의 API를 호출하지 않는다면 `dashboard-backend`에는 공개 주소가
필요 없습니다.

0.17.0부터 AI 어시스턴트용 Moss MCP 서버를 켜면(`dashboard-backend`의
`MCP_ENABLED`와 `MCP_PUBLIC_URL`, 대시보드의 `MCP_ENABLED`. 기본은 꺼짐)
어시스턴트는 대시보드 호스트의 `/mcp`에 연결합니다. 공급사의 클라우드에서
실행되는 어시스턴트가 연결하려면 그 주소에 인터넷에서 접근할 수 있어야 합니다.
[AI 어시스턴트](/ko/dashboard/ai-assistants)를 참고하세요.

### 로더의 실시간 단계

0.17.0부터 SDK에 `streamActivity: true`와 `appearance.chrome.loader: 'steps'`를
설정하면, Moss가 일하는 동안 로더가 각 단계를 보여 줍니다. 이런 턴은
`sdk-backend`의 세 경로에서 Server-Sent Events를 씁니다.

| 경로 | 처리하는 것 |
|---|---|
| `POST /api/v1/query/activity` | 입력한 질문 |
| `POST /api/v1/interactions/activity` | 가이드 단계 완료 |
| `GET /api/v1/activity/probe` | 1초 간격의 테스트 이벤트 세 개. 로그인 필요 없음 |

브라우저와 `sdk-backend` 사이의 모든 프록시는 이벤트가 쓰이는 대로 바로 전달해야
합니다.

- 이 경로에서 응답 버퍼링을 하지 마세요. nginx는 백엔드가 보내는
  `X-Accel-Buffering: no` 헤더를 따르며, 다른 프록시는 따로 설정해야 합니다.
- `text/event-stream` 응답을 압축하지 마세요.
- 유휴 또는 읽기 타임아웃은 270초 이상이어야 합니다. 240초 턴 예산에 답변을 위한
  최소 30초를 더한 값입니다. `LLM_TOTAL_TIMEOUT_SECONDS`를 늘리면 이 값도
  늘리세요. 턴이 실행되는 동안 백엔드는 10초마다 주석 줄을 보냅니다.

ingress-nginx에서는 다음과 같이 설정합니다.

```yaml
sdk-backend:
  ingress:
    annotations:
      nginx.ingress.kubernetes.io/proxy-buffering: "off"
      nginx.ingress.kubernetes.io/proxy-read-timeout: "270"
      nginx.ingress.kubernetes.io/proxy-send-timeout: "270"
```

사용자와 같은 네트워크 경로에 있는 컴퓨터에서, 고객사 `sdk-backend` 호스트로
경로를 확인하세요.

```bash
curl -sN https://moss-sdk-api.example.com/api/v1/activity/probe \
  | while IFS= read -r line; do printf '%s  %s\n' "$(date +%H:%M:%S)" "$line"; done
```

이벤트 세 개가 1초 간격으로 도착하면 경로에 문제가 없습니다. 2초쯤 지나 모든
줄이 한꺼번에 도착하면 경로의 무언가가 응답을 버퍼링하고 있습니다. ALB, Envoy,
Istio, Traefik, CDN 설정은 차트의 `docs/sse.md`에 있습니다.

스트림이 없어도 Moss는 답합니다. 로더는 고정된 행을 보여 주며, 프록시가 스트림을
거부하면 SDK가 스스로 일반 경로로 돌아갑니다.

## 자주 묻는 질문

**Moss에서 Pinecone 비공개 엔드포인트를 쓸 수 있나요?**
네, 0.16.20부터 쓸 수 있습니다. 세 워크로드 모두에
`PINECONE_USE_PRIVATE_ENDPOINT=true`를 설정하고, 인덱스 조회를 위해
`api.pinecone.io`에는 계속 연결할 수 있게 두세요.
[Pinecone 벡터 인덱스](#pinecone-벡터-인덱스)를 참고하세요.

**워커가 프록시를 거쳐야만 밖으로 나갈 수 있습니다. 무엇이 동작하나요?**
Firecrawl 호출과, 0.17.0부터 Intercom 호출은 `HTTPS_PROXY`를 따릅니다. 이미지,
사이트맵, Document360 요청은 프록시를 쓰지 않으므로 직접 나갈 수 있어야 합니다.
[프록시](#프록시)를 참고하세요.

**업그레이드 후 사내망의 이미지나 사이트맵을 불러오지 못합니다. 왜 그런가요?**
0.16.22부터 워커는 이런 요청에서 사설 주소를 거부합니다. 해당 호스트나 범위를
`WORKER_FETCH_ALLOWLIST`에 넣으세요.

**Zendesk 호출이 고객사 프록시를 거치게 할 수 있나요?**
네. 0.16.24부터 `ZENDESK_USE_ENV_PROXY=true`를 설정하고 `HTTPS_PROXY`에
`http://` 프록시를 넣으면 됩니다.

**로더에 실시간 단계가 표시되지 않습니다. 왜 그런가요?**
브라우저와 `sdk-backend` 사이의 무언가가 스트림을 버퍼링하거나 끊고 있습니다.
[로더의 실시간 단계](#로더의-실시간-단계)의 확인 명령을 실행해 보세요.

**API 액션으로 내부 API를 호출할 수 있나요?**
아니요. API 액션과, 0.17.0부터 MCP 연결은 공개 `https` 주소에만 연결하며, 이
동작은 바꿀 수 없습니다.
