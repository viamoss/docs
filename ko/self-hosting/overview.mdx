자체 호스팅 설치에서는 Moss 서버를 고객사의 Kubernetes 클러스터에서 Helm
차트로 실행합니다. 웹 앱에 SDK를 넣으면 사용자의 브라우저는 고객사 설치와
통신합니다. 관리자는 고객사 설치에 있는 Moss 대시보드를 쓰며, 고객사의 ID
공급자를 통해 로그인합니다.

이 페이지는 전체 그림을 잡기 위한 안내입니다. 운영자용 전체 레퍼런스는 차트와
함께 배포되는 README입니다. [전체 운영자 레퍼런스](#전체-운영자-레퍼런스)를
참고하세요.

## 설치에서 실행되는 것

| 워크로드 | 하는 일 |
|---|---|
| `sdk-backend` | SDK가 호출하는 API입니다. 채팅 턴, 가이드 단계, 세션 녹화, 그리고 SDK가 시작할 때 불러오는 구성을 처리합니다. |
| `dashboard-backend` | 대시보드 뒤의 API입니다. 설정, 지식 베이스, 분석, 코파일럿을 처리합니다. 지식 소스 자동 새로고침, 모니터, 대화 인사이트 같은 예약된 백그라운드 작업도 실행합니다. |
| `worker` | 지식 베이스 파이프라인입니다. 페이지를 찾아 가져오고, 페이지 속 이미지를 설명한 뒤, 나누어 색인합니다. |
| `dashboard` | 관리자와 콘텐츠 담당자가 쓰는 웹 대시보드입니다. |
| 마이그레이션 Job | 설치와 업그레이드 전에 매번 데이터베이스 마이그레이션을 실행합니다. |
| 보존 CronJob | 선택 사항이며 0.17.0부터 있습니다. 자동 삭제를 켠 애플리케이션의 데이터를 삭제합니다. [운영](/ko/self-hosting/operations#보존-cronjob)을 참고하세요. |

두 백엔드는 같은 이미지를 `SERVICE_MODE` 값(`sdk` 또는 `dashboard`)만 달리해서
실행하므로 각각 따로 확장할 수 있습니다. 차트는 기본으로 각 워크로드를 레플리카
하나로 실행합니다.

## 필요한 서비스

| 서비스 | 용도 | 참고 |
|---|---|---|
| PostgreSQL | 아래 항목을 뺀, Moss가 저장하는 모든 것 | 지식 베이스용 데이터베이스를 따로 둘 수도 있습니다(`KNOWLEDGE_BASE_DATABASE_URL`). |
| Redis | 수집 작업 큐와 SDK 요청 제한 카운터 | 백엔드와 워커가 같은 인스턴스를 써야 합니다. |
| S3 호환 오브젝트 스토리지 | 스크린샷, 세션 녹화, 페이지 스냅샷, 지식 베이스 이미지 | Amazon S3, MinIO, SeaweedFS 등 |
| Pinecone | 지식 베이스 검색 | 애플리케이션이 쓰는 임베딩 모델마다 인덱스가 하나씩 필요합니다. 프로덕션에서는 `PINECONE_API_KEY`가 없으면 두 백엔드 모두 시작하지 않습니다. |
| 모델 공급자 | 채팅 답변과 대시보드의 AI 기능 | [모델과 응답 시간](/ko/self-hosting/models-and-response-time)을 참고하세요. |
| 임베딩 공급자 | 지식 베이스 검색 | 애플리케이션을 만들 때 애플리케이션마다 고릅니다. |
| OIDC ID 공급자 | 대시보드 로그인 | Okta, Microsoft Entra ID, Keycloak 등 |

차트는 PostgreSQL, Redis, S3 호환 스토리지(SeaweedFS)를 클러스터 안에서 실행할 수
있으며, 기본값도 그렇습니다. 직접 관리하는 서비스를 쓰려면 각각 끄세요.

선택 서비스로는 웹사이트 지식 소스용 Firecrawl, 추적용 OpenTelemetry 수집기,
알림용 Slack 웹훅이 있습니다. 모든 외부 연결과 그중 사설망에 둘 수 있는 것은
[네트워크](/ko/self-hosting/network)에 정리되어 있습니다.

자격 증명은 Kubernetes Secret 세 개에 나누어 넣습니다. 백엔드용(`moss-backend`),
워커용(`moss-worker`), 대시보드용(`moss-dashboard`)입니다. 관리자가 대시보드에
입력하는 자격 증명을 암호화하는 `SECRET_ENCRYPTION_KEYS` 값은 `moss-backend`와
`moss-worker`에서 같아야 합니다. 사본을 꼭 보관하세요. 이 값이 없으면 그 자격
증명을 되살릴 방법이 없습니다.

## 배포 방식: Helm 차트와 이미지

- **차트**는 비공개 레지스트리에 있는 OCI 아티팩트
  `oci://ghcr.io/viamoss/charts/moss`입니다. 차트와 이미지를 받을 수 있는 읽기
  전용 토큰은 Moss가 발급하니 Moss 담당자에게 요청하세요. 차트와 이미지를 고객사
  레지스트리로 미러링해 써도 됩니다.
- **이미지**는 `moss-backend`(두 백엔드, 마이그레이션 Job, 보존 CronJob),
  `moss-worker`, 그리고 대시보드 이미지입니다. 대시보드는 OIDC로 로그인하는
  `moss-dashboard-oidc` 이미지를 쓰세요. 로그인 방식은 대시보드 이미지에 빌드
  시점에 들어가므로 실행 중에 바꿀 수 없고, 차트의 기본 대시보드 이미지는 호스팅
  서비스용입니다.
- **버전**: 이미지 태그는 기본으로 차트 버전을 따르므로, 차트 버전 하나에 맞는
  이미지가 함께 따라옵니다. 이미지 태그를 고정한다면 모두 차트 버전으로
  맞추세요.
- **서명**: 차트와 이미지는 cosign으로 서명되어 있습니다. 설치 전에 서명을
  확인하는 방법과 클러스터에서 서명을 강제하는 방법은 차트 README에 있습니다.
- **SDK**는 npm 패키지 `@viamoss/moss-sdk`이며, 서버와 같은 버전 번호로
  출시됩니다. [버전 및 호환성](/ko/versioning)을 참고하세요.

## 업그레이드

1. [변경 이력](/ko/changelog)에서 **해당 릴리스의 노트를 읽고** 데이터베이스를
   백업하세요. 마이그레이션은 되돌릴 수 없는 경우가 있습니다.
2. 사용 중인 values로 **차트가 렌더링되는지 확인하세요**:
   `helm template <release> oci://ghcr.io/viamoss/charts/moss --version <version> -f values.override.yaml`.
3. values 파일을 넘겨 `helm upgrade`로 **서버를 업그레이드하세요**. 새 파드가
   시작되기 전에 마이그레이션 Job이 마이그레이션을 실행합니다. 마이그레이션이
   실패하면 업그레이드가 멈추고, 로그를 읽을 수 있도록 실패한 Job이 남습니다.
4. 서버를 올린 뒤 **SDK를 같은 버전으로 업그레이드하세요**. 새 SDK는 이전 서버가
   거부하는 기능을 쓸 수 있습니다. 예를 들어 0.16.25 서버는 SDK 0.17.0이 보낼 수
   있는 1–5점 별점을 거부합니다.

<Warning>
  차트에서 각 워크로드의 `env`는 목록이며, Helm은 목록을 통째로 교체합니다.
  values 파일에 `env`를 넣으면 차트가 그 워크로드에 기본으로 넣어 둔 항목이
  `SERVICE_MODE`를 포함해 모두 빠집니다. `env`를 설정할 때는 차트의 기본 항목도
  다시 적으세요. 방법은 차트 README의 Environment Variables 섹션에 있습니다.
</Warning>

## 대시보드 로그인과 역할

자체 호스팅 대시보드는 고객사의 OIDC ID 공급자로 로그인하며, 설치 하나가 조직
하나입니다. 조직은 `ON_PREM_ORG_ID`로 정합니다. 다음을 설정하세요.

| 위치 | 설정 |
|---|---|
| 두 백엔드 | `AUTH_PROVIDER=oidc`, `OIDC_ISSUER`, `OIDC_AUDIENCE`, `ON_PREM_ORG_ID`, `OIDC_ADMIN_GROUPS`, 그리고 선택적으로 `OIDC_MEMBER_GROUPS`와 `OIDC_ROLE_CLAIM` |
| 대시보드 | `AUTH_SECRET`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `ON_PREM_ORG_ID`, `OIDC_ADMIN_GROUPS`, 그리고 선택적으로 `OIDC_MEMBER_GROUPS`, `OIDC_ROLE_CLAIM`, `OIDC_REFRESH_TOKENS` |

`OIDC_AUDIENCE`에는 쉼표로 구분한 목록을 넣습니다. 이 목록에 대시보드의 OIDC
클라이언트 ID가 없으면 사용자는 로그인할 때마다 다시 로그인 화면으로 돌아갑니다.

일반적인 구성처럼 인그레스나 리버스 프록시 뒤에 둔다면, 대시보드에
`AUTH_TRUST_HOST=true`와 공개 URL을 넣은 `AUTH_URL`도 필요할 수 있습니다.

대시보드의 역할은 **관리자**와 **멤버** 두 가지입니다. Moss는 로그인할 때마다
토큰의 `groups` 클레임에서 사용자의 그룹을 읽으며(`OIDC_ROLE_CLAIM`으로 다른
클레임을 지정할 수 있습니다), 역할을 따로 저장하지 않습니다.

| 사용자의 그룹 | 역할 |
|---|---|
| `OIDC_ADMIN_GROUPS`에 있는 그룹 중 하나 | 관리자 |
| 그 밖에, `OIDC_MEMBER_GROUPS`가 설정되지 않은 경우 | 멤버: 로그인할 수 있는 사람 모두 |
| 그 밖에, `OIDC_MEMBER_GROUPS`에 있는 그룹 중 하나 | 멤버 |
| 어느 쪽도 아님 | 거부되며 Access Denied 페이지가 표시됨 |

백엔드와 대시보드에 같은 그룹 목록을 설정하세요. 역할은 설치의 모든
애플리케이션에 똑같이 적용됩니다. 멤버는 **구성** 페이지와 **API 로그**를 열 수
없습니다. 역할별로 할 수 있는 일은 [대시보드 개요](/ko/dashboard/overview)를
참고하세요.

대시보드 세션은 ID 공급자가 발급한 ID 토큰만큼 유지됩니다. Okta라면 60분입니다.
0.16.19부터 대시보드에 `OIDC_REFRESH_TOKENS=true`를 설정하면 대시보드가 리프레시
토큰으로 토큰을 갱신합니다. 먼저 ID 공급자에서 Moss에 리프레시 토큰 그랜트를
허용하세요. 그러지 않으면 모든 로그인이 실패합니다.

## SDK 요청 제한

0.17.0부터 `sdk-backend`는 SDK 사용자마다 요청을 보낼 수 있는 속도를 제한하며,
횟수는 Redis에서 셉니다. `SDK_RATE_LIMITS_ENABLED`의 기본값은 `true`이고 차트도
`sdk-backend`에 이 값을 설정합니다. 0.16.x에서는 기본으로 꺼져 있었습니다.

| 제한 | 단위 |
|---|---|
| 분당 세션 시작 30회 | 애플리케이션별 사용자 |
| 분당 질문 60회 | 애플리케이션별 사용자 |
| 분당 가이드 단계 완료 120회 | 채팅 |
| 분당 녹화 업로드 10회 | 세션 |

제한을 넘은 요청은 `Retry-After`와 함께 429를 받습니다. 사용자에게 보이는 것은
요청마다 다릅니다.

- **질문이나 가이드 단계**: 채팅에 "요청이 너무 많습니다. 잠시 후 다시 시도해
  주세요."가 다시 시도 버튼과 함께 표시됩니다.
- **새 채팅 시작**: SDK가 30초쯤 재시도한 뒤 연결 오류 "연결 실패"를 **다시 시도**
  버튼과 함께 표시합니다.
- **녹화 업로드**: 채팅에는 아무것도 표시되지 않습니다. 브라우저 콘솔에 실패한
  업로드가 기록됩니다.

네 가지를 모두 끄려면 `sdk-backend`에 `SDK_RATE_LIMITS_ENABLED=false`를
설정하세요. 예를 들어 많은 사용자가 토큰 subject 하나를 함께 쓸 때 필요합니다.

## 자주 묻는 질문

**대시보드에서 누가 무엇을 할 수 있고, 역할은 어디서 정해지나요?**
역할은 ID 공급자의 그룹에서 정해집니다. `OIDC_ADMIN_GROUPS`의 그룹에 속한
사용자는 관리자, `OIDC_MEMBER_GROUPS`의 그룹에 속한 사용자는 멤버가 됩니다.
`OIDC_MEMBER_GROUPS`를 설정하지 않으면 로그인할 수 있는 사람 모두가 멤버입니다.
[대시보드 로그인과 역할](#대시보드-로그인과-역할)을 참고하세요.

**서버와 SDK 중 무엇을 먼저 업그레이드하나요?**
서버를 먼저 올리고, 그다음 SDK를 같은 버전으로 올리세요.
[업그레이드](#업그레이드)를 참고하세요.

**모든 설정 목록은 어디에 있나요?**
차트와 함께 배포되는 README에 있습니다. `helm show readme`로 사용 중인 버전의
README를 출력할 수 있습니다.

**설정 하나를 추가했더니 파드에서 `SERVICE_MODE`가 사라졌습니다. 왜 그런가요?**
values 파일의 `env` 목록은 그 워크로드에 대한 차트의 목록 전체를 대체합니다.
차트의 기본 항목을 그 목록에 다시 적으세요.
