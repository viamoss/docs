가이드는 Moss가 다음에 쓸 요소를 하이라이트하면서, 페이지에서 할 작업을 사용자에게 한 단계씩 안내하는 기능입니다. 이 페이지에서는 가이드가 진행되는 동안 사용자가 보는 것, 가이드가 끝나는 경우, 그리고 채팅과 가이드가 페이지 로드를 넘어 이어지도록 설정할 것을 설명합니다.

가장 흔한 설정은 다음과 같습니다. 앱의 루트 근처, 라우터보다 위에 `AgentProvider`를 한 번 마운트하고, `stability.afterReload`를 켜서 클릭하면 새 페이지가 로드되는 가이드 단계도 그 페이지에서 이어지게 하세요.

```tsx
<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  stability: {
    afterReload: { enabled: true },
  },
}}>
  <App />
  <AssistantButton />
</AgentProvider>
```

## 가이드가 진행되는 방식

1. **제안.** 질문에 대한 Moss의 답변에 페이지에서 따라 할 단계 계획이 함께 오면, Moss는 가이드를 제안합니다. 답변에 **가이드 시작** 버튼이 붙습니다. 버튼의 라벨과 아이콘은 `chrome.guideOffer`로 바꿀 수 있습니다. [외관](/ko/sdk/appearance#가이드-제안과-가이드)을 참고하세요.
2. **시작.** 사용자가 **가이드 시작**을 누르거나 채팅에서 좋다고 답하면 가이드가 시작됩니다. Moss는 가이드 바에 계획을 보여 주고 첫 단계의 요소를 하이라이트합니다.
3. **각 단계.** Moss는 사용할 요소에 외곽선을 그리고, 대상이 여러 개인 단계에는 번호 배지를 붙입니다. 사용자는 하이라이트된 요소를 사용해 단계를 마칩니다. 클릭할 대상이 없는 단계에는 **다음** 버튼과 함께 "이 단계를 마쳤으면 다음을 눌러 계속하세요."가 나옵니다.
4. **단계 사이.** Moss는 페이지가 안정될 때까지 기다린 뒤 페이지를 다시 읽고 다음 단계를 하이라이트합니다. 그동안 가이드 바에는 "작업 중…"이 나옵니다.
5. **끝.** 모든 단계를 마치면 가이드 바에 평가 버튼, **완료** 버튼과 함께 "목표 완료!"가 나옵니다.

답변이 가이드를 제안하려면 대시보드의 스위치 두 개가 모두 켜져 있어야 합니다. 둘 다 **구성 > 동작**에 있습니다.

| 스위치 | 카드 | 기본값 | 끄면 |
|--------|------|--------|------|
| **화면 가이드** | **주요 기능** | 켜짐 | Moss는 채팅으로만 답하며, 요소를 하이라이트하거나 가이드를 제안하지 않습니다. |
| **계획 기능 활성화** | **계획 진행 추적** | 꺼짐 | Moss는 답변에서 요소를 하이라이트할 수는 있지만, 가이드를 제안하지 않습니다. |

새 애플리케이션은 **계획 기능 활성화**가 꺼져 있으니, 가이드를 쓰려면 켜세요.

### 사용자가 보는 것

| 요소 | 하는 일 | 바꾸는 방법 |
|------|---------|-------------|
| 하이라이트 | 사용할 요소에 그리는 외곽선과 반투명 채우기. 기본 색은 빨간색입니다 | `colors.highlight` |
| 단계 배지 | 대상이 여러 개인 단계에서 각 대상에 붙는 번호 | `chrome.guide.targetBadges` |
| 페이지 음영 | 대상 주변의 페이지를 어둡게 하는 선택 기능 | `chrome.guide.pageTint` |
| 가이드 바 | 채팅 맨 위, 헤더 아래에 있습니다. 현재 단계의 번호와 제목, 진행 막대를 보여 줍니다. 펼침 화살표를 누르면 전체 단계 목록이 열립니다. | — |
| **다음** | 가이드 바에 있고, 클릭할 대상이 없는 단계에서는 입력창 옆에도 있습니다 | `chrome.guide.nextInBar`, `chrome.guide.nextBesideInput` |
| **가이드 종료** | 가이드 바의 단계 목록 맨 끝에 있습니다. 가이드를 끝내기 전에 "가이드를 종료하시겠습니까?"라고 묻습니다. | — |
| 패널 배치 | 플로팅 채팅 창이 하이라이트된 요소를 피해 비켜섭니다. 비켜설 수 없으면 "강조된 항목이 이 패널 뒤에 가려져 있습니다." 안내와 **패널 이동** 버튼이 나타납니다. | `layout`, `modal` |
| **최소화** | 0.17.0부터. 가이드가 진행되는 동안 플로팅 창을 헤더와 가이드 바만 남기고 줄입니다 | `chrome.guide.minimize` |

각 키의 자세한 내용은 [외관](/ko/sdk/appearance#가이드-제안과-가이드) 페이지에 있습니다.

### 직접 만드는 가이드 컨트롤

`useAgent()`는 가이드의 상태와 동작을 제공하므로, 페이지에 직접 만든 컨트롤을 둘 수 있습니다.

- `planPhase`: 가이드가 제안된 동안 `'offered'`, 진행 중에는 `'executing'`, 가이드가 없으면 `null`, Moss가 아직 상태를 알리지 않았으면 `undefined`입니다.
- `acceptGuideSuggestion()`은 **가이드 시작**처럼 제안된 가이드를 시작합니다.
- `continueGuide()`는 **다음**처럼 다음 단계로 넘어갑니다.

[Hooks](/ko/sdk/api/hooks)를 참고하세요.

## 가이드가 끝나는 경우

| 일어난 일 | 결과 |
|-----------|------|
| 사용자가 마지막 단계를 마치거나 **완료**를 누름 | 가이드가 완료로 끝납니다. |
| 사용자가 **가이드 종료**를 누르고 확인함 | 가이드가 끝나고 하이라이트가 사라집니다. |
| 사용자가 새 채팅을 시작하거나, 앱 코드가 `startNewChat()` 또는 `askMoss()`를 호출함 | 대화가 끝나고, 가이드도 함께 끝납니다. |
| Moss가 다른 가이드를 시작함 | 새 가이드가 이전 가이드를 대체합니다. |
| 사용자가 가이드에서 접수한 지원 티켓이 전송됨 | 가이드가 끝납니다. |
| 사용자가 채팅을 닫음 | 기본적으로 가이드는 계속됩니다. 하이라이트가 페이지에 남고, 채팅을 다시 열면 가이드가 이어집니다. `closingChatEndsGuide: true`이면 채팅을 닫을 때 **가이드 종료**와 같이 가이드가 끝납니다. |
| 사용자가 세션의 비활성 시간이 지난 뒤 돌아옴 | 세션 설정에 따라 다릅니다. [세션](/ko/sdk/api/session#제한을-넘었을-때의-동작)을 참고하세요. |

### `closingChatEndsGuide`

| 옵션 | 타입 | 기본값 |
|------|------|--------|
| `closingChatEndsGuide` | `boolean` | `false` |

기본값 `false`에서는 채팅이 닫혀 있는 동안에도 가이드가 계속 진행됩니다. 채팅이 닫혀 있을 때 [`FloatingActionBar`](#floatingactionbar)처럼 자체 가이드 컨트롤을 보여 주는 페이지에 맞는 설정입니다. 새로 고침하면 가이드가 돌아옵니다.

`true`이면 채팅을 어떤 방식으로 닫든 진행 중인 가이드가 **가이드 종료**와 같이 끝납니다. 채팅의 닫기 버튼, `AssistantButton`, `data-moss-trigger` 요소, 앱 코드의 `closeChat()`이나 `toggleChat()` 호출이 모두 해당합니다. 하이라이트가 사라지고, 단계의 요소를 클릭해도 아무것도 전송되지 않으며, 새로 고침해도 가이드가 돌아오지 않습니다. 채팅을 다시 열면 가이드 없이 대화가 이어집니다.

페이지에 자체 가이드 컨트롤이 없다면 `true`로 설정하세요. 그렇지 않으면 가이드 도중 채팅을 닫은 사용자에게는 하이라이트만 남고, 그 하이라이트를 설명하는 것이 화면에 없습니다.

```tsx
<AgentProvider config={{
  // ...
  closingChatEndsGuide: true,
}}>
```

## 새로 고침, 리디렉션, 새 탭

Moss는 상태를 브라우저에 오리진별로 저장합니다. 채팅 세션은 `localStorage`에, 채팅이 열려 있는지와 창의 위치는 탭별로 저장되는 `sessionStorage`에 둡니다.

| 일어난 일 | Moss의 동작 | 필요한 것 |
|-----------|-------------|-----------|
| 싱글 페이지 앱의 클라이언트 측 페이지 이동 | `AgentProvider`가 마운트된 채로 있으면 아무것도 바뀌지 않습니다. | 라우터보다 위에 마운트하세요. |
| 같은 탭에서의 새로 고침이나 리디렉션 | Moss가 같은 채팅으로 돌아옵니다. 열려 있었으면 열린 채로, 진행 중이던 가이드도 함께 돌아옵니다. | 로드되는 페이지의 `AgentProvider` |
| 클릭하면 새 페이지가 로드되는 가이드 단계 | 로드된 페이지에서 그 단계가 완료되고, 가이드가 거기서 이어집니다. | `stability.afterReload.enabled: true` |
| 가이드 단계가 직접 사용자를 다른 페이지로 보냄 | 그 페이지가 로드되면 Moss가 가이드를 이어 갑니다. | 추가로 필요한 것 없음 |
| 클릭하면 새 탭이 열리는 가이드 단계 | 가이드가 새 탭에서 이어지며, 채팅이 열려 있었다면 Moss가 새 탭에서도 채팅을 엽니다. | `stability.afterReload.enabled: true`, 그리고 새 탭 페이지의 Moss |
| 페이지가 `window.open()`으로 연 탭 | 채팅이 닫힌 상태로, 가이드 없이 시작합니다. | — |
| 같은 앱의 다른 탭 | 채팅 세션을 공유합니다. 가이드는 한 탭에서 진행되며, Moss가 열려 있는 다른 탭은 그 가이드를 채팅에 보여 줍니다. | — |
| 다른 오리진이나 서브도메인 | 처음부터 시작합니다. 브라우저 저장소는 오리진 간에 공유되지 않습니다. | — |

### `stability.afterReload`

| 옵션 | 타입 | 기본값 | 하는 일 |
|------|------|--------|---------|
| `stability.afterReload.enabled` | `boolean` | `false` | 가이드 단계의 클릭이 새 페이지를 로드하거나 새 탭을 열 때, 그 단계를 다음 페이지로 넘깁니다 |
| `stability.afterReload.pendingTTL` | `number` (ms) | `30000` | 넘겨진 단계가 다음 페이지에서 Moss가 로드되어 이어받기를 기다리는 시간 |

느린 로그인 리디렉션 뒤에 있는 페이지처럼 다음 페이지가 Moss를 로드하는 데 `pendingTTL`보다 오래 걸린다면 이 값을 늘리세요.

## 필요할 때 Moss 로드하기

도움말 메뉴처럼 사용자가 요청할 때만 Moss를 마운트하는 앱도 있습니다. 이런 앱에서는 대화나 가이드 도중에 새로 고침하거나 다른 페이지 링크를 따라가면 Moss가 마운트되지 않은 채로 남습니다. `shouldStartMoss()`는 페이지가 로드될 때, 이어 가기 위해 Moss를 마운트해야 하는지 알려 줍니다.

```tsx
import { useEffect } from 'react';
import { createRoot, type Root } from 'react-dom/client';
import { AgentProvider, useAgent } from '@viamoss/moss-sdk';
import { shouldStartMoss } from '@viamoss/moss-sdk/start';

let root: Root | null = null;
let openMoss: (() => void) | null = null;
let openRequested = false;

// 마운트된 provider의 openChat을 메뉴에 넘깁니다. provider가 렌더링되기
// 전에 들어온 클릭은 보관했다가, 렌더링되면 채팅을 엽니다.
function MossOpener() {
  const { openChat } = useAgent();
  useEffect(() => {
    openMoss = openChat;
    if (openRequested) {
      openRequested = false;
      openChat();
    }
  }, [openChat]);
  return null;
}

function mountMoss(openNow: boolean) {
  if (openNow) {
    if (openMoss) openMoss();
    else openRequested = true;
  }
  if (root) return;
  root = createRoot(document.getElementById('moss-root')!);
  root.render(
    <AgentProvider config={mossConfig}>
      <MossOpener />
    </AgentProvider>,
  );
}

// 페이지 로드 시: 이전 상태를 되살릴 때만 Moss를 마운트합니다.
if (shouldStartMoss()) mountMoss(false);

// 도움말 메뉴 항목: 아직 마운트되지 않았으면 Moss를 마운트하고 채팅을 엽니다.
helpMenuItem.addEventListener('click', () => mountMoss(true));
```

`mossConfig`는 `AgentProvider`에 넘기는 설정으로, `stability.afterReload.enabled: true`를 포함합니다.

`shouldStartMoss()`는 다음 경우에 `true`를 반환합니다.

- 페이지가 바뀌기 전에 이 탭에서 채팅이 열려 있었을 때
- 이 탭에서 `askMoss()`로 한 질문이 기다리고 있을 때
- 이 탭에서 가이드가 진행 중일 때
- 새로 고침이나 가이드의 페이지 이동 뒤에 가이드 단계가 이 페이지로 넘어오는 중이거나, 가이드 단계의 클릭으로 이 페이지가 새 탭에서 열렸을 때

규칙:

- **한 번 마운트하고 그대로 두세요.** `true`를 반환하면 채팅을 열거나 토글하지 말고 `AgentProvider`만 마운트하세요. Moss가 알아서 채팅을 다시 열고 가이드를 이어 가며, 토글하면 오히려 채팅이 닫힙니다. 나중에 채팅을 열 때는 다시 마운트하지 말고, 마운트한 Moss의 `openChat()`을 쓰세요.
- **가이드 단계를 넘기려면 `stability.afterReload.enabled: true`가 필요합니다.**
- **`stability.afterReload.pendingTTL`을 설정했다면 같은 값을 넘기세요:** `shouldStartMoss({ pendingTTL })`.
- **브라우저에서 호출하세요.** 서버나 `window`가 없는 곳에서는 `false`를 반환합니다. 서버 렌더링을 쓴다면 하이드레이션 뒤에 호출하세요.
- **읽기만 합니다.** Moss가 쓰는 브라우저 저장소를 읽을 뿐 아무것도 쓰지 않으며, 예외를 던지지 않습니다. 저장소를 읽을 수 없으면 `false`를 반환합니다. Moss의 저장소 키를 직접 쓰거나 지우지 마세요.
- **같은 오리진에서만 동작합니다.** 호스트 이름이 다르면 저장소도 따로이므로, 그곳에서는 `false`를 반환합니다.

### `@viamoss/moss-sdk/start` 진입점

`shouldStartMoss()`와 `askMoss()`는 `@viamoss/moss-sdk/start`에서 가져오세요. 이 진입점은 React를 포함하지 않고 로드될 때 DOM을 건드리지 않으므로, Moss를 로드할지 정하기 위해 SDK를 먼저 로드할 필요가 없습니다. 패키지 루트에서도 두 함수를 내보냅니다.

이 함수들은 npm 패키지용입니다. CDN 스크립트는 로드되는 모든 페이지에 Moss를 마운트합니다.

## 질문과 함께 Moss 열기

`askMoss(question)`은 Moss가 마운트되어 있든 아니든 새 채팅을 시작해 열고, 질문을 사용자의 첫 메시지로 보냅니다. 자체 도움말 위젯이나 어시스턴트가 질문을 Moss에 넘길 때 쓰세요.

```tsx
import { askMoss } from '@viamoss/moss-sdk/start';

function startInteractiveHelp(question: string) {
  const result = askMoss(question);
  if (!result.accepted) return; // 빈 질문이거나 브라우저 저장소를 쓸 수 없음
  if (result.queued) {
    // 이 페이지의 Moss가 질문을 받지 않았습니다. 채팅을 열지 말고 마운트하세요.
    // Moss가 마운트되면서 질문과 함께 채팅을 엽니다.
    mountMoss(false);
  }
  // 그 밖의 경우: 이 페이지에 이미 있던 Moss가 질문을 받아 채팅을 열었습니다.
}
```

| 결과 | 의미 |
|------|------|
| `{ accepted: true, queued: false, id }` | 마운트된 Moss가 질문을 받아 채팅을 엽니다. |
| `{ accepted: true, queued: true, id }` | 이 페이지의 Moss가 질문을 받지 않았습니다. 질문은 이 탭에서 기다리며, 대기 시간 안에 Moss를 마운트하면 마운트되면서 질문을 보냅니다. |
| `{ accepted: false, reason: 'empty' }` | 질문이 비어 있거나 문자열이 아니었습니다. |
| `{ accepted: false, reason: 'unavailable' }` | 서버에서처럼 `window`가 없거나, 이 탭의 `sessionStorage`에 쓸 수 없습니다. |

| 옵션 | 타입 | 기본값 | 하는 일 |
|------|------|--------|---------|
| `ttlMs` | `number` (ms) | `30000` | 대기 중인 질문이 Moss의 마운트를 기다리는 시간. 양수가 아닌 값은 기본값으로 처리합니다. |

Moss는 질문을 다음과 같이 처리합니다.

- **진행 중인 채팅이나 가이드는 끝납니다.** 새 질문 버튼을 누를 때와 같으며, 그 전에 평가나 '이 대화 이어가기' 안내를 보여 주지 않습니다.
- **질문을 요청한 탭에서 한 번만 보냅니다.** 그 탭이 먼저 새로 고침되거나 다른 페이지로 이동하면, 대기 시간 안에 다음 페이지의 Moss가 보냅니다. 기다리는 동안 `shouldStartMoss()`는 `true`를 반환합니다.
- **사용자 텍스트로 취급합니다.** Moss는 앞뒤 공백을 없애고, HTML이 아닌 일반 텍스트로 보여 주며, 입력한 메시지처럼 보냅니다.
- **아직 보내지 않은 질문은 나중의 호출이 대체합니다.** 보내기 전에 사용자가 채팅을 닫거나 새 채팅을 시작하면 질문은 버려집니다.
- **`onEvent`를 쓰면,** 요청이 나갈 때 `source: 'host'`로 `Moss Question Asked`가 발생합니다. [이벤트](/ko/sdk/events)를 참고하세요.
- **마운트할 때 채팅을 토글하지 마세요.** Moss가 질문을 위해 채팅을 여는데, 토글하면 채팅이 닫히고 질문이 버려집니다.
- **같은 창, 같은 오리진에서 호출하세요.** `askMoss()`는 Moss와 같은 창, 같은 오리진에서 호출해야 합니다. 탭을 구분하기 위해 `window.name`을 읽으며, 이름이 없으면 창에 이름을 붙입니다.

`askMoss()`는 React를 로드하지 않고, 아무것도 마운트하지 않으며, 예외를 던지지 않습니다.

## FloatingActionBar

`FloatingActionBar`는 채팅이 닫혀 있는 동안 페이지 아래쪽에 Moss를 보여 주는 선택 컴포넌트입니다. 사용자가 채팅을 닫은 채로 따라가는 가이드에 맞습니다.

```tsx
import { AgentProvider, AssistantButton, FloatingActionBar } from '@viamoss/moss-sdk';

<AgentProvider config={config}>
  <App />
  <AssistantButton />
  <FloatingActionBar />
</AgentProvider>
```

| Prop | 타입 | 기본값 | 하는 일 |
|------|------|--------|---------|
| `defaultRevealed` | `boolean` | `false` | 아래쪽 가장자리에서 살짝 보이는 대신 처음부터 전체를 보여 줍니다 |
| `showCoachMark` | `boolean` | `true` | 사용자가 그 브라우저 탭에서 닫을 때까지 "마우스를 올려 내용을 살펴보고, 클릭하여 채팅을 시작하세요." 안내를 보여 줍니다 |

동작 방식:

- 브라우저 창 아래쪽 가운데에 놓이며, 채팅이 열려 있는 동안에는 숨겨집니다.
- 아래쪽 가장자리에서 살짝 보이다가, 마우스를 올리면 전체가 보입니다. 클릭하면 계속 보이고, 전체가 보이는 바를 클릭하면 채팅이 열립니다.
- Moss의 최근 답변을 보여 주며, 답변이 없을 때는 "질문이 있으시면 AI 상담으로 빠르게 확인해보세요!"를 보여 줍니다.
- 가이드가 제안되면 **가이드 받기**를, 가이드 중에는 **다음**을, 가이드가 끝나면 **완료**를 보여 줍니다.
- 종료 컨트롤이 없으므로, 이 컴포넌트를 쓸 때는 `closingChatEndsGuide`를 `false`로 두세요.
- 위젯의 섀도 루트 밖, 페이지의 DOM에 렌더링됩니다. npm 패키지에서만 쓸 수 있습니다.

## 가이드를 위한 안정성 설정

Moss는 응답할 때마다, 그리고 가이드 단계마다 페이지가 안정될 때까지 기다린 뒤 페이지를 읽습니다. 콘텐츠를 여러 번에 나눠 로드하는 페이지에서는 이 대기 시간이 Moss가 다음 단계의 요소를 볼 수 있는지를 좌우합니다. `stability`에서 조정하세요. 레이어 전체에 대한 설명은 [고급 설정](/ko/sdk/advanced#안정성-튜닝)에 있습니다.

| 옵션 | 타입 | 기본값 | 하는 일 |
|------|------|--------|---------|
| `stability.maxTotalWaitMs` | `number` (ms) | `15000` | 레이어별 대기가 걸리는 최대 시간 |
| `stability.layers.loadingIndicators` | `boolean` | `false` | 로딩 표시(스피너, 스켈레톤)가 사라질 때까지 기다립니다 |
| `stability.loadingIndicators.timeoutMs` | `number` (ms) | `5000` | 이 레이어가 기다리는 최대 시간 |
| `stability.loadingIndicators.selectors` | `string[]` | 아래 목록 | 기본 목록을 대체합니다 |
| `stability.loadingIndicators.additionalSelectors` | `string[]` | — | 기본 목록에 추가합니다 |
| `stability.loadingIndicators.excludeSelectors` | `string[]` | — | 로딩으로 치지 않을 요소 |
| `stability.placeholderGuard.enabled` | `boolean` | `true` | Moss가 페이지를 읽기 직전에, 뷰포트에 보이는 로딩 자리 표시자가 사라질 때까지 마지막으로 기다립니다 |
| `stability.placeholderGuard.timeoutMs` | `number` (ms) | `4000` | 가드가 기다리는 최대 시간. `maxTotalWaitMs`에 포함되지 않습니다. |
| `stability.placeholderGuard.selectors` | `string[]` | 아래 목록 | 가드의 목록을 대체합니다 |
| `stability.placeholderGuard.additionalSelectors` | `string[]` | — | 가드의 목록에 추가합니다 |
| `stability.placeholderGuard.excludeSelectors` | `string[]` | — | `loadingIndicators.excludeSelectors`에 더해, 치지 않을 요소 |
| `stability.domMutations.quietPeriodMs` | `number` (ms) | `800` | 페이지에 DOM 변경이 없어야 하는 시간 |
| `stability.domMutations.countQuietBeforeLayer` | `boolean` | `true` | 0.17.0부터. 앞선 레이어가 진행되는 동안의 조용한 시간을 `quietPeriodMs`에 포함합니다. 앞선 레이어가 끝난 뒤 새로 기다리기 시작하지 않습니다 |

로딩 표시 레이어는 `[class*="skeleton" i]`, `[class*="loading"]`, `[class*="spinner" i]`, `[class*="placeholder"]`, `[aria-busy="true"]`, `[data-loading="true"]`, `.shimmer`, `.pulse`, `[class*="loader" i]`를 찾습니다.

자리 표시자 가드는 로딩 표시 레이어가 켜져 있든 아니든 실행됩니다. `[class*="skeleton" i]`, `[data-testid*="skeleton" i]`, `[class*="shimmer" i]`, `.placeholder-glow`, `.placeholder-wave`, `[aria-busy="true"]`, `[data-loading="true"]`를 찾습니다. `loadingIndicators.selectors`를 설정하면 가드도 그 목록을 대신 씁니다. 가드가 시간 초과되면 Moss는 그대로 페이지를 읽습니다.

```tsx
stability: {
  afterReload: { enabled: true },
  layers: { loadingIndicators: true },
  loadingIndicators: {
    additionalSelectors: ['.app-busy'],
    excludeSelectors: ['.always-on-spinner'],
  },
},
```

<Tip>
    항상 떠 있는 스피너나 클래스 이름에 "loading"이 들어간 요소처럼 로딩 선택자에 늘 걸리는 요소가 있으면, 매번 대기 시간이 끝날 때까지 기다리게 됩니다. 그런 요소는 `excludeSelectors`에 추가하세요.
</Tip>

## 자주 묻는 질문

**Moss가 왜 가이드를 제안하지 않았나요?**
Moss는 답변에 페이지에서 따라 할 단계 계획이 함께 올 때만, 그리고 **구성 > 동작**의 두 스위치가 모두 켜져 있을 때만 가이드를 제안합니다. **주요 기능**의 **화면 가이드**(기본으로 켜짐)와 **계획 진행 추적**의 **계획 기능 활성화**(기본으로 꺼짐)입니다. 새 애플리케이션에서는 **계획 기능 활성화**를 켜야 합니다.

**사용자가 채팅을 닫으면 가이드를 끝내려면 어떻게 하나요?**
`closingChatEndsGuide: true`로 설정하세요. 기본적으로는 채팅이 닫혀 있어도 가이드가 하이라이트와 함께 계속 진행됩니다.

**단계가 새 페이지를 로드하면 Moss가 가이드를 잃어버립니다. 어떻게 유지하나요?**
`stability.afterReload.enabled: true`로 설정하고, 로드되는 페이지에서 `AgentProvider`를 마운트하세요. Moss를 필요할 때만 마운트한다면 각 페이지가 로드될 때 `shouldStartMoss()`를 호출하세요.

**새 탭에서는 Moss가 닫힌 상태로 시작합니다. 정상인가요?**
네. 탭마다 열림/닫힘 상태를 따로 저장하며, 페이지가 `window.open()`으로 연 탭은 닫힌 상태로 가이드 없이 시작합니다. 예외는 가이드 단계의 클릭으로 열린 탭으로, `stability.afterReload.enabled`가 켜져 있으면 가이드를 이어 갑니다.

**자체 도움말 메뉴에서 질문과 함께 Moss를 열려면 어떻게 하나요?**
`@viamoss/moss-sdk/start`의 `askMoss(question)`을 호출하세요. Moss가 마운트되어 있든 아니든 동작합니다.

**가이드 중에 사용자가 채팅을 최소화할 수 있나요?**
0.17.0부터 플로팅 레이아웃에서 `appearance.chrome.guide.minimize: true`를 설정하면 가능합니다. [외관](/ko/sdk/appearance#가이드-제안과-가이드)을 참고하세요.

- [Hooks](/ko/sdk/api/hooks): `openChat()`, `closeChat()`, `continueGuide()`
