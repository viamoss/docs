`appearance` 옵션은 Moss 위젯의 모양을 정합니다. 색상, 글꼴, 채팅 창의 레이아웃과 위치, 헤더, 입력창, 푸터, 가이드 컨트롤, 시작 화면, 그리고 Moss가 답하지 못할 때 보여 주는 메시지까지 포함합니다. 이 페이지는 `appearance`의 전체 레퍼런스입니다.

가장 흔한 변경은 브랜드 색상, 헤더 제목, 가이드 하이라이트 색상입니다.

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  appearance: {
    colors: {
      primary: '#0F766E',
      highlight: '#0F766E',
    },
    chrome: {
      title: 'Help',
      header: { showStatusDot: true },
    },
  },
}}>
  <AssistantButton />
</AgentProvider>
```

<Note>
    `chrome.title`은 `chrome.header`가 설정되어 있을 때만 나타납니다. `{}`여도 됩니다. `chrome.header`가 없으면 위젯은 제목이 없는 기존 헤더를 그대로 씁니다. 대시보드에 저장한 **헤더 제목**도 마찬가지입니다. 앱 코드에서 `chrome.header`를 설정하거나, 대시보드에서 **상태 점 표시**를 켜거나 **새 대화 아이콘**을 고르세요.
</Note>

## 외관이 만들어지는 방식

`appearance`에는 프리셋 이름이나 객체를 넣습니다.

| 값 | 결과 |
|----|------|
| 설정하지 않음 | `'blue'` 프리셋 |
| `'blue'` | 기본 프리셋: 파란색 강조색, 반투명 패널 |
| `'purple'` | 보라색 강조색, 불투명 패널, 위쪽 모서리가 둥근 입력 영역 |
| 객체 | 앱 코드의 키를 `'blue'` 위에 병합합니다. 객체에 `name: 'purple'`이 있으면 `'purple'` 위에 병합합니다. |
| 그 밖의 문자열 | `'blue'` 프리셋 |

객체는 이렇게 병합됩니다.

- **키 단위로 병합합니다.** 설정한 키는 그 값 하나만 바꿉니다. 설정하지 않은 키는 프리셋 값을 유지합니다.
- **배열은 통째로 바뀝니다.** `zeroState.suggestedQueries`나 예외 상태의 `ctas` 같은 목록은 프리셋의 목록을 통째로 대체합니다.
- **`null`과 `undefined`는 아무것도 바꾸지 않습니다.** 토큰을 비울 수는 없으니, 원하는 값을 직접 설정하세요.
- **값에 CSS 변수를 쓸 수 있습니다.** `'var(--brand-primary)'`나 `'var(--brand-primary, #0F766E)'` 같은 값은 Moss가 외관을 만들 때 페이지의 루트 요소(`:root`)에서 읽습니다. 변수가 거기에 정의되어 있지 않고 대체값도 없으면 프리셋 값을 씁니다.

크기는 문자열이므로 어떤 CSS 길이든 쓸 수 있습니다(`'12px'`, `'0.75rem'`). 간격과 모서리 반경 토큰은 `px` 단위입니다. 글자 크기는 `rem` 단위라서 위젯의 글자가 페이지의 루트 글자 크기에 맞춰 커지거나 작아집니다.

SDK는 `mergeAppearance(base, overrides)`도 내보냅니다. 갖고 있는 완전한 `MossAppearance` 객체 위에 변경 사항을 깊게 병합합니다.

## 값을 가져오는 곳

앱 코드, 대시보드, 프리셋은 모두 같은 키를 설정할 수 있습니다. 어느 값이 보이는지는 값의 종류와 Moss를 설치한 방식에 따라 다릅니다.

| 항목 | npm 패키지 (`AgentProvider`) | CDN 스크립트 |
|------|------------------------------|--------------|
| **테마와 브랜딩 키** (아래 목록) | 프리셋, 앱 코드의 `appearance`, 대시보드 순으로 적용합니다. 대시보드에 값이 있는 키는 대시보드가 우선합니다. | 동일합니다. |
| **초기 화면** (`zeroState`) | 앱 코드에 `appearance.zeroState`를 설정했다면 그 값을 통째로 씁니다. 없으면 대시보드 값을 씁니다. | 대시보드 값을 씁니다. 단, `window.mossSettings.appearance`에 `zeroState`가 있으면 그 값을 씁니다. |
| **`layout`과 `fallbackStates`** | 앱 코드에서만 읽습니다. 대시보드 값은 적용되지 않습니다. | 애플리케이션에 저장된 값을 씁니다. 단, `window.mossSettings.appearance`를 설정하면 그 객체가 이 값들을 대체합니다. |
| **그 밖의 모든 키** (간격, 모서리 반경, 효과, `modal`, 글꼴, `colors.highlight`, 나머지 `chrome` 그룹) | 앱 코드에서만 읽습니다. | `window.mossSettings.appearance`에서만 읽습니다. |

관리자는 **구성 > 외관**에서 다음 키를 설정합니다.

| 양식 | 필드 | 키 |
|------|------|----|
| **브랜딩** | **헤더 제목** | `chrome.title` |
| **브랜딩** | **상태 점 표시** | `chrome.header.showStatusDot` |
| **브랜딩** | **새 대화 아이콘** | `chrome.header.newChatIcon` |
| **브랜딩** | **입력창**의 **배경 색상 (HEX)** | `chrome.inputBar.backgroundTint` |
| **브랜딩** | **푸터 표시**, 도움말 센터와 티켓의 라벨과 URL, 푸터의 **배경 색상 (hex)** | `chrome.footer.enabled`, `helpCenter`, `openTicket`, `backgroundTint` |
| **테마** | **테두리 색상 (hex)** | `colors.border` |
| **테마** | **패널 그림자** | `shadows.md` |
| **테마** | **제목 글자 크기 (px)** | `typography.fontSize.lg` |
| **테마** | **버튼 색상 (hex)**, **호버 색상 (hex)** | `colors.actionButton`, `colors.actionButtonHover` |
| **테마** | **기본 텍스트 (hex)**, **보조 텍스트 (hex)**, **3차 텍스트와 아이콘 (hex)** | `colors.text.primary`, `colors.text.secondary`, `colors.text.tertiary` |

이 양식에 필드가 없는 테마와 브랜딩 키 몇 개는 API로 애플리케이션에 저장할 수 있습니다. `colors.primary`, `colors.primaryLight`, `colors.primaryLighter`, `shadows.sm`, `shadows.lg`, `chrome.header.statusDotColor`, `chrome.header.newChatStyle`, `chrome.inputBar.placeholder`입니다. 저장된 값은 같은 방식으로 적용되며 앱 코드보다 우선합니다.

대시보드에서 비워 둔 필드는 앱 코드의 값이나 프리셋 값을 그대로 둡니다. 대시보드에 필드가 있는 키를 앱 코드에서 정하려면 그 필드를 비우세요.

초기 화면은 **콘텐츠 > 추천 콘텐츠**에 있습니다. 대시보드 쪽 설명은 [추천 콘텐츠](/ko/dashboard/suggested-content)를 참고하세요.

### 대시보드 값이 전달되는 시점

- **npm 패키지:** 테마, 브랜딩, 초기 화면은 채팅 세션과 함께 전달됩니다. 페이지에서 채팅을 처음 열 때나, 이어 갈 세션이 있는 페이지가 로드될 때입니다. 그전까지 위젯은 프리셋과 앱 코드의 값을 보여 주므로, 처음 열 때 잠시 뒤 모양이 바뀔 수 있습니다. 대시보드에서 바꾼 값은 사용자가 다음에 페이지를 로드하거나 새 채팅을 시작할 때 반영됩니다.
- **CDN 스크립트:** 스크립트가 로드될 때 애플리케이션 설정을 한 번 읽고, 위와 같이 세션이 테마, 브랜딩, 초기 화면을 다시 전달합니다.

CDN 스크립트에서 `window.mossSettings`는 얕게 병합됩니다. 여기에 `appearance` 객체를 넣으면 대시보드의 외관 객체 전체가 대체되며, 그 안의 `layout`과 `fallbackStates`도 함께 사라집니다. 대시보드의 테마, 브랜딩, 초기 화면은 세션과 함께 계속 전달됩니다.

## 설정이 반영되지 않을 때

잘못된 위치에 넣은 키는 오류나 콘솔 경고 없이 무시됩니다. 예를 들어 `appearance.title`은 아무 효과가 없습니다. 제목은 `appearance.chrome.title`입니다. 효과가 없는 설정은 다음 순서로 확인하세요.

1. **TypeScript로 키를 확인하세요.** `config` prop 안에 직접 쓴 객체 리터럴은 SDK의 타입으로 검사되므로, 알 수 없는 키는 컴파일 오류가 납니다. 외관을 별도 변수로 만든다면 타입을 지정해 검사가 계속되게 하세요.

    ```tsx
    import type { AppearanceInput } from '@viamoss/moss-sdk';

    const appearance: AppearanceInput = {
      colors: { primary: '#0F766E' },
      chrome: { title: 'Help', header: {} },
    };
    ```

2. **SDK 버전을 확인하세요.** `logLevel`이 `LogLevel.INFO`(기본값)나 `LogLevel.DEBUG`이면, Moss가 마운트될 때 브라우저 콘솔에 `[MossSDK] v0.17.0 initialized`가 나옵니다. 0.17.0에서 추가된 키는 이전 SDK에서는 아무 효과가 없습니다.
3. **대시보드를 확인하세요.** 위에 나온 테마와 브랜딩 키는 대시보드에 저장된 값이 앱 코드보다 우선합니다.
4. **함께 필요한 키를 확인하세요.** `chrome.title`에는 `chrome.header`가 필요하고, `streamActivity` 옵션에는 `chrome.loader: 'steps'`가 필요합니다. `chrome.guide.minimize`는 도킹 레이아웃에서는 효과가 없습니다.
5. **저장된 위치를 확인하세요.** Moss는 채팅 창의 위치와 크기를 브라우저 탭별로 저장하므로, 바꾼 `modal.defaultPosition`이나 `modal.defaultSize`는 새 탭에서, 또는 기존 헤더의 **윈도우 위치 재설정**을 누른 뒤에 반영됩니다. [사용자가 할 수 있는 동작](#사용자가-할-수-있는-동작)을 참고하세요.

## 페이지 CSS로는 위젯을 꾸밀 수 없습니다

채팅 창은 Moss가 페이지에 추가하는 섀도 루트 안에 렌더링됩니다. 페이지의 스타일시트는 그 안에 적용되지 않으며, Moss는 외관 값에서 인라인 스타일을 만들어 씁니다. 모양을 바꿀 때는 항상 `appearance`를 쓰세요.

다음 두 컴포넌트는 페이지의 DOM에 직접 렌더링되므로 페이지 CSS가 적용됩니다: `AssistantButton`, `FloatingActionBar`.

## 토큰

### 색상

| 키 | 기본값 (`'blue'`) | 적용되는 곳 |
|----|-------------------|-------------|
| `primary` | `#3b82f6` | 주 강조색 |
| `primaryLight` | `#93c5fd` | 호버 상태와 표시기 |
| `primaryLighter` | `#f0f9ff` | 옅은 강조 배경 |
| `primaryBorder` | 설정하지 않으면 `border` | 입력창 테두리 |
| `userMessage` | `#3b82f6` | 사용자 메시지 말풍선 |
| `userMessageText` | 설정하지 않으면 `text.onPrimary` | 사용자 말풍선의 글자. `userMessage`가 밝은 색일 때 설정하세요. |
| `assistantMessage` | `rgba(243, 244, 246, 0.6)` | Moss 메시지 말풍선 |
| `headerBackground` | `rgba(255, 255, 255, 0.95)` | 헤더 |
| `inputAreaBackground` | `rgba(249, 250, 251, 0.9)` | 입력창 주변 영역 |
| `modalBackground` | `rgba(255, 255, 255, 0.15)` | 패널 |
| `text.primary` | `#111827` | 본문 글자 |
| `text.secondary` | `#374151` | 보조 글자 |
| `text.tertiary` | `#6b7280` | 흐린 글자와 아이콘 |
| `text.onPrimary` | `#ffffff` | 강조색 배경 위의 글자 |
| `border` | `#e5e7eb` | 모든 가는 선: 헤더와 푸터 구분선, 카드 테두리 |
| `success` | `#22c55e` | 가이드 바의 완료 상태 |
| `error` | `#ef4444` | 오류와 부정적 평가 |
| `highlight` | 설정하지 않으면 `#FF4444` | 가이드가 가리키는 페이지 요소의 외곽선, 채우기, 배지 |
| `actionButton` | `#3b82f6` | 가이드 시작 버튼과 다음 버튼 |
| `actionButtonHover` | `#93c5fd` | 같은 버튼의 호버 상태 |

`colors.highlight`에는 `#RGB`나 `#RRGGBB` 형식의 16진수 색상을 넣습니다. Moss는 이 색상으로 반투명 채우기를 만듭니다. 이 값은 `AgentProvider`가 마운트될 때 한 번만 읽으므로, 바꾸려면 다시 마운트해야 합니다. 대시보드에서는 설정할 수 없습니다.

`colors.categoryTitle`, `effects.glassOpacity`, `progressBar.height`, `typography.lineHeight.lg`, `spacing['2xl']`은 호환성을 위해 남아 있을 뿐, 0.17.0에서는 눈에 보이는 효과가 없습니다.

### 글꼴

| 키 | 기본값 | 참고 |
|----|--------|------|
| `fontFamily` | `'Inter', system-ui, -apple-system, sans-serif` | 어떤 CSS `font-family` 값이든 됩니다 |
| `fontFaceUrl` | 설정하지 않음 | 사용자 지정 글꼴의 `@font-face` 규칙이 담긴 스타일시트 URL. 아래를 참고하세요. |
| `fontSize.xs` / `sm` / `md` / `lg` | `0.833rem` / `1rem` / `1.167rem` / `2rem` | `lg`는 헤더 제목 크기입니다 |
| `lineHeight.xs` / `sm` / `md` / `lg` | `1.167rem` / `1.333rem` / `1.833rem` / `2.833rem` | |

`rem` 기본값은 루트 글자 크기 12px에 맞춰져 있으며, 이때 10, 12, 14, 24px 글자가 됩니다. 루트가 16px인 페이지에서는 같은 값이 더 큰 글자가 되니, 정확한 크기가 필요하면 `px`로 설정하세요.

**사용자 지정 글꼴.** 브라우저는 섀도 루트 안에 선언한 `@font-face` 규칙을 불러오지 않습니다. 글꼴을 선언한 스타일시트를 `fontFaceUrl`에 지정하고, `fontFamily`에 그 글꼴 이름을 쓰세요.

```tsx
appearance: {
  typography: {
    fontFaceUrl: 'https://fonts.example.com/brand-sans.css',
    fontFamily: "'Brand Sans', system-ui, sans-serif",
  },
}
```

Moss는 그 URL로 `<link rel="stylesheet">`를 페이지의 `<head>`에 URL당 한 번 추가하고, 지우지 않습니다. 콘텐츠 보안 정책(CSP)이 스타일시트를 막으면 `fontFamily`의 다음 글꼴을 씁니다.

### 간격, 모서리 반경, 그림자

| 그룹 | 키와 기본값 |
|------|-------------|
| `spacing` | `3xs` `4px`, `2xs` `8px`, `set2` `10px`, `xs` `12px`, `sm` `16px`, `md` `20px`. 선택 키 `lg`와 `xl`은 `unavailable` 예외 상태의 여백에 쓰입니다 |
| `radius` | `sm` `6px`, `md` `12px`, `lg` `16px`, `xl` `20px` |
| `shadows` | `sm` `0 2px 2px rgba(0, 0, 0, 0.05)`, `md` `0 4px 4px rgba(0, 0, 0, 0.1)`, `lg` `0 8px 32px rgba(0, 0, 0, 0.1)` |

### 효과와 입력 영역

| 키 | 타입 | 기본값 (`'blue'`) | 하는 일 |
|----|------|-------------------|---------|
| `effects.glassmorphism` | `boolean` | `true` | 반투명하고 흐린 표면. `false`이면 불투명한 표면이 되고 헤더를 어두운 헤더로 취급합니다. 헤더 아이콘이 흰색이 되고, 기존 헤더의 **새 질문** 버튼은 `colors.text.onPrimary`를 쓰며, 헤더 아래 테두리가 사라집니다. `'purple'` 프리셋처럼 어두운 `colors.headerBackground`와 함께 설정하세요. |

| `inputBar.topShadow` | `boolean` | `true` | 입력 영역 위의 그림자 |

## 채팅 창

### 플로팅 또는 도킹

`layout`은 떠 있는 창과 브라우저 창의 한쪽 가장자리에 붙는 패널 중 하나를 고릅니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `layout.mode` | `'floating' \| 'docked'` | `'floating'` | 플로팅: 사용자가 옮기고 크기를 바꿀 수 있는 창. 도킹: 한쪽 가장자리에 고정된, 화면 높이 전체의 패널. |
| `layout.anchor` | `'left' \| 'right'` | `'right'` | 도킹 패널이 붙는 가장자리 |
| `layout.width` | `number` (px) | `420` | 도킹 패널의 너비 |

`layout`을 설정할 때는 `mode`가 필수입니다.

```tsx
appearance: {
  layout: { mode: 'docked', anchor: 'right', width: 400 },
}
```

도킹 패널은 페이지 위에 겹쳐 표시되며, 페이지 레이아웃의 크기를 바꾸지 않습니다. 끌거나 크기를 바꾸거나 최소화할 수 없고, 하이라이트된 요소를 피해 비켜서지 않으며, `modal.defaultPosition`, `modal.defaultSize`, `openChat()`에 넘긴 위치를 모두 무시합니다.

### 기본 위치와 크기

`modal`은 플로팅 창이 처음 열리는 위치와 크기를 정합니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `modal.defaultPosition.left` / `right` | `number` (px) | `right: 20` | 브라우저 창의 해당 가장자리로부터의 거리. 둘 다 설정하면 `left`가 우선합니다. |
| `modal.defaultPosition.top` / `bottom` | `number` (px) | `bottom: 20` | 해당 가장자리로부터의 거리. 둘 다 설정하면 `top`이 우선합니다. |
| `modal.defaultSize.width` | `number` (px) | `420` | |
| `modal.defaultSize.height` | `number` (px) | `650` | |

```tsx
appearance: {
  modal: {
    defaultPosition: { left: 24, top: 80 },
    defaultSize: { width: 400, height: 560 },
  },
}
```

창은 지정한 가장자리를 기준으로 고정됩니다. 그래서 `right`와 `bottom`으로 배치한 창은 브라우저 창 크기가 바뀌어도 오른쪽 아래 모서리로부터의 거리를 유지합니다.

### 사용자가 할 수 있는 동작

- **이동:** 헤더나, 메시지 목록 또는 입력 영역의 빈 곳을 끌어서 옮깁니다. 버튼을 누르면 끌기가 시작되지 않습니다.
- **크기 조절:** 왼쪽, 오른쪽, 아래쪽 가장자리나 아래쪽 모서리를 끕니다. 위쪽 가장자리로는 크기를 바꿀 수 없습니다. 눈에 보이는 손잡이는 없습니다.
- **최소 크기:** 360 × 400 px.
- **브라우저 창 안에 머뭅니다.** 들어가는 창은 크기를 유지한 채 안쪽으로 옮겨집니다. 들어가지 않는 창은 브라우저 창에서 각 변 20 px를 뺀 크기로 줄어들지만, 최소 크기보다 작아지지는 않습니다.
- **재설정:** 기존 헤더에는 창을 `modal.defaultPosition`과 `modal.defaultSize`로 되돌리는 **윈도우 위치 재설정** 버튼이 있습니다. `chrome.header`로 쓰는 헤더에는 재설정 버튼이 없습니다.

Moss는 로드되자마자 창의 위치와 크기를 브라우저 탭별로 저장하고, 사용자가 창을 옮겼는지와 관계없이 그 탭이 열려 있는 동안 새로 고침을 해도 저장된 값을 씁니다. 그래서 바꾼 `modal.defaultPosition`이나 `modal.defaultSize`는 새 탭에서, 또는 **윈도우 위치 재설정**을 누른 뒤에 반영되며, Moss가 이미 로드된 탭을 새로 고침하는 것만으로는 반영되지 않습니다.

Moss가 요소를 하이라이트하면 플로팅 창은 그 요소를 피해 비켜섭니다. 비켜설 수 없으면 "강조된 항목이 이 패널 뒤에 가려져 있습니다." 안내와 **패널 이동** 버튼이 나타납니다.

### 코드에서 위치를 정해 열기

[`useAgent()`](/ko/sdk/api/hooks)의 `openChat(position)`과 `toggleChat(position)`은 이번 한 번 열 때 쓸 위치를 선택 인자로 받습니다. `{ x, y, width, height }` 형식이며, 브라우저 창의 왼쪽 위 모서리로부터의 CSS 픽셀 값입니다.

```tsx
const { openChat } = useAgent();

openChat({ x: 24, y: 80, width: 420, height: 600 });
```

- 위치는 그때 한 번만 적용되고 저장되지 않습니다. 다음에 위치 없이 열면 창은 원래 있던 곳으로 돌아갑니다.
- 위에서 설명한 대로 Moss는 창을 브라우저 창 안에 둡니다.
- 그렇게 열린 동안 사용자가 창을 옮기거나, 크기를 바꾸거나, 재설정하면 사용자가 정한 배치가 유지됩니다.
- 채팅이 이미 열려 있으면 위치는 무시됩니다.
- 도킹 레이아웃에서는 무시됩니다.
- `AssistantButton`과 `data-moss-trigger` 요소는 위치 없이 엽니다.

### 가이드 중 최소화

0.17.0부터 `chrome.guide.minimize: true`를 설정하면 가이드가 진행되는 동안 사용자가 플로팅 창을 최소화해 페이지를 가리지 않게 할 수 있습니다. 아래의 [가이드 제안과 가이드](#가이드-제안과-가이드)를 참고하세요.

### 네이티브 모달 다이얼로그

`showModal()`로 연 `<dialog>`는 Moss를 포함해 페이지의 다른 모든 요소 위에 놓입니다. [네이티브 모달 다이얼로그](/ko/sdk/advanced#네이티브-모달-다이얼로그)를 참고하세요.

## Chrome

`chrome`은 대화 주변에 있는 위젯의 구성 요소를 묶습니다. 모든 키는 선택 사항입니다. 단, `chrome.footer`를 설정하면 `chrome.footer.enabled`는 필수입니다.

### 헤더

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.title` | `string` | "New AI chat"(한국어 화면에서는 "새 질문") | 헤더 제목. `chrome.header`가 필요합니다. |
| `chrome.header` | 객체 | 설정하지 않음 | `{}`로라도 설정하면 제목이 있는 헤더를 씁니다. 설정하지 않으면 위젯은 기존 헤더를 씁니다. **새 질문** 버튼, **윈도우 위치 재설정**, `language`를 설정하지 않았을 때의 언어 메뉴, 닫기 버튼이 있는 헤더입니다. |
| `chrome.header.showStatusDot` | `boolean` | `false` | 제목 앞의 작은 점 |
| `chrome.header.statusDotColor` | `string` | `colors.primary` | 점의 색상 |
| `chrome.header.newChatIcon` | `'plus' \| 'refresh' \| 'new-chat'` | `'plus'` | 새 질문 버튼의 아이콘 |
| `chrome.header.newChatStyle` | `'icon' \| 'outline'` | `'icon'` | 0.17.0부터. `'outline'`은 아이콘 옆에 "New AI chat"(한국어 화면에서는 "새 질문") 라벨을 붙이고, 1px 테두리의 알약 모양으로 감쌉니다. 아래를 참고하세요. |

`newChatStyle: 'outline'`이면 알약은 `colors.primary`를 씁니다. 단, `colors.primary`와 `colors.headerBackground`의 명암비가 4.5:1보다 낮으면 헤더의 글자 색을 씁니다. 라벨 때문에 제목 공간이 120px보다 좁아지면 버튼은 아이콘만 보여 줍니다.

제목이 있는 헤더에는 **윈도우 위치 재설정** 버튼과 언어 메뉴가 없습니다.

### 입력창

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.inputBar` | 객체 | 설정하지 않음 | `{}`로라도 설정하면 입력란과 전송 버튼을 테두리가 있는 알약 하나 안에 그립니다. 설정하지 않으면 기존 입력란과 별도의 전송 버튼을 유지합니다. |
| `chrome.inputBar.placeholder` | `string` | "Type a message..."(한국어 화면에서는 "메시지를 입력하세요...") | 자리 표시자 글자 |
| `chrome.inputBar.backgroundTint` | `string` | 설정하지 않음 | 입력창 뒤의 색 띠 |
| `chrome.inputBar.paddingY` | `string` | `spacing['2xs']` | 알약 안 글자의 위아래 여백 |
| `chrome.inputBar.lineHeight` | `string` | `typography.lineHeight.sm` | 숫자(`'1.5'`), 길이(`'20px'`), 백분율 중 하나 |
| `chrome.inputBar.focusBorder` | `string` | 설정하지 않으면 테두리 색이 그대로 | 입력란에 포커스가 있을 때 알약 테두리 색 |

### 푸터

푸터는 입력창 아래에 링크를 최대 두 개 보여 주는 띠입니다. `enabled`가 `true`가 아니면 표시되지 않습니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.footer.enabled` | `boolean` | 설정하지 않으면 꺼짐 | `true`이면 푸터를 보여 줍니다. 이 값이 없으면 아래 링크도 보이지 않습니다. |
| `chrome.footer.helpCenter` | `LinkConfig` | 설정하지 않음 | 첫 번째 링크 |
| `chrome.footer.openTicket` | `LinkConfig` | 설정하지 않음 | 두 번째 링크 |
| `chrome.footer.backgroundTint` | `string` | `colors.modalBackground` | 푸터 배경 |

`chrome.footer`를 설정할 때는 `enabled`가 필수입니다.

`LinkConfig`는 `{ label: string, url: string, icon?: ... }`입니다. 링크는 새 탭에서 열립니다.

`icon`에는 `'external-link'`, `'ticket'`, `'none'`이나, 인라인 SVG 같은 React 요소를 직접 넣을 수 있습니다. React 요소는 장식으로 표시되며 스크린 리더에는 숨겨집니다. 도움말 센터 아이콘은 라벨 뒤에, 티켓 아이콘은 라벨 앞에 옵니다. 설정하지 않으면 도움말 센터 링크에는 "↗"가 붙고 티켓 링크에는 아이콘이 없습니다. React 요소는 앱 코드에서만 설정할 수 있으며, 대시보드에 저장된 아이콘 이름이 있으면 그 이름이 요소를 대체합니다.

```tsx
appearance: {
  chrome: {
    footer: {
      enabled: true,
      helpCenter: { label: 'Help center', url: 'https://help.example.com' },
      openTicket: { label: 'Contact support', url: 'https://help.example.com/contact', icon: 'ticket' },
    },
  },
}
```

### 지원 티켓 카드

`chrome.ticketCard`는 Moss가 지원 티켓 초안을 만들 때 보여 주는 카드의 문구를 바꿉니다. 모든 필드는 일반 문자열이며, 사용자의 언어와 관계없이 모든 사용자에게 그대로 보입니다. 필드를 설정하지 않으면 번역된 기본 문구를 유지합니다.

| 키 | 표시되는 곳 |
|----|-------------|
| `titleLabel` | 요약의 제목 행 이름. 지원 양식의 필드 제목보다 우선합니다. |
| `descriptionLabel` | 요약의 본문 행 이름. 조건은 `titleLabel`과 같습니다 |
| `privacyNote` | 카드 헤더 아래: 티켓이 어디에 접수되는지 |
| `submittingNote` | "티켓을 접수하는 중이에요…" 아래 |
| `confirmedNote` | 성공 메시지 옆: 이제 어떻게 되는지 |
| `cancelledNote` | "접수하지 않았습니다" 행 |
| `failedNote` | "티켓을 접수하지 못했어요" 행 |

접수 과정은 [지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff)를 참고하세요.

### 답변

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.message.paragraphGap` | `string` | 설정하지 않으면 간격 없음 | 답변 안의 문단, 목록, 그 밖의 블록 사이 간격 |
| `chrome.relatedArticles.variant` | `'cards' \| 'list'` | `'cards'` | 답변 아래 관련 문서 목록: 테두리가 있는 카드, 또는 문서 아이콘이 붙은 일반 행 |
| `chrome.loader` | `'line' \| 'steps'` | `'line'` | Moss가 작업하는 동안 보여 줄 것: 계속 바뀌는 한 줄 상태 글자, 또는 Moss가 하는 일의 짧은 목록. 0.17.0부터 `AgentProvider` 옵션 `streamActivity: true`(기본으로 꺼짐)를 설정하면 `'steps'`에 백엔드의 실시간 단계가 추가됩니다. 이 옵션에는 Server-Sent Events를 통과시키는 프록시가 필요하며, 그렇지 않으면 로더는 고정된 행을 보여 줍니다. |

### 가이드 제안과 가이드

다음 키는 가이드를 제안하는 방식과 진행 중인 가이드의 모양을 바꿉니다. 가이드 자체는 [가이드와 페이지 이동](/ko/sdk/guides-and-navigation)에서 설명합니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.guideOffer.label` | `string` | "Start guide"(한국어 화면에서는 "가이드 시작") | 가이드를 시작하는 버튼의 글자 |
| `chrome.guideOffer.icon` | `'emoji' \| 'outline' \| 'none'` | `'emoji'` | 🚀, 버튼 글자 색의 윤곽선 로켓, 또는 아이콘 없음 |
| `chrome.guide.pageTint` | `boolean \| { color?, opacity? }` | 설정하지 않으면 음영 없음 | 현재 단계의 대상 주변 페이지를 어둡게 합니다. `true`는 `rgb(31, 34, 46)`을 `0.36`으로 씁니다. |
| `chrome.guide.targetBadges` | `'within-step' \| 'step'` | `'within-step'` | 하이라이트된 요소의 배지에 표시할 내용. 아래를 참고하세요. |
| `chrome.guide.nextBesideInput` | `boolean` | `true` | 클릭할 대상이 없는 단계에서 입력창 옆에 보이는 다음 버튼 |
| `chrome.guide.nextInBar` | `boolean` | `true` | `false`이면 가이드 바의 다음 버튼을 입력창 옆으로 옮깁니다 |
| `chrome.guide.minimize` | `boolean` | `false` | 0.17.0부터. 가이드가 진행되는 동안 사용자가 플로팅 창을 최소화할 수 있게 합니다. 아래를 참고하세요. |

**`pageTint`.** 채팅 패널은 어두워지지 않으며, 클릭은 그대로 페이지에 전달됩니다. 음영은 Moss가 다음 단계를 준비하는 동안 유지되고, 하이라이트할 요소가 없는 단계에서 걷힙니다. `color`는 불투명한 색으로 지정하세요. 색에 알파 값이 있으면 `opacity`와 곱해집니다.

**`targetBadges`.** `'within-step'`이면 대상이 여러 개인 단계에서 대상에 1, 2, 3 번호를 붙이고, 대상이 하나면 배지를 달지 않습니다. `'step'`이면 배지에 가이드 바와 같은 단계 번호를 표시합니다. 대상이 한 묶음이면 한 번, 여러 곳에 흩어져 있으면 각 대상에 표시하며, 흩어진 대상은 같은 단계의 선택지입니다. `'step'`을 쓰면 Moss는 여러 대상을 1, 2, 3 번호 대신 말로 구분해 안내합니다.

**`nextBesideInput`과 `nextInBar`.** `nextInBar: false`이면 가이드 바는 계획과 진행 상황만 보여 주고, 가이드 바에 다음 버튼이 있었을 모든 단계에서 다음 버튼이 입력창 옆에 놓입니다. 둘 다 `false`이면 다음 버튼이 아예 없으며, 개발 빌드는 경고를 남깁니다.

**`minimize`.** 헤더에 **채팅 최소화** 버튼이 생기고, "강조된 항목이 이 패널 뒤에 가려져 있습니다." 안내에 **최소화** 버튼이 생깁니다. 최소화된 창은 헤더와 가이드 바만 보여 주며, `nextInBar: false`여도 다음 버튼은 가이드 바에 있습니다. 창의 너비와 고정된 가장자리를 유지하고, 하이라이트를 피해 비켜서며, 끌어서 옮길 수 있습니다. 다음과 같을 때 전체 창이 돌아옵니다.

- 헤더의 **채팅 펼치기** 버튼을 누를 때
- `openChat()`, `toggleChat()`을 호출하거나 `data-moss-trigger` 요소를 누를 때
- 가이드가 끝날 때
- 평가나 티켓 초안처럼 답이 필요한 카드가 채팅에 나타날 때

같은 가이드가 진행되는 중에 새로 고침해도 창은 최소화된 상태를 유지합니다. `closeChat()`은 창을 닫습니다. 플로팅 창에서만 쓸 수 있으며, 도킹 패널에는 최소화 기능이 없습니다.

### 시작 화면

시작 화면은 첫 메시지 전에 채팅이 보여 주는 화면입니다. 최근 대화, 추천 질문, 추천 글이 나옵니다. 내용은 [`zeroState`](#초기-화면)에서 정하고, 다음 키는 모양을 정합니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.startScreen.queryIcons` | React 노드 객체 | 설정하지 않음 | 기본 아이콘 이름(`document`, `compass`, `megaphone`, `search`, `people`)마다 쓸 사용자 지정 아이콘. 앱 코드에서만 설정할 수 있습니다. |
| `chrome.startScreen.queryFontWeight` | `number \| string` | `400` | 추천 질문 글자의 굵기 |
| `chrome.startScreen.queryGap` | `string` | `spacing['3xs']` | 추천 질문 사이 간격 |
| `chrome.startScreen.articlesPaddingX` | `string` | 머리글 `spacing.sm`, 행 `spacing.xs` | 추천 글의 좌우 여백 |
| `chrome.startScreen.articlesRowGap` | `string` | 설정하지 않으면 없음 | 추천 글 행 사이 간격 |
| `chrome.startScreen.recentChats` | `false \| { limit?: number }` | `{ limit: 3 }` | 0.17.0부터. 시작 화면에 보여 줄 최근 대화 수(1~5), 또는 목록을 숨기는 `false` |

`recentChats`로 목록을 숨길 수는 있지만 켤 수는 없습니다. 목록은 애플리케이션이 사용자에게 이전 대화를 다시 열도록 허용할 때만 나타납니다. [이전 대화](/ko/sdk/api/session#이전-대화)를 참고하세요.

### 피드백

0.17.0부터. 두 키 모두 설정하지 않으면 꺼져 있습니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.feedback.askWhatWentWrong` | `boolean` | `false` | 답변에 싫어요를 누르면 무엇이 문제였는지 묻습니다. 짧은 이유 목록, 선택 의견, 건너뛰기를 보여 줍니다 |
| `chrome.feedback.sessionRating` | `'thumbs' \| 'stars'` | `'thumbs'` | 세션 끝 카드가 평가를 받는 방식. `'stars'`는 1~5점을 받으며, 어떤 점수에서든 의견을 선택적으로 남길 수 있습니다. |

`'stars'`에서는 4점과 5점을 도움이 된 것으로, 1점과 2점을 도움이 되지 않은 것으로 칩니다.

싫어요 뒤에 사용자가 고른 이유는 [`onEvent`](/ko/sdk/events) 핸들러의 `Moss Feedback Given`으로 전달되지만, 의견은 전달되지 않습니다. 세션 평가는 좋아요/싫어요든 별점이든 `onEvent`로 보내지 않습니다. 세션과 함께 저장되어 대시보드의 **세션** 목록과 세션 상세 화면에 나타납니다.

### 첨부 파일 (베타)

0.17.0부터. 베타이며 바뀔 수 있습니다.

| 키 | 타입 | 기본값 | 하는 일 |
|----|------|--------|---------|
| `chrome.attachments` | `boolean` | `false` | `true`이면 입력창 옆에 클립 버튼을 추가하고, 입력창에 파일을 끌어다 놓을 수 있게 합니다 |

사용자는 PDF, PNG, JPEG 파일을 메시지당 5개까지, 파일당 10 MB까지 첨부할 수 있습니다. 파일은 Moss 배포의 첨부 파일 저장소에 업로드되어 세션과 함께 보관됩니다. 모델은 파일을 읽지 않습니다. 사용자가 확인한 단계 중 파일을 받는 API 액션이나 MCP 도구만 파일을 받습니다. 설정하지 않거나 `false`이면 첨부 버튼이 없고 아무것도 업로드되지 않습니다.

## 초기 화면

`zeroState`는 시작 화면의 내용, 즉 추천 질문과 추천 글입니다.

```tsx
appearance: {
  zeroState: {
    suggestedQueries: [
      { question: 'How do I invite a teammate?', icon: 'people' },
      { question: 'Where do I change my billing plan?', icon: 'document' },
    ],
    recommendedArticles: {
      label: 'Popular articles',
      items: [
        { title: 'Getting started', url: 'https://help.example.com/start', readTimeMinutes: 3 },
      ],
    },
    suggestedQueryIcons: 'per-query',
  },
}
```

| 키 | 타입 | 하는 일 |
|----|------|---------|
| `suggestedQueries` | `{ question: string, icon?: ... }[]` | 시작 화면에 보이는 질문. 누르면 사용자 메시지로 전송됩니다. |
| `recommendedArticles.label` | `string` | 섹션 제목. 설정하지 않으면 "Recommended articles"입니다. |
| `recommendedArticles.items` | `{ title, url?, source?, readTimeMinutes? }[]` | 문서 링크. `url`이 없는 항목은 보이지만 누를 수 없습니다. |
| `suggestedQueryIcons` | `'uniform' \| 'per-query'` | `'uniform'`(기본값)은 모든 질문에 문서 아이콘을 보여 줍니다. `'per-query'`는 각 질문의 `icon`을 씁니다. |
| `variants` | 객체 | 페이지와 사용자 역할에 따라 다른 내용. 아래를 참고하세요. |

`icon`은 `'document'`, `'compass'`, `'megaphone'`, `'search'`, `'people'` 중 하나입니다.

**앱 코드 또는 대시보드.** `appearance.zeroState`를 조금이라도 설정하면, `{}`라도 그 값을 통째로 쓰고 대시보드의 추천 콘텐츠는 보이지 않습니다. **콘텐츠 > 추천 콘텐츠**에 저장한 내용을 쓰려면 설정하지 마세요. [추천 콘텐츠](/ko/dashboard/suggested-content)를 참고하세요.

### 페이지와 역할에 따른 콘텐츠

대시보드에는 애플리케이션 전체에 쓰는 추천 콘텐츠가 한 벌만 있습니다. 페이지마다, 또는 관리자와 다른 사용자에게 다른 내용을 보여 주려면 앱 코드에서 `variants`를 설정하고 `pageKey`를 넘기세요.

```tsx
<AgentProvider config={{
  // ...
  pageKey: 'billing-settings',
  userMetadata: { role: currentUser.isAdmin ? 'admin' : 'member' },
  appearance: {
    zeroState: {
      suggestedQueries: [{ question: 'What can Moss help me with?' }],
      variants: {
        'billing-settings': {
          admin: {
            suggestedQueries: [
              { question: 'How do I change the plan for my team?' },
              { question: 'How do I add a seat?' },
              { question: 'Where do I update the billing contact?' },
            ],
          },
          customer: {
            suggestedQueries: [
              { question: 'Where can I download my invoices?' },
              { question: 'How do I update my card?' },
              { question: 'When will I be charged?' },
            ],
          },
        },
        default: {
          admin: {
            suggestedQueries: [
              { question: 'How do I add a user?' },
              { question: 'How do I change a user\'s role?' },
              { question: 'Where are the audit logs?' },
            ],
          },
          customer: {
            suggestedQueries: [
              { question: 'How do I find my invoices?' },
              { question: 'How do I reset my password?' },
              { question: 'How do I contact support?' },
            ],
          },
        },
      },
    },
  },
}}>
  <AssistantButton />
</AgentProvider>
```

이 예시의 각 세트에는 질문이 세 개씩 있으므로, 관리자와 다른 사용자는 각자 자기 세트만 봅니다.

- `pageKey`는 페이지에 붙이는 고정된 이름입니다. `'billing-settings'`처럼 직접 정하며, URL이 아닙니다. 사용자가 다른 페이지로 이동하면 새 값을 넘기세요. 시작 화면이 바로 바뀝니다.
- **역할:** `userMetadata.role`이 `'admin'`이면(대소문자 무관) `admin`을 고릅니다. 다른 값이거나 역할이 없으면 `customer`를 고릅니다.
- **보이는 세트:** `pageKey`에 해당하는 항목, 없으면 `default` 항목, 그것도 없으면 최상위의 `suggestedQueries`와 `recommendedArticles`입니다. 페이지 항목에 다른 역할의 내용만 있어도 페이지 항목이 우선합니다.
- **채우기:** 고른 세트의 질문이나 글이 3개보다 적으면, Moss는 같은 수준에 있는 다른 역할의 세트에서, 그다음 최상위 목록에서 항목을 가져와 3개를 채웁니다. 3개보다 많은 세트는 잘리지 않습니다.
- `suggestedQueryIcons`는 최상위에서만 읽습니다. `variants` 안이 아니라 최상위에 설정하세요.

## 예외 상태

`fallbackStates`는 Moss의 기본 메시지 두 가지를 원하는 문구와 링크로 바꿉니다.

| 키 | 표시되는 때 | 형식 |
|----|-------------|------|
| `hallucination` | 답변이 Moss가 찾을 수 없는 페이지 요소를 가리킬 때. 지정한 메시지가 그 답변의 말풍선을 대신하며, 입력창은 계속 쓸 수 있습니다. | `{ variant: 'inline', body: string, ctas: LinkConfig[] }` |
| `unavailable` | 재시도 후에도 채팅이 연결되지 않을 때. 지정한 메시지가 패널 전체를 채우고 입력창은 숨겨집니다. | `{ variant: 'takeover', title: string, body?: string, icon?: string, primaryCta: LinkConfig, secondaryCta?: LinkConfig }` |
| `noAnswer` | 0.17.0에서는 표시되지 않습니다. 예약된 키입니다. | `{ variant: 'inline', body, ctas }` |

```tsx
appearance: {
  fallbackStates: {
    unavailable: {
      variant: 'takeover',
      title: 'Help is temporarily unavailable',
      body: 'You can still browse the help center.',
      primaryCta: { label: 'Open help center', url: 'https://help.example.com' },
    },
  },
}
```

`unavailable`을 설정하지 않으면 연결에 실패했을 때 Moss의 기본 오류 메시지가 나옵니다.

npm 패키지에서는 대시보드의 **콘텐츠 > 추천 콘텐츠**에 저장한 예외 상태가 적용되지 않습니다. 앱 코드에서 설정하세요.

## 자주 묻는 질문

**제목이나 색상을 설정했는데 아무것도 바뀌지 않습니다.**
키가 올바른 위치에 있는지(`title`이 아니라 `chrome.title`), 그리고 `chrome.header`가 설정되어 있는지 확인하세요. 그다음 대시보드를 확인하세요. **브랜딩**이나 **테마**에 저장된 값이 앱 코드보다 우선합니다. [설정이 반영되지 않을 때](#설정이-반영되지-않을-때)를 참고하세요.

**페이지 CSS로 위젯을 꾸밀 수 있나요?**
아니요. 채팅은 섀도 루트 안에 렌더링되므로 페이지 CSS가 닿지 않습니다. `appearance`를 쓰세요. 페이지 DOM에 렌더링되는 것은 `AssistantButton`과 `FloatingActionBar`뿐입니다.

**하이라이트된 요소의 빨간 외곽선 색을 바꾸려면 어떻게 하나요?**
`appearance.colors.highlight`에 16진수 색상을 설정하세요.

**글자를 더 크게 하려면 어떻게 하나요?**
`appearance.typography.fontSize`(와 `lineHeight`)를 설정하세요. 기본값은 `rem`이라 페이지의 루트 글자 크기도 따라갑니다.

**사용자가 채팅 창의 크기를 바꾸거나 옮길 수 있나요?**
네, 플로팅 레이아웃에서는 가능합니다. 헤더를 끌어서 옮기고, 왼쪽, 오른쪽, 아래쪽 가장자리나 아래쪽 모서리를 끌어서 360 × 400 px까지 크기를 바꿀 수 있습니다. [채팅 창](#채팅-창)을 참고하세요.

**일부 화면에서 채팅 창이 너무 높게 열립니다.**
`modal.defaultSize.height`를 설정하세요. 브라우저 창에 들어가지 않는 창은 Moss가 각 가장자리에서 20 px를 남기고 줄입니다.

**채팅이 우리 모달 다이얼로그 아래에 보입니다.**
`showModal()`로 연 `<dialog>`는 페이지의 다른 모든 요소 위에 놓입니다. Moss를 별도 요소에 마운트하고 `installModalDialogEscape()`를 호출하세요. [네이티브 모달 다이얼로그](/ko/sdk/advanced#네이티브-모달-다이얼로그)를 참고하세요.

**좋아요/싫어요보다 자세한 피드백을 받으려면 어떻게 하나요?**
0.17.0부터 `chrome.feedback.askWhatWentWrong: true`를 설정하면 싫어요 뒤에 이유를 묻고, `chrome.feedback.sessionRating: 'stars'`를 설정하면 세션을 1~5점으로 평가받습니다. [피드백](#피드백)을 참고하세요.

**페이지마다 다른 추천 질문을 보여 주려면 어떻게 하나요?**
앱 코드에서 `pageKey`를 넘기고 `appearance.zeroState.variants`를 설정하세요. 대시보드에는 애플리케이션 전체에 쓰는 세트가 하나만 있습니다. [페이지와 역할에 따른 콘텐츠](#페이지와-역할에-따른-콘텐츠)를 참고하세요.

**대시보드에서 추천 질문을 수정했는데 위젯에는 예전 질문이 나옵니다.**
앱 코드에서 `appearance.zeroState`를 설정했기 때문입니다. 이 값은 대시보드 콘텐츠를 통째로 대체합니다. 대시보드 값을 쓰려면 앱 코드에서 이 설정을 지우세요.
