# 설정

SDK는 `AgentProvider`의 `config` prop(npm 패키지)이나 `window.mossSettings`(CDN 스크립트)로 설정합니다. 타입은 `MossSDKConfig`입니다. 이 페이지는 0.17.0에서 지원하는 모든 옵션을 나열하며, Moss 자체 도구용으로 예약된 몇 가지 옵션은 뺐습니다. 각 옵션의 자세한 설명은 링크된 페이지에 있습니다.

## 필수 필드

```tsx
<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',   // Moss 백엔드
  applicationId: 'YOUR_APP_ID',            // 구성 > 일반 > 애플리케이션 ID
  userId: currentUser.id,                  // 사용자의 변하지 않는 식별자
  getJwt: () => fetchMossToken(),          // 서명된 토큰을 반환합니다
}}>
```

| 필드 | 타입 | 의미 |
|-------|------|---------|
| `apiUrl` | `string` | Moss 백엔드의 기본 URL. 0.17.0부터 끝의 `/`는 무시합니다. |
| `applicationId` | `string` | 애플리케이션의 ID. **구성 > 일반**에 **애플리케이션 ID**로 표시됩니다. |
| `userId` | `string` | 현재 사용자를 가리키는 변하지 않는 식별자. |
| `getJwt` 또는 `jwt` | 아래 참고 | SDK의 인증 방식. [인증](/ko/sdk/authentication)을 참고하세요. |

<Info>
    예전 연동을 위해 타입은 `applicationId` 대신 `applicationName`도 받습니다. `applicationId`를 쓰세요. 이 값이 없으면 SDK가 토큰의 `app` 클레임이 같은 애플리케이션을 가리키는지 확인할 수 없어 경고를 남깁니다.
</Info>

## 설정을 읽어 오는 곳

**npm 패키지.** SDK는 넘겨받은 `config`에서만 옵션을 읽습니다. 대시보드에서 바꾼 설정 가운데 다음 항목은 새 세션마다 백엔드가 보내 주므로 반영됩니다.

- 애플리케이션의 **비전 사용** 설정. `useVision`을 설정하지 않았을 때 씁니다.
- 대시보드의 테마와 크롬. `appearance` 위에 값 단위로 적용됩니다.
- 대시보드의 추천 콘텐츠. `appearance`에 `zeroState`가 없을 때 씁니다.
- 비활성 후 돌아온 사용자를 어떻게 맞을지 정한 대시보드 설정. `sessionConfig.onReturnAfterInactivity`를 설정하지 않았을 때 씁니다.
- 애플리케이션의 답변 링크 호스트. [`replyLinks`](#replylinks)에 더해집니다.
- 애플리케이션의 프로액티브 가이드. 첫 세션 전에는 SDK가 애플리케이션의 공개 설정에서도 읽어 옵니다.

언어, 세션 시간 초과, 화면 기록, 페이지 컨텍스트, 로그, 관찰 영역, 예외 상태(**콘텐츠 > 추천 콘텐츠 > 예외 상태**)의 대시보드 값은 그것만으로는 npm 설치에 반영되지 않습니다. **세션 리플레이 활성화**는 다릅니다. 0.17.0부터는 이 스위치가 꺼져 있으면 서버가 녹화를 거부하므로, `enableSessionRecording: true`인 npm 앱이라도 대시보드 스위치로 녹화가 멈춥니다. 대시보드의 **DOM 안정성** 설정과 **스크린샷** 설정은 0.17.0에서 두 설치 방식 모두에 아무 영향을 주지 않습니다. [대시보드 설정](/ko/configurations/dashboard-settings#고급-설정)을 참고하세요. 그 밖의 대시보드 값을 쓰려면 대시보드 설정으로 config를 만드세요.

```tsx
import { fetchAppConfig, convertBackendConfig } from '@viamoss/moss-sdk';

// 요청이 실패하면 예외를 던집니다. 그때는 직접 만든 config로 대신하세요.
const dashboard = await fetchAppConfig('YOUR_APP_ID', 'https://moss-api.viamoss.ai');
const config = {
  ...convertBackendConfig(dashboard, currentUser.id, 'YOUR_APP_ID', 'https://moss-api.viamoss.ai'),
  getJwt: () => fetchMossToken(),
};
```

`convertBackendConfig()`는 언어, 세션 설정, 녹화 스위치, 페이지 컨텍스트, 관찰 영역, 로그 레벨, 외관(예외 상태 포함)을 대시보드에서 가져옵니다. `debugMode`는 항상 `false`로 설정합니다. 위의 `getJwt`처럼 필요한 옵션을 그 위에 더하세요.

**CDN 스크립트.** 스크립트는 애플리케이션의 대시보드 설정에서 시작해, 그 위에 `window.mossSettings`를 키 단위로 덮어씁니다. `appearance`나 `sessionConfig`처럼 객체를 설정하면 그 키에 해당하는 대시보드 객체 전체를 대체합니다. `applicationId`는 항상 스크립트 URL에서 가져옵니다. 설정 요청이 실패하면 스크립트는 내장 기본값을 씁니다.

대시보드 쪽 설정은 [설정 개요](/ko/configurations/overview)를 참고하세요.

### 한 번만 읽는 값

SDK는 `apiUrl`, `jwt`, `getJwt`, `getBridgeCode`, `applicationId`를 `AgentProvider`가 마운트될 때 한 번만 읽습니다. 페이지 텍스트에 쓰는 `redactionSelectors`와 `redactAllInputs`도 마찬가지입니다. 다른 사용자가 로그인할 때처럼 이 값을 바꾸려면 프로바이더를 다시 마운트하세요. 예를 들어 사용자에 따라 바뀌는 `key`를 `AgentProvider`에 넘기면 됩니다.

### 0.17.0에서 제거된 옵션

`displayMode`, `headless`, `forcedActivationFlow`는 더 이상 없으며, `useAgent()`의 `displayMode`도 없어졌습니다. TypeScript는 이 옵션들을 거부하고, 런타임에서는 무시되어 채팅이 평소처럼 동작합니다. 내보내던 타입 `HeadlessConfig`, `ForcedActivationFlowConfig`, `ForcedActivationFlowDefinition`도 없어졌습니다.

## 언어

`language`를 설정하지 않으면 SDK는 다음 순서로 `'en'`이나 `'ko'`를 고릅니다. `lng` 쿼리 매개변수, 이 브라우저에서 채팅이 마지막으로 쓴 언어(`localStorage` 키 `mossLng`), `i18next` 쿠키, `sessionStorage`의 `i18nextLng` 항목, 페이지의 `<html lang>`, 브라우저 언어입니다. 그 밖의 언어는 영어로 돌아갑니다. 채팅에는 언어 메뉴가 표시됩니다.

`language`를 설정하면 SDK는 그 언어를 쓰고 언어 메뉴를 숨깁니다.

## replyLinks

0.17.0부터 답변은 주소가 허용된 호스트에 있을 때만 링크를 렌더링하거나 이미지를 불러옵니다. 허용된 호스트는 다음과 같습니다.

- 페이지 자체의 출처
- 답변이 인용한 지식 베이스 문서
- 세션마다 전달되는 애플리케이션의 허용 도메인과 지식 베이스 호스트
- `replyLinks.allowedHosts`에 나열한 호스트

그 밖의 링크는 텍스트로, 그 밖의 이미지는 대체 텍스트로 보여 주므로 요청이 일어나지 않습니다.

```tsx
<AgentProvider config={{
  // ...
  replyLinks: { allowedHosts: ['help.example.com', '*.example.org'] },
}}>
```

항목은 호스트(`help.example.com`), 하위 도메인을 뜻하는 `*.example.com`(`example.com` 자체는 포함하지 않음), 이 둘에 `:port`를 붙인 형태, 또는 호스트를 뜻하는 `http(s)` URL입니다. 애플리케이션 자체의 목록과 달리, 이 항목은 여러 소유자가 함께 쓰는 호스트(`*.github.io` 등)인지 확인하지 않으므로 정확한 호스트를 쓰는 편이 좋습니다.

## AssistantButton props

`AssistantButton`은 채팅을 열고 닫는 플로팅 버튼입니다. 섀도 루트 밖, 페이지 안에 `position: fixed`로 렌더링됩니다.

```tsx
<AssistantButton
  iconVariant="question"                 // 'question'(기본값) 또는 'default'(Moss 로고)
  iconUrl="/custom-icon.svg"             // iconVariant보다 우선합니다
  position={{ bottom: 20, right: 80 }}   // 뷰포트 가장자리로부터의 픽셀 거리
  onButtonClick={() => {}}               // 채팅이 열리거나 닫힌 뒤 실행됩니다
/>
```

| Prop | 타입 | 기본값 | 의미 |
|------|------|---------|---------|
| `iconVariant` | `'default' \| 'question'` | `'question'` | 내장 아이콘. `'default'`는 Moss 로고, `'question'`은 물음표입니다 |
| `iconUrl` | `string` | — | 직접 만든 아이콘 이미지의 URL. `iconVariant`보다 우선합니다. 이미지는 흰색 실루엣으로 그려집니다 |
| `position` | `{ bottom?, right?, top?, left? }` | `{ bottom: 20, right: 80 }` | 뷰포트 가장자리로부터의 거리(픽셀). 넘긴 값이 기본값 전체를 대체하므로, `{ bottom: 40 }`만 넘기면 가로 위치는 정해지지 않습니다 |
| `onButtonClick` | `() => void` | — | 클릭으로 채팅이 열리거나 닫힌 뒤 호출됩니다 |
