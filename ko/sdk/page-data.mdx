이 페이지는 Moss SDK가 페이지에서 무엇을 읽는지, Moss 백엔드로 무엇을 보내는지, 그리고 각각을 어떻게 제어하는지 설명합니다. 대부분의 앱에서 핵심은 다음 세 가지입니다.

1. Moss가 절대 읽으면 안 되는 영역에 `data-moss-redact`를 붙이세요.
2. `redactAllInputs`를 켜 둔 채로 두세요(기본값). 그러면 네이티브 폼 필드(`input`, `textarea`, `select`, 편집 가능한 영역)의 값이 페이지 텍스트, 녹화, 화면 기록에 들어가지 않습니다. `div`로 만든 드롭다운처럼 다른 요소로 만든 커스텀 컨트롤은 일반 페이지 텍스트로 읽히므로 `data-moss-redact`를 붙이세요.
3. 비전 스크린샷과 세션 녹화를 켤지 정하세요. 둘 다 페이지 텍스트보다 많은 것을 보내며, 비전 스크린샷에는 마스킹이 적용되지 않습니다.

## 페이지 텍스트

질문과 가이드 단계마다 SDK는 모델에 보낼 수 있도록 페이지를 텍스트로 직렬화합니다. `observeTargetSelector`에 맞는 요소(기본값 `'body'`)와 그 안의 모든 것을 읽으며, 스크롤해야 보이는 아래쪽 콘텐츠와 스크롤 영역 안의 콘텐츠도 포함합니다.

**텍스트에 들어가는 것:**

- 화면에 보이는 각 요소의 태그와 정해진 속성. `id`, `class`, `role`, `name`, `value`, `placeholder`, `href`, `title`, `alt`, `src`, `type`, `for`, 자주 쓰는 `aria-*` 속성, `checked`, `disabled`, `required`, `min`, `max` 같은 폼 속성, `data-testid`, `data-id` 등이 여기에 속합니다.
- 마스킹되지 않은 `select`의 경우, 선택된 옵션과 처음 몇 개의 옵션.
- 텍스트. 버튼, 링크 같은 인터랙티브 요소는 그 안의 텍스트 전체를, 그 밖의 요소는 자식 요소의 텍스트를 빼고 자기 텍스트만 읽습니다. 텍스트는 요소마다 100자에서 잘립니다.
- 요소의 `aria-describedby`가 가리키는 텍스트(최대 200자). 마우스를 올려야 보이는 툴팁처럼 그 텍스트가 숨겨져 있어도 읽습니다.
- 열린 섀도 루트와 같은 출처 iframe 안의 콘텐츠.
- 맨 앞의 짧은 요약: 링크, 버튼, 폼 필드의 개수와, 화면에 보이는 경고, 유효하지 않은 필드, 비어 있는 필수 필드.

**텍스트에서 빠지는 것:**

- `display: none`, `visibility: hidden`, `opacity: 0`으로 숨긴 요소, `inert` 하위 트리 안의 요소, 사용자가 스크롤해도 볼 수 없는 요소.
- `<script>`, `<style>`, `<head>`, `<meta>`, `<link>`, `<noscript>`.
- 닫힌 섀도 루트, 그리고 브라우저가 SDK의 접근을 막는 다른 출처나 샌드박스 iframe.
- Moss 자체의 인터페이스.
- 같은 태그의 형제 요소가 10개 넘게 이어지면, 그 뒤는 개수로만 요약합니다.

### 보낼 페이지 컨텍스트의 양: `pageContext`

| 값 | 페이지 텍스트 | 비전 스크린샷 | URL | 페이지 제목 |
|-------|-----------|-------------------|-----|------------|
| `'full'` (기본값) | 예 | 비전이 켜져 있으면 | 예 | 아니요 |
| `'metadata'` | 아니요 | 아니요 | 예 | 예 |
| `'none'` | 아니요 | 아니요 | 아니요 | 아니요 |

```tsx
<AgentProvider config={{
  // ...
  pageContext: 'metadata', // Moss는 지식 베이스로 답하고, 페이지는 읽지 않습니다
}}>
```

- URL은 쿼리 문자열과 프래그먼트를 포함한 페이지의 전체 주소(`window.location.href`)입니다.
- `'metadata'`나 `'none'`에서는 Moss가 페이지의 요소를 보지 못하므로, 사용자를 요소 단위로 안내할 수 없습니다.
- `pageContext`는 [세션 녹화](#세션-녹화)나 [화면 기록](#화면-기록)을 끄지 않습니다. 둘은 각자 스위치가 따로 있습니다.
- **npm 패키지:** config에 넣은 값이 적용되며, 설정하지 않으면 `'full'`입니다.
- **CDN 스크립트:** `window.mossSettings.pageContext`로 정하지 않으면 애플리케이션의 설정이 적용됩니다. **구성 > 동작 > 주요 기능**에서 **화면 가이드**를 끄면, 애플리케이션은 보통 `'metadata'` 수준으로 수집합니다.

### Moss가 읽는 영역 제한하기: `observeTargetSelector`

`observeTargetSelector`에 CSS 선택자를 넣으면, Moss는 그 선택자에 처음으로 맞는 요소와 그 안에서만 페이지 텍스트를 읽습니다. 기본값은 `'body'`입니다. 맞는 요소가 없으면 SDK가 `Could not find target element`를 로그에 남기고, 읽을 페이지가 없게 됩니다.

이 옵션이 제한하는 것은 페이지 텍스트뿐입니다([안정성 대기](/ko/sdk/advanced#dom-관찰-범위)의 일부도 함께 좁혀집니다). 비전 스크린샷, 세션 녹화, 화면 기록은 여전히 페이지 전체를 대상으로 합니다. 녹화와 화면 기록에는 `data-recording-block`이나 마스킹을 쓰세요.

## 마스킹

마스킹은 페이지의 일부를 Moss가 읽는 내용에서 가립니다. 마커는 네 가지이고, 각각 적용되는 출력이 다릅니다.

### `data-moss-redact`

어떤 요소에든 `data-moss-redact`를 붙이세요. 그 요소와 안에 있는 모든 것이 깊이와 상관없이 마스킹되며, 요소의 섀도 루트와 그 안의 같은 출처 iframe 콘텐츠도 포함됩니다.

```html
<section data-moss-redact>
  <p>Account balance: $12,340.56</p>
  <input type="text" name="card-number" />
</section>
```

페이지 텍스트에서 마스킹된 요소는 태그가 남아 있어 Moss가 무언가 있다는 것은 알지만, 다음과 같이 처리됩니다.

- 텍스트는 `[REDACTED]`로 바뀝니다.
- `value`, `placeholder`, `title`, `alt`, `aria-label`, `aria-labelledby`, `aria-describedby`, `name`, `data-testid`, `data-id`, `href`, `src`, `id` 속성의 값이 `[REDACTED]`로 바뀝니다.
- 안에 있는 `iframe`은 전혀 읽지 않습니다.

또한 Moss는 `data-moss-redact` 영역 안의 요소를 하이라이트하지 않습니다.

### 폼 필드: `redactAllInputs`와 `data-moss-unredact`

`redactAllInputs`는 기본값이 `true`입니다. 모든 `input`, `textarea`, `select`, 편집 가능한(`contenteditable`) 요소의 값을 같은 방식으로 마스킹하고, 편집 가능한 영역 안에 있는 것도 마스킹합니다.

해당하는 것은 이 네이티브 필드뿐입니다. `div`로 만든 드롭다운, 콤보박스, 날짜 선택기처럼 값을 일반 텍스트로 보여 주는 커스텀 컨트롤은 Moss가 폼 필드로 보지 않으므로, 그 텍스트는 다른 텍스트처럼 읽힙니다. 이런 컨트롤에는 `data-moss-redact`를 붙이세요.

`redactAllInputs`가 켜져 있을 때 입력값 마스킹이 막아 주는 범위는 다음과 같습니다.

| 출력 | 네이티브 필드(`input`, `textarea`, `select`, 편집 가능한 영역) | 다른 요소로 만든 커스텀 컨트롤 |
|--------|------------------------------------------------------------------|-------------------------------------------|
| 페이지 텍스트와 가이드 단계 보고 | 값을 마스킹 | 텍스트를 읽음 |
| 세션 녹화(0.17.0부터) | 차단: 빈 상자로 표시 | 녹화됨 |
| 화면 기록(0.17.0부터) | 입력이 기록되지 않음 | 기록됨 |
| 비전 스크린샷 | 보임 | 보임 |

검색창처럼 Moss가 읽어도 되는 필드는 그 필드나 그 필드를 감싼 컨테이너에 `data-moss-unredact`를 붙이세요.

```html
<input type="search" data-moss-unredact placeholder="Search products…" />
```

`data-moss-unredact`는 입력값 마스킹만 풉니다. `data-moss-redact`나 `redactionSelectors`보다 우선하지 않으며, 세션 녹화에는 영향을 주지 않습니다.

입력값 마스킹을 완전히 끄려면 `redactAllInputs: false`로 설정하세요.

<Warning>
    `redactAllInputs: false`에서는 사용자가 폼 필드에 입력한 내용이 페이지 텍스트, 가이드 단계 보고, 화면 기록, 세션 녹화를 통해 Moss에 전달될 수 있습니다. 녹화와 화면 기록은 여전히 `type="password"` 필드를 마스킹하지만, 페이지 텍스트와 가이드 단계 보고에는 비밀번호 전용 규칙이 없습니다. 이 옵션을 끈다면 비밀번호와 그 밖의 민감한 필드에 `data-moss-redact`를 붙이세요.
</Warning>

### 직접 지정한 선택자: `redactionSelectors`

앱에서 FullStory의 `.fs-exclude`처럼 다른 도구를 위해 이미 민감한 요소를 표시해 두었다면, 곳곳에 `data-moss-redact`를 붙이는 대신 그 선택자를 `redactionSelectors`에 나열하세요.

```tsx
<AgentProvider config={{
  // ...
  redactionSelectors: ['.fs-exclude', '.fs-mask', '[data-private]'],
}}>
```

맞는 요소는 페이지 텍스트와 녹화에서 `data-moss-redact` 요소와 같이 마스킹됩니다. 차이는 두 가지입니다. Moss가 그 안의 컨트롤을 하이라이트할 수 있고, 섀도 루트는 마스킹한 상태로 읽습니다.

- `data-moss-redact`는 이 목록과 상관없이 항상 적용됩니다.
- 잘못된 선택자는 페이지 텍스트에서는 건너뜁니다. 세션 녹화와 화면 기록에서는 해당 세션의 녹화를 멈추고, 콘솔에 오류를 남깁니다.

### `data-recording-block`

`data-recording-block`은 요소를 세션 녹화와 화면 기록에서만 뺍니다. 페이지 텍스트에는 영향을 주지 않습니다.

### 마커별 적용 범위

| 마커 | 페이지 텍스트와 가이드 단계 보고 | 비전 스크린샷 | 세션 녹화와 화면 기록 | Moss가 안쪽을 하이라이트할 수 있음 |
|--------|----------------------------------|--------------------|--------------------------------------|---------------------------|
| `data-moss-redact` | 마스킹 | 적용 안 됨 | 차단(0.17.0부터) | 아니요 |
| `redactionSelectors` | 마스킹 | 적용 안 됨 | 차단(0.17.0부터) | 예 |
| `redactAllInputs` (기본으로 켜짐) | 값을 마스킹 | 적용 안 됨 | 차단(0.17.0부터) | 예 |
| `data-moss-unredact` | 입력값 마스킹을 풂 | 적용 안 됨 | 영향 없음 | 예 |
| `data-recording-block` | 영향 없음 | 적용 안 됨 | 차단 | 예 |

"차단"은 리플레이에서 해당 요소가 같은 크기의 빈 상자로 보인다는 뜻입니다. 0.17.0 이전의 녹화는 `data-recording-block`(과 아래의 `rr-block` 클래스)만 차단했고, 비밀번호 필드 말고는 폼 필드를 마스킹하지 않았습니다.

<Note>
    Moss는 페이지 텍스트에 쓸 `redactionSelectors`와 `redactAllInputs`를 `AgentProvider`가 마운트될 때 한 번 읽습니다. 마운트할 때 넘기는 config에 넣으세요.
</Note>

### 프로그래밍 방식의 변경: `pageSanitizationScript`

`pageSanitizationScript`는 마스킹 도구가 아닙니다. SDK가 페이지를 관찰하기 시작할 때, 그리고 함수 자체나 `observeTargetSelector`가 바뀔 때마다 실제 페이지에서 실행되므로, 사용자에게 보이는 화면도 바뀝니다. [고급 > 프로그래밍 방식의 페이지 변경](/ko/sdk/advanced#프로그래밍-방식의-페이지-변경)을 참고하세요.

## 비전 스크린샷

Moss는 다음 세 가지가 모두 충족될 때만, 사용자가 공유한 화면(보통 이 탭)의 스크린샷을 질문이나 가이드 단계와 함께 보냅니다.

1. **비전이 켜져 있습니다.** **구성 > 동작 > 주요 기능**의 **비전 사용** 스위치나, config의 `useVision: true`로 켭니다.
2. **`pageContext` 값이 `'full'`입니다**(기본값).
3. **사용자가 브라우저의 화면 캡처 요청을 허용합니다.**

**비전을 켤지 정하는 쪽:**

- config의 `useVision`은 애플리케이션 설정을 양쪽 방향으로 덮어씁니다. `useVision: true`는 **비전 사용**이 꺼져 있어도 스크린샷을 찍고, `useVision: false`는 켜져 있어도 찍지 않습니다.
- `useVision`을 설정하지 않으면 세션마다 전달되는 애플리케이션 설정을 따릅니다. 새 애플리케이션에서는 **비전 사용**이 기본으로 꺼져 있습니다.
- CDN 스크립트에서는 같은 옵션을 `window.mossSettings.useVision`으로 설정하세요.

**스크린샷을 찍는 과정:**

1. 첫 질문에서 Moss는 브라우저에 화면 공유를 요청하면서, 브라우저 탭과 현재 탭을 선호한다고 알립니다. 그래도 브라우저의 요청 창에서 사용자는 다른 탭, 창, 전체 화면을 고를 수 있습니다.
2. Moss는 공유된 화면이 이 탭의 뷰포트와 크기가 비슷한지만 확인합니다(가로 약 100픽셀, 세로 약 200픽셀 이내). 크기가 다르면 다시 요청하고, 두 번 잘못 고르면 더 이상 요청하지 않습니다.
3. 크기가 비슷한 다른 탭이나 브라우저 창 전체도 이 확인을 통과합니다. 그러면 Moss는 사용자가 공유한 화면, 즉 다른 탭이나 탭 표시줄과 주소 표시줄까지 포함한 창 전체의 프레임을 보냅니다.
4. 공유가 허용되면 그 질문과 이후의 모든 질문, 그리고 각 가이드 단계마다 프레임을 하나씩 보냅니다. 프레임은 가로 최대 1,920픽셀의 JPEG이며, 서명된 업로드 URL로 Moss 배포의 저장소에 올라갑니다. 업로드에 실패하면 요청에 직접 담아 보냅니다.
5. 사용자가 취소하면 Moss는 스크린샷을 보내지 않고, 페이지를 새로 고칠 때까지 다시 묻지 않습니다. 사용자가 공유를 멈추면 스크린샷도 멈춥니다.

<Warning>
    비전 스크린샷은 탭에 보이는 화면을 마스킹 없이 그대로 담은 프레임입니다. `data-moss-redact`, `redactionSelectors`, `redactAllInputs`는 그 내용을 바꾸지 않습니다. (세션 녹화는 다릅니다. [세션 녹화](#세션-녹화)를 참고하세요.) 제어 수단은 비전을 끄는 것(`useVision: false`, 또는 `useVision`을 설정하지 않고 **비전 사용**을 끔), `pageContext`를 `'metadata'`나 `'none'`으로 낮추는 것, 또는 `display-capture`를 허용하지 않는 `Permissions-Policy` 헤더를 보내 브라우저가 화면 캡처를 거부하게 하는 것입니다.
</Warning>

`screenshotMode`(`'fullpage'` 또는 `'viewport'`)는 0.17.0에서 이 스크린샷에 아무 영향을 주지 않습니다.

## 세션 녹화

세션 녹화는 페이지를 녹화해 대시보드의 **세션 리플레이**에서 다시 볼 수 있게 합니다. 직접 켜지 않으면 꺼져 있습니다.

<Info>
    **0.17.0에서 바뀐 점.** 이제 Moss는 **세션 리플레이 활성화**를 켜서 저장한 애플리케이션에서만 녹화하고, 그 밖에는 서버가 녹화를 거부합니다. 따라서 `enableSessionRecording: true`를 설정한 npm 앱도 이 스위치를 켜야 합니다. 0.16.x에서는 CDN 스크립트가 이 스위치를 한 번도 저장하지 않은 애플리케이션에서 녹화했고, 서버는 어느 SDK가 보낸 녹화든 받았습니다. npm 패키지의 `enableSessionRecording`은 그때도 직접 설정하지 않으면 꺼져 있었습니다.
</Info>

**Moss는 다음이 모두 충족될 때만 녹화합니다.**

1. **애플리케이션이 허용합니다.** **구성 > 동작 > 주요 기능**에서 **세션 리플레이 활성화**가 켜져 있어야 합니다. 0.17.0부터 이 스위치가 꺼진 애플리케이션의 녹화는 서버가 거부합니다.
2. **SDK가 녹화합니다.**
   - **npm 패키지:** `enableSessionRecording: true`로 설정하세요.
   - **CDN 스크립트:** `window.mossSettings.enableSessionRecording`을 설정하지 않으면 애플리케이션 설정이 적용됩니다.
3. **채팅이 열려 있고 세션이 있습니다.** 녹화는 채팅이 열릴 때 시작됩니다. 채팅이 닫히거나 마우스, 키보드, 스크롤, 터치 동작이 15분 동안 없으면 녹화를 멈추고 남은 부분을 업로드합니다.

```tsx
<AgentProvider config={{
  // ...
  enableSessionRecording: true, // 애플리케이션의 세션 리플레이 활성화도 켜져 있어야 합니다
}}>
```

**녹화되는 것:** 페이지의 구조와 그 변화, 마우스 움직임, 클릭, 스크롤, 폼 입력을 rrweb 라이브러리로 기록합니다. SDK는 30초마다 Moss 백엔드로 업로드합니다. 캔버스 내용은 녹화하지 않으며, 이미지는 복사하지 않고 URL로 참조합니다. 녹화에는 각 채팅 턴이 시작되는 지점이 사용자 메시지의 앞 120자와 함께 표시됩니다.

**마스킹되는 것:** [마커별 적용 범위](#마커별-적용-범위)를 참고하세요. 녹화기는 rrweb 클래스 이름인 `rr-block`(요소를 빈 상자로 표시), `rr-mask`(텍스트를 마스킹), `rr-ignore`(입력 이벤트를 기록하지 않음)도 따릅니다.

## 화면 기록

화면 기록은 이전 질문이나 가이드 단계 이후 사용자가 페이지에서 한 일을 짧은 타임라인으로 모델에 전달합니다. 클릭, 폼 입력, 스크롤, 페이지 이동, 페이지의 큰 변화와 현재 경로가 들어갑니다. 기본으로 꺼져 있습니다.

- **npm 패키지:** `enableScreenHistoryRecording: true`로 설정하세요.
- **CDN 스크립트:** `window.mossSettings`로 설정하지 않으면 **구성 > 동작 > 주요 기능**의 **LLM용 화면 기록 활성화** 설정이 적용됩니다.

화면 기록은 세션 녹화와 같은 녹화기를 쓰며, 브라우저 안에서 채팅이 열려 있는 동안에만 동작합니다. 마스킹도 똑같이 적용되며, 세션 녹화가 함께 켜져 있지 않으면 녹화를 업로드하지 않습니다. 입력한 값은 입력값 마스킹이 가리지 않는 한 값마다 최대 50자까지 들어갑니다.

## 가이드 단계 보고

사용자가 하이라이트된 버튼을 클릭하는 식으로 가이드 단계를 마치면, SDK는 사용자가 조작한 요소의 텍스트, 레이블, 마크업을 보고합니다. 마스킹된 부분은 페이지 텍스트에서처럼 바뀝니다. 요소 자체가 마스킹되어 있으면 아무것도 보내지 않습니다.

`stability.afterReload`가 켜져 있으면 SDK는 사용자가 클릭하는 순간 이 보고를 `localStorage`에도 기록합니다. 클릭으로 다른 페이지가 로드되면 그 페이지가 보고를 보낼 수 있게 하기 위해서입니다. 이 기록은 `pendingTTL`(기본 30초) 동안 유효합니다.

## 사용자 메타데이터

`userMetadata`는 사용자의 역할이나 요금제처럼 Moss에 사용자를 설명하는 값입니다.

```tsx
<AgentProvider config={{
  // ...
  userMetadata: { role: 'admin', plan: 'enterprise', permissions: ['billing:read'] },
}}>
```

- 세션이 시작될 때 보내며, 세션과 함께 저장됩니다.
- Moss는 이 값을 답변을 다듬는 데 쓸 데이터로 모델에 넘깁니다. config에서 온 값은 자기 신고 값이므로 아무 권한도 열어 주지 않습니다.
- 제한: 키는 최대 20개, 키 길이는 최대 100자입니다. 값은 최대 200자의 문자열, 숫자, 불리언, 또는 전체 500자 이내의 문자열 배열입니다.
- 토큰의 `metadata` 클레임에도 같은 키가 있으면 토큰의 값을 씁니다. [인증](/ko/sdk/authentication)을 참고하세요.
- 특정 역할에만 허용된 프로시저는 토큰에 서명된 `role`만 열 수 있습니다. config에만 있는 `role`로는 열리지 않습니다.
- 이름, 이메일 주소, 전화번호가 아니라 역할과 범주를 넣으세요.

## 메시지와 파일

사용자가 입력한 내용은 입력한 그대로 보냅니다. 채팅 메시지에는 마스킹이 적용되지 않습니다.

0.17.0부터 **구성 > 보안**의 **백엔드 개인정보 필터링**은 Moss가 요청을 저장하거나 모델로 보내기 전에, 흔한 개인정보 패턴(이메일 주소, 미국 전화번호, 결제 카드 번호, 미국 사회보장번호, 직접 추가한 패턴)을 `[REDACTED]`로 바꿉니다. 애플리케이션이나 배포에서 켜지 않으면 꺼져 있습니다. 적용 대상은 텍스트입니다. 페이지 텍스트, 화면 기록 타임라인, 페이지 제목, 가이드 단계 보고, 그리고 선택하면 채팅 메시지에 적용됩니다. 스크린샷과 녹화는 바꾸지 않습니다.

0.17.0부터 사용자가 첨부한 파일(베타 기능, 기본으로 꺼짐)은 Moss 배포의 저장소에 업로드됩니다. [외관](/ko/sdk/appearance)을 참고하세요.

## 수집 켜고 끄기

0.17.0부터는 두 가지 옵션으로 Moss를 실행할지 말지를 여러분의 정책에 따라 정할 수 있습니다.

### `collectionEnabled`

`collectionEnabled: false`로 설정하면 Moss가 시작하지 않습니다.

- **npm 패키지:** `AgentProvider`는 자식 요소를 포함해 아무것도 렌더링하지 않습니다. 앱의 UI는 프로바이더 밖에 두세요.
- **CDN 스크립트:** 스크립트를 불러오기 전에 `window.mossSettings = { collectionEnabled: false }`로 설정하면 스크립트가 시작하지 않습니다. `window.MossSDK.boot({ collectionEnabled: true })`를 호출할 때까지 요청을 하나도 보내지 않습니다. 다만 불러올 때 `localStorage`에 값 하나, 즉 위젯의 인터페이스 언어를 `mossLng` 키로 기록합니다. npm 패키지를 import해도 같은 키를 기록합니다.

### `collectionControl`

`MossCollectionControl`은 앱 코드가 쥐고 있는 스위치입니다. Moss는 이 스위치가 켜져 있는 동안에만 마운트됩니다.

```tsx
import { AgentProvider, AssistantButton, MossCollectionControl } from '@viamoss/moss-sdk';

// 여러분의 백엔드가 이 사용자의 Moss 사용을 허용한 뒤:
const control = new MossCollectionControl({
  applicationId: policy.applicationId,
  userId: policy.userId,
  companyKey: policy.companyKey, // 사용자의 회사를 가리키는 자체 식별자
});
if (policy.enabled) control.enable();

root.render(
  <AgentProvider config={{
    apiUrl: 'https://moss-api.viamoss.ai',
    applicationId: policy.applicationId,
    userId: policy.userId,
    getJwt: () => fetchMossToken(),
    collectionControl: control,
  }}>
    <AssistantButton />
  </AgentProvider>
);

// 사용자가 계정이나 회사를 바꾸기 전에:
control.disable();
```

- 컨트롤은 꺼진 상태로 시작합니다. `enable()`로 Moss를 마운트하고, `disable()`로 마운트를 해제하세요.
- `disable()`은 진행 중인 Moss 요청을 취소하고, 아직 보내지 않은 녹화를 마지막 업로드 없이 버립니다.
- 컨트롤 아래에서 Moss가 마운트되거나 해제될 때마다 자체 브라우저 상태를 지우므로, 마운트를 넘어 이어지는 채팅은 없습니다. 앱의 저장소는 절대 지우지 않습니다.
- 컨트롤의 `applicationId`와 `userId`는 프로바이더 config와 같아야 하며, 다르면 프로바이더가 오류를 던집니다. 세 가지 식별 필드는 모두 필수입니다.
- 다른 사용자나 회사로 바꿀 때는 이전 컨트롤을 끈 다음, 새 컨트롤과, 토큰 함수를 따로 넣은 새 config를 만드세요.
- 컨트롤은 브라우저가 수집할지만 정합니다. 서버에서는 아무것도 허가하지 않으며, 허가는 여전히 토큰이 합니다.
- 컨트롤이 꺼져 있는 동안 프로바이더는 자식 요소를 하나도 렌더링하지 않습니다.

**CDN 스크립트:**

```html
<script>window.mossSettings = { collectionEnabled: false };</script>
<script
  src="https://cdn.viamoss.ai/moss-sdk@latest.min.js?applicationId=YOUR_APP_ID"
  data-api-base="https://moss-api.viamoss.ai"
></script>
<script>
  // 정책 확인이 끝난 뒤:
  const control = new window.MossSDK.CollectionControl({
    applicationId: 'YOUR_APP_ID',
    userId: policy.userId,
    companyKey: policy.companyKey,
  });
  control.enable();
  window.MossSDK.boot({
    collectionEnabled: true,
    collectionControl: control,
    userId: policy.userId,
    getJwt: () => fetchMossToken(),
  });

  // 끌 때:
  control.disable();
  window.MossSDK.shutdown();
</script>
```

## SDK가 읽지 않는 것

- **쿠키와 저장소.** SDK는 `moss`로 시작하는 키에 자체 상태를 보관합니다. [브라우저에 저장되는 항목](/ko/sdk/overview#브라우저에-저장되는-항목)을 참고하세요. 예외는 언어 감지 하나입니다. 인터페이스 언어를 고르기 위해 `lng` 쿼리 매개변수, `i18next` 쿠키, `sessionStorage`의 `i18nextLng` 항목을 확인합니다.
- **브라우저가 SDK의 접근을 막는 콘텐츠:** 닫힌 섀도 루트와 다른 출처의 iframe.
- **SDK가 마운트되지 않은 페이지.**

## 자주 묻는 질문

**`data-moss-redact`가 스크린샷에서도 내용을 가리나요?**
아니요. 비전 스크린샷은 사용자가 공유한 화면을 그대로 담은 프레임입니다. 그런 페이지에서는 비전을 끄거나(`useVision: false`) `pageContext`를 `'metadata'`나 `'none'`으로 낮추세요. 마스킹은 페이지 텍스트와 가이드 단계 보고, 그리고 0.17.0부터는 세션 녹화와 화면 기록에도 적용됩니다.

**세션이 하나도 녹화되지 않는 이유는 무엇인가요?**
[세션 녹화](#세션-녹화)의 세 가지 조건을 확인하세요. 애플리케이션에서 **세션 리플레이 활성화**가 켜져 있어야 하고, npm 연동이라면 `enableSessionRecording: true`가 있어야 하며, 채팅이 열려 있어야 합니다. 0.17.0부터는 이 설정을 한 번도 저장하지 않은 애플리케이션은 녹화하지 않습니다.

**Moss가 페이지를 아예 읽지 못하게 할 수 있나요?**
`pageContext: 'none'`을 쓰고 비전, 세션 녹화, 화면 기록을 끈 채로 두세요. 그러면 Moss에는 대화와 `userMetadata`만 남습니다. Moss를 페이지에서 완전히 빼려면 그 페이지에 마운트하지 않거나 `collectionEnabled: false`로 설정하세요.

**Moss가 비밀번호 필드를 읽나요?**
`redactAllInputs`가 켜져 있으면(기본값) 페이지 텍스트, 가이드 단계 보고, 녹화, 화면 기록에서 읽지 않습니다. 비전 스크린샷에는 사용자가 보는 그대로 페이지가 담깁니다. `redactAllInputs: false`에서는 녹화와 화면 기록이 여전히 `type="password"` 필드를 마스킹하지만 페이지 텍스트와 가이드 단계 보고는 그렇지 않으므로, 비밀번호 필드에 `data-moss-redact`를 붙이세요.

**이 데이터는 누가 받나요?**
SDK는 이 데이터를 설정한 `apiUrl`로만 보내고, 스크린샷과 첨부 파일은 Moss 배포가 지정한 저장소에 업로드합니다. 백엔드가 그다음 모델 제공자에게 무엇을 보내는지는 Moss의 배포 방식에 따라 다릅니다. [데이터 보호](/ko/security/data-protection)를 참고하세요.
