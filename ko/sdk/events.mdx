두 가지 선택 콜백으로 Moss에서 일어나는 일을 앱 코드에 전달받을 수 있습니다.

- **`onEvent`** 콜백은 질문, 답변 전달, 가이드 완료 같은 사용 이벤트를 받아 분석 도구로 보낼 수 있게 합니다.
- **`onError`** 콜백은 채팅이 사용자에게 보여 주는 모든 문제를, 누가 해결할 수 있는지와 지원 문의용 참조 번호와 함께 받습니다.

설정하지 않으면 아무것도 바뀌지 않습니다.

## 분석 도구로 이벤트 보내기

`AgentProvider` 설정에 `onEvent`를 넘기세요. 호출될 때마다 이벤트 하나, `{ name, properties }`를 받습니다. 이름은 Segment의 "Object Action" 형식을 따르고 속성은 camelCase이므로, 대부분의 분석 도구에 그대로 넣을 수 있습니다.

```tsx
import { AgentProvider, AssistantButton, type MossEvent } from '@viamoss/moss-sdk';
import { analytics } from './analytics'; // Segment, Amplitude 등의 클라이언트

function trackMossEvent(event: MossEvent) {
  analytics.track(event.name, event.properties);
}

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  onEvent: trackMossEvent,
}}>
  <AssistantButton />
</AgentProvider>
```

Google Analytics 4처럼 이벤트 이름에 공백을 받지 않는 도구라면, 먼저 이름을 `moss_question_asked`처럼 바꾸세요.

`MossEvent`는 `name`으로 좁혀지는 유니언 타입이라, TypeScript가 이벤트마다 속성을 알고 있습니다.

```tsx
onEvent: (event) => {
  if (event.name === 'Moss Answer Delivered') {
    metrics.timing('moss.answer_latency', event.properties.latencyMs);
  }
},
```

**CDN 스크립트를 쓴다면** 스크립트가 로드되기 전에 `window.mossSettings`에 같은 함수를 설정하세요.

```html
<script>
  window.mossSettings = {
    onEvent: function (event) { analytics.track(event.name, event.properties); },
  };
</script>
```

### 이벤트가 전달되는 방식

- 각 이벤트는 Moss가 해당 작업을 마친 뒤 마이크로태스크에서 전달됩니다. 핸들러가 Moss의 코드 안에서 실행되는 일은 없습니다.
- 핸들러가 예외를 던지거나 거부되는 promise를 반환하면, Moss는 경고를 남기고 계속 동작합니다. 채팅에는 영향이 없습니다.
- Moss는 이벤트를 전달할 때마다 핸들러와 `eventQueryText`를 읽습니다. 그래서 새 함수를 넘기면 `AgentProvider`를 다시 마운트하지 않아도 바로 적용됩니다.
- Moss가 여러 탭에 열려 있으면, 가이드 이벤트는 가이드가 진행되는 탭에서 발생합니다.

## 공통 속성

모든 이벤트에는 다음 속성이 있습니다.

| 속성 | 타입 | 의미 |
|------|------|------|
| `sessionId` | `string \| null` | Moss 채팅 세션. 세션이 생기기 전에는 `null`입니다. |
| `userId` | `string` | 넘긴 `userId` |
| `timestamp` | `string` | 발생 시각(ISO 8601) |
| `pageKey` | `string`, 선택 | 넘긴 `pageKey`. 설정했을 때만 있습니다 |

## 이벤트 목록

SDK가 내보내는 `MOSS_EVENT_NAMES`에 모든 이름이 들어 있습니다.

| 이벤트 | 발생 시점 | 속성 |
|--------|-----------|------|
| `Moss Chat Opened` | 채팅이 열릴 때. 페이지가 로드될 때 이미 열려 있던 채팅, 즉 새로 고침 후 복원된 채팅은 세지 않습니다. | 없음 |
| `Moss Chat Closed` | 채팅이 닫힐 때. | 없음 |
| `Moss Question Asked` | 사용자가 질문을 보낼 때. 직접 입력한 질문, 추천 질문, 앱 코드가 `sendMessage()`로 보낸 텍스트가 모두 `source: 'user'`로 셉니다. 앱 코드가 `askMoss()`로 한 질문은 요청이 나갈 때 한 번, `source: 'host'`로 셉니다. 가이드 시작과 다음 버튼은 세지 않습니다. | `messageId: string`, `mode: 'chat' \| 'guide'`, `source: 'user' \| 'host'`, `queryText?: string` |
| `Moss Answer Delivered` | 질문에 대한 답변이 도착할 때. | `messageId?: string`, `latencyMs: number`, `hasHighlight: boolean`, `hasCitation: boolean` |
| `Moss No Answer` | `empty_response`: 질문에 대한 응답에 아무 내용이 없을 때로, Answer Delivered 대신 발생합니다. `target_not_found`: 답변이 페이지에 없는 요소를 가리켰을 때로, 메시지당 한 번 발생합니다. | `messageId?: string`, `reason: 'empty_response' \| 'target_not_found'` |
| `Moss Error` | 사용자에게 보이는 무언가가 실패했을 때. | `errorType`(아래 참고). `request_failed`이면 `code?`, `side?`, `status?`, `reference?`도 있습니다 |
| `Moss Plan Started` | 가이드가 시작될 때. 제안된 가이드는 사용자가 수락했을 때 셉니다. 새로 고침 후 복원된 가이드는 다시 알리지 않습니다. | `planId: string`, `stepCount: number` |
| `Moss Plan Step Completed` | 가이드 단계가 완료될 때. 단계마다 한 번 발생하며, 건너뛴 단계는 세지 않습니다. | `planId: string`, `stepId: string`, `stepIndex: number` (0부터 시작) |
| `Moss Plan Finished` | 가이드가 끝날 때. 가이드마다 한 번 발생합니다. | `planId: string`, `outcome: 'completed' \| 'abandoned'` |
| `Moss Feedback Given` | 사용자가 답변에 좋아요나 싫어요를 누를 때. | `messageId: string`, `rating: 'up' \| 'down'`, `reason?: FeedbackReason` |
| `Moss Ticket Opened` | Moss가 지원 티켓 초안 카드를 보여 줄 때. 초안마다 페이지당 한 번 발생합니다. 세션과 함께 복원된 카드는 세지 않습니다. | `handoffId: string` |
| `Moss Ticket Submitted` | 사용자가 티켓 카드를 제출하고 결과가 정해졌을 때. | `handoffId: string`, `outcome: 'filed' \| 'failed' \| 'unconfirmed'` |
| `Moss Recent Chat Opened` | 0.17.0부터. 사용자가 시작 화면의 최근 대화에서 이전 대화를 열 때. | `pastSessionId: string` |

일부 이벤트의 세부 사항은 다음과 같습니다.

- **`Moss Question Asked`**: 가이드가 진행되는 동안 `mode`는 `'guide'`입니다. `queryText`는 직접 켰을 때만 있습니다. [질문 텍스트](#질문-텍스트)를 참고하세요.
- **`Moss Answer Delivered`**: `latencyMs`는 질문을 보낸 때부터 답변이 도착한 때까지의 시간입니다. `hasHighlight`는 답변이 페이지의 요소를 가리킨다는 뜻이고, `hasCitation`은 도움말 문서를 인용한다는 뜻입니다. `messageId`는 답변 메시지의 ID로, `Moss Feedback Given`이 평가하는 그 메시지입니다. 하이라이트만 있는 답변처럼 메시지를 추가하지 않는 답변이거나, 답변 텍스트가 사용자가 단계를 진행하기를 기다리는 경우에는 없습니다.
- **`Moss Plan Finished`**: Moss가 가이드를 완료로 보고하거나 사용자가 가이드를 끝까지 마치면 `completed`입니다. 사용자가 가이드를 종료하거나, 대화가 끝나거나(`askMoss()`가 시작한 새 채팅이나 비활성 후 Moss가 시작한 새 채팅 포함), Moss가 가이드를 다른 가이드로 바꾸거나, 사용자가 가이드에서 접수한 지원 티켓이 전송되면 `abandoned`입니다.
- **`Moss Feedback Given`**: 0.17.0부터 `chrome.feedback.askWhatWentWrong`을 켜면, 사용자가 이유를 고른 싫어요는 같은 메시지에 대해 `reason`과 함께 한 번 더 전송됩니다. `reason`은 `'steps_mismatch'`, `'hard_to_follow'`, `'not_solved'`, `'wrong_answer'`, `'not_answered'`, `'other'` 중 하나입니다. 이 설정을 켜면, 끝난 가이드의 "목표 완료!" 카드에서 사용자가 싫어요를 누르고 이유를 고른 경우에도 이 이벤트가 `rating: 'down'`과 `reason`을 담아 가이드의 마지막 답변에 대해 발생합니다. 사용자의 의견은 페이지로 전송되지 않으며, 세션 평가도 마찬가지입니다.
- **`Moss Ticket Submitted`**: `filed`는 `onSupportTicket`이 티켓 접수를 확인했다는 뜻입니다. `failed`는 콜백이 실패를 알렸거나, 제출이 거부되었거나 전송되지 않았다는 뜻입니다. `unconfirmed`는 콜백이 시간 초과되었거나 예외를 던지는 등 결과를 확인해 준 곳이 없다는 뜻으로, 티켓이 이미 만들어졌을 수 있습니다. [지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff)를 참고하세요.

### `Moss Error` 유형

| `errorType` | 의미 |
|-------------|------|
| `connection_failed` | 재시도 후에도 채팅이 연결되지 않았습니다. |
| `connection_timeout` | 채팅이 연결되지 않았고, 마지막 시도가 시간 초과되었습니다. |
| `connection_blocked` | 콘텐츠 보안 정책(CSP)이 연결을 막았습니다. `connect-src`에 Moss API URL을 허용하세요. |
| `request_failed` | 질문, 가이드 시작, 다음 버튼, 가이드 단계가 응답을 받지 못했거나 Moss가 오류로 응답했습니다. 0.17.0부터는 [`onError`](#onerror)에서 설명하는 문제의 `code`, `side`, `status`, `reference`를 함께 담습니다. |

## 질문 텍스트

사용자가 입력한 내용에는 개인 정보나 고객 데이터가 있을 수 있습니다. 그래서 `Moss Question Asked`는 `eventQueryText`로 직접 켜지 않는 한 텍스트를 담지 않습니다.

| `eventQueryText` | `Moss Question Asked`의 `queryText` |
|------------------|--------------------------------------|
| `'omit'` (기본값) | 없음 |
| `'include'` | 사용자가 입력한 그대로의 텍스트 |
| `(text: string) => string` | 함수가 반환한 값. 함수가 예외를 던지거나 문자열이 아닌 값을 반환하면 없으며, 예외는 로그에 남습니다. |

```tsx
eventQueryText: (text) => text.replace(/[\w.+-]+@[\w-]+\.[\w.]+/g, '[email]'),
```

다른 이벤트 속성에는 사용자나 모델이 쓴 자유 텍스트, URL, 페이지 내용이 들어가지 않습니다.

## onError

`onError`는 채팅이 사용자에게 알리는 모든 문제마다 호출됩니다. 실패한 응답, 도구 하나 없이 작성된 답변, 서버에 닿지 못한 요청 등입니다. 0.17.0에서 새로 생겼습니다.

```tsx
<AgentProvider config={{
  // ...
  onError: (error) => {
    errorTracker.captureMessage(`Moss: ${error.code}`, {
      level: error.fixBy === 'admin' ? 'error' : 'warning',
      extra: { ...error },
    });
  },
}}>
```

`onError`는 `onEvent`와 같은 방식으로 전달됩니다. 마이크로태스크에서 전달되며, 핸들러가 예외를 던지거나 거부되면 로그만 남기고 무시합니다.

### 오류 객체 (`MossError`)

| 필드 | 타입 | 의미 | 활용 방법 |
|------|------|------|-----------|
| `code` | `string` | `connection_lost`나 `integration_unavailable` 같은 고정 식별자. 아래 목록을 참고하세요. | 문제를 이 값으로 묶고 세세요. 새 코드는 어느 릴리스에서든 추가될 수 있으니, 모르는 코드도 처리하세요. |
| `side` | `'moss' \| 'integration' \| 'settings' \| 'procedure' \| 'input' \| 'client'` | 실패한 곳 | 담당자를 정하는 데 쓰세요. `procedure` 문제와 대부분의 `settings` 문제는 Moss 대시보드에서 바꿔야 합니다. 단, `sign_in_failed`는 페이지의 토큰 문제이고, `storage_not_configured`는 배포의 파일 저장소 문제입니다. `integration` 문제는 연결된 서비스에 있습니다. |
| `fixBy` | `'user' \| 'admin' \| 'moss'` | 조치할 수 있는 사람 | `user`: 사용자가 다시 시도하거나 보낸 내용을 바꿀 수 있습니다. `admin`: Moss 애플리케이션 관리자가 무언가를 바꿔야 합니다. `moss`: Moss 쪽 문제이며 자동으로 보고됩니다. |
| `retryable` | `boolean` | 다시 보내면 도움이 되는지 | `true`이면 채팅에 **다시 시도**가 나타납니다. 요청이 이미 실행되었을 수 있어 다시 보내면 같은 작업이 반복될 수 있을 때는 `false`입니다. |
| `message` | `string` | 사용자에게 보여 준 문구. 채팅의 언어로 되어 있습니다 | 보여 주거나 로그에 남기세요. 파싱하지 마세요. |
| `status` | `number`, 선택 | 응답의 HTTP 상태 코드 | 응답이 오지 않았으면 없습니다. |
| `reference` | `string`, 선택 | Moss 지원팀에 알려 줄 참조 번호 | 오류와 함께 로그에 남기세요. 서버가 요청을 받지 못했으면 없습니다. |

채팅에서 사용자는 메시지 아래에서 같은 문제를 봅니다. 무엇이 잘못되었는지, 사용자가 직접 해결할 수 없을 때는 "관리자가 Moss에서 해결할 수 있습니다." 또는 "Moss 쪽 문제이며 이미 보고되었습니다.", 그리고 참조 번호가 나옵니다. 다시 보내서 도움이 될 때는 **다시 시도**를, 프로시저가 끝나기 전에 멈췄을 때는 **계속**을 보여 줍니다.

채팅이 아예 연결되지 않을 때는 `onError`가 호출되지 않습니다. 이때는 `connection_*` 유형의 `Moss Error`를 받으세요.

### 코드

| `code` | `side` | `fixBy` | 사용자에게 보이는 문구 |
|--------|--------|---------|------------------------|
| `model_overloaded` | moss | moss | 지금 어시스턴트에 요청이 몰리고 있습니다. 다시 시도해 주세요. |
| `model_timeout` | moss | moss | 답변하는 데 시간이 너무 오래 걸렸습니다. 다시 시도해 주세요. |
| `model_blocked` | moss | user | 안전 필터가 이 요청을 차단했습니다. |
| `no_answer` | moss | moss | 어시스턴트가 쓸 수 있는 답을 내지 못했습니다. 다시 시도해 주세요. |
| `step_limit` | moss | user | 어시스턴트가 쓸 수 있는 단계를 모두 썼습니다. 더 작게 나누어 다시 요청해 주세요. |
| `internal_error` | moss | moss | Moss 쪽에서 문제가 발생했습니다. |
| `tools_unavailable` | moss | moss | 이 답변에는 어시스턴트의 도구 일부를 불러오지 못했습니다. |
| `tool_failed` | moss | moss | 어시스턴트의 도구 하나가 실패해서 그 도구 없이 답변했습니다. |
| `integration_unavailable` | integration | user | *서비스*에서 응답이 없습니다. |
| `integration_rejected` | integration | user | *서비스*에서 요청을 거부했습니다. |
| `integration_rate_limit` | integration | user | *서비스*에 요청이 너무 많습니다. 잠시 후 다시 시도해 주세요. |
| `step_failed` | integration | user | 단계 하나가 완료되지 않았습니다. |
| `integration_auth` | settings | admin | *서비스*에서 Moss의 인증 정보를 거부했습니다. |
| `connection_disabled` | settings | admin | Moss에서 *서비스* 연결이 꺼져 있습니다. |
| `connection_missing` | settings | admin | Moss에 *서비스* 연결이 없습니다. |
| `sign_in_failed` | settings | admin | 이 페이지가 어시스턴트에 로그인하지 못했습니다. |
| `storage_not_configured` | settings | admin | 이 앱에는 파일 저장소가 설정되어 있지 않습니다. |
| `not_permitted` | procedure | admin | 이 작업을 실행할 권한이 없습니다. |
| `procedure_unavailable` | procedure | admin | 이 절차는 더 이상 사용할 수 없습니다. |
| `procedure_unfinished` | procedure | user | 아직 끝나지 않았습니다. |
| `proposal_changed` | procedure | user | 이 카드는 더 이상 유효하지 않습니다. 새로 요청해 주세요. |
| `card_expired` | procedure | user | 이 카드는 만료되었습니다. 새로 요청해 주세요. |
| `file_missing` | input | user | 첨부한 파일을 찾지 못했습니다. 다시 첨부해 주세요. |
| `file_refused` | input | user | 첨부한 파일을 받을 수 없습니다. |
| `rate_limited` | input | user | 요청이 너무 많습니다. 잠시 후 다시 시도해 주세요. |
| `invalid_request` | input | moss | 어시스턴트가 이 요청을 읽지 못했습니다. |
| `connection_lost` | client | user | 응답을 받기 전에 연결이 끊어졌습니다. |
| `page_unreadable` | client | moss | 어시스턴트가 이 페이지를 읽지 못했습니다. |
| `target_not_found` | client | user | 어시스턴트가 이 페이지에서 해당 항목을 찾지 못했습니다. |
| `navigation_failed` | client | moss | 어시스턴트가 해당 페이지를 열지 못했습니다. |

*서비스* 자리에는 지원 데스크나 API 연결처럼 연결된 서비스의 이름이 들어갑니다.

`sign_in_failed`는 대개 페이지의 토큰이 거부되었다는 뜻입니다. `getJwt`와 토큰의 클레임을 확인하세요. [인증](/ko/sdk/authentication)을 참고하세요.

## 이름의 안정성

이벤트 이름과 속성은 공개된 계약입니다. 이름 변경과 삭제는 그 변경이 들어가는 릴리스보다 먼저 릴리스 노트에서 알립니다. 새 이벤트와 새 선택 속성은 어느 릴리스에서든 추가될 수 있으니, 트래킹 계획은 아직 모르는 이벤트와 속성도 받아들이도록 만드세요.

## 자주 묻는 질문

**Moss 사용 데이터를 Segment, Amplitude, Google Analytics로 보내려면 어떻게 하나요?**
`onEvent`를 넘기고, 각 이벤트를 분석 도구의 track 호출로 전달하세요. [분석 도구로 이벤트 보내기](#분석-도구로-이벤트-보내기)를 참고하세요.

**사용자가 무엇을 물었는지 볼 수 있나요?**
직접 켰을 때만 볼 수 있습니다. `eventQueryText`를 `'include'`로 설정하거나, 텍스트를 먼저 가리는 함수로 설정하세요.

**핸들러에서 오류가 나면 채팅이 멈추나요?**
아니요. Moss가 오류를 잡아 경고를 남기고 계속 동작합니다.

**가이드 시작이나 다음 버튼에는 왜 `Moss Question Asked`가 오지 않나요?**
질문이 아니기 때문입니다. 가이드 진행 상황은 `Moss Plan` 이벤트로 전달됩니다.

**사용자가 문제를 겪을 때 알 수 있나요?**
`onError`를 넘기세요. 호출될 때마다 무엇이 실패했는지, 누가 해결할 수 있는지, 지원팀에 알려 줄 참조 번호를 알려 줍니다. 채팅이 아예 연결되지 않는 경우는 `connection_*` 유형의 `Moss Error`를 받으세요.
