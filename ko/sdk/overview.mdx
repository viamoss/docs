# SDK 개요

Moss SDK는 웹 앱에 Moss 어시스턴트를 넣습니다. 사용자가 보고 있는 페이지를 읽고, 사용자의 질문을 그 컨텍스트와 함께 Moss 백엔드로 보내고, 답변을 채팅 패널에 보여 줍니다. 답변이 여러 단계로 이루어져 있으면 클릭할 요소를 한 단계씩 하이라이트할 수 있습니다.

## 작동 방식

사용자가 질문하거나 가이드 단계를 진행하면 SDK는 다음과 같이 동작합니다.

1. **페이지가 안정되기를 기다립니다.** 렌더링이 덜 끝난 화면을 읽지 않기 위해서입니다. [안정성 튜닝](/ko/sdk/advanced#안정성-튜닝)을 참고하세요.
2. **페이지를 읽습니다.** 화면에 보이는 구조와 텍스트를 읽고, 민감한 부분은 마스킹합니다. 비전이 켜져 있고 사용자가 화면 캡처를 허용하면, 사용자가 공유한 화면(보통 이 탭)의 스크린샷도 찍습니다. 이 스크린샷은 마스킹되지 않습니다. [페이지 데이터와 개인정보 보호 설정](/ko/sdk/page-data)을 참고하세요.
3. **질문과 페이지를 Moss 백엔드로 보냅니다.** 백엔드는 지식 베이스와 지금까지의 대화를 바탕으로 답합니다.
4. **답변을 채팅 패널에 보여 줍니다.** 답변이 가이드라면 페이지의 요소를 하이라이트합니다.

채팅 패널과 가이드 UI는 [Shadow DOM](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM) 안에 렌더링되므로, 페이지의 스타일 규칙이 닿지 않습니다. `AssistantButton`처럼 `AgentProvider` 안에 렌더링하는 컴포넌트는 페이지에 일반 요소로 렌더링됩니다. [Shadow DOM](/ko/sdk/advanced#shadow-dom)을 참고하세요.

## 통합 방법

| 방법 | 적합한 경우 | 설치 |
|--------|----------|---------|
| **npm 패키지** | React 앱 | `npm install @viamoss/moss-sdk` |
| **CDN 스크립트 태그** | 모든 웹 페이지 | `<script src="…">` |

두 방법 모두 같은 채팅 패널과 가이드를 보여 줍니다. 차이는 제어할 수 있는 범위에 있습니다.

| | npm 패키지 | CDN 스크립트 |
|---|---|---|
| 설정 | 직접 넘기는 `config` prop | 대시보드 설정 위에 `window.mossSettings`를 덮어씀 |
| 실행 버튼 | `AssistantButton`, `FloatingActionBar`, 자체 버튼, 또는 없음 | 항상 `AssistantButton` |
| 코드로 제어 | `useAgent()` 훅, `askMoss()`, `shouldStartMoss()` | `window.MossSDK.boot()`, `identify()`, `updateConfig()`, `shutdown()` |
| 네이티브 다이얼로그 지원 | `installModalDialogEscape()` | 지원하지 않음 |

두 방법 모두 `data-moss-trigger` 요소와 함께 쓸 수 있습니다. [설치](/ko/sdk/installation)를 참고하세요.

## 읽어서 보내는 것

질문과 가이드 단계마다 SDK는 백엔드로 다음을 보냅니다.

- **페이지 텍스트:** 화면에 보이는 요소의 구조, 레이블, 텍스트. 마스킹이 적용됩니다.
- **페이지 URL:** 쿼리 문자열을 포함합니다.
- **사용자가 공유한 화면의 스크린샷:** 보통 이 탭이며, 비전이 켜져 있고 사용자가 브라우저의 화면 캡처 요청을 허용했을 때만 보냅니다. 마스킹되지 않습니다.
- **최근 사용자 동작의 짧은 타임라인:** 화면 기록을 켰을 때만 보냅니다.

대시보드에서 다시 보기 위한 세션 녹화는 별개의 기능이며 기본으로 꺼져 있습니다. 사용자가 입력한 내용은 입력한 그대로 보냅니다.

[페이지 데이터와 개인정보 보호 설정](/ko/sdk/page-data)에서 각 항목과 모든 제어 수단(`data-moss-redact`, `redactAllInputs`, `redactionSelectors`, `pageContext`, 수집 스위치)을 자세히 설명합니다.

### 페이지 텍스트에서 빠지는 것

- **숨겨진 요소:** `display: none`, `visibility: hidden`, `opacity: 0`, 그리고 `inert` 하위 트리 안의 모든 것. 예외가 하나 있습니다. 보이는 요소의 `aria-describedby`가 가리키는 텍스트는 숨겨져 있어도 읽습니다.
- **네이티브 폼 필드의 값**(`input`, `textarea`, `select`, 편집 가능한 영역): `redactAllInputs`가 켜져 있을 때(기본값). `div`로 만든 드롭다운처럼 다른 요소로 만든 커스텀 컨트롤은 일반 텍스트로 읽히므로 `data-moss-redact`를 붙이세요.
- **닫힌 섀도 루트와 다른 출처의 iframe:** 브라우저가 SDK의 접근을 막습니다.

이 제한은 페이지 텍스트에만 해당합니다. 세션 녹화와 화면 기록을 켜면, 차단하거나 마스킹한 요소를 빼고는 숨겨진 요소도 기록됩니다. 비전 스크린샷에는 공유된 화면에 보이는 모든 것이 담깁니다. [페이지 데이터](/ko/sdk/page-data)를 참고하세요.

**쿠키와 저장소**는 읽지 않습니다. SDK는 `moss`로 시작하는 키에 자체 상태를 보관합니다. 인터페이스 언어를 고르기 위해 `lng` 쿼리 매개변수, `i18next` 쿠키, `sessionStorage`의 `i18nextLng` 항목도 확인합니다.

<Info>
    모든 요청은 설정한 `apiUrl`로 HTTPS를 통해 갑니다. 0.17.0부터 `streamActivity`를 켜면 턴의 응답이 같은 백엔드에서 Server-Sent Events로 오며, 중간의 프록시가 이를 통과시켜야 합니다. 비전 스크린샷과 0.17.0부터의 첨부 파일은 서명된 URL을 통해 Moss 배포의 파일 저장소로 바로 업로드됩니다. SDK는 WebSocket을 쓰지 않습니다.
</Info>

### 브라우저에 저장되는 항목

대화가 페이지 이동과 새로 고침 뒤에도 이어지도록, SDK는 자체 상태를 브라우저 저장소에 조금 보관합니다.

| 저장소 | 보관하는 것 | 유지 기간 |
|---------|---------------|----------|
| `sessionStorage` | 이 탭의 채팅 메시지, 채팅이 열려 있는지 여부, 패널의 위치와 크기, 진행 중인 가이드, `askMoss()`로 대기 중인 질문 | 탭을 닫을 때까지 |
| `localStorage` | 현재 세션의 ID와 시간 정보, 최근 세션 ID, 이 기기에서 끝낸 가이드, 인터페이스 언어, 다음 페이지로 넘어가는 중인 가이드 단계 | 지울 때까지 |

페이지 텍스트와 스크린샷은 브라우저 저장소에 기록하지 않습니다. `stability.afterReload`가 켜져 있으면, 다음 페이지가 보낼 수 있도록 가이드 단계 보고(클릭한 요소의 마스킹된 마크업 포함)를 `localStorage`에 최대 `pendingTTL`(기본 30초) 동안 보관합니다. CDN 스크립트는 사용자 ID도 `moss_user_id`로 저장합니다.

## Moss가 페이지에서 바꾸는 것

- **호스트 요소.** npm 패키지는 `AgentProvider`가 있는 자리에 고정 위치 `<div>`를 렌더링하고, CDN 스크립트는 `<body>`에 `<div id="moss-sdk-root">`를 추가합니다.
- **인터랙티브 요소에 붙이는 자체 속성.** SDK는 페이지를 읽을 때마다, 찾은 버튼, 링크, 필드를 가리킬 수 있도록 자체 `data-` 속성을 붙입니다. 내부용으로 취급하세요. 읽을 때마다 바뀝니다.
- **가이드 중의 하이라이트.** 하이라이트된 요소에 속성이 붙고, SDK가 `<head>`(그리고 그 요소를 담은 섀도 루트나 같은 출처 프레임)에 추가한 `<style>` 요소가 그 요소에 윤곽선을 그립니다. 번호 배지는 페이지 위에 배치됩니다. 단계가 끝나면 속성과 배지는 사라집니다.
- **`data-moss-trigger` 요소.** 이 요소를 클릭하면 채팅이 열리거나 닫히고 `preventDefault()`가 호출되므로, 이 속성이 붙은 링크는 페이지를 이동하지 않습니다. 0.17.0부터는 애플리케이션이 Moss 패널에 지원 대화를 보여 주는 경우, 읽지 않은 답장이 있으면 각 트리거 안에 개수 배지가 생기고 트리거에 `data-moss-unread` 속성이 붙습니다. [커스텀 트리거](/ko/sdk/installation#커스텀-트리거)를 참고하세요.
- **`fetch`와 `XMLHttpRequest`.** 페이지의 요청이 끝났는지 알기 위해, SDK는 프로바이더가 마운트될 때부터 페이지와 같은 출처 프레임의 `window.fetch`와 `XMLHttpRequest`의 `open`, `send`를 감쌉니다. 요청은 바뀌지 않고 그대로 전달됩니다.
- **웹 폰트 링크:** 외관 설정에서 `typography.fontFaceUrl`을 지정한 경우.
- **`window.name`.** 페이지가 이름을 붙이지 않은 창에서 채팅이 열리면, SDK가 탭을 구분하기 위해 창에 이름(`moss-tab-…`)을 붙입니다. 페이지가 붙인 이름은 그대로 둡니다.

`pageSanitizationScript`를 설정했다면 이 함수도 페이지를 바꿉니다. [고급](/ko/sdk/advanced#프로그래밍-방식의-페이지-변경)을 참고하세요.
