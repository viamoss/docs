**구성 > 데이터 및 개인정보**에서 관리자는 애플리케이션의 데이터를 얼마나 보관할지 정하고, 요청이 오면 사용자 한 명의 데이터를 삭제합니다. 이 페이지는 0.17.0에서 개편되었습니다. 0.16.x의 **구성 > 데이터 및 개인정보** 화면에는 트래픽 로그(API 로그)만 있습니다. 보관 기간 설정, 사용자 삭제 화면, 수집 항목 요약은 0.17.0에서 추가되었고, API로 사용자 데이터를 삭제하는 기능은 그 전부터 있었습니다.

**자동 삭제는 관리자가 켜기 전까지 모든 애플리케이션에서 꺼져 있습니다.** 꺼져 있는 동안 Moss는 대화, 스크린샷, 녹화, 페이지 스냅샷, API 로그를 누군가 삭제할 때까지 보관합니다.

이 페이지에는 카드가 네 개 있습니다.

- **Moss가 수집하는 데이터**: 이 애플리케이션에서 켜져 있는 수집 항목
- **데이터 보관 기간**: 데이터 종류별 보관 기간과 **자동 삭제** 스위치
- **사용자 데이터 삭제**: 이 애플리케이션이 한 사람에 관해 가진 모든 데이터를 삭제하며, 진행 상태와 삭제 증명서를 보여 줌
- **API 상세 로그 수집**: API 요청과 응답을 기록하는 스위치

오른쪽 위의 **변경 기록**을 누르면 이 페이지에서 바꾼 내용만 걸러 낸 감사 로그가 열립니다.

데이터 및 개인정보는 **구성** 아래에 있으므로 관리자만 열 수 있습니다. 여기의 설정은 모두 애플리케이션 하나에만 적용됩니다.

<Note>
    채팅 자체의 세션 제한(위젯이 언제 새 채팅을 시작하는지)은 아무것도 삭제하지 않습니다. 이 제한은 [세션](/ko/sdk/api/session)에서 설명합니다. 데이터를 얼마나 저장할지는 이 페이지에서 정합니다.
</Note>

## Moss가 수집하는 데이터

이 카드는 애플리케이션의 수집 설정을 칩으로 보여 줍니다. 칩을 누르면 해당 설정을 바꾸는 곳으로 이동하고, **동작에서 변경**을 누르면 **구성 > 동작**이 열립니다.

| 칩 | 켜지는 조건 | 바꾸는 곳 |
| --- | --- | --- |
| **비전 스크린샷** | **비전 사용**이 켜져 있고 애플리케이션이 전체 페이지 컨텍스트를 보낼 때 | **구성 > 동작 > 주요 기능** |
| **전체 페이지 텍스트** | 애플리케이션이 전체 페이지 컨텍스트를 보낼 때. **화면 가이드**가 켜져 있으면(기본값) 그렇게 합니다 | **구성 > 동작 > 주요 기능** |
| **세션 리플레이** | **세션 리플레이 활성화**가 켜져 있을 때 | **구성 > 동작 > 주요 기능** |
| **LLM용 화면 기록** | **LLM용 화면 기록 활성화**가 켜져 있을 때 | **구성 > 동작 > 주요 기능** |
| **API 로그** | API 로그 기록이 켜져 있을 때 | **분석 > API 로그**, 또는 이 페이지 아래쪽의 스위치 |
| **마스킹** | **백엔드 개인정보 필터링**이 켜져 있을 때. 추가 패턴이나 사용자 지정 패턴이 켜져 있으면 "마스킹: 기본 + 규칙 N개", 아니면 "마스킹: 기본 규칙"으로 표시되고, 꺼져 있으면 "마스킹: 꺼짐"으로 표시됩니다 | **구성 > 보안** |

칩은 애플리케이션의 설정을 보여 줄 뿐, 각 페이지가 실제로 무엇을 하는지는 보여 주지 않습니다. 페이지의 코드로 일부 수집 항목을 바꿀 수 있고, 서버는 이를 이 설정과 대조하지 않습니다.

- `useVision` 옵션은 **비전 사용** 설정과 관계없이 스크린샷을 켜거나 끕니다.
- `pageContext`와 `enableScreenHistoryRecording` 옵션은 페이지 컨텍스트와 화면 기록을 어느 쪽으로든 정합니다. CDN 스크립트에서는 페이지가 `window.mossSettings`에 이 값을 넣으면 애플리케이션 설정보다 우선합니다. npm 설치는 두 값 모두 자체 설정만 따릅니다.
- 세션 녹화만은 예외입니다. 페이지에서 끌 수는 있지만, **세션 리플레이 활성화**가 꺼져 있으면 서버가 녹화를 받지 않습니다.

데이터 종류별 설명과 모든 제어 방법은 [데이터 보호](/ko/security/data-protection)와 [페이지 데이터](/ko/sdk/page-data)에 있습니다.

## 데이터 보관 기간

### 자동 삭제

카드 위쪽의 스위치가 **자동 삭제**입니다. 기본값은 꺼짐이며, 카드에는 "자동 삭제가 꺼져 있습니다. 직접 삭제하기 전까지 모든 데이터를 보관합니다."라고 표시됩니다.

켜는 방법:

1. 표에서 데이터 종류별 보관 기간을 고르거나([보관 기간](#보관-기간) 참고) 기본값을 그대로 둡니다.
2. **자동 삭제**를 켭니다.
3. **자동 삭제를 켤까요?** 대화상자에 데이터 종류별로 적용될 기간이 나옵니다. 직접 고르지 않은 기간에는 **기본값, 직접 선택하지 않음** 표시가 붙습니다.
4. "이 기간보다 오래된 데이터가 영구히 삭제된다는 것을 이해했습니다." 항목을 체크하고 **켜기**를 누릅니다.

켠 뒤에 일어나는 일:

- **기존 데이터도 대상입니다.** 0.17.0 이전에 저장된 파일을 포함해, 이미 보관 기간이 지난 데이터는 모두 삭제됩니다. 복구할 수 없습니다.
- **삭제는 저장할 때가 아니라 예약된 실행 때 일어납니다.** 스위치 옆에는 첫 실행 전까지 **켜짐 · 첫 실행 대기 중**이, 그 뒤에는 **켜짐 · 마지막 실행**과 실행 시각이 표시됩니다.
- **켜는 순간 기간이 고정됩니다.** 대화상자에 나온 기간이 애플리케이션에 저장되므로, 나중에 Moss의 기본값이 바뀌어도 이 기간은 바뀌지 않습니다.
- **쌓인 데이터가 많으면 여러 번 실행해야 끝납니다.** 표의 **마지막 삭제** 열에서 데이터 종류별로 몇 개가 언제 삭제되었는지 볼 수 있습니다.

자동 삭제가 켜져 있을 때 기간을 줄이면 먼저 확인을 받습니다. 예를 들어 **스크린샷 보관 기간을 줄일까요?** 대화상자가 나오고, 새 기간보다 오래된 데이터는 다음 실행 때 삭제됩니다. 기간을 늘리면 아무것도 삭제되지 않습니다.

**자동 삭제**를 끄면 바로 적용되어, 진행 중인 실행을 포함해 이후 실행이 모두 멈춥니다. 이미 삭제된 데이터는 돌아오지 않습니다.

### 보관 기간

| 데이터 | 자동 삭제를 켰을 때의 기본값 | 기간을 세는 기준 |
| --- | --- | --- |
| **대화** | 삭제할 때까지 보관 | 대화의 마지막 메시지 |
| **스크린샷** | 7일 | 각 스크린샷을 찍은 시점 |
| **녹화 (세션 리플레이)** | 삭제할 때까지 보관 | 녹화를 시작한 시점 |
| **페이지 스냅샷** | 삭제할 때까지 보관 | 각 페이지를 저장한 시점 |
| **API 로그** | 90일 | 각 요청을 보낸 시점 |

종류마다 **7일**, **30일**, **90일**, **1년**, **삭제할 때까지 보관**, 또는 **직접 입력…** 중에서 고릅니다. 직접 입력할 때는 1에서 36,500 사이의 일수를 정수로 넣습니다. 종류별 기본값에는 **(기본값)** 표시가 붙습니다.

대화에 속한 스크린샷, 녹화, 페이지 스냅샷, API 로그는 그 대화가 삭제될 때 더 일찍 함께 삭제될 수도 있습니다. 표의 기간 아래에 "또는 대화와 함께, 대화의 마지막 메시지로부터 30일 후."처럼 표시됩니다.

### 대화와 함께 삭제되는 데이터

대화가 보관 기간에 이르면 Moss는 대화 전체를 삭제합니다.

- 대화의 메시지, 스크린샷, 녹화, 페이지 스냅샷, 업로드한 파일, API 로그
- 그 대화에서 나온 평가 점수, 대화 인사이트, 모니터 결과, 헬프데스크 이관 기록

그 대화를 인용한 제안은 남지만, 대화로 이어지는 연결과 대화를 바탕으로 쓴 텍스트는 지워집니다.

**사용자는 마지막 대화와 함께 삭제됩니다.** 남은 대화가 없고 대화 보관 기간 동안 프로필이 바뀌지 않은 사용자는 프로필도 삭제됩니다.

### 대화가 닫힌 것으로 보는 시점

자동 삭제는 닫힌 대화만 삭제하므로, 아직 진행 중인 채팅은 삭제하지 않습니다.

- 서버는 메시지가 30분 동안 없으면(기본값) 대화를 닫습니다. 15분마다 확인하므로, 마지막 메시지 후 최대 45분까지 열린 상태로 남을 수 있습니다.
- 닫힌 대화에 새 메시지가 오면 대화가 다시 열리고, 보관 기간도 그 메시지부터 다시 셉니다.
- 아직 접수될 수 있는 지원 티켓이 있는 대화는 그 티켓이 접수될 수 있는 동안 보관됩니다.

이것은 채팅의 세션 시간 제한과 다릅니다. [세션](/ko/sdk/api/session)에서 설명하는 시간 제한과 최대 유지 시간은 위젯이 언제 새 채팅을 시작할지만 정하며, 서버에서 아무것도 닫거나 삭제하지 않습니다.

### 최소 기간과 법적 보존

Moss 관리자는 이 페이지의 관리자가 바꿀 수 없는 두 가지를 정할 수 있습니다. Moss 호스팅 서비스에서는 Moss가, 자체 호스팅 설치에서는 운영자가 Moss 관리자입니다.

**최소 기간**은 데이터 종류별로 허용되는 가장 짧은 보관 기간입니다. 최소 기간은 데이터를 더 오래 보관하게 할 뿐입니다.

- 해당 종류의 행에 "Moss 관리자가 정한 최소 기간은 N일입니다."라고 표시됩니다.
- 이보다 짧은 기간을 고르면 Moss는 최소 기간 동안 보관하고, 행에 두 값을 모두 보여 줍니다. "X일을 선택했습니다. Moss 관리자가 정한 최소 기간은 N일입니다."
- 대화를 삭제하면 그 대화의 스크린샷, 녹화, 페이지 스냅샷, API 로그도 삭제되므로, 대화는 이들의 최소 기간 중 가장 긴 기간 이상 보관됩니다.
- 최소 기간 안에 있는 API 로그는 **분석 > API 로그**에서 직접 삭제할 수도 없습니다.

**법적 보존**은 애플리케이션의 모든 삭제를 멈춥니다. 카드에 **법적 보존으로 일시 중지됨** 상태와 보존이 시작된 날짜가 표시되고, "보존 중에는 아무것도 삭제하지 않습니다."라는 안내가 붙습니다. 보존 중에는 다음과 같습니다.

- 자동 삭제가 실행되지 않고, 스위치와 기간도 바꿀 수 없습니다("법적 보존으로 잠겨 있습니다. Moss 관리자가 관리합니다.").
- **사용자 데이터 삭제**는 새 요청과 다시 시도를 거부하며, 아무것도 기록하지 않습니다.
- API 로그를 직접 삭제할 수 없습니다.
- 애플리케이션의 감사 이벤트가 기간 경과로 삭제되지 않습니다.

Moss 호스팅 서비스에서 법적 보존에 관해서는 Moss 지원팀에 문의하세요.

### 자동 삭제가 다루지 않는 데이터

카드의 **삭제 대상이 아닌 항목** 목록에는 다음이 나옵니다.

- **헬프데스크로 이미 보낸 티켓**
- **사용자 브라우저에 남은 사본**
- **고객사 백업**
- **감사 이벤트 (Moss 관리자가 정한 기간 동안 보관)**: Moss 관리자가 바꾸지 않았다면 365일입니다. [감사 로깅](/ko/security/audit-logging)을 참고하세요.
- **투어와 설문의 가이드 이벤트 (사용자를 삭제할 때까지)**

자동 삭제는 Moss 데이터베이스에 있는 애플리케이션의 레코드와 파일 저장소에 있는 파일에만 적용됩니다. 파일 저장소가 보관하는 이전 파일 버전은 지우지 않으며, 모델 제공업체나 다른 외부 서비스에 삭제 요청을 보내지 않습니다.

### 상태와 문제

스위치 옆의 줄은 자동 삭제의 현재 상태를 보여 줍니다.

| 상태 | 의미 |
| --- | --- |
| **꺼짐** | 아무것도 자동으로 삭제되지 않습니다. |
| **켜짐 · 첫 실행 대기 중** | 켜졌지만 아직 첫 실행이 없었습니다. |
| **켜짐 · 마지막 실행**과 실행 시각 | 정상적으로 실행되고 있습니다. |
| **켜짐 · 지연됨** | 일부 데이터가 보관 기간을 하루 넘게 지났거나, 애플리케이션이 차례를 기다리고 있습니다. 자동으로 따라잡습니다. |
| **켜짐 · 마지막 실행 실패** | 마지막 실행이 실패했습니다. 다음 실행 때 다시 시도합니다. |
| **켜짐 · 아직 실행되지 않음** / **켜짐 · 실행 멈춤** | 예상보다 오랫동안 실행이 없었습니다. |
| **법적 보존으로 일시 중지됨** | [최소 기간과 법적 보존](#최소-기간과-법적-보존)을 참고하세요. |

문제가 있으면 표 위의 배너에 내용과 **자세히** 버튼이 나옵니다. **자동 삭제 상세 정보**에는 **최근 실행**과 **다음에 할 일**이 있습니다. Moss 호스팅 서비스에서는 언제 Moss 지원팀에 문의해야 하는지 알려 주고, 자체 호스팅 설치에서는 운영자가 실행할 명령을 보여 줍니다.

## 사용자 데이터 삭제

애플리케이션이 한 사람에 관해 가진 모든 데이터를 삭제할 때 씁니다. 예를 들어 사용자가 자신의 데이터 삭제를 요청한 경우입니다. **삭제는 되돌릴 수 없습니다.**

### 절차

1. **구성 > 데이터 및 개인정보**를 열고 **사용자 데이터 삭제** 카드에서 **새 요청**을 누릅니다.
   사용자 화면에서 시작할 수도 있습니다. **분석 > 사용자**에서 사용자를 열고 **위험 구역 > 이 사용자의 데이터 삭제 > 삭제 검토**를 누르세요.
2. **사용자를 찾습니다.** 사용자 ID 앞부분을 3자 이상 입력하고 **일치하는 사용자** 목록에서 고릅니다. ID가 더 짧거나 Moss에 프로필이 없는 사용자라면 전체 ID를 입력하고 **정확한 ID “…” 사용**을 고르세요. 검색 결과마다 프로필이 있는지, 대화가 몇 개인지, 마지막 접속 시각, 그리고 그 ID가 API 로그나 가이드 이벤트에도 있는지(**API 로그에 있음**, **가이드 이벤트에 있음**)가 표시됩니다.
3. **삭제를 검토합니다.** 화면에 **삭제되는 데이터**, **수정되는 데이터**, **삭제되지 않는 데이터**가 나옵니다(아래 참고).
4. 필요하면 **티켓 참조 번호 (선택)** 칸에 개인정보 요청 번호 등을 입력합니다. 이 번호는 요청과 삭제 증명서에 표시됩니다.
5. 확인 칸에 사용자 ID를 입력하고 **이 사용자의 데이터 삭제**를 누릅니다.

요청 화면이 열리고 상태가 자동으로 업데이트됩니다. 그 ID에 해당하는 데이터가 Moss에 없으면 버튼이 **요청 기록**으로 바뀝니다. 이때 Moss는 아무것도 삭제하지 않고 요청만 기록하므로, 요청을 처리했다는 삭제 증명서를 남길 수 있습니다.

사용자 한 명에게는 진행 중인 요청이 하나만 있을 수 있습니다. 두 번째 요청은 "이 사용자에게 이미 진행 중인 요청이 있습니다. 새 요청은 기록되지 않았습니다." 메시지와 함께 거부되고, 진행 중인 요청으로 가는 링크가 나옵니다. **실패** 상태의 요청도 진행 중인 요청으로 봅니다. 그 요청에서 **다시 시도**를 누르세요.

### 삭제되는 데이터와 삭제되지 않는 데이터

| 삭제되는 데이터 | 삭제되지 않는 데이터 |
| --- | --- |
| 사용자 프로필 | 백업과 이전 파일 버전 (만료될 때까지) |
| 모든 대화와 그 메시지, 스크린샷, 녹화, 페이지 스냅샷, 첨부 파일 | Moss 밖의 사본 (이미 보낸 헬프데스크 티켓, 사용자 브라우저) |
| 해당 대화의 평가 점수, 인사이트, 모니터 결과, 헬프데스크 이관 기록 | 관리자 작업에 관한 그 밖의 감사 기록 |
| 이 사용자 ID가 담긴 API 로그와 가이드 이벤트 | 삭제 증명으로 보관하는 이 요청 |
| 팀이 이 사용자의 대화를 검토하거나 열람한 기록을 포함한, 이 사용자에 관한 감사 기록. 단, 감사 최소 기간으로 보관되는 기록은 제외(아래 참고) | |

**수정되는 데이터:** 이 사용자의 대화를 인용한 제안에서 대화로 이어지는 연결과 대화를 바탕으로 쓴 텍스트가 지워집니다. 제안의 나머지 부분은 바뀌지 않습니다.

**Moss 관리자가 감사 최소 기간을 정해 두었다면**(기본값은 없음) 이 사용자에 관한 감사 기록 일부가 보관됩니다. 팀원이나 API 키가 한 작업 가운데 내용이 담기지 않은 기록, 즉 사용자 대화의 평가, 사용자 메타데이터 삭제, AI 어시스턴트의 도구 호출 기록 중 최소 기간보다 최근의 것입니다. 이 기록은 일반 감사 보관 기간이 지나 삭제될 때까지 남으며, 삭제 증명서의 JSON에 보관된 기록으로 표시됩니다.

사용자의 삭제 요청이 진행 중인 동안에는 위젯의 이전 대화 목록이 비어 있습니다.

### 상태

| 상태 | 의미 |
| --- | --- |
| **진행 중** | 지금 삭제하고 있습니다. |
| **예상보다 오래 걸림** | 15분 넘게 실행되고 있습니다. **다시 시도**를 누르면 같은 요청 ID로 다시 실행합니다. |
| **대기 중** | 실행을 기다리고 있습니다. "다음 자동 삭제 실행 때 완료"가 함께 표시되면 다음 예약 실행 때 끝납니다. "실행되지 않는 자동 삭제를 기다리는 중"이 함께 표시되면 삭제 일정이 설정될 때까지 아무것도 실행하지 않습니다. [자체 호스팅 설치](#자체-호스팅-설치)를 참고하세요. |
| **완료** | 실행이 끝났습니다. 화면에 날짜, 삭제된 항목, 삭제 증명서가 나옵니다. |
| **데이터 없음** | Moss에 이 ID의 데이터가 없었습니다. 요청은 기록으로 보관됩니다. |
| **실패** | 끝까지 진행하지 못했고, 일부 항목은 이미 삭제되었을 수 있습니다. 화면에 원인이 나옵니다. **다시 시도**를 누르세요. |

요청을 바로 끝낼 수 없으면 다음 예약 실행을 기다립니다. 예를 들어 같은 애플리케이션에서 다른 삭제가 동시에 진행 중이거나, 사용자의 감사 기록을 예약 작업만 지울 수 있는 경우입니다.

**모든 요청**을 누르면 **삭제 요청** 화면이 열립니다. 애플리케이션의 모든 요청이 요청자, 참조 번호, 상태, 삭제된 항목 수와 함께 나옵니다. 사용자 ID 앞부분이나 티켓 참조 번호로 검색할 수 있습니다.

### 삭제 증명서

요청이 **완료** 상태가 되면 요청 화면에 **삭제 증명서**가 나옵니다.

- 모든 확인을 통과하면 제목이 "검증됨: 이 앱에서 이 사용자의 레코드를 찾지 못했습니다"이고, 그렇지 않으면 "모두 검증되지는 않았습니다."와 함께 이유와 다음에 할 일이 나옵니다.
- 각 행에서 **이 앱의 데이터**와 **이 사용자에 관한 감사 기록**이 검증되었는지, **남은 레코드**가 몇 개인지, **확인 시각**이 언제인지 볼 수 있습니다.
- **포함되지 않음** 행은 항상 "백업, 이전 파일 버전, Moss 밖의 사본"입니다.
- **보관** 행은 삭제 증명으로 보관하는 요청 자체입니다.

**삭제 증명서 보기 (JSON)** 버튼을 누르면 전체 증명서가 나옵니다. `deleted_items`에는 데이터 종류별 삭제 개수가 들어 있고, `verification.complete`는 요청이 끝났고 남은 데이터가 없으며 사용자에 관한 감사 기록이 검증되었을 때만 `true`입니다. `verification.not_verified`에는 항상 이전 객체 버전, 백업, 외부 처리자 사본이 나열됩니다.

요청과 삭제 증명서는 증명용으로 보관됩니다. Moss 관리자는 완료된 요청을 삭제할 기간을 정할 수 있으며, 기본값은 계속 보관입니다.

### API로 삭제하기

같은 요청을 대시보드 API로도 처리할 수 있습니다. 애플리케이션이 속한 조직의 관리자로 로그인해야 합니다.

| 메서드와 경로 | 동작 |
| --- | --- |
| `POST /api/v1/applications/{application_id}/deletion-requests` | 본문 `{"user_id": "…", "request_reference": "…"}` (`request_reference`는 선택). 요청과 그 `status`를 담아 `201`을 반환합니다. |
| `GET /api/v1/applications/{application_id}/deletion-requests` | 요청 목록을 반환합니다. |
| `GET /api/v1/applications/{application_id}/deletion-requests/{request_id}` | 요청 하나와 그 상태를 반환합니다. |
| `GET /api/v1/applications/{application_id}/deletion-requests/{request_id}/certificate` | 요청이 `completed`가 된 뒤 JSON 삭제 증명서를 반환합니다. 그 전에는 `400`을 반환합니다. |
| `POST /api/v1/applications/{application_id}/deletion-requests/{request_id}/retry` | 실패했거나 멈춘 요청을 같은 ID로 다시 실행합니다. 0.17.0에서 추가되었습니다. |

법적 보존 중에는 새 요청과 다시 시도가 코드 `legal_hold`와 함께 `423`으로 거부되며, 아무것도 기록되지 않습니다. 진행 중인 요청이 있는 사용자에 대한 두 번째 요청은 코드 `request_open`과 함께 `409`를 받습니다. `201`을 받았다고 데이터가 삭제된 것은 아닙니다. 요청의 `status`를 확인하세요.

## API 상세 로그 수집

마지막 카드에는 **API 상세 로그 수집** 스위치가 있습니다. 설명은 "이 앱에서 지원하는 API 요청과 응답을 기록합니다."이며, 기본값은 꺼짐입니다.

- **분석 > API 로그**의 **API 로그 기록** 스위치와 같은 설정입니다. 그쪽 스위치는 켜기 전에 확인을 받고 로그 보관 기간을 알려 줍니다.
- 끄면 기록이 멈춥니다. 이미 기록된 로그는 카드 안내대로("수집이 꺼져 있습니다. 기존 로그는 계속 조회할 수 있습니다.") 남아 있다가, **API 로그** 보관 기간이 지나거나 직접 삭제하면 지워집니다.
- 0.17.0부터 요청과 응답 본문은 저장하기 전에 마스킹됩니다. 무엇을 마스킹하는지, 그리고 0.16.x에서는 어땠는지는 [데이터 보호](/ko/security/data-protection#api-로그의-마스킹)에 있습니다.
- 0.16.x에서는 이 스위치가 **트래픽 로그 활성화**이고, 로그 목록도 이 페이지에 있습니다. 0.17.0부터 목록은 **분석 > API 로그**에 있습니다.
- 번들을 가져와 만든 애플리케이션은 기록이 꺼진 상태로 시작합니다.

API 로그를 보거나 내보내거나 삭제하려면 [API 로그](/ko/dashboard/analytics#api-로그)를 참고하세요.

## 변경 기록

**변경 기록**을 누르면 **구성 > 감사 로그**가 열리고, 최근 90일 동안의 다음 기록이 나옵니다.

- 관리자가 자동 삭제나 보관 기간을 바꾼 기록
- Moss 관리자가 최소 기간이나 법적 보존을 바꾼 기록
- 0.17.0으로 업그레이드할 때 이전 버전에서 옮겨진 보관 설정
- API 로그 기록 설정을 바꾼 기록

보관 설정의 변경마다 누가 바꿨는지와 바꾸기 전후의 값이 나옵니다. 자동 삭제 실행은 따로 기록되며 이 화면에는 나오지 않습니다. [감사 로깅](/ko/security/audit-logging)을 참고하세요.

## 자체 호스팅 설치

자체 호스팅 설치에서는 운영자가 설정하는 예약 작업 하나, 보존 CronJob이 삭제를 맡습니다. 이 작업은 설치의 모든 애플리케이션을 처리하며 기본적으로 15분마다 실행됩니다. 운영자가 켜기 전까지는 꺼져 있습니다. 설정과 규모 조정은 [운영](/ko/self-hosting/operations#보존-cronjob)에 있습니다.

이 작업이 없으면:

- **아무것도 자동으로 삭제되지 않습니다.** 관리자가 자동 삭제를 켤 수는 있지만, 카드에 "자동 삭제가 켜져 있지만 실행할 일정이 없습니다."라고 표시됩니다. 자동 삭제가 꺼져 있을 때는 "이 설치 환경에는 아직 자동 삭제 일정이 설정되지 않았습니다."라고 표시됩니다.
- **일부 사용자 삭제가 끝나지 않습니다.** 기다려야 하는 요청은 **대기 중** 상태에 "실행되지 않는 자동 삭제를 기다리는 중"이 함께 표시됩니다. 요청 화면에는 운영자가 실행해 요청을 끝낼 수 있는 명령이 나옵니다.

그러니 자동 삭제를 꺼 둘 계획이라도 이 작업은 설정하세요.

작업이 파일 저장소에 접근할 수 없으면 **자동 삭제 상세 정보**에 "이 설치 환경에는 파일 저장소가 설정되어 있지 않아 API 로그만 삭제됩니다. 대화, 스크린샷, 녹화, 페이지 스냅샷은 저장소가 설정될 때까지 보관됩니다."라고 나옵니다. 운영자는 백엔드가 쓰는 것과 같은 파일 저장소를 이 작업에 연결해야 합니다.

운영자는 그 밖에도 최소 기간과 법적 보존, 감사 최소 기간(기본값은 없음. [삭제되는 데이터와 삭제되지 않는 데이터](#삭제되는-데이터와-삭제되지-않는-데이터) 참고), 감사 이벤트 보관 기간(기본값 365일), 완료된 삭제 요청 보관 기간(기본값은 계속 보관)을 정합니다.

## 0.17.0 이전

0.16.x의 **구성 > 데이터 및 개인정보** 화면에는 트래픽 로그만 있습니다. **트래픽 로그 활성화** 스위치, 기록된 요청 목록, 내보내기가 전부이며, 대시보드에 보관 기간이나 삭제 요청은 없습니다.

- 아무것도 자동으로 삭제되지 않습니다. 대화, 스크린샷, 녹화, 페이지 스냅샷, API 로그는 삭제할 때까지 남습니다. 0.16.x에서도 API로 API 로그 보관 기간을 저장할 수는 있지만 적용되지 않으며, 0.17.0으로 옮겨지지도 않습니다.
- 사용자 데이터는 API로만 삭제할 수 있습니다. `POST /api/v1/applications/{application_id}/deletion-requests`로 요청한 뒤, 요청을 `GET`으로 조회해 상태와 삭제 증명서를 확인합니다. **다시 시도** 기능은 없습니다.
- 감사 이벤트는 0.17.0과 마찬가지로 365일이 지나면 삭제됩니다.

0.17.0으로 업그레이드하면 모든 애플리케이션이 자동 삭제가 꺼진 상태로 시작합니다. 관리자가 켜기 전까지는 아무것도 삭제되지 않습니다(자체 호스팅 설치라면 보존 CronJob도 실행되어야 합니다).

## 자주 묻는 질문

**Moss는 기본적으로 무언가를 자동 삭제하나요?**
아니요. 관리자가 이 페이지에서 켜기 전까지 모든 애플리케이션에서 자동 삭제는 꺼져 있습니다. 예외는 감사 이벤트로, Moss 관리자가 정한 기간(기본값 365일)이 지나면 삭제됩니다.

**자동 삭제를 켜면 이미 있는 데이터는 어떻게 되나요?**
기존 데이터도 대상입니다. 첫 실행 때 0.17.0 이전에 저장된 파일을 포함해 보관 기간이 지난 데이터가 모두 삭제됩니다. [자동 삭제](#자동-삭제)를 참고하세요.

**채팅 세션 시간 제한을 30분으로 정했습니다. 그러면 대화가 삭제되나요?**
아니요. 시간 제한은 위젯이 언제 새 채팅을 시작할지만 정합니다. 대시보드에서 대화를 삭제하는 것은 자동 삭제와 사용자 데이터 삭제 요청뿐입니다. [대화가 닫힌 것으로 보는 시점](#대화가-닫힌-것으로-보는-시점)을 참고하세요.

**한 사람의 데이터를 삭제하고 그 사실을 증명하려면 어떻게 하나요?**
[사용자 데이터 삭제](#사용자-데이터-삭제)를 이용하세요. 요청이 **완료** 상태가 되면 삭제 증명서에서 무엇이 삭제되고 무엇이 검증되었는지 확인할 수 있고, JSON으로도 볼 수 있습니다. 백업과 Moss 밖의 사본은 포함되지 않습니다.

**사용자를 삭제하면 헬프데스크로 보낸 티켓도 지워지나요?**
아니요. 헬프데스크에 이미 접수된 티켓은 그대로 남으니 해당 도구에서 삭제하세요. Moss는 사용자 대화에 대한 자체 이관 기록만 삭제합니다.

**자동 삭제를 끄면 삭제된 데이터를 되돌릴 수 있나요?**
아니요. 끄면 이후 삭제만 멈추며, 이미 삭제된 데이터는 돌아오지 않습니다.

**법적 보존이나 최소 기간은 누가 정하나요?**
Moss 관리자입니다. Moss 호스팅 서비스에서는 Moss가, 자체 호스팅 설치에서는 운영자가 정합니다. 관리자는 이 페이지에서 볼 수는 있지만 바꿀 수는 없습니다.

**애플리케이션을 내보내면 이 설정도 함께 옮겨지나요?**
직접 고른 보관 기간은 옮겨집니다. 자동 삭제 스위치, 법적 보존, 최소 기간은 옮겨지지 않으므로, 가져온 애플리케이션은 자동 삭제가 꺼진 상태로 시작합니다. API 로그 기록도 꺼진 상태로 시작합니다.

**스크린샷과 녹화는 어디에 저장되고, 모델에는 무엇이 전달되나요?**
[데이터 보호](/ko/security/data-protection)를 참고하세요.
