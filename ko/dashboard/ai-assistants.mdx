0.17.0부터는 MCP(Model Context Protocol)로 자신의 AI 어시스턴트를 Moss에 연결할 수 있습니다. 어시스턴트는 애플리케이션, 세션, 분석, 지식 베이스, 구성을 조회할 수 있고, 조직에서 허용하면 지식, 지침, 설정, 프로시저, 제안에 대한 변경을 준비할 수 있습니다. 어시스턴트는 나로서 동작하며, 연결할 때의 내 역할을 넘는 접근 권한은 갖지 않습니다. 모든 변경은 적용 전에 미리 보기를 거치고, 어시스턴트의 도구 호출은 모두 감사 로그에 기록됩니다.

지원하는 클라이언트는 Claude(웹과 데스크톱), ChatGPT, Claude Code, Cursor, VS Code, Codex입니다. 그 밖에도 HTTP로 MCP를 쓰고 헤더를 보낼 수 있는 클라이언트라면 토큰으로 연결할 수 있습니다.

<Note>
  이 페이지는 **내** 어시스턴트를 **Moss에** 연결하는 방법을 설명합니다. 대화 중에 Moss가 **고객사의** MCP 서버에 있는 도구를 호출하게 하려면 **구성 > 연동**의 **MCP 서버** 카드를 쓰세요. [연동](/ko/dashboard/integrations)을 참고하세요.
</Note>

## 시작하기 전에

스위치 두 개가 켜져 있어야 하며, 둘 다 기본값은 꺼짐입니다.

1. **배포.** Moss 배포에서 이 기능이 켜져 있으면 모든 페이지의 사용자 메뉴(오른쪽 위)에 **AI 어시스턴트**가 나타나고, 애플리케이션을 열지 않은 상태에서는 사이드바의 **애플리케이션** 옆에도 나타납니다. 애플리케이션 안의 사이드바에는 나오지 않습니다. 두 곳 모두에 **AI 어시스턴트**가 없다면 배포에서 이 기능이 꺼져 있는 것입니다.
2. **조직.** 관리자가 **AI 어시스턴트** 페이지에서 조직에 이 기능을 켭니다(아래 참고). 켜기 전에는 조직의 누구도 어시스턴트를 연결할 수 없습니다.

### 자체 호스팅 설치에서 켜기

운영자가 다음 환경 변수를 설정합니다. Helm 차트의 `values.yaml`에는 꺼진 상태로 들어 있습니다.

| 변수 | 설정 위치 | 값 |
|---|---|---|
| `MCP_ENABLED` | 대시보드 백엔드와 대시보드 | `true`(`1`, `yes`, `on`도 가능). 백엔드는 시작할 때 이 값을 읽으므로, 바꾼 뒤에는 다시 시작하세요. |
| `MCP_PUBLIC_URL` | 대시보드 백엔드 | 사용자가 어시스턴트에 붙여 넣는 URL입니다. `https`이고 `/mcp`로 끝나야 합니다(예: `https://moss.example.com/mcp`). 대시보드가 `/mcp`를 백엔드로 전달하므로 대시보드 주소를 써도 됩니다. 올바른 값이 없으면 기능이 꺼진 채로 남습니다. 나중에 바꾸면 모든 어시스턴트의 로그인이 풀립니다. |
| `MCP_ALLOWED_ORIGINS` | 대시보드 백엔드 | 선택 사항입니다. `/mcp`에 `Origin` 헤더를 보낼 수 있는 정확한 출처 목록이며, 브라우저 기반 클라이언트에만 필요합니다. |
| `MCP_DASHBOARD_URL` | 대시보드 백엔드 | 선택 사항입니다. `MCP_PUBLIC_URL`이 대시보드가 아니라 백엔드를 가리킬 때 대시보드의 출처를 지정합니다. 로그인 페이지와 승인 링크가 이 값을 씁니다. |

Claude와 ChatGPT는 각 제공업체의 클라우드에서 연결하므로, 이 둘을 쓰려면 `MCP_PUBLIC_URL`과 그 로그인 경로에 인터넷에서 접근할 수 있어야 합니다. Claude Code, Cursor, VS Code, Codex는 사용자의 컴퓨터에서 실행되므로 그 컴퓨터의 네트워크나 VPN에서만 접근할 수 있으면 됩니다.

## 조직에서 켜기

이 설정은 관리자만 바꿀 수 있고, 멤버에게는 요약만 보입니다.

1. 사용자 메뉴에서, 또는 애플리케이션을 열지 않은 상태의 사이드바에서 **AI 어시스턴트**를 엽니다.
2. **조직 접근**에서 **켜기**를 누릅니다.
3. 확인 창에 적용될 설정이 나옵니다. 이 설정을 한 번도 정하지 않은 조직이라면 **읽기: 허용**, **대화 내용: 켜짐**, **Moss에서 승인: 꺼짐**입니다. **켜기**를 누릅니다.
4. 아래 설정을 조정합니다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| **AI 어시스턴트 허용** | 켠 뒤에는 켜짐 | 끄면 다시 켤 때까지 조직의 모든 연결이 중지됩니다. 연결이 철회되지는 않습니다. |
| **어시스턴트가 할 수 있는 일** | **읽기**만 | **읽기**는 항상 포함됩니다. **지식**을 선택하면 어시스턴트가 웹사이트 소스와 문서를 추가하고, 소스를 새로 고치고, 마크다운 페이지를 편집할 수 있습니다. **구성**을 선택하면 지침, 정해진 일부 설정, 프로시저를 바꾸고, 제안을 결정하고, 구성을 내보낼 수 있습니다. 연결은 조직이 허용하는 동안에만 권한을 쓸 수 있으므로, 여기서 선택을 해제하면 기존 연결 모두의 권한이 즉시 줄어듭니다. |
| **대화 내용** | 켜짐 | 어시스턴트가 최종 사용자가 쓴 내용(대화 기록, 원본 질문, 인용, 피드백 댓글)을 읽을 수 있습니다. 끄면 이 내용은 빠집니다. |
| **Moss에서 승인 필요** | 꺼짐 | 켜면 어시스턴트가 준비한 변경마다, 그 어시스턴트를 연결한 사람이 Moss에서 승인할 때까지 기다립니다([미리 보기와 승인](#미리-보기와-승인) 참고). |

<Warning>
  **Moss에서 승인 필요**가 꺼져 있으면, 대부분의 변경은 어시스턴트 자체의 확인 질문만 거쳐 적용되며, 사람이 변경 내용을 봤는지 Moss는 알 수 없습니다. 이를 감수할 수 없다면 켜세요.
</Warning>

## 어시스턴트 연결하기

조직에서 허용하면, 대시보드에 로그인할 수 있는 사람은 관리자든 멤버든 누구나 자신의 어시스턴트를 연결할 수 있습니다. **AI 어시스턴트**를 열면 **연결** 카드에 **MCP URL**과 클라이언트별 연결 방법이 나옵니다.

연결하는 방법은 두 가지입니다.

- **로그인**(OAuth): Claude, ChatGPT, Claude Code에서 씁니다. 토큰을 다룰 필요가 없습니다.
- **개인 액세스 토큰**: Claude Code, Cursor, VS Code, Codex와 그 밖의 클라이언트에서 씁니다.

### 로그인

| 클라이언트 | 방법 |
|---|---|
| Claude(claude.ai 또는 Claude Desktop) | MCP URL로 사용자 지정 커넥터를 추가한 뒤 로그인합니다. |
| ChatGPT | 개발자 모드를 켜고 MCP URL로 커넥터를 추가한 뒤 로그인합니다. |
| Claude Code | `claude mcp add --transport http moss <MCP URL>`을 실행한 뒤 `/mcp` 메뉴에서 로그인합니다. |

그러면 브라우저에서 Moss의 **AI 어시스턴트 연결** 페이지가 열립니다. 로그인하라는 안내가 나오면 로그인하고, 결정하기 전에 페이지를 확인하세요.

- **요청한 곳**: 앱 이름에는 **미확인** 표시가 붙습니다. 앱이 직접 정한 이름이며 Moss가 확인하지 않았다는 뜻입니다. **돌아갈 주소**는 결정한 뒤 Moss가 보내 줄 주소입니다. Moss가 알지 못하는 주소라면, 직접 시작한 연결일 때만 계속하라는 경고가 나옵니다.
- **조직**: 연결은 이 조직에 만들어집니다. 여러 조직에 속해 있다면 여기서 바꿀 수 있습니다.
- **권한**: **읽기**는 항상 포함됩니다. **지식**과 **구성**은 조직이 허용할 때만 나옵니다. 어시스턴트가 요청한 권한(**요청됨** 표시)이라도 미리 선택되어 있지 않으니, 원하는 권한을 직접 선택하세요. 권한마다 변경이 Moss에서의 승인을 기다리는지 함께 표시됩니다.
- **애플리케이션**: **모든 애플리케이션** 또는 직접 고른 애플리케이션(최대 50개)입니다.
- **유지 기간**: 30일입니다. 기간이 지나면 다시 승인해야 합니다.

**허용** 또는 **거부**를 누르세요. 요청은 10분 동안 유효하며, 한 번만 결정할 수 있습니다. 직접 시작한 연결만 허용하세요.

**연결** 카드에 로그인을 쓸 수 없다고 나오면, 배포에 로그인 연결이 설정되어 있지 않은 것입니다. 토큰을 쓰세요.

### 토큰 사용

1. **내 연결**에서 **토큰 만들기**를 누릅니다.
2. 대화 상자를 채웁니다.
   - **라벨**: 토큰을 구분할 수 있도록 1~100자로 입력합니다.
   - **권한**: **읽기**, 그리고 조직이 허용하면 **지식**이나 **구성**을 선택합니다. 이 두 권한이 없는 토큰은 아무것도 바꿀 수 없습니다.
   - **애플리케이션**: **모든 애플리케이션** 또는 **선택한 애플리케이션**(최대 50개)입니다.
   - **만료 기간**: 7일, 30일, 90일 중에서 고릅니다(기본값 30일).
3. **토큰 만들기**를 누르고 토큰을 복사합니다. 토큰은 `moss_pat_`로 시작하며 한 번만 표시됩니다. Moss는 토큰의 해시만 보관합니다.
4. 커밋하는 파일이 아니라 환경 변수에 토큰을 저장하고, 클라이언트에 Moss를 추가합니다. `<MCP URL>`은 **연결** 카드의 URL로 바꾸세요.

```bash
export MOSS_MCP_TOKEN='moss_pat_…'
```

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http moss <MCP URL> --header "Authorization: Bearer $MOSS_MCP_TOKEN"
    ```

  </Tab>
  <Tab title="Cursor">
    프로젝트의 `.cursor/mcp.json`에, 또는 모든 프로젝트에 쓰려면 `~/.cursor/mcp.json`에 다음을 추가하세요.
    ```json
    {
      "mcpServers": {
        "moss": {
          "url": "<MCP URL>",
    ```

  </Tab>
  <Tab title="VS Code">

    ```json
    {
      "inputs": [
        { "type": "promptString", "id": "moss-token", "description": "Moss access token", "password": true }
      ],
      "servers": {
        "moss": {
          "type": "http",
          "url": "<MCP URL>",
          "headers": { "Authorization": "Bearer ${input:moss-token}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    `~/.codex/config.toml`에 다음을 추가하세요.
    ```toml
    [mcp_servers.moss]
    url = "<MCP URL>"
    bearer_token_env_var = "MOSS_MCP_TOKEN"
    ```
  </Tab>
  <Tab title="기타">
    MCP URL로 보내는 모든 요청에 토큰을 Bearer 토큰으로 넣으세요.
    ```text
    Authorization: Bearer <token>
    ```
  </Tab>
</Tabs>

활성 토큰은 최대 10개까지 가질 수 있습니다. 토큰을 교체하려면 새 토큰을 만들고 이전 토큰을 철회하세요.

연결한 뒤에는 어시스턴트에게 Moss 애플리케이션 목록을 보여 달라고 하세요. 다른 도구는 그 답에 나온 애플리케이션 ID를 씁니다.

## 어시스턴트가 읽을 수 있는 것

**읽기** 권한이 있는 어시스턴트는 다음 도구를 쓸 수 있습니다. 이 도구들은 아무것도 바꾸지 않습니다.

| 도구 | 돌려주는 것 |
|---|---|
| `list_applications` | 연결이 쓸 수 있는 애플리케이션과, 연결이 누구로서 동작하는지(조직, 역할, 권한, 만료) |
| `get_analytics` | 기간별 분석 보고서. **분석** 페이지와 같은 내용입니다. |
| `get_insights` | 대화에서 드러나는 것: 의도, 마찰, 결과, 공백, 평가 점수, 모니터 리뷰 큐 |
| `search_sessions` | 날짜, 키워드, 평가, 해결 여부 등의 조건에 맞는 세션 |
| `get_session` | 세션 하나의 대화 기록, 단계, 가져온 문서, 평가 점수. **대화 내용**이 켜져 있어야 합니다. |
| `list_proposals`, `get_proposal` | 프로시저, 지침, 지식에 대해 제안된 변경 |
| `list_knowledge_sources`, `list_knowledge_pages`, `get_knowledge_page` | 지식 소스, 소스의 페이지, 페이지의 마크다운 |
| `get_application_config` | 애플리케이션의 이름, 설정(비밀 값은 가림), 어시스턴트 지침 |
| `list_procedures`, `get_procedure` | 프로시저와 그 성과 |
| `query_audit_log` | 애플리케이션이나 조직의 감사 이벤트. **관리자만** 쓸 수 있습니다. |
| `export_application_config` | 애플리케이션의 내보내기 번들(인증 정보 제외). **구성** 권한이 필요합니다. **관리자만** 쓸 수 있습니다. |

"관리자만"은 관리자가 만든 연결이라는 뜻입니다. 어시스턴트에게는 그 연결이 쓸 수 있는 도구만 보입니다.

## 어시스턴트가 바꿀 수 있는 것

| 도구 | 바꾸는 것 | 권한 | 사용할 수 있는 사람 |
|---|---|---|---|
| `add_knowledge_source` | 공개 `https` 웹사이트를 지식 소스로 추가하고 크롤링을 시작합니다. | **지식** | 누구나 |
| `add_knowledge_document` | 새 마크다운 소스나 기존 마크다운 소스에 마크다운 페이지 하나를 추가합니다. | **지식** | 누구나 |
| `refresh_knowledge_source` | 소스를 새로 고치거나, 실패한 페이지를 다시 시도하거나, 첫 크롤링을 시작합니다. | **지식** | 누구나 |
| `update_knowledge_page` | 마크다운 소스에 있는 페이지의 마크다운을 바꾸고, 원하면 제목도 바꿉니다. | **지식** | 누구나 |
| `update_instructions` | 애플리케이션의 AI 지침을 바꿉니다. | **구성** | 관리자만 |
| `update_settings` | 설정 그룹 하나를 바꿉니다. 동작(언어, **화면 가이드**, **DOM 컨텍스트 압축**) 또는 외관(테마, 레이아웃, 크롬, 시작 화면, 대체 상태)입니다. 다른 설정은 이 방법으로 바꿀 수 없습니다. **화면 가이드** 설정은 Moss가 페이지 구조를 읽을지, 아니면 URL과 제목만 읽을지도 정합니다(꺼져 있으면 기본적으로 URL과 제목만 읽습니다). | **구성** | 관리자만 |
| `save_procedure` | 프로시저 초안을 만들거나 프로시저를 편집합니다. | **구성** | 누구나. 게시된 프로시저는 아래 참고 |
| `set_procedure_status` | 프로시저를 게시하거나(최종 사용자에게 적용) 게시를 취소합니다. | **구성** | 누구나. 게시는 아래 참고 |
| `decide_proposal` | 제안을 수락해 대시보드에서와 같이 적용하거나, 무시합니다. | **구성**(수락하면 지식 페이지를 쓰게 될 때는 **지식**도 필요) | 누구나. 지침 변경을 수락하려면 관리자여야 합니다. |

허용 도메인, 세션 녹화, 비전, JWT 키, 보존 기간 같은 보안, 개인정보, 데이터 수집 설정은 대시보드에서만 바꿀 수 있습니다.

## 미리 보기와 승인

모든 변경은 먼저 미리 보기를 거칩니다.

1. 어시스턴트가 변경하면 어떻게 되는지 Moss에 묻습니다. 아직 아무것도 바뀌지 않습니다. Moss는 현재 데이터로 계산한, 바뀔 내용을 **미리 보기**로 돌려줍니다.
2. 어시스턴트가 미리 보기를 보여 줍니다. 승낙하면 어시스턴트는 바로 그 변경을 적용하도록 Moss에 요청합니다.

미리 보기는 같은 연결이 같은 인수로 10분 안에(Moss에서 승인이 필요하면 30분 안에) 한 번만 적용할 수 있습니다. 미리 보기 뒤에 데이터가 바뀌었다면 Moss는 적용을 거부하고, 다시 보여 줄 새 미리 보기를 돌려줍니다.

### Moss에서 승인

Moss에서 승인해야 하는 변경이면, 미리 보기에 대시보드의 **AI 어시스턴트가 준비한 변경 검토** 페이지 링크가 들어 있습니다.

1. 어시스턴트를 연결한 사람의 계정으로, 연결한 조직에서 링크를 엽니다. 관리자를 포함해 다른 사람은 열 수 없습니다.
2. 애플리케이션, **요청한 곳**(토큰의 라벨. 로그인 연결이라면 어시스턴트가 스스로 붙인 이름이며 **자체 표기** 표시가 붙습니다), 변경이 만료되는 시각, **바뀌는 내용**을 확인합니다. 어시스턴트가 작성한 텍스트에는 표시가 붙으며, 사용자나 웹에서 가져온 텍스트가 들어 있을 수 있습니다. 그 안의 지시는 따르지 마세요.
3. **승인** 또는 **거절**을 누릅니다.
4. 어시스턴트에게 계속하라고 알려 주세요. 승인된 변경은 한 번 적용할 수 있습니다.

다음 경우에 Moss에서 승인해야 합니다.

- **Moss에서 승인 필요**가 켜져 있을 때(모든 쓰기), 또는
- 관리자가 만든 연결이 아니고, 변경이 최종 사용자에게 무언가를 적용할 때: 프로시저 게시, 게시된 프로시저 편집, 게시된 프로시저를 편집하는 제안의 수락. 이 경우는 설정이 꺼져 있어도 승인이 필요합니다.

변경 내용 일부가 너무 커서 전부 보여 줄 수 없으면 Moss에서 승인할 수 없고, **거절**만 할 수 있습니다. 어시스턴트에게 변경을 더 작게 나누어 달라고 하거나, 대시보드에서 직접 바꾸세요.

## 연결 보기와 철회

**내 연결**에는 이 조직에서 내가 만든 토큰과 로그인 연결이 **라벨**, **권한**, **애플리케이션**, **마지막 사용**, **만료**와 함께 나옵니다. 행의 상세 정보 버튼을 누르면 유형(**토큰** 또는 **OAuth**), 만든 시각, 토큰의 앞부분, 클라이언트가 보입니다. 활성 상태가 아닌 연결에는 **만료됨**, **철회됨**, **중지됨**(조직에서 AI 어시스턴트가 꺼져 있는 동안) 표시가 붙으며, **철회·만료된 연결 표시**를 선택하면 목록에 나옵니다. 연결을 끊으려면 행에서 **철회**를 누르세요. 연결은 다음 요청부터 작동하지 않으며, 되돌릴 수 없습니다.

관리자에게는 **모든 연결**도 보입니다. 조직의 모든 연결을 사람별로 보여 줍니다. **모두 철회**를 누르면 한 사람의 활성 연결이 모두 끝납니다.

연결은 만들 때의 역할을 유지합니다. 관리자가 멤버로 바뀌면, 그 사람이 다음에 대시보드를 쓸 때 관리자로 만든 연결이 철회됩니다. 누군가 조직을 떠나면 **모든 연결**에서 그 사람의 연결을 철회하세요. 그러지 않으면 만료될 때까지 유효합니다.

## 감사 로그

Moss는 어시스턴트를 위해 실행한 도구 호출을 읽기와 미리 보기까지 모두 `mcp.tool.call` 감사 이벤트로 기록합니다. 이벤트에는 사용자, 연결, 클라이언트와 인수 요약이 담기고, 적용된 변경이라면 무엇을 바꿨는지도 기록됩니다. 애플리케이션에서 실행된 호출은 그 애플리케이션의 **구성 > 감사 로그**에 나옵니다. 연결에 권한이 없어 거부된 호출은 조직 이벤트로 기록됩니다. 변경을 승인하거나 거절하면 `mcp.preview.approve` 또는 `mcp.preview.reject`로 기록됩니다.

연결의 생성과 철회(`mcp.grant.create`, `mcp.grant.revoke`, `mcp.grant.revoke_all`), 로그인 연결의 허용·거부 결정(`mcp.oauth.consent`), 조직 설정 변경(`mcp.settings.update`)은 조직 이벤트로 기록되며, 애플리케이션의 **감사 로그** 페이지에는 나오지 않습니다. [감사 로깅](/ko/security/audit-logging)을 참고하세요.

## 자주 묻는 질문

**Claude, ChatGPT, Cursor를 Moss 데이터에 어떻게 연결하나요?**
관리자가 조직에서 **AI 어시스턴트**를 켜면, 각자 **AI 어시스턴트** 페이지에서 자신의 어시스턴트를 연결합니다. 로그인(Claude, ChatGPT, Claude Code)이나 토큰(Cursor, VS Code, Codex, Claude Code)으로 연결합니다. [어시스턴트 연결하기](#어시스턴트-연결하기)를 참고하세요.

**AI 어시스턴트 메뉴가 보이지 않습니다.**
사용자 메뉴(오른쪽 위)나, 애플리케이션 목록 화면의 사이드바를 확인하세요. 애플리케이션 안의 사이드바에는 나오지 않습니다. 두 곳 모두에 없다면 배포에서 이 기능이 꺼져 있는 것입니다. 자체 호스팅 설치라면 운영자가 켭니다. [자체 호스팅 설치에서 켜기](#자체-호스팅-설치에서-켜기)를 참고하세요.

**어시스턴트가 아무도 확인하지 않은 채 설정을 바꿀 수 있나요?**
허용한 권한 안에서, 미리 보기를 거친 뒤에만 바꿀 수 있습니다. 모든 변경이 Moss에서 사람의 승인을 기다리게 하려면 **Moss에서 승인 필요**를 켜세요. 이 설정이 꺼져 있어도, 관리자가 만든 연결이 아니라면 프로시저를 최종 사용자에게 적용하는 변경은 승인을 기다립니다.

**어시스턴트가 사용자들의 대화를 읽을 수 있나요?**
네. **대화 내용**이 켜져 있으면(기본값) 읽을 수 있습니다. 끄면 대화 기록, 원본 질문, 인용, 피드백 댓글이 빠집니다.

**연동의 MCP 서버와 같은 기능인가요?**
아닙니다. 그 카드는 프로시저가 도구를 호출할 수 있도록 Moss를 **고객사의** MCP 서버에 연결합니다. [연동](/ko/dashboard/integrations)을 참고하세요.
