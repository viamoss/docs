**콘텐츠 > 추천 콘텐츠**에서는 사용자가 빈 채팅을 열었을 때 보이는 내용, 즉 몇 개의 추천 질문과 추천 글 목록을 정합니다. Moss를 사용할 수 없을 때나 Moss가 페이지에서 찾을 수 없는 대상을 가리켰을 때 위젯이 보여 주는 메시지도 여기서 정합니다.

조직의 누구나 이 페이지를 열 수 있습니다. 변경 사항은 관리자만 저장할 수 있으며, 멤버에게는 저장 버튼이 비활성화되고 "관리자만 초기 화면을 저장할 수 있습니다"라는 안내가 표시됩니다.

## 추천 질문과 추천 글 바꾸기

1. 애플리케이션을 열고 **콘텐츠 > 추천 콘텐츠**로 이동합니다.
2. **초기 화면** 카드의 **추천 질문**에서 **질문 추가**를 누릅니다. 아이콘을 고르고 질문을 입력합니다. 화살표로 순서를 바꾸고, 삭제 버튼으로 지웁니다.
3. **추천 글**에서 필요하면 **섹션 라벨**을 입력합니다. 그다음 **글 추가**를 누르고 **제목**, **URL**, **출처**, **읽기 (분)** 필드를 채우거나, **지식 베이스 검색**을 눌러 페이지를 고르거나 URL을 붙여 넣습니다.
4. 편집기 옆의 미리보기를 확인합니다. 미리보기는 레이아웃을 보여 주며, 색상과 글꼴은 외관 설정을 따릅니다.
5. 카드 아래쪽에 나타나는 막대에서 **저장**을 누릅니다. **되돌리기**를 누르면 변경 사항이 취소됩니다.

변경 사항은 위젯이 있는 페이지가 다음에 로드되거나 사용자가 새 채팅을 시작할 때 모든 설치 방식에 적용됩니다. 단, 앱 코드가 자체 목록을 지정한 경우는 예외입니다([코드가 대시보드 설정을 대체하는 경우](#코드가-대시보드-설정을-대체하는-경우) 참고).

### 제한

| 항목 | 제한 |
|------|------|
| 추천 질문 | 최대 5개입니다. 각 질문에는 아이콘(**문서**, **나침반**, **확성기**, **검색**, **사람** 중 하나)과 질문이 있습니다. 질문이 없는 행은 저장되지 않습니다. |
| 추천 글 | 정해진 상한은 없지만, 시작 화면에는 4개 정도가 들어갑니다. 그보다 많으면 편집기가 알려 줍니다. 글에는 **제목**과 **URL**이 있어야 하며, 둘 중 하나라도 없는 행은 저장되지 않습니다. |
| **지식 베이스 검색** | 앞쪽 지식 소스 10개에서 소스마다 최대 50개 페이지를 검색합니다. 계속 입력하면 목록이 좁혀집니다. |
| 범위 | 애플리케이션 전체에 한 세트입니다. 페이지나 역할별로 다르게 하려면 [페이지나 역할마다 다른 콘텐츠 보여 주기](#페이지나-역할마다-다른-콘텐츠-보여-주기)를 참고하세요. |

### 사용자에게 보이는 모습

- 추천 질문을 누르면 그 질문이 사용자의 메시지로 Moss에게 전송됩니다.
- 질문마다 고른 아이콘이 표시됩니다.
- 추천 글을 누르면 새 탭에서 해당 URL이 열립니다. 글 카드에는 출처(**출처**를 비워 두면 **Help center**)와, 설정한 경우 읽는 데 걸리는 시간이 표시됩니다.
- 추천 글의 제목은 **섹션 라벨**에 입력한 값이며, 비워 두면 **Recommended articles**입니다.
- **사용자가 이전 대화를 다시 열 수 있도록 허용**이 켜져 있으면 사용자의 최근 대화가 추천 질문 위에 나타납니다. [세션](/ko/sdk/api/session#이전-대화)을 참고하세요.

## 예외 상태

**예외 상태** 카드에서는 두 가지 상황에서 위젯이 보여 주는 문구와 버튼을 정합니다. **예외 상태 저장**으로 저장하며, 관리자만 저장할 수 있습니다.

| 상태 | 위젯이 표시하는 때 | 필드 |
|------|--------------------|------|
| **사용 불가 (전체 화면)** | 위젯이 재시도한 뒤에도 Moss에 연결하지 못했을 때입니다. 메시지가 채팅 패널 전체를 대신하고 입력창을 숨깁니다. | **제목**, **본문**, **기본 CTA (라벨 + URL)**, **보조 CTA (선택, 라벨 + URL)**. 제목과 기본 CTA는 필수이며, 없으면 저장할 때 이 상태가 지워집니다. |
| **환각 응답 (인라인 버블)** | Moss의 답변이 페이지에서 찾을 수 없는 요소를 가리켰을 때입니다. 메시지가 그 답변을 대신하며, 사용자는 계속 입력할 수 있습니다. | **본문**과 **CTA 버튼 (선택)**. 본문은 필수이며, 없으면 저장할 때 이 상태가 지워집니다. |

상태를 설정하지 않으면 위젯은 기본 동작을 보여 줍니다. 사용 불가일 때는 연결 오류 패널을, 환각 응답일 때는 답변을 원래대로 보여 줍니다.

<Warning>
    예외 상태는 **CDN 스크립트**를 쓰는 앱에 적용됩니다. 단, 페이지가 `window.mossSettings.appearance`를 설정하면 그 객체가 색상만 지정한 것이라도 대시보드의 예외 상태를 대체합니다. 이 경우 `appearance.fallbackStates`도 거기에 함께 지정하세요. **npm 패키지**를 쓰는 앱은 대시보드에서 예외 상태를 받지 않으므로, `AgentProvider` 설정에 `appearance.fallbackStates`를 지정하세요. 외관 레퍼런스의 [예외 상태](/ko/sdk/appearance#예외-상태)를 참고하세요.
</Warning>

## 코드가 대시보드 설정을 대체하는 경우

앱이 Moss 설정에 `appearance.zeroState`를 지정하면, 위젯은 그 값을 쓰고 대시보드의 추천 질문과 추천 글은 완전히 무시합니다. 지정한 값이 비어 있어도 마찬가지입니다. npm 패키지에서는 `AgentProvider` 설정이, CDN 스크립트에서는 `window.mossSettings.appearance.zeroState`가 여기에 해당합니다.

대시보드 설정으로 시작 화면을 정하려면 코드에서 `appearance.zeroState`를 지우세요.

## 페이지나 역할마다 다른 콘텐츠 보여 주기

대시보드에는 애플리케이션 전체에 한 세트만 있습니다. 특정 페이지에서, 또는 관리자와 다른 사용자에게 서로 다른 질문이나 글을 보여 주려면 앱 코드에서 설정하세요.

- `pageKey` 옵션으로 페이지에 바뀌지 않는 이름을 붙입니다. 예: `'billing-settings'`.
- `appearance.zeroState.variants` 아래에 그 이름으로 항목을 추가하고, `admin` 목록이나 `customer` 목록, 또는 둘 다를 넣습니다. `default` 항목은 자체 항목이 없는 페이지에 적용됩니다.
- Moss는 `userMetadata.role`이 `'admin'`이면 사용자를 `admin`으로, 그 밖에는 `customer`로 봅니다.
- 고른 목록의 항목이 3개보다 적으면 Moss가 같은 페이지의 다른 역할 목록에서, 그다음 최상위 목록에서 항목을 채웁니다.

코드의 `zeroState`가 대시보드 설정을 대체하므로, 애플리케이션 전체에 쓸 질문과 글도 코드의 최상위 목록에 함께 넣으세요.

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider
  config={{
    apiUrl: 'https://moss-api.viamoss.ai',
    applicationId: 'YOUR_APP_ID',
    userId: currentUser.id,
    getJwt: fetchMossToken,
    pageKey: 'billing-settings',
    userMetadata: { role: currentUser.isAdmin ? 'admin' : 'member' },
    appearance: {
      zeroState: {
        suggestedQueries: [{ question: 'How do I invite a teammate?' }],
        variants: {
          'billing-settings': {
            customer: { suggestedQueries: [{ question: 'Where can I download my invoices?' }] },
            admin: { suggestedQueries: [{ question: 'How do I change our billing plan?' }] },
          },
        },
      },
    },
  }}
>
  <AssistantButton />
</AgentProvider>
```

목록마다 아이콘과 추천 글을 넣는 방법을 포함한 전체 옵션은 외관 레퍼런스의 [페이지와 역할에 따른 콘텐츠](/ko/sdk/appearance#페이지와-역할에-따른-콘텐츠)을 참고하세요.

## 자주 묻는 질문

**특정 페이지 하나에서만 추천 글을 바꾸려면 어떻게 하나요?**
대시보드로는 할 수 없습니다. 대시보드에는 애플리케이션마다 한 세트만 있습니다. [페이지나 역할마다 다른 콘텐츠 보여 주기](#페이지나-역할마다-다른-콘텐츠-보여-주기)처럼 코드에서 `pageKey`를 전달하고 `appearance.zeroState.variants`를 설정하세요.

**대시보드에서 추천 질문을 바꿨는데 위젯에는 여전히 예전 질문이 보입니다.**
먼저 페이지를 새로 고치세요. 위젯은 로드될 때나 사용자가 새 채팅을 시작할 때 변경 사항을 가져옵니다. 그래도 예전 질문이 보이면 앱 코드가 `appearance.zeroState`를 설정하고 있는 것이며, 이 값이 대시보드 목록을 대체합니다. 코드에서 이 값을 지우거나, 코드에서 질문을 고치세요.

**왜 저장할 수 없나요?**
저장은 관리자만 할 수 있습니다. 조직의 관리자에게 요청하거나 [역할](/ko/dashboard/overview#역할)을 참고하세요.

**사용 불가 메시지를 설정했는데 앱에는 기본 오류가 보입니다.**
npm 패키지를 쓰는 앱은 대시보드에서 예외 상태를 받지 않으며, `window.mossSettings.appearance`를 설정한 CDN 페이지도 마찬가지입니다. `AgentProvider` 설정이나 `window.mossSettings.appearance`에 `appearance.fallbackStates`를 지정하세요.
