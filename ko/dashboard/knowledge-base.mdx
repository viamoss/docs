지식 베이스에는 어시스턴트가 답변할 때 참고하는 도움말 콘텐츠가 들어 있습니다. **소스**(웹사이트, URL 목록, 마크다운 파일, Document360 프로젝트, Intercom 도움말 센터)를 추가하면 Moss가 소스의 각 **페이지**를 여러 조각으로 나누어 색인합니다. 어시스턴트는 질문이 들어올 때마다 색인된 조각을 검색합니다.

사이드바에서 **콘텐츠 > 지식 베이스**를 열고 **Add Content**를 누르세요.

<Note>
지식 소스는 어시스턴트가 답변에 쓸 텍스트만 제공합니다. 내용이 API 문서라 해도 어시스턴트가 API를 호출하거나 제품 안에서 동작을 실행하게 되지는 않습니다. 어시스턴트가 동작을 실행하게 하려면 [연동](/ko/dashboard/integrations)에서 API나 도구를 연결하고 [프로시저](/ko/dashboard/procedures)에서 사용하세요.
</Note>

관리자와 멤버 모두 소스를 추가하고, 새로고침하고, 끄고, 삭제할 수 있습니다.

## 콘텐츠 추가

**Add Content**를 누르면 탭 다섯 개가 있는 **Add Content to Knowledge Base** 창이 열립니다.

| 탭 | 용도 | 입력할 내용 | 버튼 |
|---|---|---|---|
| **Crawl Website** | 공개된 문서 사이트나 도움말 사이트 | **Base URL**(필수), **Source Name**, **Description**, **Sitemap URL (optional)** | **Start Crawling** |
| **URL List** | 정해진 공개 페이지 목록 | **URLs (one per line)**. **Or upload .txt/.csv**로 입력란을 채울 수도 있습니다 | **Start Import** |
| **Markdown** | 크롤러가 읽지 못하는 콘텐츠, 또는 어시스턴트용으로 직접 쓴 콘텐츠 | `.md`, `.mdx`, `.txt` 파일 하나 이상, 또는 **Select Folder** | **Upload & Process** |
| **Document360** | Document360 지식 베이스 | **Project Version**, **Language**, **Include drafts**, **Source Name** | **Start Import** |
| **Intercom** | Intercom 도움말 센터 | **Languages**, **Collections**, **Include drafts**, **Source Name** | **Start Import** |

**Source Name**을 비워 두면 Moss가 웹사이트의 호스트 이름(Crawl Website, URL List)이나 첫 파일의 제목(Markdown)으로 소스 이름을 정합니다.

### Crawl Website

Moss는 **Base URL**을 수집 범위로 봅니다. 같은 사이트에서 주소가 Base URL로 시작하는 페이지만 가져옵니다. 원하는 콘텐츠가 들어 있는 가장 좁은 경로로 지정하세요. 예를 들어 `https://docs.example.com/api`로 지정하면 API 레퍼런스만 가져오고 사이트의 나머지는 제외합니다. 주소를 텍스트로 비교하므로 `/api`는 `/api-v2`와 `/apis`도 함께 가져옵니다.

0.17.0부터 크롤링은 다음 순서로 페이지를 찾습니다.

1. 사이트의 `robots.txt`를 읽습니다. `robots.txt`가 막은 페이지는 가져오지 않습니다.
2. 사이트맵을 읽습니다. **Sitemap URL (optional)** 입력란에 넣은 사이트맵과 `robots.txt`에 적힌 사이트맵을 읽고, 둘 다 없으면 흔히 쓰는 사이트맵 이름을 시도합니다. 여기에는 시작 페이지가 선언한 언어의 사이트맵(예: `sitemap-en.xml`)도 포함됩니다. 사이트맵에 있는 페이지 중 Base URL 아래에 있는 페이지는 모두 가져옵니다.
3. 경로가 얕은 페이지부터 열고, 찾은 링크를 따라갑니다. 연속 20개 페이지에서 새 링크가 나오지 않거나 페이지를 300개(기본값) 열면 멈춥니다.

크롤링에서 제외되는 항목은 다음과 같습니다.

- Base URL 바깥의 페이지, 다른 호스트의 페이지
- `rel="nofollow"`가 붙은 링크
- PDF, 텍스트 파일, 이미지 같은 파일 링크. 페이지로 보지 않습니다.
- 링크의 `#fragment` 부분. `?page=2`는 별도 페이지지만 `#section`은 아닙니다.
- "찾을 수 없음" 화면이나 로그인 화면으로 확인된 페이지, 단어가 세 개 미만인 페이지, 같은 소스의 다른 페이지와 거의 같은 페이지. 이런 페이지는 **Skipped** 또는 **Duplicate**로 표시됩니다.
- 로그인해야 볼 수 있는 페이지. Moss는 사이트에 로그인할 수 없습니다.

0.17.0에서 새로 생긴 항목: `robots.txt`, `nofollow`, 파일 링크 제외, `?query` 부분 유지(`?page=2`를 별도 페이지로 취급), 그리고 찾을 수 없음·로그인·짧은 페이지·거의 같은 페이지 검사입니다. 0.16.25까지는 크롤링이 `?query` 부분을 통째로 버려서 `?page=2`를 같은 페이지로 셌고, 콘텐츠 검사로는 리디렉션된 페이지와 내용이 완전히 같은 페이지만 건너뛰었습니다.

링크를 따라가서 다 찾을 수 없을 만큼 페이지가 많은 사이트라면 사이트맵을 지정하세요. 사이트맵에 있는 페이지는 항상 가져오며, 300개 제한은 링크를 따라갈 때만 적용됩니다.

### URL List

Moss는 입력한 URL만 정확히 가져오고, 그 페이지의 링크는 따라가지 않습니다. **New Source**를 고르거나, **Existing Source**를 골라 이미 있는 웹사이트 소스나 URL 목록 소스에 URL을 추가하세요.

크롤링으로 찾지 못하는 페이지는 URL 목록 소스로 추가하세요. 크롤링한 웹사이트를 새로고침하면 페이지 찾기를 다시 실행해 찾은 페이지만 남기지만, URL 목록 소스를 새로고침하면 같은 목록을 다시 가져옵니다.

### Markdown

파일 하나가 페이지 하나가 됩니다. 페이지 제목은 파일의 첫 `# ` 제목이고, 제목이 없으면 파일 이름입니다. **New Source**를 고르거나, **Existing Source**를 골라 이미 있는 마크다운 소스에 파일을 추가하세요.

한 번에 올릴 수 있는 양은 선택한 파일을 모두 합해 약 10MB입니다. Moss가 보내는 요청 크기로 계산하므로 실제로 올릴 수 있는 양은 그보다 조금 적습니다. 더 많으면 여러 번에 나누어 같은 소스에 올리세요. 0.17.0부터는 이보다 큰 업로드가 "Request body exceeds the 10485760 byte limit." 메시지와 함께 거부됩니다. 이전 버전에서도 실패했지만 오류 메시지가 덜 명확했습니다.

같은 파일을 다시 올리면 페이지가 하나 더 생깁니다. 제목이 같은 기존 페이지를 바꾸지 않습니다. 페이지 내용을 바꾸려면 [페이지 하나만 업데이트하기](#페이지-하나만-업데이트하기)를 참고하세요.

Moss가 파일은 저장했지만 처리를 시작하지 못하면 "Content saved, but processing could not be started. Please retry shortly." 메시지가 표시됩니다. 파일은 저장되어 있으니, 서비스가 복구되면 파일을 다시 올리지 말고 소스에서 **마크다운 재처리**를 누르세요.

### Document360

먼저 **구성 > 연동 > Document360**에서 Document360을 연결하세요([연동](/ko/dashboard/integrations) 참고). 연결하기 전에는 탭에 "Document360 is not configured for this application."이 표시됩니다.

0.17.0부터 Moss는 두 가지 Document360 자격 증명을 모두 받습니다.

- 향상된(v3) API 키. 가져올 워크스페이스에 접근할 수 있는 Draft writer 또는 Editor 콘텐츠 역할이 있어야 합니다.
- v2 API 토큰. Project Versions, Categories, Articles에 대한 GET 권한이 있어야 합니다.

Moss는 Document360에서 읽기만 합니다. 소스 하나는 프로젝트 버전 하나(v3 키에서는 워크스페이스 하나)의 언어 하나를 가져옵니다. 여러 언어를 가져오려면 언어마다 소스를 하나씩 추가하세요. **Include drafts**를 켜면 아직 초안인 아티클도 가져옵니다.

### Intercom

0.17.0부터 Intercom 도움말 센터를 가져올 수 있습니다. 먼저 **구성 > 연동 > Intercom**에서 Intercom을 연결하세요([연동](/ko/dashboard/integrations) 참고). 액세스 토큰에는 도움말 센터 아티클과 컬렉션을 읽을 권한이 있어야 합니다.

- **Languages**: 선택한 언어마다 아티클을 한 번씩 가져옵니다.
- **Collections**: 모두 선택하지 않으면 컬렉션에 속하지 않은 아티클까지 포함해 도움말 센터 전체를 가져옵니다. 컬렉션을 선택하면 그 하위 컬렉션도 포함됩니다.
- **Include drafts**: 아직 초안인 언어 버전도 가져옵니다.

### 그 밖에 콘텐츠가 들어오는 경로

- **제안**: 지식 공백 제안을 적용하면 **Moss Suggestions**라는 소스에 마크다운 페이지가 작성됩니다. 이 소스는 처음 적용할 때 만들어집니다. [답변 개선하기](/ko/dashboard/improving-answers#제안)를 참고하세요.
- **AI 어시스턴트**: 설치에서 AI 어시스턴트가 켜져 있으면, **지식** 권한으로 연결된 어시스턴트가 웹사이트 소스와 마크다운 페이지를 추가할 수 있습니다. [AI 어시스턴트](/ko/dashboard/ai-assistants)를 참고하세요.

### 지원하지 않는 형식

PDF, Word, HTML 파일 업로드, OpenAPI나 Swagger 명세 파일, GitHub 저장소, 로그인해야 볼 수 있는 페이지는 지원하지 않습니다. 이런 콘텐츠는 마크다운으로 바꿔서 올리세요.

## 크롤러가 읽지 못하는 콘텐츠

Moss는 웹 페이지를 처음 불러왔을 때의 모습으로 읽고, 아무것도 클릭하지 않습니다. 탭, 아코디언, "더 보기" 버튼, 같은 자리에서 섹션을 바꿔 보여 주는 단일 페이지 앱처럼 클릭해야 나타나는 콘텐츠는 놓치고 첫 화면만 가져옵니다.

이런 콘텐츠나 로그인해야 볼 수 있는 콘텐츠는 다음과 같이 추가하세요.

1. 콘텐츠를 내보내거나 복사해 주제마다 마크다운 파일 하나로 만들고, 각 파일을 `# ` 제목으로 시작하세요.
2. **지식 베이스 > Add Content > Markdown**으로 이동합니다.
3. **Select Folder**를 누르거나 파일을 고른 뒤 **Upload & Process**를 누르세요.
4. 콘텐츠가 바뀌면 페이지를 업데이트하거나([페이지 하나만 업데이트하기](#페이지-하나만-업데이트하기) 참고), 새 파일을 새 소스에 올리고 기존 소스를 삭제하세요.

사이트의 봇 차단 때문에 Moss가 막히면 소스에 "The source site's bot protection is blocking most pages. Try uploading the content as markdown instead."가 표시됩니다. 이때도 같은 방법으로 마크다운을 올리면 됩니다.

## 소스가 사용되는지 확인하기

어시스턴트는 다음 두 조건을 모두 만족하는 소스만 사용합니다.

- 소스 상태가 **Ready**입니다.
- 소스 머리글의 **AI 답변에 사용** 스위치가 켜져 있습니다.

### 소스 상태

소스를 처리하는 동안 머리글에 단계(**페이지 찾는 중**, **페이지 가져오는 중**, **검색 준비 중**)와 페이지 수가 표시됩니다. 목록은 10초마다 갱신됩니다. 처리는 페이지 찾기, 페이지 수집, 이미지 설명(비전 모델이 이미지마다 텍스트 설명을 써서 검색할 수 있게 합니다), 나누기와 색인, 마무리의 다섯 단계로 진행됩니다.

처리가 끝나면 머리글에 상태, 페이지 수, 소스를 마지막으로 업데이트한 시각이 표시됩니다.

| 상태 | 의미 | 답변에 사용 |
|---|---|---|
| **Pending** | 시작을 기다리는 중 | 아니요 |
| **Processing** | 페이지를 찾거나 수집하거나 색인하는 중 | 아니요. 새로고침 중에는 현재 버전이 계속 답변에 쓰입니다([소스 새로고침](#소스-새로고침) 참고) |
| **Ready** | 완료. 일부 페이지가 실패했을 수 있으며, 성공한 페이지는 사용됩니다 | 예. **AI 답변에 사용**이 켜져 있을 때 |
| **Error** | 쓸 수 있는 결과 없이 끝남. 소스에 페이지가 없거나, 모든 페이지가 실패했거나, 색인에 실패한 페이지가 있습니다 | 아니요 |

**Ready** 상태이지만 실패한 페이지가 있는 소스에는 "페이지 N개를 가져오지 못했습니다"라는 주황색 칩이 표시됩니다. 칩을 누르면 그 페이지만 목록에 보입니다. 접근 거부나 봇 차단처럼 소스 전체에 관한 Moss 메시지는 머리글 아래에 표시됩니다.

목록의 각 페이지에는 상태 점(**Ready**, **Processing**, **Pending**, **Error**, **Skipped**, **Duplicate**)이 표시됩니다. 수집은 됐지만 색인에 실패한 페이지도 **Processing**으로 표시됩니다. 페이지를 열면 Moss가 추출한 텍스트를 볼 수 있습니다.

### AI 답변에 사용

소스는 남겨 두고 답변에서만 빼려면 **AI 답변에 사용**을 끄세요. 그러면 머리글에 "답변에서 제외됩니다. 콘텐츠는 유지되며 언제든 다시 켤 수 있습니다."가 표시되고 사이드바의 소스에 **꺼짐**이 붙습니다. 변경은 몇 분 안에 적용됩니다. 이 설정은 소스의 새 버전에도 이어지며, 꺼져 있는 동안에도 새로고침과 자동 새로고침은 계속 실행됩니다.

### 답변에서 확인하기

- **분석 > 아티클**에는 선택한 기간에 답변에 쓰인 모든 페이지가 쓰인 횟수, 평가와 함께 표시됩니다. [분석](/ko/dashboard/analytics)을 참고하세요.
- 세션 대화 기록에서 답변의 "문서 N개" 칩을 누르면 **가져온 문서**가 열리고, 그 답변이 참고한 페이지가 관련성순으로 표시됩니다. [세션](/ko/dashboard/sessions)을 참고하세요.
- **분석 > 콘텐츠 공백**과 세션의 콘텐츠 공백 필터에서는 관련 있는 내용을 찾지 못한 질문을 볼 수 있습니다.

기본적으로 Moss는 질문과의 관련성 점수가 0.45 미만인 조각을 모델에 넘기기 전에 버립니다. 주제를 전반적으로 다룬 페이지는 구체적인 질문에 쓰이지 않을 수 있습니다. 제목과 소제목에 작업 이름이 들어간 페이지가 더 잘 맞습니다.

## 소스 새로고침

모든 소스의 머리글에는 새로고침 버튼이 있습니다. 버튼 이름은 소스 유형에 따라 다릅니다.

| 소스 유형 | 버튼 | 하는 일 |
|---|---|---|
| 웹사이트 | **새로고침** | 페이지 찾기를 포함해 크롤링 전체를 다시 실행합니다 |
| URL 목록 | **URL 다시 수집** | 같은 URL을 다시 가져옵니다 |
| 마크다운 | **마크다운 재처리** | 이미 저장된 페이지를 다시 처리합니다. 새 파일은 읽지 않습니다 |
| Document360, Intercom | **새로고침** | 플랫폼에서 아티클을 다시 가져옵니다 |

새로고침은 현재 버전 옆에 소스의 **새 버전**을 만듭니다.

1. 새 버전을 처리하는 동안 현재 버전이 계속 답변에 쓰입니다.
2. 새 버전이 **Ready**로 끝나면 현재 버전을 대체합니다. 기존 버전은 **Outdated**가 되어 목록에서 숨겨지고, **Outdated** 상태로 48시간이 지나면 Moss가 삭제합니다.
3. 새 버전이 실패하면 현재 버전이 계속 쓰이고 실패한 사본은 숨겨집니다. 새로고침한 소스가 **Error** 상태였다면 새 실행이 시작되는 즉시 그 소스는 사용이 중지됩니다.

"새로고침을 시작했습니다. 새 소스 버전이 선택되었습니다." 알림은 대시보드가 이제 새 버전을 보여 준다는 뜻입니다. 한 소스에서는 새로고침을 한 번에 하나만 실행할 수 있으며, 첫 새로고침이 끝날 때까지 두 번째는 거부됩니다. 24시간 동안 진행이 없는 새로고침은 더 이상 새 새로고침을 막지 않습니다.

**새로고침이 기존 버전을 가리키던 항목에 미치는 영향.** 새 버전에는 새 소스 ID가, 그 페이지에는 새 페이지 ID가 붙습니다.

- **분석 > 아티클**은 페이지별로 집계하므로, 새로고침 뒤에는 페이지 집계가 새 버전에서 다시 시작됩니다. 기존 버전의 행에는 이전에 쓰인 답변이 그대로 남습니다.
- 마크다운 페이지를 수정하는 지식 공백 제안은 제안이 만들어질 때의 버전에 있던 페이지를 가리킵니다. 이런 제안은 **마크다운 재처리**를 누르기 전에 적용하거나, 재처리한 뒤 직접 수정하세요.
- 소스 ID를 저장해 둔 스크립트나 AI 어시스턴트는 소스를 다시 조회해야 합니다.
- **AI 답변에 사용** 설정과 자동 새로고침 일정은 그대로 이어집니다.

### 페이지 하나만 업데이트하기

- **웹사이트, URL 목록, Document360, Intercom 페이지**: 페이지를 열고 **Re-crawl**을 누르세요. Moss가 그 페이지를 비우고 소스에서 다시 처리합니다. 소스의 나머지 페이지는 건드리지 않습니다.
- **마크다운 페이지**: 페이지를 열고 **Edit Content**를 눌러 텍스트를 고친 뒤 **Save & Re-index**를 누르세요.
- **Delete**는 지식 베이스에서 페이지 하나를 삭제합니다.

### 실패한 페이지 재시도

실패한 페이지가 있으면 머리글에 **실패한 페이지 재시도 (N)** 버튼이 표시됩니다. 실패한 페이지만 다시 처리하고, 성공한 페이지는 그대로 둡니다. 0.17.0부터는 수집은 됐지만 색인에 실패한 페이지도 다시 시도합니다. 이런 실패는 소스를 **Error** 상태로 만들며, 이 버튼으로 복구할 수 있습니다. 이런 페이지는 **Processing** 점으로 표시되며 버튼의 숫자에도 포함됩니다. 재시도하는 동안 **Ready** 상태인 소스가 답변에서 빠지는 일은 없습니다.

### 소스 삭제

소스 머리글의 **...** 메뉴를 열고 **소스 삭제…** 항목을 고르세요. 소스와 모든 페이지, 자동 새로고침 일정이 삭제됩니다.

## 자동 새로고침

자동 새로고침은 소스마다 설정하며 **기본값은 꺼짐**입니다. **...** 메뉴 > **자동 새로고침…** 항목을 고르거나, 소스 머리글의 **자동 새로고침 꺼짐** 칩을 누르세요.

| 설정 | 값 | 기본값 |
|---|---|---|
| **자동 새로고침 사용** | 켜짐 또는 꺼짐 | 꺼짐 |
| **새로고침 간격** | **매주**(7일), **매월**(30일), **직접 입력**: 1~366일 | 매주 |
| **선호 시간대 (선택)** | **아무 때나**, 또는 UTC 기준 0~23시 | 아무 때나 |

- **첫 자동 실행은 저장하고 간격 한 번이 지난 뒤**에 일어나며, 바로 실행되지 않습니다. 선호 시간대를 정하면 실행 예정일의 그 시간으로 옮겨집니다. 지금 바로 최신 콘텐츠가 필요하면 **새로고침**도 누르세요.
- 자동 실행은 매번 [소스 새로고침](#소스-새로고침)에서 설명한 전체 새로고침입니다. 새 버전을 만드는 동안 현재 버전이 계속 답변에 쓰입니다.
- 실행 예정 시각부터 최대 15분 안에 시작되므로, 함께 저장한 소스가 한꺼번에 시작되지 않습니다.
- 예약된 새로고침은 **시작**되면 실행된 것으로 셉니다. 그 뒤에 실패하면 현재 버전이 계속 답변에 쓰이고, 실패한 사본은 숨겨지며, 다음 자동 실행은 간격 한 번이 다 지난 뒤에 옵니다. 창에 표시되는 "마지막 새로고침 성공"은 새로고침이 끝났다는 뜻이 아니라 시작됐다는 뜻입니다.
- 예약된 새로고침을 시작조차 하지 못하면(예: 연동 자격 증명이 삭제된 경우) Moss는 6시간 뒤, 12시간 뒤, 24시간 뒤처럼 대기 시간을 두 배씩 늘려 다시 시도하되, 설정한 간격보다 오래 기다리지는 않습니다. 일정이 스스로 꺼지는 일은 없습니다.
- 자동 새로고침은 **Ready** 버전이 있는 소스만 새로고침합니다. **Error** 상태인 소스는 **새로고침**이나 **실패한 페이지 재시도**로 복구할 때까지 실행 때마다 건너뜁니다.

머리글 칩에는 간격과 다음 실행 시각(예: "매주 자동 새로고침")이 표시되고, 예약된 새로고침을 시작하지 못했다면 연속 실패 횟수도 표시됩니다. **자동 새로고침…** 창에는 다음 실행 시각과 마지막 결과가 표시됩니다. 지식 베이스 도구 모음에는 자동 새로고침 중인 소스 수와 다음 실행 시각이 표시됩니다.

새로고침이 시작된 뒤 실패해도 창에는 실패로 표시되지 않으므로, 자동 새로고침을 켠 소스는 가끔 직접 확인하세요. 소스를 하나씩 열어 **Ready** 상태인지, "업데이트" 날짜가 마지막 예약 실행 이후인지 보면 됩니다. 실패한 사본은 숨겨지므로, 날짜가 오래되었다면 마지막 새로고침이 끝나지 못했다는 뜻입니다.

## 제한

| 항목 | 값 |
|---|---|
| 웹사이트 크롤링의 링크 따라가기 | 기본적으로 페이지 300개를 열면 멈춥니다. 사이트맵에 있는 페이지는 이 제한을 받지 않습니다 |
| 마크다운 업로드 | 한 번에 올리는 파일 전체 약 10MB |
| 마크다운 파일 형식 | `.md`, `.mdx`, `.txt` |
| 자동 새로고침 간격 | 1~366일 |
| 소스당 동시에 실행할 수 있는 새로고침 | 1개 |
| 새로고침 뒤 Outdated 버전 보관 기간 | 48시간 |
| 지식 베이스 페이지에 표시되는 소스 | 가장 최근에 추가하거나 새로고침한 50개. 그 밖의 소스도 답변에는 계속 쓰입니다 |
| 조각이 모델에 전달되는 데 필요한 관련성 | 기본값 0.45 |

지식 소스는 애플리케이션 내보내기에 포함되지 않습니다. [애플리케이션을 가져온](/ko/dashboard/export-import) 뒤에는 소스를 다시 추가하세요.

## 오류와 대처 방법

메시지는 소스 머리글 아래(소스 전체에 관한 메시지)나 실패한 페이지에 표시됩니다.

| 메시지 | 대처 방법 |
|---|---|
| "Most pages at the source URL could not be found. Please verify the base URL." | **Base URL**에 오타가 없는지, 페이지가 실제로 있는 경로인지 확인하세요. |
| "Access to most pages was denied by the source site. Authentication may be required, or the URL needs to be changed." | 페이지에 로그인이 필요하거나 외부 방문자를 막고 있습니다. 콘텐츠를 마크다운으로 올리세요. |
| "The source site's bot protection is blocking most pages. Try uploading the content as markdown instead." | 사이트 담당 팀에 크롤러 허용을 요청하거나, 콘텐츠를 마크다운으로 올리세요. |
| "The source site is heavily rate-limiting us. We'll continue retrying but progress may be slow." | 기다리세요. Moss가 계속 재시도합니다. |
| "Part of this content could not be processed. The rest is available." | 소스는 사용할 수 있습니다. 실패한 페이지를 확인하고 **실패한 페이지 재시도**를 누르세요. 링크 따라가기가 300페이지 제한에서 멈춘 크롤링도 이 메시지를 표시합니다. 이때는 사이트맵을 추가하세요. |
| "This page no longer exists at the source URL." | 페이지를 삭제하거나 소스를 새로고침하세요. |
| "Access to this page was denied by the source site." | 로그인이 필요한 페이지입니다. 마크다운으로 올리세요. |
| "The source site took too long to respond. We'll retry automatically." 및 그 밖의 "We'll retry automatically" 메시지 | 기다린 뒤에도 페이지가 계속 실패하면 **실패한 페이지 재시도**를 누르세요. |
| "Document360 API token is invalid or expired." | **구성 > 연동 > Document360**에서 토큰을 다시 입력하세요. |
| "Document360 credentials lack read access. …" | [Document360](#document360)에 적힌 콘텐츠 역할을 키에, 또는 GET 권한을 토큰에 부여하세요. |
| "Stored Document360 credentials cannot be decrypted …" | **구성 > 연동 > Document360**에서 토큰을 다시 입력하세요. |
| "The Document360 host must be a Document360 API host …" | `https://`, 포트, 경로 없이 `apihub.document360.io`나 `apihub.us.document360.io` 같은 호스트를 입력하세요. |
| "Intercom access token is invalid or expired." 또는 "… cannot be decrypted …" | **구성 > 연동 > Intercom**에서 토큰을 다시 입력하세요. |
| "Intercom access token lacks read access to Help Center articles and collections." | 토큰에 그 권한을 부여한 뒤 다시 입력하세요. |
| "Article no longer exists in Document360 and was skipped." (Intercom도 같음) | 할 일은 없습니다. 원본에서 아티클이 삭제되었습니다. |
| "We couldn't process this content. Please retry, and contact support if it persists." | **실패한 페이지 재시도**를 누르세요. |
| "Something went wrong on our end. Please contact support." | Moss 서비스나 설정의 문제입니다. 지원팀에 문의하거나, 자체 호스팅 설치라면 운영 담당자에게 문의하세요. |
| "A refresh for this source is already in progress" | 진행 중인 새로고침이 끝날 때까지 기다리세요. |
| "Request body exceeds the 10485760 byte limit." | 마크다운 업로드가 약 10MB를 넘었습니다. 파일을 더 작게 나누어 올리세요. |

## 자체 호스팅: 웹사이트 소스의 네트워크 요구 사항

모든 소스는 워커가 모델 제공자, 오브젝트 스토리지, 벡터 인덱스에 접근할 수 있어야 하며, 해당 호스트는 [네트워크](/ko/self-hosting/network)에 정리되어 있습니다. Document360과 Intercom 소스는 각 플랫폼의 API 호스트에도 접근해야 합니다. 웹사이트와 URL 목록 소스에는 다음도 필요하며, 모두 **워커**에서 나가는 연결입니다.

- **사이트.** 워커가 헤드리스 브라우저로 시작 페이지를 열고, `robots.txt`와 사이트맵을 읽고, 링크를 따라갑니다. 이 브라우저는 페이지가 불러오는 스크립트, 폰트, CDN 파일 같은 리소스도 불러옵니다.
- **Firecrawl.** 워커는 호스팅형 스크래핑 서비스인 Firecrawl(`api.firecrawl.dev`)을 통해 각 페이지의 내용을 가져옵니다. 워커에 `FIRECRAWL_API_KEY`를 설정하고 `api.firecrawl.dev`로 나가는 연결을 허용하세요. Firecrawl은 자체 서버에서 페이지를 가져오므로 페이지가 공개 인터넷에서 접근 가능해야 하고, 페이지 내용은 Firecrawl을 거칩니다. 자체 호스팅할 수 있는 대안은 없습니다. 키가 없으면 수집 단계가 실패해 페이지를 하나도 가져오지 못합니다.
- **사설 주소.** 워커는 사설, 루프백, 링크 로컬 주소에 있는 `robots.txt`, 사이트맵, 이미지를 가져오지 않습니다. 단, `WORKER_FETCH_ALLOWLIST`(쉼표로 구분한 호스트와 CIDR, 기본값은 비어 있음)에 들어 있으면 가져옵니다.
- **이 요청에는 프록시를 쓰지 않음.** 워커는 `HTTP_PROXY`와 `HTTPS_PROXY`를 무시하고 `robots.txt`, 사이트맵, 이미지를 직접 가져옵니다. 포워드 프록시를 거쳐야만 인터넷에 나갈 수 있는 워커는 공개 주소든 사설 주소든 이 요청을 하나도 보낼 수 없습니다.

네트워크를 고친 뒤에는 영향을 받은 소스마다 **실패한 페이지 재시도**나 **새로고침**을 누르세요. 전체 호스트 목록은 [네트워크](/ko/self-hosting/network)를 참고하세요.

자동 새로고침은 워커가 아니라 대시보드 백엔드가 시작합니다. `PULSE_ENABLED`와 `PULSE_KB_REFRESH_ENABLED`(둘 다 기본값은 켜짐)로 끌 수 있습니다.

## 자주 묻는 질문

### API 문서를 소스로 추가했는데 어시스턴트가 쓰지 않습니다.

소스가 **Ready**인지, **AI 답변에 사용**이 켜져 있는지, 페이지가 Skipped나 Error가 아니라 **Ready**인지 확인하세요. 공개된 HTML 문서를 **Base URL**을 문서 경로로 지정해 크롤링하거나, OpenAPI 명세를 마크다운으로 바꿔 올리세요. 명세 파일 자체는 지원하지 않습니다. 소스는 어시스턴트가 답변에 쓸 텍스트만 제공합니다. 어시스턴트가 API를 호출하게 하려면 [연동](/ko/dashboard/integrations)을 참고하세요.

### 자동 새로고침이 꺼져 있습니다. 켜면 얼마나 자주 실행되나요?

기본값은 매주이며, 매월이나 1~366일마다로 바꿀 수 있고 UTC 기준 선호 시간대도 정할 수 있습니다. 첫 실행은 저장하고 간격 한 번이 지난 뒤입니다. [자동 새로고침](#자동-새로고침)을 참고하세요.

### 사이트의 일부 페이지가 빠져 있는 이유는 무엇인가요?

크롤링은 **Base URL** 아래 페이지만 가져오고, `robots.txt`가 막은 페이지와 nofollow 링크는 건너뛰며, 링크를 따라가다 300페이지에서 멈춥니다. 사이트맵을 추가하거나 빠진 페이지를 URL 목록 소스에 넣으세요. [Crawl Website](#crawl-website)를 참고하세요.

### 문서 페이지가 섹션을 하나씩만 보여 주는데, 어시스턴트는 첫 섹션만 압니다.

Moss는 페이지를 처음 불러왔을 때의 모습으로 읽고 클릭하지 않습니다. 그 콘텐츠는 마크다운으로 올리세요. [크롤러가 읽지 못하는 콘텐츠](#크롤러가-읽지-못하는-콘텐츠)를 참고하세요.

### Moss는 어떤 Document360 키를 받나요?

0.17.0부터는 Draft writer 또는 Editor 콘텐츠 역할이 있는 향상된(v3) API 키, 또는 Project Versions, Categories, Articles에 대한 GET 권한이 있는 v2 API 토큰을 받습니다. 이전 버전은 v2 토큰만 받습니다.

### 새로고침하면 콘텐츠가 답변에서 빠지나요?

아니요. 새 버전이 **Ready**가 될 때까지 현재 버전이 계속 답변에 쓰입니다. 새 버전이 실패하면 현재 버전이 그대로 남습니다. [소스 새로고침](#소스-새로고침)을 참고하세요.
