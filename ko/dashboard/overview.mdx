Moss 대시보드에서는 애플리케이션을 만들고, Moss가 답변에 쓰는 콘텐츠를 추가하고, 어시스턴트의 동작을 정하고, 대화를 검토합니다. 호스팅 서비스의 대시보드 주소는 [dashboard.viamoss.ai](https://dashboard.viamoss.ai)입니다. 자체 호스팅 설치는 자체 대시보드를 제공하며, 주소는 운영자가 알려 줍니다.

로그인한 사람은 모두 **관리자** 또는 **멤버**입니다. 멤버는 대시보드의 대부분을 쓸 수 있고, **구성** 아래의 설정은 관리자만 다룹니다. [역할](#역할)을 참고하세요.

## 애플리케이션

애플리케이션은 하나의 Moss 어시스턴트입니다. 지식 베이스, 프로시저, 설정, 대화가 애플리케이션에 속합니다. 앱 코드는 애플리케이션 ID로 애플리케이션에 연결합니다.

로그인하면 **애플리케이션** 화면이 나오며, 조직의 애플리케이션마다 카드가 하나씩 있습니다. 카드를 누르면 애플리케이션이 **분석** 페이지로 열립니다. 애플리케이션 안에서는 사이드바 맨 위의 전환 메뉴로 다른 애플리케이션으로 옮기거나 목록으로 돌아갑니다.

여러 조직에 속해 있다면 **애플리케이션** 화면의 조직 선택 메뉴나 사용자 메뉴의 **조직 전환**으로 조직을 고르세요.

### 애플리케이션 만들기

관리자 역할이 필요합니다.

1. **애플리케이션** 화면에서 **새 애플리케이션**을 누릅니다.
2. **애플리케이션 이름**을 입력합니다. 이름은 조직 안에서 고유해야 하며, 대시보드에서는 나중에 이름을 바꿀 수 없습니다.
3. Moss가 스크린샷을 모델에 보내기를 원하지 않는다면 **비전 사용**은 꺼 둔 채로 두세요. 나중에 **구성 > 동작**에서 바꿀 수 있습니다.
4. 지식 베이스를 색인하는 모델인 **임베딩 모델**을 고릅니다. 애플리케이션을 만든 뒤에는 바꿀 수 없습니다. 기본으로 **Voyage 3.5**가 선택되어 있고, Google Vertex AI를 쓰는 설치에서는 **Google Gemini Embedding 2**가 선택되어 있습니다. 자체 호스팅 설치에서는 운영자가 준비해 둔 모델을 고르세요.
5. **애플리케이션 생성**을 누릅니다. 대화 상자에 새 애플리케이션 ID가 표시됩니다.

앱을 연결하기 전에 다음을 진행하세요.

1. **구성 > 보안**에서 JWT 서명 키를 생성합니다. 키가 없으면 SDK가 연결할 수 없습니다. [인증](/ko/sdk/authentication)을 참고하세요.
2. **구성 > 설치**에서 설치 코드를 복사합니다. [설치](/ko/sdk/installation)를 참고하세요.
3. **지식 베이스**에 도움말 콘텐츠를 추가합니다.

다른 환경의 애플리케이션을 가져오려면 **애플리케이션** 화면에서 **번들 가져오기**를 쓰세요. [내보내기와 가져오기](/ko/dashboard/export-import)를 참고하세요.

대시보드에서는 애플리케이션을 삭제할 수 없습니다.

## 애플리케이션 안의 페이지

사이드바는 세 그룹으로 나뉩니다.

### 분석

| 페이지 | 용도 |
|--------|------|
| **분석** | 사용량, 피드백, 자주 묻는 질문, 해결률, 콘텐츠 공백, 추천 글의 성과를 보여 줍니다. [분석](/ko/dashboard/analytics)을 참고하세요. |
| **코파일럿** | 채팅 세션에 대해 자연어로 질문하고 보고서 형식의 답을 받습니다. 프로시저 초안도 만들 수 있습니다. [답변 개선](/ko/dashboard/improving-answers)을 참고하세요. |
| **세션** | 대화를 찾아 기록을 읽고, 어시스턴트가 무엇을 했는지 확인합니다. [세션](/ko/dashboard/sessions)을 참고하고, 내보내려면 [세션 데이터 내보내기](/ko/dashboard/session-data-export)를 참고하세요. |
| **사용자** | 앱에서 Moss를 사용한 사람들과 그들의 대화입니다. [사용자](/ko/dashboard/analytics#사용자)를 참고하세요. |
| **API 로그** | 관리자 전용입니다. 기록이 켜져 있을 때 저장된 API 요청과 응답입니다. 0.17.0부터 별도 페이지가 되었으며, 그 전에는 **구성 > 데이터 및 개인정보**에 있었습니다. [API 로그](/ko/dashboard/analytics#api-로그)를 참고하세요. |
| **제안** | 코파일럿과 오토파일럿이 제안한 변경 사항입니다. 변경 내용을 검토한 뒤 수락하거나 무시합니다. [답변 개선](/ko/dashboard/improving-answers)을 참고하세요. |
| **모니터** | 대화를 평가하는 품질 기준입니다. 플래그된 세션은 리뷰 큐에서 기다립니다. [답변 개선](/ko/dashboard/improving-answers)을 참고하세요. |

### 콘텐츠

| 페이지 | 용도 |
|--------|------|
| **지식 베이스** | Moss가 답변에 쓰는 도움말 콘텐츠입니다. 문서 소스와 업로드한 콘텐츠가 여기에 있습니다. [지식 베이스](/ko/dashboard/knowledge-base)를 참고하세요. |
| **프로시저** | 한 종류의 요청에 대한 단계별 지침입니다. 작성하고, 테스트하고, 게시합니다. [프로시저](/ko/dashboard/procedures)를 참고하세요. |
| **추천 콘텐츠** | 채팅 시작 화면의 추천 질문과 추천 글, 그리고 문제가 생겼을 때 보여 주는 메시지입니다. [추천 콘텐츠](/ko/dashboard/suggested-content)를 참고하세요. |

### 구성

관리자 전용입니다. 멤버에게는 그룹 이름 옆에 자물쇠가 표시됩니다.

| 페이지 | 용도 |
|--------|------|
| **일반** | 애플리케이션 ID, 이름, 임베딩 모델, 언어를 보고, 애플리케이션을 내보냅니다. [일반](/ko/configurations/dashboard-settings#일반)을 참고하세요. |
| **설치** | 앱에 넣을 설치 코드와 CDN 스크립트용 설정입니다. [설치](/ko/configurations/dashboard-settings#설치)를 참고하세요. |
| **외관** | 채팅 위젯의 브랜딩과 색상입니다. [외관](/ko/configurations/dashboard-settings#외관)을 참고하세요. |
| **동작** | 모델, 주요 기능, AI 어시스턴트 프롬프트, 계획 기능, 세션 동작입니다. [동작](/ko/configurations/dashboard-settings#동작)을 참고하세요. |
| **보안** | 허용 도메인, JWT 키와 클레임, 개인정보 필터링, API 로그 접근 키입니다. [보안](/ko/configurations/dashboard-settings#보안)을 참고하세요. |
| **연동** | Document360, Intercom, 고객의 API, 고객의 MCP 서버, Zendesk입니다. [연동](/ko/dashboard/integrations)을 참고하세요. |
| **데이터 및 개인정보** | 데이터 보존 기간, API 로그 기록, 한 사용자의 데이터 삭제입니다. [데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요. |
| **감사 로그** | 누가 시스템에 접근했고 무엇이 바뀌었는지 보여 줍니다. [감사 로깅](/ko/security/audit-logging)을 참고하세요. |

### 애플리케이션 밖의 메뉴

사이드바에는 **애플리케이션** 옆에 **AI 어시스턴트**가 나타날 수 있습니다. 여기서 Claude 같은 AI 어시스턴트를 Moss 데이터에 연결합니다. 배포 환경이 이 기능을 제공할 때만 나타납니다. [AI 어시스턴트](/ko/dashboard/ai-assistants)를 참고하세요.

배포 환경에 따라 이 페이지에서 다루지 않는 메뉴가 사이드바에 더 나타날 수 있습니다.

### 사용자 메뉴

**테마**(라이트, 다크, 시스템), 대시보드 자체의 **언어**(English 또는 한국어), 여러 조직에 속한 경우 **조직 전환**, 그리고 **로그아웃**이 있습니다.

## 역할

역할은 **관리자**와 **멤버** 두 가지입니다. 역할은 조직의 모든 애플리케이션에 똑같이 적용됩니다.

| | 멤버 | 관리자 |
|---|:---:|:---:|
| 분석, 코파일럿, 세션, 사용자, 제안, 모니터 | 예 | 예 |
| 지식 베이스와 프로시저 | 예 | 예 |
| **추천 콘텐츠** 보기 | 예 | 예 |
| **추천 콘텐츠** 저장 | | 예 |
| **API 로그** | | 예 |
| AI 어시스턴트 프롬프트를 바꾸는 제안 수락 | | 예 |
| **구성** 아래의 모든 페이지 | | 예 |
| 사용자 데이터 삭제 | | 예 |
| 애플리케이션 생성, **번들 가져오기**, **번들 내보내기** | | 예 |
| **AI 어시스턴트**(제공되는 경우)에서 조직의 접근 설정 변경, 모든 사람의 연결 보기 | | 예 |

멤버가 관리자 전용 페이지를 열면 대시보드에 "관리자 권한이 필요합니다"가 대신 표시됩니다.

### 역할이 정해지는 방식

- **호스팅 서비스**: 조직에서의 역할을 따릅니다. 조직 관리자는 Moss의 관리자이고, 그 밖의 구성원은 모두 멤버입니다.
- **자체 호스팅 설치**: 로그인 공급자가 발급한 토큰의 그룹을 따릅니다. 운영자가 관리자 그룹을 `OIDC_ADMIN_GROUPS`에, 멤버 그룹을 `OIDC_MEMBER_GROUPS`에 지정합니다. 관리자 그룹에 속한 사용자는 관리자이고, 멤버 그룹에 속한 사용자는 멤버입니다. `OIDC_MEMBER_GROUPS`가 비어 있으면 로그인할 수 있는 사람은 모두 멤버가 됩니다. 비어 있지 않다면 두 목록 어디에도 없는 사용자는 로그인할 수 없습니다. 그룹은 토큰의 `groups` 클레임에서 읽으며, 운영자가 `OIDC_ROLE_CLAIM`으로 다른 클레임을 지정할 수 있습니다.

자체 호스팅 설치에서 누군가의 역할을 바꾸려면 로그인 공급자에서 그 사람의 그룹을 바꾸세요.

## 자주 묻는 질문

**관리자는 할 수 있고 멤버는 할 수 없는 일은 무엇인가요?**
**구성** 아래의 모든 설정, **API 로그** 페이지, **추천 콘텐츠** 저장, 애플리케이션 생성·가져오기·내보내기, 사용자 데이터 삭제, AI 어시스턴트 프롬프트를 바꾸는 제안 수락, 조직 단위의 **AI 어시스턴트** 설정입니다. [역할](#역할)을 참고하세요.

**구성 메뉴에 자물쇠가 보이는 이유는 무엇인가요?**
멤버이기 때문입니다. 조직의 관리자에게 변경을 요청하거나, 관리자 역할을 달라고 요청하세요.

**자체 호스팅 설치에서는 역할이 어디서 정해지나요?**
로그인 공급자의 그룹에서 정해지며, `OIDC_ADMIN_GROUPS`와 `OIDC_MEMBER_GROUPS`로 연결됩니다. [역할이 정해지는 방식](#역할이-정해지는-방식)을 참고하세요.

**애플리케이션 하나에만 접근 권한을 줄 수 있나요?**
아니요. 역할은 조직의 모든 애플리케이션에 적용됩니다.

**구성에서 설정을 바꿨는데 앱에는 아무 변화가 없습니다.**
npm 패키지를 쓰는 앱에는 대시보드 설정이 모두 적용되지는 않습니다. [앱에 적용되는 설정](/ko/configurations/dashboard-settings#앱에-적용되는-설정)을 참고하세요.
