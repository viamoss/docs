프로시저는 환불, 로그인 문제, 티켓 접수처럼 한 가지 요청 유형에 대해 어시스턴트가 따르는 단계입니다. 언제 적용되는지, 어시스턴트가 무엇을 묻고 무엇을 할지, 어떤 도구를 쓸 수 있는지를 정합니다. 프로시저는 **게시**한 뒤에야 사용자에게 실행됩니다.

사이드바에서 **콘텐츠 > 프로시저**를 여세요. 관리자와 멤버 모두 프로시저를 만들고, 수정하고, 게시하고, 삭제할 수 있습니다.

## 프로시저와 AI 지침

애플리케이션에서 어시스턴트의 동작을 정하는 곳은 두 군데입니다. 규칙의 성격에 맞는 곳을 쓰세요.

| | AI 지침 | 프로시저 |
|---|---|---|
| 위치 | **구성 > 동작 > AI 어시스턴트 프롬프트**(관리자 전용) | **콘텐츠 > 프로시저** |
| 적용 시점 | 모든 대화의 모든 메시지 | 어시스턴트가 그 프로시저가 다루는 요청을 처리하는 동안에만 |
| 용도 | 항상 지킬 규칙과 배경 정보: 용어, 제품에서 기능의 위치, 말투, 절대 하지 말아야 할 말, 사용자에게 권한이 없을 때마다 보여 줄 링크 | 사용자가 요청하는 작업: 물어볼 질문, 단계 순서, 호출할 도구 |
| 도구 | 없음 | **사용할 수 있는 도구**에 지정한 도구 |

항상 지켜야 하는 규칙은 AI 지침에 넣으세요. 예를 들면 "관리자가 아니어서 설정을 찾지 못하는 사용자에게는 관리자 목록 페이지 링크를 보여 준다" 같은 규칙입니다. 프로시저는 사용자의 요청에서 시작하므로, 이런 규칙을 프로시저에 넣으면 그 프로시저가 실행되는 동안에만 적용됩니다. AI 지침 입력란은 [대시보드 설정](/ko/configurations/dashboard-settings)을 참고하세요.

## 프로시저 만들기

1. **콘텐츠 > 프로시저**로 이동해 **새 프로시저**를 누르세요.
2. 시작 방법을 고르세요(0.17.0부터. 0.16.25까지는 목록 페이지에 **문서에서 가져오기**가 있었고, 붙여 넣은 문서를 초안으로 바꾼 뒤 **초안 만들기**로 생성했습니다).
   - **AI로 초안 쓰기**: 상황을 설명하거나 팀에서 이미 쓰는 가이드를 붙여 넣으면 Moss가 초안을 씁니다. 초안은 바로 **초안** 상태로 저장되고, 편집기에 "Moss가 쓴 초안입니다. 확인하고 오른쪽에서 테스트한 뒤 게시하세요."라는 안내와 함께 열립니다. 그대로 이어서 작업하려면 **유지**, 설명을 바꿔 새 초안을 받으려면 **다시 만들기**, 삭제하려면 **버리기**를 누르세요.
   - **직접 작성하기**: 빈 편집기에서 시작합니다.
3. 아래 필드를 채운 뒤 **저장**을 누르세요.
4. **테스트** 패널에서 시험해 보세요.
5. **게시**를 누르세요.

### 필드

| 필드 | 역할 | 제한 |
|---|---|---|
| **이름** | 프로시저를 구별합니다. 애플리케이션 안에서 고유해야 합니다. 어시스턴트가 프로시저를 고를 때도 이 이름을 봅니다 | 200자 |
| **언제 사용하나요?** | 이 프로시저가 다루는 요청을 설명합니다. 어시스턴트는 이 내용을 읽고 프로시저를 쓸지 정합니다 | 2,000자. 어시스턴트가 프로시저를 고를 때는 앞 200자만 봅니다 |
| **트리거 키워드** | "메시지에 이 단어가 있으면 바로 이 프로시저를 씁니다." 키워드를 입력하고 Enter를 누르세요 | 키워드 24개 |
| **어떻게 처리하나요?** | 단계를 평이한 말로 씁니다. `@`를 입력하면 도구를 넣을 수 있으며, 넣은 도구는 **사용할 수 있는 도구**에도 추가됩니다 | 8,000자 |
| **사용할 수 있는 도구** | 이 프로시저가 실행되는 동안 어시스턴트가 호출할 수 있는 도구: **기본 제공**, **API 액션**, **MCP 도구** | |

0.17.0부터 **어떻게 처리하나요?** 필드에는 8,000자까지 쓸 수 있고 어시스턴트가 전부 사용합니다. 편집기에는 글자 수가 표시됩니다. 0.16.25까지는 편집기가 더 긴 텍스트도 받았지만 어시스턴트는 앞 4,000자만 썼습니다. 0.17.0 전에 저장한 8,000자 초과 프로시저는 계속 작동하지만 어시스턴트는 앞 8,000자만 쓰며, 변경 사항을 저장하려면 먼저 8,000자 이하로 줄여야 합니다.

0.16.25까지는 필드 이름이 **이 프로시저는 언제 트리거되어야 하나요?**, **정책 (일상 언어)**, **허용된 액션**이었습니다.

### 테스트 패널

오른쪽의 **테스트** 패널은 초안이든 게시된 프로시저든 시험해 볼 수 있는 샌드박스 채팅입니다. 고객이 보낼 법한 메시지를 보내 보세요.

- **마지막으로 저장된** 버전을 테스트합니다. 최근 수정 사항을 테스트하려면 먼저 저장하세요.
- "도구는 실제로 실행되지 않습니다." 어시스턴트가 호출한 도구는 인자와 함께 표시됩니다. 0.17.0부터는 어시스턴트가 보여 줄 확인 카드도 표시되며, 확인을 눌러도 아무것도 실행되지 않습니다.
- 0.17.0부터 테스트 메시지에 PDF, PNG, JPEG 파일을 최대 5개, 파일당 10MB까지 첨부할 수 있습니다. 어시스턴트에는 파일 내용이 아니라 파일 이름만 전달됩니다.
- **초기화**를 누르면 새 테스트 대화가 시작됩니다.

## 초안, 게시, 버전

| 상태 | 사용자에게 실행 | 이 상태가 되는 경우 |
|---|---|---|
| **초안** | 아니요. **테스트** 패널에서만 실행됩니다 | 새로 만든 모든 프로시저, **게시 취소** |
| **게시됨** | 예 | **게시** |

- **게시**하면 어시스턴트가 프로시저를 바로 쓸 수 있게 되고 버전 번호가 1 올라갑니다.
- **게시된 프로시저를 수정**해도 게시 상태는 유지됩니다. **저장**할 때마다 바로 반영되고 버전 번호가 1 올라갑니다. **테스트** 패널은 마지막으로 저장된 버전을 실행하므로, 게시된 프로시저의 수정 사항을 반영 전에 테스트할 방법은 없습니다. 큰 변경을 먼저 시험하려면 새 텍스트로 이름이 다른 초안 프로시저를 따로 만들어 테스트한 뒤, 그 텍스트를 게시된 프로시저에 옮기세요.
- **초안을 수정**해도 버전 번호는 바뀌지 않습니다.
- **게시 취소**하면 프로시저가 **초안**으로 돌아가고 바로 사용이 중지됩니다. 이 프로시저를 쓰던 대화는 일반 채팅으로 이어집니다.
- **프로시저 삭제**는 프로시저를 영구히 삭제합니다. "이 프로시저를 사용 중인 대화는 일반 채팅으로 전환됩니다. 되돌릴 수 없습니다."

목록에는 프로시저마다 **상태**, **버전**, **트리거 키워드**, **수정일**이 표시됩니다. 세션 상세 페이지에서는 어떤 프로시저의 어떤 버전이 그 세션을 안내했는지 볼 수 있습니다([세션](/ko/dashboard/sessions) 참고).

**이전 버전으로 되돌리기.** Moss는 게시된 버전을 모두 기록하지만, 0.17.0 대시보드에는 버전 기록 보기나 복원 기능이 없습니다. 되돌리려면 이전 텍스트를 다시 넣고 저장하세요. 그것이 새 버전이 됩니다. 크게 수정하기 전에는 텍스트를 따로 복사해 두세요.

**시스템** 배지가 붙은 프로시저는 "Moss가 관리하는 시스템 프로시저입니다. 수정하거나 삭제할 수 없습니다."

## 어시스턴트가 프로시저를 고르는 방식

사용자 메시지가 올 때마다 Moss는 어떤 게시된 프로시저를 적용할지, 또는 적용하지 않을지 정합니다.

1. **트리거 키워드.** 메시지 어딘가에 게시된 프로시저 딱 하나의 키워드가 있으면 그 프로시저를 씁니다("자동 매칭"). 대소문자를 구분하지 않고, 더 긴 단어 안에 들어 있는 키워드도 찾습니다. 예를 들어 `refund`는 "refunds"에도 맞습니다. `order_status`처럼 밑줄로 이은 단어는 무시하므로, 밑줄이 들어간 키워드는 절대 맞지 않습니다.
2. **키워드가 여러 프로시저에 맞을 때.** 한 프로시저에서 맞은 키워드가 다른 프로시저에서 맞은 키워드를 모두 포함하고 더 많으면 그 프로시저가 선택됩니다. 예를 들어 "track my shipment"는 `track`과 `shipment`가 있는 프로시저와 `shipment`만 있는 프로시저에 모두 맞는데, 앞의 프로시저가 선택됩니다. 그렇지 않으면 3단계처럼 어시스턴트가 고릅니다.
3. **어시스턴트의 선택.** 키워드로 하나가 정해지지 않으면 어시스턴트가 게시된 프로시저의 **이름**과 **언제 사용하나요?** 필드를 보고, 요청에 분명히 맞는 프로시저가 있으면 그것을 씁니다("에이전트 선택"). 분명히 맞는 것이 없으면 평소처럼 답변합니다.
4. **이어서 사용.** 한번 선택된 프로시저는 이메일 주소를 알려 주는 답장 같은 이후 메시지에서도 계속 쓰입니다. 다른 프로시저의 키워드가 맞거나, 새 요청에 더 맞는 프로시저로 어시스턴트가 바꾸면 그때 바뀝니다. 프로시저가 게시 취소되거나 삭제되면 대화는 일반 채팅으로 이어집니다.

### 두 프로시저가 같은 작업을 다룰 때

같은 작업을 다루는 게시된 프로시저가 둘이면 서로 경쟁합니다. 메시지마다 키워드나 어시스턴트의 판단으로 둘 중 어느 쪽이든 선택될 수 있어서, 같은 작업에 대한 대화라도 서로 다른 단계를 따를 수 있습니다. 하나만 게시해 두세요. 프로시저를 교체할 때는 이전 프로시저를 **게시 취소**하세요.

### 고를 수 있는 프로시저 수 제한

어시스턴트가 설명을 보고 고를 수 있는 게시된 프로시저는 최대 30개이며, 먼저 만든 30개입니다(이미 사용 중인 프로시저는 세지 않습니다). 31번째 이후의 프로시저는 트리거 키워드가 맞을 때만 실행됩니다.

## 도구와 지원 티켓

**사용할 수 있는 도구**에서 프로시저가 실행되는 동안 어시스턴트가 호출할 수 있는 도구를 고르세요.

- **기본 제공**: `zendesk_ticket`("사용자를 대신해 Zendesk 지원 티켓을 생성합니다"), 그리고 0.17.0부터 `intercom_conversation`("채팅 안의 Intercom 대화로 사용자를 지원팀에 연결합니다")
- **API 액션**: 관리자가 등록한 고객사 API 요청
- **MCP 도구**(0.17.0부터): 관리자가 연결한 MCP 서버의 도구. "읽기 전용" 또는 "데이터 변경"으로 표시됩니다.

API 액션과 MCP 도구는 그 도구를 지정한 프로시저가 실행되는 동안에만 어시스턴트가 쓸 수 있습니다. 따라서 이런 도구가 필요한 작업마다 게시된 프로시저가 있어야 합니다. Zendesk, Intercom, API 액션, MCP 서버 연결은 [연동](/ko/dashboard/integrations)에서 다룹니다.

프로시저에 `zendesk_ticket`을 지정해도 Moss가 티켓을 제안하려면 조건이 있습니다. 애플리케이션에 Zendesk 티켓 접수가 설정되어 켜져 있어야 하고, 페이지에서 직접 티켓을 접수하는 방식이라면 페이지가 `onSupportTicket`을 넘겨야 합니다. 조건을 채우지 못하면 어시스턴트는 티켓 단계를 쓸 수 없다는 안내를 받고, 사용자 정보를 모으는 대신 지원팀으로 안내합니다. 페이지 쪽 티켓 접수는 [지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff)를 참고하세요.

프로시저가 쓰는 도구를 MCP 서버가 더 이상 제공하지 않으면 편집기에 "MCP 서버가 더 이상 이 도구를 제공하지 않습니다"가 표시됩니다. 서버가 다시 제공하거나 프로시저에서 그 도구를 뺄 때까지 프로시저는 그 도구 없이 실행됩니다.

## 프로시저 작성하기

### 단계

어시스턴트가 따를 순서대로 단계를 번호 목록으로 쓰세요. 무엇을 묻고, 무엇을 확인하고, 어느 시점에 어떤 도구를 호출할지 적으세요. 규칙은 그 규칙이 적용되는 단계에 한 번만 쓰세요.

어시스턴트는 대화로 단계를 진행합니다. 관련된 정보는 한 번에 묻고, 사용자가 이미 준 정보는 다시 묻지 않으며, 사용자가 주지 않은 값을 지어내지 않습니다.

### 사용자에게 질문하기

어시스턴트가 실행 전에 질문하게 하려면 단계로 쓰세요. 예: "티켓을 접수하기 전에 사용자가 무엇을 하려 했고 실제로 무슨 일이 일어났는지 물어본다. 질문은 세 개까지만 한다." 사용자는 직접 입력해서 답합니다. 채팅에 답변 선택 버튼은 없습니다.

0.17.0부터는 답변이 프로시저를 중간에 남겨 두면(완료, 중단, 사용자 응답 대기 중 어느 것도 아니면) 채팅에 "아직 끝나지 않았습니다."와 **계속** 버튼이 표시됩니다.

### 여러 언어

답변 언어는 프로시저를 어떤 언어로 썼든 **구성 > 일반**의 **언어** 설정으로 정해집니다([대시보드 설정](/ko/configurations/dashboard-settings) 참고).

- **영어** 또는 **한국어**: 사용자가 어떤 언어로 쓰든 어시스턴트는 항상 그 언어로 답변합니다.
- **자동**(기본값): **화면 가이드**가 켜져 있으면(기본값) 어시스턴트는 애플리케이션과 페이지의 언어로 답변합니다. 사용자가 다른 언어로 온전한 문장을 쓰면 그 언어로 바꾸고, 단어 하나만으로는 바꾸지 않으며, 바꾼 뒤에는 그 언어를 유지합니다. **화면 가이드**가 꺼져 있으면 사용자가 쓰는 언어로 답변합니다.

이 설정의 도움말에는 위젯 화면 언어만 언급되어 있지만, 답변 언어도 이 설정으로 정해집니다.

따라서 프로시저 하나로 모든 사용자를 지원할 수 있습니다. 두 가지는 주의하세요.

- **트리거 키워드**는 쓴 그대로 비교합니다. 사용자가 쓰는 모든 언어로 키워드를 추가하세요.
- **제품 용어.** 단계에서 버튼, 페이지, 요금제를 언급할 때는 제품에 표시되는 이름을 쓰세요. 언어마다 이름이 다르면 각 이름을 모두 적으세요.

### 사용자의 역할과 권한

앱이 역할이나 요금제 같은 사용자 속성을 넘기면, 어시스턴트가 그 속성을 보고 사용자에 맞게 답변을 다듬을 수 있습니다. 그러면 프로시저에 "사용자의 역할이 admin이 아니면 이 단계는 관리자가 해야 한다고 알려 준다"처럼 쓸 수 있습니다.

속성은 SDK 설정의 `userMetadata`와 서명된 사용자 토큰의 `metadata` 클레임에서 옵니다. 두 곳에 같은 키가 있으면 토큰의 값이 우선합니다. 둘을 합쳐 속성은 최대 20개이며, 그보다 많으면 세션 시작이 거부됩니다. 넘기는 방법은 [인증](/ko/sdk/authentication)과 [설정](/ko/sdk/configuration)을 참고하세요.

<Warning>
속성은 어시스턴트가 하는 말에만 영향을 줍니다. 어시스턴트는 이 속성을 근거로 접근을 허용하거나 거부하지 않도록 지시받습니다. 권한 확인은 고객사 API에서 하세요.
</Warning>

## 메시지당 제한

편집기에는 사용자 메시지 하나당 제한이 "메시지마다 도구 10회·240초까지, 확인한 카드도 240초까지 실행됩니다."처럼 표시됩니다. 0.17.0부터의 기본값이며, 0.16.25까지는 도구 라운드 3회와 120초였습니다. 자체 호스팅 설치에서는 이 값을 바꿀 수 있고, 편집기에는 해당 설치에 적용되는 값이 표시됩니다. [모델과 응답 시간](/ko/self-hosting/models-and-response-time)을 참고하세요.

- **도구 라운드.** 라운드 하나는 모델 호출 한 번과 그 호출이 요청한 도구 호출입니다. 라운드를 다 쓰면 어시스턴트는 도구를 더 호출하지 않고 그때까지의 정보로 답변합니다. 0.17.0부터는 채팅에 "어시스턴트가 쓸 수 있는 단계를 모두 썼습니다. 더 작게 나누어 다시 요청해 주세요."라는 안내가 붙습니다.
- **시간.** 시간 제한은 모델 호출과 도구 호출을 합친 메시지 전체에 적용됩니다. 시간이 다 되면 사용자에게 "I'm sorry, that took too long to answer. Please try again."이 표시됩니다.

시간 초과 답변은 사용량과는 관계가 없습니다. "I'm sorry, the service is currently experiencing high traffic. Please try again in a few moments."라는 다른 답변은 모델 제공자가 바빴거나 오류를 돌려줬다는 뜻입니다.

프로시저에서 메시지 시간이 자주 초과되면 메시지 하나에서 하는 일을 줄이세요. 예를 들어 각각 도구를 여러 번 호출하는 단계 사이에 사용자 확인을 넣으세요.

## 프로시저 개선하기

- **제안**(사이드 패널, 0.17.0부터): 코파일럿이나 오토파일럿이 이 프로시저에 대해 낸 대기 중인 제안입니다. **적용**하면 저장된 프로시저가 제안 내용으로 바뀌므로 먼저 수정 사항을 저장하세요. **무시**하면 제안이 닫힙니다. [답변 개선하기](/ko/dashboard/improving-answers#제안)를 참고하세요.
- **AI로 개선**: 이 프로시저의 최근 지표와 대화 기록을 검토하고 변경을 제안해 달라는 요청과 함께 코파일럿을 엽니다. 코파일럿의 제안은 **제안**에 들어옵니다.
- **성과**(사이드 패널): 최근 7일, 30일, 전체 기간에 대해 다음을 보여 줍니다.
  - 0.17.0부터: 세션이 프로시저를 어떤 상태로 떠났는지(**완료**, **중단**, **사용자 응답 대기**, **미완료**)와 상태별 세션 수
  - 프로시저의 도구를 호출한 세션 수, 실패한 호출 수, 도구별·결과별 호출 수
  - 각 도구 호출. Zendesk 티켓이나 Intercom 대화는 보낸 내용이 표시됩니다. API 액션과 MCP 도구는 메서드와 소요 시간만 표시되며, 요청과 응답은 **API 로그 기록**이 켜져 있을 때 **API 로그**(관리자 전용)에 보관됩니다.

## 프로시저와 인터랙티브 가이드

프로시저는 어시스턴트가 채팅에서 무엇을 묻고 무엇을 할지 정합니다. 인터랙티브 가이드는 페이지에서 컨트롤을 하나씩 강조하며 사용자를 단계별로 안내하고, 어시스턴트는 **가이드 시작** 버튼으로 가이드를 제안합니다.

어시스턴트는 다음 두 설정이 모두 켜져 있을 때만 가이드를 제안합니다.

- **구성 > 동작 > 주요 기능**의 **화면 가이드**(기본값 켜짐)
- **구성 > 동작 > 계획 진행 추적**의 **계획 기능 활성화**(기본값 꺼짐)

둘 중 하나라도 꺼져 있으면 어시스턴트는 답변은 하지만 가이드를 제안하지 않습니다. 앱에서 가이드가 시작되고 끝나는 방식은 [가이드와 내비게이션](/ko/sdk/guides-and-navigation)을 참고하세요.

## 자주 묻는 질문

### 저장하면 프로시저가 바로 반영되나요?

새 프로시저는 아닙니다. 새 프로시저는 **게시**를 누를 때까지 초안입니다. 이미 게시된 프로시저는 저장하는 즉시 반영됩니다. [초안, 게시, 버전](#초안-게시-버전)을 참고하세요.

### 사용자가 무언가를 할 수 없을 때마다 링크를 보여 주고 싶습니다. 프로시저와 지침 중 어디에 넣나요?

AI 지침에 넣으세요. 프로시저는 그 프로시저가 다루는 요청을 처리하는 동안에만 적용됩니다. [프로시저와 AI 지침](#프로시저와-ai-지침)을 참고하세요.

### 앱을 새로 배포하지 않고 흐름 속 어시스턴트의 동작을 바꿀 수 있나요?

예. 대시보드에서 프로시저를 수정하세요. 게시된 프로시저는 저장하는 즉시 반영됩니다.

### 이전 프로시저와 새 프로시저가 둘 다 실행됩니다. 왜 그런가요?

둘 다 게시되어 있고 같은 작업을 다루므로 서로 경쟁합니다. 이전 프로시저를 게시 취소하세요. [두 프로시저가 같은 작업을 다룰 때](#두-프로시저가-같은-작업을-다룰-때)를 참고하세요.

### 어시스턴트가 질문할 때 클릭할 수 있는 선택지를 보여 줄 수 있나요?

아니요. 사용자는 직접 입력해서 답합니다.

### 사용자가 한국어로 쓰면 프로시저가 작동하나요?

예. **구성 > 일반**의 **언어**가 **자동**이면 사용자가 한국어로 쓸 때 어시스턴트도 한국어로 바꿉니다. **한국어**로 정하면 항상 한국어로 답변합니다. 키워드는 쓴 그대로 비교하므로 트리거 키워드도 한국어로 추가하세요. [여러 언어](#여러-언어)를 참고하세요.

### 어시스턴트가 사용자에게 권한이 없다는 것을 미리 알려 줄 수 있나요?

예. 앱이 사용자의 역할이나 권한을 속성으로 넘기고, 프로시저나 AI 지침에 그때 어떻게 할지 적어 두면 됩니다. [사용자의 역할과 권한](#사용자의-역할과-권한)을 참고하세요.

### 사용자에게 "that took too long to answer"가 표시됐습니다. 서비스에 부하가 걸린 건가요?

아니요. 그 메시지에 답하는 데 시간 제한(기본값 240초)을 다 썼다는 뜻입니다. [메시지당 제한](#메시지당-제한)을 참고하세요.

### 어시스턴트가 가이드를 제안하지 않은 이유는 무엇인가요?

어시스턴트는 애플리케이션에서 **화면 가이드**(기본값 켜짐)와 **계획 기능 활성화**(기본값 꺼짐)가 모두 켜져 있고, 페이지에서 하는 작업에 대해 단계별 계획으로 답할 때만 **가이드 시작**을 제안합니다. [프로시저와 인터랙티브 가이드](#프로시저와-인터랙티브-가이드)와 [가이드와 내비게이션](/ko/sdk/guides-and-navigation)을 참고하세요.
