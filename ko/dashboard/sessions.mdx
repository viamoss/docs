**세션** 페이지에는 한 애플리케이션에서 사용자들이 Moss와 나눈 대화가 나열됩니다. 세션을 열면 대화 기록을 읽고, 턴마다 어시스턴트가 무엇을 찾아봤는지, 어떤 프로시저가 안내했는지, 어떤 도구를 실행했는지, 무엇이 잘못됐는지, 사용자가 어떻게 평가했는지 확인할 수 있습니다.

사이드바의 **분석 > 세션**에서 엽니다. 관리자와 멤버 모두 사용할 수 있습니다.

대화를 빨리 찾으려면 목록 위의 **세션 ID로 이동**에 세션 ID를 붙여 넣거나, 사용자가 쓴 단어를 검색창에 입력하세요. 자주 하는 검색은 [필요한 세션 찾기](#필요한-세션-찾기)를 참고하세요.

## 세션이란

세션은 위젯의 채팅 하나입니다. 첫 메시지부터 위젯이 새 채팅을 시작할 때까지 오간 사용자의 메시지와 어시스턴트의 답변이 한 세션에 담깁니다. 세션은 애플리케이션 하나와 사용자 ID 하나에 속하며, 사용자 ID는 앱이 Moss에 넘기는 ID입니다. 세션 ID는 `cs_`로 시작합니다.

새 채팅을 언제 시작할지는 위젯이 정합니다. 일정 시간 활동이 없을 때, 최대 유지 시간이 지났을 때, 사용자가 새 채팅을 요청할 때입니다. 이 채팅 한도는 [세션](/ko/sdk/api/session)에서 설명하며, 대시보드는 그 결과만 보여 줍니다.

목록에는 메시지가 하나 이상 있는 세션만 나옵니다. 위젯을 열기만 하고 쓰지 않았다면 여기에 행이 생기지 않습니다.

### 활성과 종료

서버는 세션마다 **활성** 또는 **종료** 상태도 관리합니다.

- 메시지 없이 **30분**이 지나면 세션이 종료됩니다. 서버는 15분마다 확인하므로, 마지막 메시지 뒤 최대 45분가량 활성 상태로 남을 수 있습니다. 자체 호스팅 설치에서는 운영자가 대시보드 백엔드(Helm 차트의 `dashboard-backend`)의 `SESSION_IDLE_CLOSE_MINUTES` 환경 변수로 이 30분을 바꿀 수 있습니다.
- 종료된 세션에 새 메시지가 오면 다시 활성 상태가 됩니다. 대화는 같은 세션에서 이어집니다.

이 상태는 위젯의 채팅 한도와는 별개입니다. 세션이 종료되어도 위젯이 새 채팅을 시작하지 않고, 위젯이 새 채팅을 시작할 때 이전 세션이 종료되기를 기다리지도 않습니다. 종료된다고 삭제되는 것도 없습니다. 세션을 얼마나 보관할지는 **구성 > 데이터 및 개인정보**에서 정합니다([데이터 및 개인정보](/ko/dashboard/data-privacy) 참고).

상태는 **세션 요약** 내보내기의 `status` 열에서 볼 수 있습니다([세션 데이터 내보내기](/ko/dashboard/session-data-export) 참고). 종료된 세션만 읽는 **분석 > 주요 질문 > 주제**에도 영향을 줍니다([분석](/ko/dashboard/analytics#주요-질문) 참고).

## 세션 목록

### 목록 위의 카드

카드 세 개는 애플리케이션 전체를 전 기간에 걸쳐 셉니다. 필터와 검색은 이 숫자를 바꾸지 않습니다.

| 카드 | 보여 주는 것 |
|---|---|
| **평가율** | 사용자가 평가한 세션 중 도움됨으로 평가된 세션의 비율입니다. 보통 평가(1~5점 중 3점)는 평가한 것으로 세지만 도움됨으로는 세지 않습니다. 아래 줄에는 평가된 세션 수가 나옵니다. |
| **도움 됨** | 도움됨으로 평가된 세션입니다(평가 카드의 👍, 또는 4점이나 5점). |
| **도움 안됨** | 도움 안됨으로 평가된 세션입니다(평가 카드의 👎, 또는 1점이나 2점). |

### 열

| 열 | 보여 주는 것 |
|---|---|
| **첫 사용자 질문** | 세션에서 사용자가 처음 입력한 질문입니다. |
| **사용자** | 앱이 넘긴 사용자 ID입니다. 잘린 ID는 마우스를 올리면 전체가 보입니다. |
| **생성일** | 세션이 시작된 시각이며, 브라우저의 시간대로 표시됩니다. |
| **마지막 활동** | 마지막 메시지가 기록된 시각입니다. |
| **단계** | 세션에 담긴 메시지 수입니다. 사용자의 질문, Moss의 안내를 따라 사용자가 페이지에서 한 동작, 어시스턴트의 답변을 셉니다. 실패했거나 다른 턴으로 대체된 턴은 세지 않습니다. |
| **도구 실행** | Moss가 세션에 기록한 단계 수이며, 작업만 세는 것이 아닙니다. 티켓 하나를 접수하면 보통 여러 개가 늘어납니다. [도구 실행이 세는 것](#도구-실행이-세는-것)을 참고하세요. |
| **녹화** | 다시 볼 수 있는 녹화가 있으면 카메라 아이콘이 표시됩니다. |
| **평가** | 사용자가 세션 전체에 준 평가입니다. 1~5점 점수이거나 👍 또는 👎입니다. 마우스를 올리면 평가한 시각이, 점수나 👎일 때는 사용자의 코멘트도 함께 보입니다. 대시(-)는 평가가 없다는 뜻입니다. |

목록은 한 페이지에 세션 20개씩, 가장 최근에 갱신된 세션부터 보여 줍니다. 행을 누르면 세션이 열립니다.

### 도구 실행이 세는 것

**도구 실행** 수에는 Moss가 세션에 기록한 단계가 모두 들어가며, 하나만 빠집니다. 답변 전에 Moss가 스스로 하는 지식 베이스 검색(대화 기록에는 `kb_search`로 표시)입니다. 다음이 포함됩니다.

- 어시스턴트의 작업: API 액션, 지원 티켓(`zendesk_ticket`), 지원팀으로의 핸드오프(`intercom_conversation`), 연결된 MCP 서버의 도구, 프로시저 액션
- 어시스턴트가 직접 한 조회: `search_knowledge_base`(어시스턴트가 직접 하기로 한 검색), `get_page_context`, `get_user_metadata`, `report_procedure_state` 등
- 턴 사이에 기록된 이벤트: 티켓이나 핸드오프의 제출(`handoff_submitted`)이나 취소(`handoff_cancelled`), 그리고 고객사 시스템이 알려 준 결과
- AI 모델 제공업체가 차단한 턴의 표시

**도구 실행** 필터에도 같은 이름이 나열되므로, 작업뿐 아니라 조회와 이벤트도 들어 있습니다.

### 검색

검색창(**대화 내용 검색 또는 세션 ID 붙여넣기...**)은 사용자 질문이나 어시스턴트 답변에 입력한 텍스트가 들어 있는 세션을 찾습니다. 대소문자를 구분하지 않고, 단어의 일부도 찾습니다. 전체 세션 ID나, 적어도 첫 하이픈까지의 앞부분(예: `cs_3f1c9a2e-`)을 붙여 넣어 그 세션을 찾을 수도 있습니다.

**세션 ID로 이동**은 세션을 바로 엽니다. ID를 붙여 넣고 **이동**을 누르세요. Moss가 그 ID의 세션을 찾지 못하면 목록은 그대로이고, 안내 메시지가 나옵니다.

### 필터

**필터**를 눌러 목록을 좁힙니다. 적용된 필터는 버튼 옆에 칩으로 표시됩니다. 칩의 **x**를 누르면 그 필터가 해제되고, **필터 초기화**를 누르면 모두 해제됩니다. 필터와 검색어는 페이지 주소에 남으므로, 필터를 건 목록을 북마크하거나 동료에게 보낼 수 있습니다.

| 그룹 | 필터 | 보여 주는 세션 |
|---|---|---|
| **주제** | 주제 | 주제 분석에서 이 주제로 분류된 세션([주제](/ko/dashboard/analytics#주요-질문) 참고). 선택 목록에는 최근 90일 동안 가장 많았던 주제 50개가 나옵니다. |
| **사용자 및 기간** | **사용자 ID** | 입력한 텍스트가 들어 있는 사용자 ID의 세션. 대소문자를 구분하지 않으므로 `42`를 입력하면 `user-142`도 찾습니다. |
| | **생성일** | 두 날짜 사이에 시작된 세션 |
| | **마지막 활동** | 두 날짜 사이에 마지막 메시지가 있었던 세션 |
| **평가** | **세션 평가** | 세션 전체가 **도움됨**, **도움 안됨**, **보통**으로 평가된 세션, 또는 **미평가** 세션 |
| | **메시지 평가** | 답변 하나 이상이 **도움됨**으로, 또는 **도움 안됨**으로 평가된 세션. **도움 안됨**은 어시스턴트가 이후 턴에서 스스로 바로잡은 답변도 찾습니다. |
| **결과** | **답변 상태** | **답변됨**: 세션의 지식 베이스 검색이 모두 알맞은 내용을 찾았습니다. **콘텐츠 공백**: 적어도 한 번은 찾지 못했습니다([콘텐츠 공백](/ko/dashboard/analytics#콘텐츠-공백) 참고). 지식 베이스를 한 번도 검색하지 않은 세션은 어느 쪽에도 해당하지 않습니다. |
| | **해결 여부** | **해결됨**: 도움됨으로 평가되었거나, 사용자가 세션에서 인터랙티브 가이드를 끝까지 마쳤습니다. **미해결**: 나머지 전부이며, 아무도 평가하지 않은 세션도 포함됩니다. |
| | **녹화** | 녹화가 있는(**있음**) 세션 또는 없는(**없음**) 세션 |
| **도구 실행** | 이름 하나 이상 | 선택한 단계 중 하나 이상이 기록된 세션. 목록에는 이 애플리케이션에서 기록된 이름만 나오며, 하나라도 생기면 표시됩니다. 도구 외에 `search_knowledge_base`나 `handoff_submitted` 같은 조회와 이벤트도 들어 있습니다([도구 실행이 세는 것](#도구-실행이-세는-것) 참고). |

**분석** 페이지의 링크로 이 목록을 열면 필터가 미리 적용되어 있으며, **아티클**이나 **콘텐츠 공백 기간**처럼 **필터** 패널에 없는 필터도 있습니다. 이런 필터도 칩으로 표시됩니다. **주요 질문**에서 왔다면 **인기 질문으로 돌아가기**를 눌러 같은 기간으로 돌아갈 수 있습니다.

## 필요한 세션 찾기

| 찾는 것 | 방법 |
|---|---|
| 사용자가 불만족한 답변 | **필터 > 평가 > 메시지 평가 > 도움 안됨**. 세션 전체를 나쁘게 평가한 세션을 보려면 **세션 평가 > 도움 안됨**을 쓰세요(1점이나 2점도 도움 안됨으로 셉니다). |
| 👎 이유가 있는 세션 | **메시지 평가 > 도움 안됨** 목록에서 세션을 여세요. 각 답변의 평가 옆에 이유가 보입니다. 애플리케이션 전체의 이유별 횟수는 **분석 > 피드백**에서 봅니다. |
| 지원 티켓이나 상담원 핸드오프가 있는 세션 | **필터 > 도구 실행**에서 `zendesk_ticket`(Zendesk 티켓)이나 `intercom_conversation`(Intercom 핸드오프)을 선택하세요. 어시스턴트가 초안을 만든 세션이 모두 나오며, 사용자가 취소한 초안도 포함됩니다. 결과는 각 세션의 카드에서 확인하세요. Zendesk에서는 Moss에서 온 티켓에 `moss-created` 태그가 붙습니다([지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff) 참고). |
| 사용자가 인터랙티브 가이드를 따라간 세션 | 0.17.0에는 이를 위한 필터가 없습니다. **해결 여부 > 해결됨**에는 가이드를 끝까지 마친 세션이 도움됨으로 평가된 세션과 섞여 있습니다. 세션 안에서는 사용자가 페이지에서 마친 단계마다 별도 카드로 표시되고([대화 기록](#대화-기록) 참고), **전체 대화 기록** 내보내기에서는 `system_continuation` 행입니다. |
| 지식 베이스가 답하지 못한 질문 | **필터 > 결과 > 답변 상태 > 콘텐츠 공백**. 질문 자체는 **분석 > 콘텐츠 공백**에서 봅니다. |
| 특정 지식 베이스 아티클을 사용한 세션 | **분석 > 아티클**에서 해당 아티클 행의 **세션 보기**를 누르세요. |
| 사용자 한 명의 세션 | **필터 > 사용자 및 기간 > 사용자 ID**를 쓰거나, **사용자** 페이지에서 사용자를 열고 **모든 세션 보기**를 누르세요. |
| 녹화가 있는 세션 | **필터 > 결과 > 녹화 > 있음** |

결과를 스프레드시트에서 다루려면 **내보내기**를 누르세요. 내보내기에 담기는 내용은 [세션 데이터 내보내기](/ko/dashboard/session-data-export)를 참고하세요.

## 세션 페이지

### 헤더

- **세션 목록으로 돌아가기**를 누르면 목록으로 돌아갑니다.
- **API 로그** 버튼은 이 세션의 API 로그를 엽니다. 세션이 시작되기 5분 전부터 마지막 메시지 5분 뒤까지의 로그입니다. 관리자에게만 보입니다([API 로그](/ko/dashboard/analytics#api-로그) 참고).
- 평가 원은 세션의 점수나 👍/👎를 보여 줍니다. 마우스를 올리면 코멘트와 평가 시각이 보입니다.
- **세션 ID**와 복사 버튼이 있습니다.
- 어시스턴트가 세션에서 지원 티켓, 핸드오프, 작업 제안의 초안을 만들었다면 **지원 티켓 1건 · #1234 접수 완료** 같은 칩이 나타납니다. 각각이 어떻게 끝났는지 요약하며, 누르면 대화 기록의 해당 카드로 이동합니다.

그 아래에는 **사용자**(복사 버튼 포함), **지속 시간**(세션이 시작된 때부터 마지막 메시지까지. 시작은 첫 메시지보다 이를 수 있습니다), **단계**(목록과 같은 수이며, 뒤에 사용자가 입력한 질문 수가 붙습니다), **생성일**, **마지막 활동**이 있습니다.

### 적용된 프로시저

[프로시저](/ko/dashboard/procedures)가 세션을 안내했다면, 그 프로시저와 당시 게시되어 있던 버전이 한 줄로 표시됩니다.

- **마지막으로 적용된 프로시저**는 세션을 마지막으로 안내한 프로시저입니다.
- 프로시저 여러 개가 세션을 안내했다면 대신 **적용된 프로시저 (순서대로)** 줄이 나옵니다. 오래된 것부터 나열하며, 각 프로시저가 넘겨받은 시각과 방식을 보여 줍니다.
  - **자동 매칭**: 사용자 메시지의 트리거 키워드로 선택되었습니다.
  - **에이전트 선택**: 어시스턴트가 게시된 프로시저 중에서 설명을 보고 골랐습니다.
  - **재게시됨**: 이미 세션을 안내하던 프로시저의 새 버전이 게시되었습니다.
  - **중단됨 — 게시 취소되거나 삭제됨**: 세션을 안내하는 도중에 프로시저가 내려갔습니다.

그 뒤 삭제되었거나 게시 취소된 프로시저는 ID와 함께 **확인할 수 없는 프로시저**로 표시됩니다.

사용자가 세션 평가와 함께 코멘트를 남겼다면 **평가 코멘트** 아래에 나옵니다.

### 대화 기록

**대화 기록**은 세션을 카드로 이어서 보여 줍니다. 오래된 것부터 나오며, 날짜가 바뀌는 곳에 날짜 줄이 있습니다. 각 카드는 어시스턴트가 응답하게 된 계기로 시작합니다.

- 사용자가 입력한 질문, 또는
- Moss의 안내를 따라 사용자가 페이지에서 한 동작(**클릭함**, **입력함** 등). 사용자가 쓴 요소의 미리보기가 함께 나옵니다.

그 아래에 어시스턴트의 응답이 위에서 아래로 이어집니다.

1. **어시스턴트가 가진 정보.** 페이지 URL, **문서 N개**(가져온 지식 베이스 내용, 관련성순), **페이지 구조**, **스크린샷** 칩이 캡처된 경우에 표시됩니다. 칩을 누르면 내용이 열립니다.
2. **어시스턴트가 거친 단계.** 기록된 단계마다 한 행씩 나옵니다. 실행한 도구와 조회가 나오며, 지식 베이스 검색이 기록되었다면 그 `kb_search` 행도 있습니다. 각 행에는 이름, 상태, 걸린 시간이 있고, 티켓이나 핸드오프라면 어떻게 끝났는지도 나옵니다. **자동 연결** 표시가 붙은 행은 어시스턴트가 고른 것이 아니라 핸드오프 규칙이 맞아서 실행된 것입니다. 프로시저가 도구를 실행했다면 행에서 그 프로시저로 이동할 수 있습니다. 행을 펼치면 **Input**, **Output**, 실행 세부 정보가 보입니다. 실패한 도구 실행이 API 로그를 남겼다면 **API 로그 항목** 링크가 있습니다. API 로그 페이지는 관리자 전용입니다.
3. **답변.** 사용자가 본 답변입니다.
4. **턴이 끝난 방식.** 정상적으로 끝나지 않았을 때 **실패**(답변 없음), **진행 중**(아직 답변하는 중), **미완료**(결과를 남기지 않음) 중 하나와 설명이 나옵니다.
5. **답변한 모델.** 애플리케이션이 **구성 > 동작**의 **모델** 카드에서 모델을 골랐을 때, 답변한 모델, 데이터 처리자와 리전, 턴에 걸린 시간(초)을 한 줄로 보여 줍니다. 다른 모델이 대신 답변했거나 어떤 모델도 답변하지 못했다면 그 사실과 이유도 나옵니다. 0.17.0부터 표시됩니다.
6. 사용자에게 표시된 문제. 무언가 잘못됐을 때 나옵니다([턴의 문제](#턴의-문제) 참고).
7. **티켓, 핸드오프, 작업 카드.** 어시스턴트가 지원 티켓 초안을 만들었거나, 사용자를 지원팀에 연결했거나, 사용자가 확인할 작업을 제안했을 때 나옵니다. 각 카드는 사용자가 본 그대로의 내용, 제출 전에 사용자가 바꾼 내용, 고객사 시스템이 알려 준 결과를 보여 줍니다. 흐름은 [지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff)에서 설명합니다.
8. **추천 동작.** 답변이 사용자에게 페이지의 요소를 가리켰을 때, 상호작용 종류(예: `click`)와 함께 나옵니다.
9. **이 답변에 대한 사용자 피드백.** **도움됨** 또는 **도움안됨** 배지, 👎 뒤에 사용자가 고른 이유, **사용자 의견**이 나옵니다. **도움안됨 (AI)** 배지는 같은 세션의 이후 답변이 이 답변을 바로잡았다는 뜻입니다.

대화 기록 위의 도구 모음에는 다음이 있습니다.

- **(재)전체 평가**, 그리고 답변마다 아래에 있는 **응답 평가하기**. AI 평가자가 답변을 평가해 **적절함** 또는 **부적절함** 판정, **근거**·**완성도**·**명확성**(**LLM 응답 품질**)과 **관련성**·**커버리지**·**중복성**(**RAG 검색 품질**)의 5점 만점 점수, 찾아낸 문제, **수정 제안**, 판단 근거를 보여 줍니다. 결과는 세션에 저장됩니다. 끝까지 완료된 답변만 평가할 수 있습니다.
- **디버그 정보 표시**: 메시지마다 순번과 답변의 원본 구성 요소를 추가로 보여 줍니다.
- **녹화 표시**와 **녹화 숨기기**: 세션에 녹화가 있을 때 나옵니다.

### 평가와 점수, 이유

사용자는 위젯의 두 곳에서 평가할 수 있습니다.

- **답변마다** 👍 또는 👎를 누릅니다. **메시지 평가** 필터와 각 답변의 배지가 이 평가입니다.
- **세션 전체**를 평가 카드에서 평가합니다. **평가** 열과 **세션 평가** 필터가 이 평가입니다.

0.17.0부터는 위젯 옵션 두 개로 더 많이 받을 수 있습니다.

- `chrome.feedback.sessionRating: 'stars'`를 쓰면 평가 카드가 👍/👎 대신 1~5점 점수를 묻습니다. 4점과 5점은 **도움됨**, 1점과 2점은 **도움 안됨**, 3점은 **보통**으로 셉니다. 대시보드에는 "5점 중 3점"처럼 점수 자체가 표시됩니다.
- `chrome.feedback.askWhatWentWrong: true`를 쓰면 답변에 👎를 누른 사용자에게 무엇이 잘못됐는지 묻고, 코멘트도 선택해 남길 수 있게 합니다.

두 옵션 모두 설정하지 않으면 꺼져 있습니다. [외관](/ko/sdk/appearance)을 참고하세요. 사용자가 고를 수 있는 이유는 정해져 있습니다.

| 표시되는 이유 | 저장되는 값 | 👎 뒤에 제시되는 대상 |
|---|---|---|
| 단계가 화면과 맞지 않았어요 | `steps_mismatch` | 가이드 |
| 가이드를 따라 하기 어려웠어요 | `hard_to_follow` | 가이드 |
| 문제가 해결되지 않았어요 | `not_solved` | 가이드 |
| 답변이 틀렸어요 | `wrong_answer` | 가이드 밖의 답변 |
| 질문에 대한 답이 아니었어요 | `not_answered` | 가이드 밖의 답변 |
| 기타 | `other` | 둘 다 |

**분석 > 피드백**에서 점수 분포와 이유별 횟수를 볼 수 있습니다. 내보내기에는 저장되는 값이 담깁니다.

### 턴의 문제

0.17.0부터는 Moss가 답변하는 동안 무언가 잘못되면 채팅에서 사용자에게 알리고, 문제를 턴과 함께 기록하고, 세션 페이지의 답변 아래에 보여 줍니다. 각 문제에는 다음이 나옵니다.

- 누가 해결할 수 있는지: **사용자가 해결 가능**, **관리자가 해결 가능**, **Moss가 해결**
- 무슨 일이 있었는지(아래 표)
- 관련된 연동과 단계가 있으면 그 이름, 그리고 HTTP 상태 같은 짧은 세부 정보
- 해결할 곳이 **구성 > 연동**이면 **연동 열기** 링크
- **참조 번호**: 세션 ID와 턴 ID이며, 사용자도 채팅에서 같은 번호를 봅니다. Moss 지원팀에 문의할 때 이 번호를 알려 주세요.

프로시저가 턴을 안내했다면 문제 위에 그 프로시저와 진행 상태(**완료**, **중단**, **사용자 응답 대기**, **미완료**)가 어시스턴트가 밝힌 이유와 함께 나옵니다.

| 표시되는 문제 | 해결할 수 있는 쪽 | 사용자에게 보이는 안내 |
|---|---|---|
| 모델이 과부하 상태였습니다 | Moss | 지금 어시스턴트에 요청이 몰리고 있습니다. 다시 시도해 주세요. |
| 모델 응답이 너무 오래 걸렸습니다 | Moss | 답변하는 데 시간이 너무 오래 걸렸습니다. 다시 시도해 주세요. |
| 안전 필터가 요청을 차단했습니다 | 사용자 | 안전 필터가 이 요청을 차단했습니다. |
| 모델이 쓸 수 있는 답변을 내지 못했습니다 | Moss | 어시스턴트가 쓸 수 있는 답을 내지 못했습니다. 다시 시도해 주세요. |
| 어시스턴트가 단계 한도에 도달했습니다 | 사용자 | 어시스턴트가 쓸 수 있는 단계를 모두 썼습니다. 더 작게 나누어 다시 요청해 주세요. |
| Moss 내부 오류 | Moss | Moss 쪽에서 문제가 발생했습니다. |
| 도구를 불러오지 못했습니다 | Moss | 이 답변에는 어시스턴트의 도구 일부를 불러오지 못했습니다. |
| 도구가 실패했습니다 | Moss | 어시스턴트의 도구 하나가 실패해서 그 도구 없이 답변했습니다. |
| 연동 서비스가 응답하지 않았습니다 | 사용자 | *연동 이름*에서 응답이 없습니다. |
| 연동 서비스가 요청을 거부했습니다 | 사용자 | *연동 이름*에서 요청을 거부했습니다. |
| 연동 서비스가 요청 수를 제한하고 있습니다 | 사용자 | *연동 이름*에 요청이 너무 많습니다. 잠시 후 다시 시도해 주세요. |
| 단계가 완료되지 않았습니다 | 사용자 | 단계 하나가 완료되지 않았습니다. |
| 연동 서비스가 Moss의 인증 정보를 거부했습니다 | 관리자 | *연동 이름*에서 Moss의 인증 정보를 거부했습니다. |
| 연결이 꺼져 있습니다 | 관리자 | Moss에서 *연동 이름* 연결이 꺼져 있습니다. |
| 사용자에게 실행 권한이 없습니다 | 관리자 | 이 작업을 실행할 권한이 없습니다. |
| 프로시저가 끝나지 않았습니다 | 사용자 | 아직 끝나지 않았습니다. |
| 요청을 읽지 못했습니다 | Moss | 어시스턴트가 이 요청을 읽지 못했습니다. |
| 페이지에서 해당 컨트롤을 찾지 못했습니다 | 사용자 | 어시스턴트가 이 페이지에서 해당 항목을 찾지 못했습니다. |

위 표의 사용자 안내는 위젯의 한국어 문구이며, 위젯은 채팅 언어에 맞는 문구를 보여 줍니다. *연동 이름*은 연결의 이름이며, 이름이 없으면 "연결된 서비스"로 표시됩니다.

사용자가 확인한 작업 카드의 단계가 실패하면, 채팅의 카드에 그 이유가 나옵니다. 연결이 설정되어 있지 않은 경우와 첨부 파일을 찾지 못한 경우, 이 두 가지 문제는 이렇게만 알려집니다. 세션 페이지에서 이런 문제는 해당 턴의 문제 목록이 아니라, 카드를 제안한 턴에 있는 그 단계의 세부 정보(**Input**)에 들어 있습니다.

위젯은 턴이 되지 못한 요청의 문제도 사용자에게 알릴 수 있습니다. 페이지가 로그인하지 못했을 때, 요청이 너무 많을 때, 첨부 파일이 거부되었을 때, 카드가 만료되었거나 더 이상 맞지 않을 때, 연결이 끊어졌을 때, 페이지를 읽거나 열지 못했을 때입니다. 이런 문제는 턴과 함께 기록되지 않으므로 세션 페이지에 나오지 않습니다. 추적하려면 `onError`를 넘기세요. 채팅이 보여 주는 문제를 모두 `code`와 참조 번호와 함께 받습니다([onError](/ko/sdk/events#onerror) 참고). 실패한 요청에는 `Moss Error` 이벤트도 발생하지만, 모든 문제에 발생하지는 않습니다.

### 녹화

세션에 녹화가 있으면 세션 페이지의 왼쪽에 대화 기록이, 오른쪽에 사용자 페이지의 재생 화면이 나옵니다. **녹화 숨기기**를 누르면 대화 기록이 전체 너비를 씁니다. 녹화가 대화 기록과 맞물리면, 재생하는 동안 재생 중인 턴이 강조되고 화면에 보이도록 스크롤되며, 턴마다 **여기서부터 재생**으로 재생 위치를 그 턴으로 옮길 수 있습니다.

녹화는 **구성 > 동작**에서 **세션 리플레이 활성화**가 켜져 있을 때만 남습니다. npm 패키지를 쓴다면 `AgentProvider` 설정에서 `enableSessionRecording: true`도 지정하세요.

<Warning>
  **0.17.0에서 바뀌었습니다.** 0.17.0 전에는 누군가 끄기 전까지 **세션 리플레이 활성화**가 켜진 것으로 취급되었습니다. 그래서 이 스위치를 한 번도 저장하지 않은 애플리케이션도 스크립트 태그 설치에서는 세션을 녹화했고, npm 설치에서는 서버가 이 스위치를 확인하지 않았습니다. 0.17.0부터는 관리자가 켜기 전까지 꺼져 있고, 꺼져 있는 동안에는 설치 방식과 관계없이 서버가 녹화를 받지 않습니다. 업그레이드한 뒤에는 스위치를 한 번도 저장하지 않은 애플리케이션의 녹화가 멈추며, 관리자가 **세션 리플레이 활성화**를 켜야 다시 녹화됩니다.
</Warning>

스위치는 [대시보드 설정](/ko/configurations/dashboard-settings)을, 녹화가 담는 내용과 관련 설정은 [페이지 데이터와 개인정보 보호 설정](/ko/sdk/page-data)을 참고하세요.

녹화 보관 기간은 대화와 별도로 **구성 > 데이터 및 개인정보**에서 정합니다([데이터 및 개인정보](/ko/dashboard/data-privacy) 참고).

## 자주 묻는 질문

**세션은 얼마나 유지되고, 어디서 제한하나요?**
새 채팅을 언제 시작할지는 위젯이 정합니다. 기본값은 30분 동안 활동이 없거나, 시작한 지 모두 2시간이 지났을 때입니다. 두 값을 어디서 설정하는지는 [세션](/ko/sdk/api/session)을 참고하세요. 이와 별개로, 서버는 메시지 없이 30분이 지나면 세션을 종료 상태로 표시하고, 새 메시지가 오면 다시 엽니다.

**인터랙티브 가이드를 쓴 세션만 볼 수 있나요?**
0.17.0에는 이를 위한 필터가 없습니다. 가장 가까운 방법은 [필요한 세션 찾기](#필요한-세션-찾기)를 참고하세요.

**1~5점 점수와 👎 이유는 어디에 나오나요?**
점수는 **평가** 열, 세션 페이지, **분석 > 피드백**, 두 내보내기 유형 모두에 나옵니다. 이유는 세션 페이지의 각 답변, **분석 > 피드백**, **전체 대화 기록** 내보내기에 나옵니다. 위젯에서 `chrome.feedback.sessionRating: 'stars'`와 `chrome.feedback.askWhatWentWrong: true`로 켜세요.

**어떤 티켓이 Moss를 거쳐 왔는지 어떻게 알 수 있나요?**
Zendesk에서는 Moss에서 온 티켓에 `moss-created` 태그가 붙습니다. 대시보드에서는 **도구 실행 > `zendesk_ticket`** 필터를 쓰세요. 어시스턴트가 티켓 초안을 만든 세션이 사용자가 취소한 초안까지 모두 나오며, 각 세션의 티켓 카드에서 결과와 백엔드가 돌려준 티켓 번호를 볼 수 있습니다. [지원 티켓 핸드오프](/ko/sdk/support-ticket-handoff)를 참고하세요.

**"experiencing high traffic"이나 "that took too long to answer" 답변은 무슨 뜻인가요?**
둘 다 AI 모델이 답변하지 못했다는 뜻이며, 고객사 사이트의 트래픽과는 관계가 없습니다. "The service is currently experiencing high traffic"은 Moss가 다시 시도한 뒤에도 모델 제공업체가 계속 바쁘다고 하거나 서버 오류를 냈다는 뜻입니다. 또는 애플리케이션이 고른 모델이 답변할 수 없는데 다른 모델의 대체 답변이 허용되지 않았다는 뜻입니다. 이때 턴에는 **모델이 과부하 상태였습니다**가 표시됩니다. "That took too long to answer"는 턴의 제한 시간 안에 모델이 답변하지 못했다는 뜻이며, **모델 응답이 너무 오래 걸렸습니다**가 표시됩니다. 자체 호스팅 설치라면 [모델과 응답 시간](/ko/self-hosting/models-and-response-time)을 참고하세요.

**목록의 단계 수가 대화 기록보다 적은 이유는 무엇인가요?**
**단계**는 완료된 메시지만 셉니다. 실패했거나 아직 진행 중인 턴은 대화 기록에는 보이지만 세지 않습니다.

**사용자의 세션은 어떻게 삭제하나요?**
**구성 > 데이터 및 개인정보**에서 삭제합니다. [데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요.
