title: "설정 개요"
description: "Moss가 각 설정을 앱 코드와 대시보드 중 어디에서 읽는지, 두 곳에 모두 있으면 어느 쪽이 우선하는지"
---

Moss는 설정을 두 곳에서 읽습니다. 앱 코드와 Moss 대시보드입니다. 어느 쪽 값이 적용되는지는 설정마다, 그리고 Moss를 설치한 방식에 따라 다릅니다.

- **npm 패키지** (`AgentProvider`): 위젯 동작은 대부분 앱 코드에서 넘긴 `config`를 따릅니다. 대시보드는 채팅 세션과 함께 전달되는 값을 제공합니다. 테마와 브랜딩, 추천 콘텐츠, 비전, 몇 가지 세션 옵션, 그리고 서버가 결정하는 모든 것입니다.
- **CDN 스크립트**: 스크립트가 로드되면서 애플리케이션의 대시보드 설정을 읽고, 그 위에 `window.mossSettings`를 적용합니다. `window.mossSettings`에 있는 키가 우선합니다. 단, `applicationId`는 스크립트 URL에 넣습니다. 스크립트 URL의 `userId`와 스크립트 태그의 `data-api-base` 속성도 `window.mossSettings`보다 우선합니다.

테마와 브랜딩은 두 방식 모두에서 예외입니다. 대시보드에 저장한 값이 앱 코드의 같은 키보다 우선합니다.

## 각 설정을 읽어 오는 위치

| 설정 | 대시보드 위치 | npm 패키지 | CDN 스크립트 |
|------|---------------|------------|--------------|
| **테마와 브랜딩**: 색상, 제목 크기, 패널 그림자, 헤더, 입력창, 푸터 링크 | **구성 > 외관** | 앱 코드의 `appearance`를 적용한 뒤 그 위에 대시보드 값을 적용합니다. 대시보드에 값이 있는 키는 **대시보드가 우선합니다**. | 동일합니다. |
| **그 밖의 외관**: 글꼴, 간격, 하이라이트 색상, 가이드와 피드백 옵션 | 없음 | 앱 코드의 `appearance` | `window.mossSettings.appearance` |
| **추천 질문과 추천 글** (초기 화면) | **콘텐츠 > 추천 콘텐츠** | 앱 코드에 `appearance.zeroState`를 설정했다면 그 값을 통째로 씁니다. 없으면 대시보드 값을 씁니다. | 대시보드 값을 씁니다. 단, `window.mossSettings.appearance`에 `zeroState`가 있으면 그 값을 씁니다. |
| **예외 상태** | **콘텐츠 > 추천 콘텐츠** | 앱 코드의 `appearance.fallbackStates`만 씁니다. **대시보드 값은 적용되지 않습니다.** | 대시보드 값을 씁니다. 단, `window.mossSettings.appearance`를 설정하면 그 객체가 대시보드 값을 대체합니다. |
| **위젯 언어** | **구성 > 일반 > 언어** | 앱 코드의 `language`. 설정하지 않으면 사용자가 이전에 고른 언어, 페이지의 `<html lang>`, 브라우저에서 언어를 감지합니다. **대시보드 값은 위젯에 적용되지 않습니다.** | 대시보드 값을 쓰며, `window.mossSettings.language`가 우선합니다. |
| **세션 시간 제한과 알림** | **구성 > 동작 > 세션 동작** | 앱 코드의 `sessionConfig`. **대시보드 값은 적용되지 않습니다.** | 대시보드 값을 씁니다. `window.mossSettings.sessionConfig` 객체를 설정하면 그 객체가 대시보드 값을 통째로 대체합니다. |
| **비활성 후 사용자가 돌아오면** | **구성 > 동작 > 세션 동작** | 앱 코드에 `sessionConfig.onReturnAfterInactivity`를 설정하면 그 값, 없으면 대시보드 설정, 그것도 없으면 `'ask'`입니다. | 대시보드 값을 쓰며, `window.mossSettings.sessionConfig.onReturnAfterInactivity`가 우선합니다. `sessionConfig` 객체에서 이 필드를 빼면 대시보드 설정을 그대로 따릅니다. |
| **최근 대화** (0.17.0부터) | **구성 > 동작 > 세션 동작** | 대시보드에서 켭니다. 앱 코드의 `appearance.chrome.startScreen.recentChats`로 목록을 숨기거나 표시 개수를 제한할 수 있습니다. | 동일합니다. |
| **비전** (모델에 보내는 스크린샷) | **구성 > 동작 > 주요 기능 > 비전 사용** | 대시보드 값이 세션과 함께 전달되며, 새 애플리케이션에서는 기본으로 꺼져 있습니다. 앱 코드에서 `useVision`을 설정하면 켜든 끄든 그 값이 우선합니다. | 동일하며, `window.mossSettings.useVision`이 우선합니다. |
| **세션 리플레이 녹화** | **구성 > 동작 > 주요 기능 > 세션 리플레이 활성화** | 둘 다 필요합니다. 앱 코드의 `enableSessionRecording: true`와 켜진 대시보드 스위치입니다. | 대시보드 스위치를 따릅니다. 브라우저에서는 `window.mossSettings.enableSessionRecording`이 우선합니다. |
| **LLM용 화면 기록** | **구성 > 동작 > 주요 기능 > LLM용 화면 기록 활성화** | 앱 코드의 `enableScreenHistoryRecording`. **대시보드 값은 적용되지 않습니다.** | 대시보드 값을 쓰며, `window.mossSettings`가 우선합니다. |
| **페이지를 얼마나 보낼지** (`pageContext`) | **구성 > 동작 > 주요 기능 > 화면 가이드** | 앱 코드의 `pageContext`, 기본값 `'full'`. **화면 가이드**를 꺼도 npm 패키지가 보내는 내용은 줄지 않습니다. | **화면 가이드**가 켜져 있으면 `'full'`, 꺼져 있으면 `'metadata'`(URL과 제목, 화면 기록이 켜져 있으면 사용자 동작 타임라인까지)입니다. `window.mossSettings.pageContext`가 우선합니다. |
| **로그 레벨, DOM 대상 선택자** | **구성 > 설치 > 고급 설정** | 앱 코드의 `logLevel`, `observeTargetSelector`. **대시보드 값은 적용되지 않습니다.** | 대시보드 값을 쓰며, `window.mossSettings`가 우선합니다. |
| **DOM 안정성** | **구성 > 설치 > 고급 설정 > DOM 안정성** | 앱 코드의 `stability` | `window.mossSettings.stability` |
| **디버그 모드** | 없음 | 앱 코드의 `debugMode` | `window.mossSettings.debugMode` |
| **답변이 링크할 수 있는 호스트** (0.17.0부터) | **구성 > 보안 > 허용 도메인**, 그리고 지식 베이스의 호스트 | 두 목록을 합칩니다. 애플리케이션의 목록과 앱 코드의 `replyLinks.allowedHosts`입니다. | 동일합니다. |
| **콜백**: `getJwt`, `onEvent`, `onError`, `onSupportTicket`, `getBridgeCode` | 없음 | 앱 코드의 설정 | `window.mossSettings` |

표에 대한 참고 사항:

- **대시보드에서 설정한 언어**는 설치 방식과 관계없이 Moss가 답변하는 언어도 정합니다. npm 패키지에서는 위젯의 버튼과 레이블 언어는 바뀌지 않으니, 앱 코드에서 `language`를 설정하세요.
- **세션 리플레이:** npm 패키지의 `enableSessionRecording` 기본값은 0.16.x와 같이 `false`입니다. 0.17.0에서 바뀐 것은 애플리케이션 설정입니다. **세션 리플레이 활성화**가 꺼져 있으면 페이지가 무엇을 요청하든 서버가 녹화를 거부하고, 이 스위치를 한 번도 저장하지 않은 애플리케이션은 이제 꺼진 것으로 봅니다. 0.16.x에서는 켜진 것으로 보았기 때문에 CDN 스크립트가 기본으로 녹화했지만, 이제는 관리자가 스위치를 켜기 전까지 녹화하지 않습니다. [페이지 데이터와 개인정보 보호 설정](/ko/sdk/page-data#세션-녹화)을 참고하세요.
- **비전은 양쪽 방향으로 덮어씁니다.** `useVision: true`는 **비전 사용**이 꺼져 있어도 스크린샷을 보내고, `useVision: false`는 켜져 있어도 보내지 않습니다. 비전 스크린샷은 사용자가 허용한 화면 공유의 한 프레임이며, 마스킹이 적용되지 않습니다. [비전 스크린샷](/ko/sdk/page-data#비전-스크린샷)을 참고하세요.
- **고급 설정**의 **스크린샷**과 앱 코드의 `screenshotMode`는 0.17.0에서 채팅용 스크린샷에 아무 영향을 주지 않습니다.
- **대시보드의 DOM 안정성:** 0.17.0 SDK는 **스마트 대기 (디바운스)** 값과 **고정 지연** 값을 읽지 않습니다. 대기 시간은 앱 코드의 `stability`로 조정하세요. [고급 설정](/ko/sdk/advanced#안정성-튜닝)을 참고하세요.
- **`window.mossSettings`는 얕게 병합됩니다.** 여기에 설정한 객체는 같은 키의 대시보드 객체를 통째로 대체합니다. `sessionConfig`에서는 빠뜨린 시간 초과, 최대 유지 시간, 알림 필드가 기본값으로 돌아가므로, 하나를 설정한다면 세 필드를 모두 설정하세요. `onReturnAfterInactivity`는 빠뜨려도 대시보드 설정을 따릅니다. `appearance`에서는 대시보드의 예외 상태가 더 이상 적용되지 않지만, 테마와 브랜딩, 추천 콘텐츠는 세션마다 대시보드에서 계속 전달됩니다.
- **디버그 모드는 어떤 설치 방식에서도 대시보드 값을 쓰지 않습니다.**
- **대시보드 값이 전달되는 시점.** npm 패키지에서는 대시보드 값이 채팅 세션과 함께 전달됩니다. 페이지에서 채팅을 처음 열 때나, 이어 갈 세션이 있는 페이지가 로드될 때입니다. 변경한 값은 사용자가 다음에 페이지를 로드하거나 새 채팅을 시작할 때 반영됩니다. CDN 스크립트는 로드되면서 대시보드 값을 읽습니다.

영역별 자세한 내용은 다음 페이지에 있습니다.

- 외관, 초기 화면, 예외 상태: [외관](/ko/sdk/appearance#값을-가져오는-곳)
- 세션 제한: [세션](/ko/sdk/api/session#각-설정을-읽어-오는-위치)
- 비전, 녹화, 화면 기록, `pageContext`: [페이지 데이터와 개인정보 보호 설정](/ko/sdk/page-data)

## 예: 두 곳에 모두 설정한 경우

대시보드에서 **언어**를 영어로 설정한 애플리케이션에서, 페이지가 `language: 'ko'`를 넘기는 경우입니다.

```tsx
<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  language: 'ko',
}}>
  <AssistantButton />
</AgentProvider>
```

위젯의 버튼과 레이블은 앱 코드에 따라 한국어로 나옵니다. Moss의 답변은 대시보드에 따라 영어로 나옵니다.

이번에는 관리자가 **구성 > 외관 > 브랜딩**에서 헤더 제목을 "Support"로 저장했고, 페이지는 `appearance: { chrome: { title: 'Help', header: {} } }`를 넘기는 경우입니다. 제목은 `chrome.header`가 설정되어 있을 때만 나타나며, 이 값은 앱 코드의 `appearance`에서 오거나 대시보드에 저장된 헤더 옵션에서 옵니다. 헤더에는 "Support"가 나옵니다. 테마와 브랜딩은 대시보드가 우선하기 때문입니다. 대시보드에 제목만 저장했다면 `chrome.header`를 설정하지 않은 페이지에는 제목이 나타나지 않습니다. 관리자가 **상태 점 표시**를 켰거나 **새 대화 아이콘**도 골랐다면 나타납니다.

## 대시보드에만 있는 설정

다음 설정은 모든 설치 방식에 적용되며, SDK 옵션이 없습니다.

- **구성 > 동작**의 **AI 어시스턴트 프롬프트**와 **모델**
- **화면 가이드**(기본으로 켜짐)는 Moss가 요소를 하이라이트할지 결정하고, **계획 기능 활성화**(기본으로 꺼짐)는 Moss가 가이드를 제안하는 데 함께 필요합니다. 둘 다 **구성 > 동작**에 있습니다. CDN 스크립트에서는 **화면 가이드**가 `pageContext`도 정합니다. [가이드와 페이지 이동](/ko/sdk/guides-and-navigation#가이드가-진행되는-방식)을 참고하세요.
- **구성 > 보안**의 **허용 도메인**과 JWT 클레임 검사
- 지식 베이스, 프로시저, 연동
- **구성 > 데이터 및 개인정보**의 데이터 보존

각 필드는 [대시보드 설정](/ko/configurations/dashboard-settings)을 참고하세요.

## 자주 묻는 질문

**대시보드에서 설정을 바꿨는데 React 앱에는 아무 변화가 없습니다.**
npm 패키지에서는 위젯 언어, 세션 시간 제한, 로그 레벨, 화면 기록, 예외 상태를 앱 코드에서 읽습니다. `AgentProvider`에 넘기는 config에 설정하세요. 위의 표를 참고하세요.

**앱 코드에서 색상을 설정했는데 위젯에는 다른 색상이 나옵니다.**
테마와 브랜딩 키는 **구성 > 외관**에 저장한 값이 앱 코드보다 우선합니다. 앱 코드의 값을 쓰려면 대시보드에서 해당 필드를 비우세요.

**대시보드에서 추천 질문을 수정했는데 위젯에는 예전 질문이 나옵니다.**
앱 코드에서 `appearance.zeroState`를 설정했기 때문입니다. 이 값은 대시보드 콘텐츠를 통째로 대체합니다. 대시보드 값을 쓰려면 앱 코드에서 이 설정을 지우세요.
