이 페이지는 0.17.0 기준으로 대시보드 **구성** 그룹의 모든 설정을 사이드바 순서대로 설명합니다. 이 페이지들은 관리자만 열 수 있습니다. [역할](/ko/dashboard/overview#역할)을 참고하세요.

<Warning>
    대시보드 설정이 모두 앱에 적용되는 것은 아니며, 일부 대시보드 설정은 코드로 재정의할 수 없습니다. 어느 쪽인지는 Moss를 설치한 방식에 따라 다릅니다.
</Warning>

## 앱에 적용되는 설정

Moss의 설치 방식은 두 가지입니다.

- **npm 패키지**: 앱 코드가 `@viamoss/moss-sdk`에서 `AgentProvider`를 가져옵니다. **구성 > 설치**의 **Self-hosted (npm)** 탭이 이 방식입니다.
- **CDN 스크립트**: 페이지가 `<script>` 태그로 Moss 스크립트를 불러오고 `window.mossSettings`를 설정합니다. **JavaScript** 탭과 **Next.js (App Router)** 탭이 이 방식입니다.

| 설정 | npm 패키지 | CDN 스크립트 |
|------|------------|--------------|
| **모델**, **AI 어시스턴트 프롬프트**, **계획 기능 활성화**, **DOM 컨텍스트 압축**, **화면 가이드**, **언어**(답변 언어), **백엔드 개인정보 필터링**, **허용 도메인**, JWT 설정 | 서버에서 적용됩니다. 코드로 재정의할 수 없습니다. | 서버에서 적용됩니다. 코드로 재정의할 수 없습니다. |
| **브랜딩**, **테마** | 적용됩니다. 필드별로 대시보드 값이 코드의 값을 대체합니다. | 동일합니다. |
| **비전 사용**, **초기 화면**(추천 콘텐츠), **비활성 후 사용자가 돌아오면** | 적용됩니다. 단, 코드에서 `useVision`(켜기와 끄기 모두 코드 값이 우선), `appearance.zeroState`, `sessionConfig.onReturnAfterInactivity`를 설정하면 그 값을 따릅니다. | 동일하며, 해당 키는 `window.mossSettings`에 설정합니다. |
| **Interactive Element Whitelist**, **사용자가 이전 대화를 다시 열 수 있도록 허용** | 적용됩니다. | 적용됩니다. |
| **세션 리플레이 활성화** | 서버에서 적용됩니다. 이 스위치가 꺼져 있으면 Moss는 모든 설치 방식에서 오는 녹화를 거부합니다. 녹화하려면 앱 설정에 `enableSessionRecording: true`도 있어야 합니다. | 적용됩니다. `window.mossSettings.enableSessionRecording: false`로 녹화를 끌 수 있지만, 스위치가 꺼져 있을 때 `true`로 켤 수는 없습니다. |
| **시간 초과 (분)**, **최대 유지 시간 (시간)**, **알림**, **LLM용 화면 기록 활성화**, **고급 설정**, **예외 상태**(추천 콘텐츠), **언어**(위젯 자체의 텍스트) | **적용되지 않습니다.** `AgentProvider` 설정에서 해당 옵션을 지정하세요. | 적용됩니다. 단, `window.mossSettings`에 같은 키가 있으면 그 값을 따릅니다. **예외 상태**의 경우 그 키는 `appearance`입니다. 거기에 `appearance` 객체가 있으면 색상만 지정한 객체라도 대시보드의 예외 상태를 대체합니다. |

단, **고급 설정**의 **DOM 안정성**과 **스크린샷**은 0.17.0에서 두 설치 방식 모두 아무 효과가 없습니다. [고급 설정](#고급-설정)을 참고하세요.

CDN 스크립트에서는 `window.mossSettings`의 키가 대시보드 값을 대체하고, 객체는 대시보드의 객체 전체를 대체합니다. 예를 들어 거기에 `sessionConfig`가 있으면 대시보드의 **시간 초과 (분)**, **최대 유지 시간 (시간)**, **알림** 설정을 통째로 대체합니다. 빠뜨린 필드는 대시보드 값이 아니라 기본값으로 돌아갑니다. **비활성 후 사용자가 돌아오면**은 거기에 `onReturnAfterInactivity`를 설정하지 않는 한 대시보드 설정을 그대로 따릅니다.

각 옵션을 코드에서 설정하는 방법은 [SDK 옵션](/ko/configurations/sdk-options)을 참고하세요.

## 일반

**구성 > 일반**에는 **애플리케이션 정보**, **애플리케이션 내보내기**, **주의 구역** 카드가 있습니다.

### 애플리케이션 정보

| 필드 | 기본값 | 하는 일 |
|------|--------|---------|
| **애플리케이션 이름** | 애플리케이션을 만들 때 정함 | 읽기 전용입니다. |
| **애플리케이션 ID** | 생성 시 부여됨 | 읽기 전용입니다. 앱 코드에서는 `applicationId`로, CDN 스크립트 URL에서는 `?applicationId=`로 전달하세요. |
| **생성일** | | 읽기 전용입니다. |
| **임베딩 모델** | 생성 시 선택 | 읽기 전용입니다. 지식 베이스를 색인하는 모델입니다. 애플리케이션을 만들 때 고정되므로, 바꾸려면 새 애플리케이션을 만들어야 합니다. |
| **언어** | **자동** | **자동**, **영어**, **한국어** 중에서 고르며, 고르는 즉시 저장됩니다. 아래를 참고하세요. |

**언어**는 두 가지에 영향을 줍니다.

- **답변 언어(모든 설치 방식).** **영어**나 **한국어**를 고르면 사용자가 어떤 언어로 쓰든 Moss는 항상 그 언어로 답합니다. **자동**이면 Moss는 사용자의 언어로 답합니다. **화면 가이드**가 켜져 있으면 페이지의 언어로 시작하고, 사용자가 다른 언어로 온전한 메시지를 쓰면 그 언어로 바꿉니다.
- **위젯 자체의 텍스트(CDN 스크립트만).** 위젯의 버튼과 라벨이 선택한 언어로 표시되고, 위젯의 언어 선택기는 숨겨집니다. **자동**이면 위젯이 언어를 감지하고 언어 선택기를 보여 줍니다. npm 패키지에서는 대신 앱 설정에 `language: 'en' | 'ko'`를 지정하세요.

### 애플리케이션 내보내기

**번들 내보내기**는 이 애플리케이션의 설정을 파일로 내려받습니다. 이 파일은 다른 환경이나 리전으로 가져올 수 있습니다. 자격 증명은 절대 포함되지 않습니다. [내보내기와 가져오기](/ko/dashboard/export-import)를 참고하세요.

### 주의 구역

대시보드에서는 애플리케이션을 삭제할 수 없습니다.

## 설치

### SDK 설치

애플리케이션 ID가 채워진 설치 코드를 세 개의 탭으로 보여 주므로 그대로 복사해 쓸 수 있습니다.

- **JavaScript**: CDN 스크립트입니다.
- **Next.js (App Router)**: `next/script`로 불러오는 CDN 스크립트입니다.
- **Self-hosted (npm)**: npm 패키지입니다. Moss를 직접 호스팅하는지와 관계없이, npm에서 패키지를 설치하는 모든 앱을 위한 탭입니다.

코드 아래에는 다음이 표시됩니다.

- 상태 줄: **SDK 설치됨 — 세션 N건 기록됨** 또는 **애플리케이션의 첫 세션을 기다리는 중…**
- **인증**: 애플리케이션에 활성 JWT 서명 키가 있는지 알려 주며, **보안에서 관리** 링크가 있습니다. SDK가 연결하려면 키가 하나 있어야 합니다.

스니펫의 `/api/moss-jwt`는 백엔드에 직접 만드는 예시 엔드포인트입니다. 현재 사용자를 인증하고, 서명된 Moss 토큰을 `token` 필드에 담아 반환해야 합니다. [인증](/ko/sdk/authentication)을 참고하세요.

### 고급 설정

이 설정은 **CDN 스크립트에만** 적용됩니다. npm 패키지에서는 마지막 열의 옵션을 앱 설정에 지정하세요. **고급 설정 저장**으로 저장합니다.

| 설정 | 기본값 | 하는 일 | npm 옵션 |
|------|--------|---------|----------|
| **스크린샷** | **전체 페이지** | **전체 페이지** 또는 **뷰포트**. 채팅 턴의 스크린샷은 공유된 브라우저 탭의 프레임이므로, 0.17.0에서는 이 선택이 스크린샷을 바꾸지 않습니다. | `screenshotMode: 'fullpage' \| 'viewport'` |
| **로그 레벨** | **정보** | **에러**, **경고**, **정보**, **디버그**: 위젯이 브라우저 콘솔에 남기는 로그의 양입니다. | `logLevel` (`LogLevel` enum) |
| **DOM 대상 선택자** | `body` | Moss가 페이지 변화를 감시하는 요소의 CSS 선택자입니다. | `observeTargetSelector` |
| **DOM 안정성** | **스마트 대기 (디바운스)**: **초기 지연** 300 ms, **최대 대기 시간** 2000 ms | 0.17.0에서는 적용되지 않습니다. 아래 참고를 보세요. | `stability` |

<Note>
    0.17.0의 위젯은 **DOM 안정성** 값을 읽지 않으므로, 여기서 무엇을 고르든 효과가 없습니다. 페이지가 안정될 때까지 Moss가 기다리는 시간을 조정하려면 `window.mossSettings`나 `AgentProvider` 설정에 `stability`를 지정하세요. [SDK 옵션](/ko/configurations/sdk-options)을 참고하세요.
</Note>

0.17.0부터는 **디버그** 스위치가 없습니다. 디버그 모드는 대시보드에서 가져오지 않습니다. 개발하는 동안 앱 코드에서 켜고, 프로덕션에서는 절대 켜지 마세요.

## 외관

**구성 > 외관**에서 채팅 위젯의 모양을 정합니다. 두 카드 모두 모든 설치 방식에 적용됩니다. 값을 입력한 필드는 코드나 SDK 프리셋이 정한 값을 대체하고, 비워 둔 필드는 그 값을 그대로 둡니다. 코드 쪽 설정은 외관 레퍼런스의 [값을 가져오는 곳](/ko/sdk/appearance#값을-가져오는-곳)을 참고하세요.

**브랜딩 저장**으로 저장합니다.

| 구역 | 필드 | 하는 일 |
|------|------|---------|
| 헤더 | **헤더 제목** | 채팅 패널 맨 위의 제목입니다. |
| 헤더 | **상태 점 표시** | 어시스턴트가 온라인임을 알리는 작은 원을 제목 옆에 표시합니다. |
| 헤더 | **새 대화 아이콘** | **SDK 프리셋 기본값**, **플러스**, **새로고침**, **작성** 중에서 고릅니다. |
| 입력창 | **배경 색상 (HEX)** | 채팅 입력창의 강조 색상입니다. |
| 푸터 | **푸터 표시** | 기본값은 꺼짐입니다. 입력창 아래에 도움말 센터 링크와 티켓 열기 링크가 있는 푸터를 표시합니다. 끄면 두 링크가 모두 지워집니다. |

### 테마

**테마 저장**으로 저장합니다.

| 구역 | 필드 | 하는 일 |
|------|------|---------|
| 패널 | **테두리 색상 (hex)** | 위젯의 모든 가는 선에 쓰이는 한 가지 색상입니다. 구분선, 카드 외곽선, 입력창 테두리에 적용됩니다. |
| 패널 | **패널 그림자** | **SDK 프리셋 기본값**, **은은하게**, **강하게** 중에서 고릅니다. |

| 액션 버튼 | **버튼 색상 (hex)**, **호버 색상 (hex)** | 가이드 버튼과 다음 단계 버튼의 기본 상태와 마우스를 올린 상태에 적용됩니다. |
| 텍스트와 아이콘 | **기본 텍스트 (hex)**, **보조 텍스트 (hex)**, **3차 텍스트와 아이콘 (hex)** | 텍스트 색상입니다. 헤더와 카드 아이콘도 이 색상을 따릅니다. |

## 동작

**구성 > 동작**에는 최대 여섯 개의 카드가 다음 순서로 있습니다.

### 모델

0.17.0부터 제공됩니다. 배포 환경이 이 애플리케이션에 모델 선택지를 제공하거나, 이미 선택된 모델이 있을 때만 카드가 나타납니다.

- 목록에는 선택할 수 있는 모델이 나옵니다. **기본 모델**에는 "다른 모델을 고르지 않은 모든 애플리케이션이 사용합니다."라는 설명이 붙어 있습니다.
- 다른 모델을 고르면 확인을 요청하고, 전환 전후에 이 애플리케이션의 데이터를 누가 처리하는지 알려 줍니다. 변경은 다음 메시지부터 적용됩니다.
- 선택한 모델을 사용할 수 없으면 카드에 대신 답하고 있는 모델이 표시됩니다. 보통은 서버 기본값입니다. **대체 없음**으로 표시된 모델은 다른 모델로 대체되지 않으므로, 다시 사용할 수 있을 때까지 아무것도 답하지 않습니다.
- 이 선택은 이 애플리케이션의 코파일럿, 모니터, 카드에 나열된 다른 기능에도 적용됩니다. 검색, 임베딩, 지식 베이스 이미지 설명, 스크린샷 분석기는 각자의 모델을 그대로 씁니다.

관리자만 모델을 바꿀 수 있습니다. 서버에서 모든 설치 방식에 적용됩니다. 모델 변경과 채팅 답변의 대체 기록은 [감사 로그](#감사-로그)에 남습니다. 다른 기능이 기본 모델로 대체될 때는 아무 기록도 남지 않습니다. 내보내기 번들에는 모델 선택이 포함되지 않습니다.

### 주요 기능

스위치를 바꾸는 즉시 저장됩니다. 0.17.0부터 **세션 리플레이 활성화**와 **LLM용 화면 기록 활성화**에는 서버가 허용하는지(**서버 허용** 또는 **서버 OFF**)와 값의 출처(**앱별 설정** 또는 **기본값 (OFF)**)도 표시됩니다. 브라우저 권한과 앱 코드가 수집을 더 제한할 수 있습니다.

| 스위치 | 기본값 | 하는 일 | 적용 범위 |
|--------|--------|---------|-----------|
| **비전 사용** | 꺼짐 | 켜면 페이지 컨텍스트가 전체(full)이고 사용자가 현재 탭에 대한 브라우저의 화면 캡처 요청을 허용한 경우, Moss가 채팅 턴에서 스크린샷을 찍을 수 있습니다. 사용자가 거부하면 스크린샷을 찍지 않습니다. | 모든 설치 방식. SDK 설정에서 `useVision`을 지정한 앱은 그 값이 이 스위치보다 우선합니다. `true`는 스위치가 꺼져 있어도 스크린샷을 켜고, `false`는 끕니다. |
| **세션 리플레이 활성화** | 꺼짐 | 페이지 구조와 이벤트를 기록하고, 대시보드에서 다시 볼 수 있도록 업로드합니다. 0.17.0부터는 이 스위치가 꺼져 있으면 서버가 모든 설치 방식에서 오는 녹화를 거부합니다. 이 스위치를 한 번도 저장하지 않은 애플리케이션은 업그레이드 후 관리자가 켤 때까지 녹화가 멈춥니다. | 모든 설치 방식(서버). npm: `enableSessionRecording: true`도 설정하세요. [세션 녹화](/ko/sdk/page-data#세션-녹화)를 참고하세요. |
| **LLM용 화면 기록 활성화** | 꺼짐 | 사용자의 클릭, 입력 이벤트, 페이지 이동, 페이지 변화를 모델이 보는 정보에 추가합니다. 서버는 이 스위치를 강제하지 않습니다. `enableScreenHistoryRecording: true`를 설정한 npm 앱은 스위치에 **서버 OFF**가 표시되어도 화면 기록을 보냅니다. | CDN 스크립트. npm: `enableScreenHistoryRecording`. |
| **DOM 컨텍스트 압축** | 꺼짐 | 페이지 텍스트가 모델에 가기 전에 불필요한 요소(CSS 클래스, SVG 경로, 빈 태그)를 걷어 내 토큰을 줄입니다. | 모든 설치 방식(서버). |
| **화면 가이드** | 켜짐 | Moss가 요소를 강조하고 페이지에서 사용자를 안내할 수 있게 합니다. 끄면 Moss는 채팅만 하는 어시스턴트가 됩니다. CDN 스크립트에서는 이때 위젯이 페이지 URL과 제목만 보내고, 페이지 텍스트와 스크린샷은 보내지 않습니다. npm 패키지에서는 앱 코드의 `pageContext`가 위젯이 보내는 내용을 정합니다. | 모든 설치 방식(서버). |

<Warning>
    스크린샷은 공유된 브라우저 탭의 프레임이며, 마스킹이 적용되지 않습니다. `data-moss-redact`와 직접 지정한 마스킹 선택자도 스크린샷에서는 아무것도 가리지 않습니다. 관련 제어 방법은 [페이지 데이터와 개인정보 제어](/ko/sdk/page-data)를 참고하세요.
</Warning>

**구성 > 데이터 및 개인정보**의 **비전 스크린샷** 상태는 이 애플리케이션의 설정이 스크린샷을 허용하는지, 즉 **비전 사용**과 **화면 가이드**가 모두 켜져 있는지를 보여 줍니다. 앱 코드에서 지정한 `useVision` 값은 반영하지 않습니다.

다른 스위치가 수집하는 내용과 앱 코드에서 쓸 수 있는 제어 방법은 [페이지 데이터와 개인정보 제어](/ko/sdk/page-data)에서 다룹니다.

### AI 어시스턴트 프롬프트

이 애플리케이션에서 AI의 시스템 프롬프트에 추가되는 텍스트입니다. 앱에만 있는 탐색 방식, UI 맥락, 예외 상황, 도메인 용어 등을 적습니다. 최대 30,000자입니다. **프롬프트 저장**으로 저장합니다.

프롬프트는 서버에서 모든 설치 방식에 적용됩니다. SDK 코드에서는 설정할 수 없습니다.

```
When users ask about 'dashboard', always guide them to the Analytics
section first, not the Overview. The main navigation menu collapses
on mobile devices and requires clicking the hamburger icon in the
top-left corner.
```

### 계획 진행 추적

**계획 기능 활성화**는 기본값이 꺼짐이며, 바꾸는 즉시 저장됩니다. 켜면 여러 단계가 필요한 작업에 도움을 요청했을 때 단계별 진행 상황을 추적하는 안내 계획이 만들어집니다. 서버에서 모든 설치 방식에 적용됩니다.

### 세션 동작

위젯에서 채팅이 얼마나 유지되는지, 사용자가 오래된 채팅으로 돌아오면 어떻게 되는지를 정합니다. **세션 설정 저장**으로 저장합니다. 제한이 동작하는 방식은 [세션](/ko/sdk/api/session)을 참고하세요.

| 필드 | 기본값 | 하는 일 | 적용 범위 |
|------|--------|---------|-----------|
| **시간 초과 (분)** | 30 | 활동이 없는 채팅을 시간 초과로 보기까지의 시간(분)입니다. | CDN 스크립트. npm: `sessionConfig.inactivityTimeout`. |
| **최대 유지 시간 (시간)** | 2 | 채팅이 시작된 뒤 활동과 관계없이 만료로 보기까지의 시간입니다. | CDN 스크립트. npm: `sessionConfig.maxSessionAge`. |
| **비활성 후 사용자가 돌아오면** | **이어서 할지 새로 시작할지 묻기** | **이어서 할지 새로 시작할지 묻기**: 시간 초과 후에는 이어서 할지 새 채팅을 시작할지 고르는 카드가 나타나고, 최대 유지 시간을 넘은 뒤에는 새 채팅이 시작되며 카드가 이를 알립니다. **새 채팅 시작**은 카드 없이 새 채팅을 엽니다. | 모든 설치 방식. npm에서는 앱 코드의 `sessionConfig.onReturnAfterInactivity`가 우선합니다. |
| **사용자가 이전 대화를 다시 열 수 있도록 허용** | 꺼짐 | 0.17.0부터 제공됩니다. 사용자는 최근 30일 동안의 본인 대화를 읽기 전용으로 열 수 있으며, 보존 기간이 지난 대화는 열 수 없습니다. Moss는 이 대화를 답변에 사용하지 않습니다. | 모든 설치 방식. |
| **알림** | 켜짐 | Moss가 스스로 새 채팅을 시작하면 짧은 알림을 보여 줍니다. | CDN 스크립트. npm: `sessionConfig.showNotification`. |

<Warning>
    npm 패키지를 쓰는 경우 여기서 **시간 초과 (분)**, **최대 유지 시간 (시간)** 값을 바꿔도 효과가 없습니다. `AgentProvider` 설정에서 지정하세요.
</Warning>

**사용자가 이전 대화를 다시 열 수 있도록 허용**은 사용자마다 본인 계정으로 로그인하는 경우에만 켜세요. 여러 사람이 같은 사용자 ID를 쓰면 서로의 대화가 보입니다.

이 제한은 사용자가 채팅에서 보는 내용만 바꿀 뿐, 아무것도 삭제하지 않습니다. 대화를 얼마나 오래 저장할지는 **구성 > 데이터 및 개인정보**에서 정합니다. [데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요.

### Interactive Element Whitelist

마우스를 올려야만 나타나는 컨트롤처럼, Moss가 페이지만 보고는 상호작용 가능한지 알 수 없는 요소를 상호작용 요소로 표시하는 규칙입니다. 맨 위의 **Enabled** 스위치로 모든 규칙을 한꺼번에 켜고 끕니다. 기본값은 켜짐입니다.

**Add Rule**을 눌러 규칙을 추가합니다. 각 규칙에는 **Description**, **Pattern Type**(**CSS Selector (Recommended)**, **XPath**, **Structural Pattern** 중 하나), **Pattern**, **Priority**(기본값 100, 높은 값부터 먼저 확인), 규칙별 **Enabled** 스위치가 있습니다. 규칙은 채팅이 시작될 때 모든 설치 방식에 전달됩니다.

## 보안

**구성 > 보안**에는 카드가 다섯 개 있습니다.

### 도메인 접근 제어

**허용 도메인**은 SDK가 실행될 수 있는 사이트 목록입니다. 항목마다 **추가**를 누른 다음 **보안 설정 저장**을 누르세요. 이 버튼은 이 카드와 **JWT 클레임 강제** 카드를 함께 저장합니다.

- `app.example.com`은 그 호스트에만 일치합니다.
- `*.example.com`은 깊이와 관계없이 모든 하위 도메인에 일치하지만, `example.com` 자체에는 일치하지 않습니다. 둘 다 필요하면 둘 다 추가하세요.
- `localhost:3000`처럼 포트가 있는 항목은 그 포트에만 일치합니다. 포트가 없는 항목은 모든 포트에 일치하므로 `:443`은 붙이지 마세요.
- Moss는 요청의 `Origin` 헤더에서 페이지를 읽고, 없으면 `Referer`에서 읽습니다. 목록에 항목이 있는 동안에는 샌드박스 프레임이나 `file://` 페이지에서 온 요청을 거부합니다.
- 목록에 없는 페이지는 `DOMAIN_NOT_ALLOWED` 코드와 함께 `403`을 받습니다.

목록이 비어 있으면 SDK는 어느 도메인에서나 실행됩니다. 단, 배포 환경이 도메인을 필수로 설정했다면 목록이 비어 있는 동안 SDK가 차단되고 요청은 `ORIGIN_REQUIRED`로 실패합니다. 자체 호스팅 설치에서는 운영자가 `SDK_REQUIRE_ORIGIN=true`로 이 설정을 켭니다. 이 설정은 `Origin`과 `Referer` 헤더가 모두 없는 요청도 거부합니다. 이 설정이 없으면 그런 요청은 목록과 대조하지 않습니다.

```
app.example.com
*.staging.example.com
localhost:3000
```

<Warning>
    목록을 저장하기 전에 스테이징과 로컬 개발 환경을 포함해 앱이 실행되는 모든 환경을 넣으세요.
</Warning>

### JWT 클레임 강제

**필수 발급자 (iss)**, **필수 대상 (aud)** 두 필드가 있습니다. 값을 설정하면 모든 SDK 토큰의 `iss` 또는 `aud` 클레임에 그 값이 있어야 합니다. 비워 둔 필드는 검사하지 않습니다.

### JWT 서명 키

백엔드가 SDK용으로 서명한 토큰을 Moss가 확인할 때 쓰는 키입니다. 별도의 SDK API 키는 없습니다.

- **키 생성**은 HMAC 시크릿을 만듭니다. 시크릿은 한 번만 표시되니 백엔드에 저장하세요.
- **공개 키 등록**은 PEM(SubjectPublicKeyInfo) 형식의 RS256 또는 ES256 공개 키를 받습니다. 서명은 고객의 개인 키로 하며, 개인 키를 붙여 넣으면 Moss가 거부합니다.
- **폐기**를 누르면 유예 기간을 고릅니다: **즉시**, **24시간**, **72시간**. 유예 기간이 끝나면 그 키로 서명한 토큰은 더 이상 동작하지 않습니다.

각 키에는 생성 시각과 마지막 사용 시각이 표시됩니다. [인증](/ko/sdk/authentication)을 참고하세요.

### 백엔드 개인정보 필터링

0.17.0부터 제공됩니다. Moss가 요청을 저장하거나 모델로 보내기 전에 일반적인 개인정보 패턴을 `[REDACTED]`로 바꿉니다. 이미 저장된 데이터는 바뀌지 않습니다. 서버에서 모든 설치 방식에 적용됩니다. **개인정보 설정 저장**으로 저장합니다.

| 설정 | 기본값 | 하는 일 |
|------|--------|---------|
| **이 애플리케이션의 요청 필터링** | 배포 기본값. 운영자가 켜지 않았다면 꺼져 있습니다 | **배포 기본값 사용**을 누르면 배포 기본값으로 돌아갑니다. |
| **필터링 대상**: **페이지 컨텍스트** | 켜짐 | 페이지 텍스트, 화면 기록 타임라인, 페이지 제목. |
| **필터링 대상**: **상호작용 보고** | 켜짐 | 사용자가 조작한 요소의 텍스트, 레이블, 마크업. |
| **필터링 대상**: **채팅 메시지** | 꺼짐 | 사용자가 입력한 내용. 사용자가 묻는 값 자체를 지울 수 있어 기본으로 꺼져 있습니다. |
| **추가 패턴** | 꺼짐 | **IPv4 주소**, **IBAN(체크섬 검증)**, **주민등록번호**. |
| **사용자 정의 패턴** | 없음 | RE2 문법으로 최대 25개, 패턴당 최대 200자입니다. 전방·후방 탐색과 역참조는 지원하지 않습니다. 이름에는 영문 소문자, 숫자, 밑줄만 쓸 수 있습니다. |

필터링이 켜져 있으면 이메일 주소, 미국 전화번호, 결제 카드 번호, 미국 사회보장번호는 항상 필터링됩니다.

### API 로그 접근 키

외부 도구에서 이 애플리케이션의 API 로그를 읽기 위한 키입니다. `X-Traffic-API-Key` 헤더에 담아 보내세요. 읽기 전용이라 로그를 삭제하거나 기록을 켜고 끌 수 없습니다.

**키 생성**을 누르면 키가 한 번만 표시됩니다. **키 폐기**를 누르면 키가 즉시 동작을 멈춥니다. 0.16.x에서는 이 카드의 이름이 **트래픽 로그 API 키**였습니다.

## 데이터 및 개인정보

**구성 > 데이터 및 개인정보**는 Moss가 이 애플리케이션에서 수집하는 데이터를 요약하고, 데이터를 얼마나 오래 보존할지 정합니다. 0.17.0부터 다음 항목이 있습니다.

[데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요.

## 감사 로그

**구성 > 감사 로그**는 누가 시스템에 접근했고 무엇이 바뀌었는지 보여 줍니다. 설정, 키, 모델 변경, 보존 기간, 가져오기와 내보내기가 기록됩니다. 행위자, 작업, 대상 유형, 결과, 날짜로 필터링할 수 있으며, 처음에는 최근 7일이 표시됩니다. **내보내기**로 필터링한 이벤트를 JSON 또는 CSV로 내려받습니다.

[감사 로깅](/ko/security/audit-logging)을 참고하세요.

## 자주 묻는 질문

**채팅 세션의 TTL은 어디서 제한하나요?**
CDN 스크립트에서는 **구성 > 동작 > 세션 동작**의 **시간 초과 (분)**, **최대 유지 시간 (시간)** 필드에서 정합니다. npm 패키지에서는 앱 코드에 `sessionConfig.inactivityTimeout`과 `sessionConfig.maxSessionAge`를 설정하세요. 이 값은 위젯의 규칙이며 저장 기간이 아닙니다. [세션](/ko/sdk/api/session)과 [데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요.

**대시보드에서 설정을 바꿨는데 React 앱에는 아무 변화가 없습니다.**
npm 패키지는 대시보드 설정을 모두 적용하지는 않습니다. [앱에 적용되는 설정](#앱에-적용되는-설정)의 표를 확인하세요.

**0.17.0으로 업그레이드한 뒤 세션 리플레이가 멈췄습니다.**
0.17.0부터는 **세션 리플레이 활성화**가 꺼져 있으면 서버가 녹화를 거부하며, 이 스위치를 한 번도 저장하지 않은 애플리케이션에서는 꺼져 있습니다. **구성 > 동작 > 주요 기능**에서 켜세요. npm 앱은 `enableSessionRecording: true`도 필요합니다.

**코드에서 색상을 지정했는데 위젯에는 다른 색상이 보입니다.**
대시보드에 저장된 **브랜딩**과 **테마** 값은 필드별로 코드의 값을 대체합니다. 코드의 값을 쓰려면 대시보드에서 해당 필드를 비우세요.

**허용 도메인에 와일드카드를 쓸 수 있나요?**
네. `*.example.com`은 모든 하위 도메인에 일치하지만 `example.com` 자체에는 일치하지 않습니다. [도메인 접근 제어](#도메인-접근-제어)를 참고하세요.

**허용 도메인 목록이 비어 있는데 왜 SDK가 차단되나요?**
배포 환경이 도메인을 필수로 설정했기 때문입니다. SDK가 실행되는 도메인을 모두 추가하세요.

**SDK용 API 키는 어디서 찾나요?**
그런 키는 없습니다. SDK는 백엔드가 서명한 토큰으로 인증합니다. 키는 [JWT 서명 키](#jwt-서명-키)에서 관리하세요.

**이 설정을 다른 환경이나 리전으로 복사하려면 어떻게 하나요?**
번들을 내보낸 뒤 그곳에서 가져오세요. [내보내기와 가져오기](/ko/dashboard/export-import)를 참고하세요.

**애플리케이션은 어떻게 삭제하나요?**
0.17.0에서는 대시보드에서 삭제할 수 없습니다.
