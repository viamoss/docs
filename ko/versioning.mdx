# 버전 및 호환성

## 하나의 버전 번호

`@viamoss/moss-sdk`와 Moss 플랫폼(백엔드와 대시보드)은 버전 번호 하나를 함께 씁니다. SDK 0.17.0은 Moss 0.17.0의 클라이언트입니다. 0.13.0부터 이 방식을 써 왔습니다.

모든 버전에 두 부분이 다 있는 것은 아닙니다.

- **SDK만 바뀐 릴리스.** 0.16.26은 SDK만 바꿨습니다. 0.16.25 서버와 함께 동작하며, 0.16.26 서버는 없었습니다.
- **플랫폼만 바뀐 릴리스.** 0.16.24는 자체 호스팅 설치용으로만 게시되고 npm에는 게시되지 않았으므로, SDK는 0.16.23에서 0.16.25로 넘어갔습니다.

릴리스마다 어떤 부분이 있는지는 [변경 이력](/ko/changelog)에 나와 있습니다.

## 함께 쓸 수 있는 조합

**이전 SDK와 최신 플랫폼**은 계속 동작합니다. SDK의 모든 요청에는 SDK 버전이 실리고, 백엔드는 이전 SDK에 그 버전이 기대하는 방식으로 응답합니다. 이후에 추가된 기능과 수정 사항은 이전 SDK에 없습니다.

**최신 SDK와 이전 플랫폼**에서는 대부분의 기능이 동작하지만, 최신 백엔드가 필요한 기능은 동작하지 않습니다. 백엔드를 먼저 업그레이드한 뒤 SDK를 업그레이드하세요. SDK 0.17.0과 0.16.x 백엔드를 함께 쓰면 다음과 같습니다.

- **답변의 링크와 이미지.** 이전 백엔드는 허용 호스트 목록을 보내지 않으므로, 지식 베이스와 허용 도메인으로 가는 링크는 일반 텍스트로, 그 이미지는 대체 텍스트로 보입니다. 페이지 자체의 출처와 `replyLinks.allowedHosts`의 호스트만 동작합니다. [replyLinks](/ko/sdk/configuration#replylinks)를 참고하세요.
- `appearance.chrome.feedback.sessionRating: 'stars'`: 이전 백엔드가 별점 평가를 거부하므로 세션의 평가가 사라집니다.
- `appearance.chrome.feedback.askWhatWentWrong`: 이전 백엔드는 오류 없이 이유와 의견을 버립니다.
- 최근 대화 목록에는 0.17.0 백엔드가 필요합니다.
- `streamActivity`: 최신 백엔드의 스트리밍 경로가 없으면 SDK는 일반 요청으로 대신하고, 단계 로더는 고정된 행을 보여 줍니다.

페이지에서 실행 중인 SDK 버전은 기본 로그 레벨에서 브라우저 콘솔에 남는 SDK 시작 로그 `[MossSDK] v0.17.0 initialized …`에서 확인하세요.

## 이 문서가 다루는 범위

이 문서는 **최신 릴리스인 0.17.0**을 설명합니다. 0.16.25 이후에 새로 생기거나 바뀐 내용에는 "0.17.0부터"처럼 표시해 두었습니다. 이전 버전을 쓴다면 이런 표시가 없는 내용은 0.16.25에 있는 것으로 보고, 쓰는 버전 이후에 추가된 내용은 [변경 이력](/ko/changelog)에서 확인하세요.

## 최신 버전 유지

패키지 매니저로 업그레이드하세요.

```bash
npm install @viamoss/moss-sdk@latest
```

한 버전에 계속 고정하지 말고 최근 버전을 유지하세요. 수정 사항은 그 수정이 들어간 버전에만 반영됩니다. 자체 호스팅 설치에서는 SDK보다 백엔드를 먼저 업그레이드하세요. 릴리스마다 고객에게 보이는 주요 변경 사항은 [변경 이력](/ko/changelog)에 정리되어 있습니다.

<Info>
    설정 변경이나 호환성을 깨는 API 변경처럼 고객 측의 조치가 필요한 릴리스는 직접 알려 드립니다. 특정 버전이 연동에 영향을 주는지 알고 싶다면 대시보드를 통해 지원팀에 문의하세요.
</Info>
