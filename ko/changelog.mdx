# 변경 이력

Moss SDK(`@viamoss/moss-sdk`)와 Moss 대시보드에서 고객에게 드러나는 주요 변경
사항입니다. v0.13.0부터 SDK 버전은 Moss 플랫폼 버전을 따릅니다.

## 0.16.22 — 2026-11-10

### 추가

- **비활성 후 돌아올 때의 동작.** Configure > Behavior > Session Behavior에 새 항목
  "When a user returns after inactivity"(한국어 화면: "비활성 후 사용자가
  돌아오면")가 추가되었습니다. "Ask to continue or start new"("이어서 할지 새로
  시작할지 묻기", 기본값이며 이전과 같습니다)와 "Start a new chat"("새 채팅
  시작") 중에서 고를 수 있습니다. "Start a new chat"을 고르면, 비활성 시간
  초과(기본 30분)나 최대 유지 시간(기본 2시간)을 지난 세션으로 사용자가 돌아올 때
  카드나 평가 요청 없이 새 채팅이 열립니다. Moss가 시간 초과된 세션으로 로드될
  때, 그리고 열어 둔 페이지에서 사용자가 런처, `openChat()`, `data-moss-trigger`
  요소로 채팅을 다시 열 때 적용됩니다. 이전 채팅은 다시 열 수 없습니다.
  - SDK에서는 `sessionConfig.onReturnAfterInactivity`에 `'new_chat'` 또는
    `'ask'`를 지정합니다. 설정에 지정한 값이 우선합니다. 지정하지 않으면
    애플리케이션의 대시보드 설정이 적용되며, 이 값은 백엔드 0.16.22 이상이 세션
    시작 시 전달합니다. 둘 다 없으면 `'ask'`입니다. npm 패키지로 Moss를 넣은 앱은
    이 항목만 대시보드에서 가져오며, 비활성 시간 초과, 최대 유지 시간,
    `showNotification`은 설정에 지정한 값을 그대로 씁니다.
    `convertBackendConfig()`로 만든 설정은 네 항목 모두 대시보드에서 가져옵니다.
  - SDK보다 백엔드와 대시보드를 먼저 업데이트하세요. 이전 백엔드는 저장할 때 이
    설정을 오류 없이 버리고, 이전 SDK는 이 설정을 무시합니다. 이전 백엔드에서
    SDK 0.16.22는 설정에 이 항목을 지정하지 않는 한 이어서 할지 묻습니다.
  - `askMoss()`, 프로액티브 플로우, 온보딩 플로우처럼 Moss가 직접 채팅을 여는
    경우에는 확인하지 않습니다. `openChat()` 다음에 `sendMessage()`를 호출하면,
    메시지는 새 채팅이 연결된 뒤 그 채팅으로 전송됩니다. Moss는 이렇게 메시지를
    하나만 보관하며, 보내지 못하면 콘솔 경고를 남깁니다.
  - 채팅을 닫은 채 진행한 가이드 단계와, 다른 탭에서 같은 세션으로 한 활동도
    활동으로 칩니다. 시간 초과를 지나도록 멈춰 있던 가이드는 세션과 함께 끝나며,
    이 탭에서 실행된 가이드라면 이전 세션의 `sessionId`로
    `outcome: 'abandoned'`인 `Moss Plan Finished`가 보고됩니다.
- **채팅 창 옮기기.** 채팅 창을 헤더와 가장자리뿐 아니라 대화의 빈 공간과 메시지
  입력란 주변에서도 드래그할 수 있으므로, 헤더가 화면 밖으로 나간 창도 다시 끌어올
  수 있습니다. 메시지, 링크, 버튼, 카드, 가이드 바, 스크롤바에서는 드래그되지
  않으며, 드래그해도 텍스트가 선택되지 않습니다. 터치에서는 대화가 스크롤되고,
  창은 헤더, 가장자리, 메시지 입력란 주변에서 옮길 수 있습니다.

### 변경

- **워커가 자체 요청에서 사설 주소를 거부합니다.** 이미지 다운로드, 사이트맵,
  디스커버리의 페이지 샘플링, Document360 디스커버리와 스크래핑은 이제 공개
  주소에만 연결합니다. 업그레이드 전에 다음을 확인하세요.
  - **Document360, 이미지, 사이트맵 요청에는 더 이상 포워드 프록시를 사용하지
    않습니다.** 이 요청들은 직접 연결되며 `HTTP_PROXY`와 `HTTPS_PROXY`를
    무시하고, 아직 프록시를 거치도록 하는 설정은 없습니다. 워커의 외부 연결에
    프록시가 꼭 필요하다면 업그레이드 전에 연락해 주세요. Firecrawl, LLM과 임베딩
    제공자, Pinecone, 스토리지 업로드, Slack, 디스커버리 중 브라우저의 페이지
    로딩은 바뀌지 않습니다.
  - 인트라넷의 이미지와 사이트맵은 해당 호스트나 대역을 새 워커 설정
    `WORKER_FETCH_ALLOWLIST`에 넣기 전까지 동작하지 않습니다. 값은 쉼표로
    구분한 호스트와 CIDR이며(예: `wiki.corp.example.com,10.20.0.0/16`), 기본값은
    비어 있습니다.
  - `localhost`는 별도 항목이 필요합니다. 클라우드 메타데이터 주소는 어떤
    경우에도 허용할 수 없습니다. 잘못된 항목이 있으면 워커가 시작 단계에서
    멈춥니다. 오브젝트 스토리지(`S3_ENDPOINT`)는 항목이 필요 없습니다.
  - 거부된 이미지는 실패로 기록되고 원래 주소를 유지합니다. 거부된 호스트의
    디스커버리 시작 URL은 즉시 실패합니다. 이미지가 아닌 다운로드 본문은 저장하지
    않습니다.
- **Document360 API 호스트.** Document360 호스트(`*.document360.io` 또는
  `*.document360.com`, 예: `apihub.document360.io`)여야 합니다. 다른 호스트는 저장할
  때 거부되고, 이전에 저장된 호스트는 동기화할 때 다시 입력하라는 메시지와 함께
  거부됩니다. 자체 도메인의 헬프 센터는 API 호스트가 아니므로 영향이 없습니다.
- **Zendesk 서브도메인.** 전체 주소가 아닌 `acme` 같은 계정 이름만 입력해야
  합니다. 대문자도 받으며 소문자로 저장합니다.
- **CSV 내보내기**(대화, 트래픽 로그, 감사 로그). `=`, `+`, `-`, `@`, 탭 또는 캐리지
  리턴으로 시작하는 셀 앞에는 아포스트로피가 붙어, 스프레드시트가 수식이 아닌
  텍스트로 엽니다. 음수도 해당하여 `-1`은 `'-1`로 내보내집니다.
- **Slack 알림.** 알림 텍스트를 이스케이프하고 길이를 제한합니다. 워커 작업 알림에는
  결과, 오류 코드, 통계가 담기며 오류 원문은 담기지 않습니다. 자세한 내용은 Moss의
  작업 기록에 남습니다.
- 새 선택 설정: 워커의 `WORKER_FETCH_ALLOWLIST`. Helm 차트의 `values.yaml`에는
  주석 처리된 예시만 추가됩니다.
- **가이드 중의 지원 티켓.** 티켓 카드가 열려 있는 동안에는 가이드 바가
  숨겨집니다. 카드를 취소하면 같은 단계에서 가이드가 다시 나타납니다. 티켓이
  등록되거나 결과가 확인되지 않으면(unconfirmed) 가이드는 끝나고 다시 나타나지
  않습니다. 이때 `onEvent`는 `Moss Ticket Submitted`에 이어
  `outcome: 'abandoned'`인 `Moss Plan Finished`를 보고합니다. 실패로 보고된
  티켓은 가이드를 그대로 둡니다. 티켓 이후에 시작한 가이드는 평소처럼 가이드 바를
  보여 줍니다.
- **티켓 카드가 Moss의 답변에서 열립니다.** Moss가 지원 티켓 초안을 만들면, 채팅이
  티켓 양식의 맨 아래가 아니라 양식 위에 있는 Moss의 메시지에서 열립니다.
- **티켓 등록 후 평가 요청.** 지원 티켓이 등록되면 "Was this conversation
  helpful?"이 티켓 확인 아래에 바로 나타나므로, 티켓 번호와 링크가 계속 보입니다.
  응답해도 대화는 그대로 유지되며, 그 대화에 대해 New chat에서 다시 묻지 않습니다.
  다음 메시지를 보내거나 가이드 단계를 진행하면 사라집니다. 실패했거나, 결과가
  확인되지 않았거나, 취소된 티켓에는 나타나지 않습니다. 평가를 보내지 못하면 버튼이
  다시 나타납니다.
- **오래 멈춘 뒤 진행한 가이드 단계.** 사용자가 가이드 도중 비활성 시간 초과를
  지나도록 멈춰 있다가 새 페이지를 여는 단계 대상을 클릭하면, 새 페이지는 세션을
  유지한 채 가이드를 이어 가며, 이어서 할지 새로 시작할지 묻는 카드를 띄우지
  않습니다.
- **세션 설정 저장.** 설정을 저장하면 `sessionConfig`가 저장된 설정과 병합됩니다.
  세션 설정을 일부만 보낸 저장은 나머지를 유지하고, `null`로 보낸 항목은
  지워집니다. `sessionConfig: null`로 저장해도 더 이상 모든 세션 설정이 지워지지
  않습니다.
- **기본 로딩 표시 선택자.** 로딩 표시(loading indicators) 안정성 레이어를 켜고
  기본 선택자를 쓰면, `skeleton`, `spinner`, `loader` 클래스가 대소문자와
  관계없이 일치합니다.
- 이번 릴리스의 SDK 변경은 모두 어떤 백엔드에서도 동작합니다. 단, 비활성 후
  돌아올 때의 대시보드 설정에는 백엔드 0.16.22가 필요합니다.
- 이번 릴리스에는 데이터베이스 마이그레이션이 없습니다. 새 환경 설정은 위에 적은
  워커의 선택 설정 `WORKER_FETCH_ALLOWLIST` 하나입니다.

### 수정

- Moss가 아직 로딩 플레이스홀더를 그리고 있는 페이지를 읽지 않습니다. SDK는 턴의
  페이지 컨텍스트를 보내기 전에 화면에 보이는 플레이스홀더(스켈레톤 등)가
  사라지기를 최대 4초 동안 기다리므로, 답변이 아직 로딩 중이라고 말하는 대신
  로드된 페이지를 설명합니다. 화면에 플레이스홀더가 없으면 기다리지 않습니다. 끝내
  사라지지 않는 플레이스홀더는 한 번만 기다리고, 그 뒤에는 사라지거나 페이지
  주소가 바뀔 때까지 건너뜁니다. 설정은 `stability.placeholderGuard`(`enabled`,
  `timeoutMs`, `excludeSelectors`, `additionalSelectors`, `selectors`)에
  있습니다. `stability.loadingIndicators.selectors`를 설정하면 그 목록을
  사용합니다.
- 이전 턴이 아직 페이지가 안정되기를 기다리는 동안 시작된 턴도 이제 기다립니다.
  이전에는 기다리지 않고 페이지를 읽을 수 있었습니다.
- 가이드 단계의 클릭이 `target=_blank` 링크, `window.open()`, 리디렉션되는 링크로
  새 탭을 열면, 새 탭에서 채팅이 다음 단계와 함께 나타나고 단계는 한 번만
  전송됩니다. 같은 탭에서 리디렉션되거나 로드되면서 주소를 바꾸는 페이지에서도
  가이드가 멈추지 않습니다. 단계를 클릭한 직후 탭을 전환해도 가이드가 끝나지
  않습니다. 로드되면서 주소가 바뀌는 페이지에 관한 0.16.21의 알려진 문제가 이것으로
  수정되었습니다.

### 보안

- Document360과 Zendesk의 통합 호스트를 검증하며, CSV 내보내기를 스프레드시트에서
  안전하게 열 수 있습니다.
- 알림과 감사 기록을 신뢰할 수 없는 입력에 대비해 강화했습니다.
- **워커의 사설 주소 요청 (High).** 크롤링한 페이지가 이미지나 사이트맵 링크를
  내부 주소로 지정하면 워커가 그 주소를 요청할 수 있었습니다. 이제 워커는 자체
  요청에서 사설, 루프백, 링크 로컬, 메타데이터 주소를 거부하고, 이미지인 본문만
  저장합니다.
- 이미지는 최신 베이스 이미지 패키지로 다시 빌드되었으며, 의존성 변경은 없습니다.

### 알려진 문제

- 일부 정상 이미지가 거부되어 원래 주소를 유지합니다. UTF-16 SVG, `</svg>`를
  포함한 주석으로 끝나는 SVG, 마지막 박스 크기가 0인 AVIF 또는 HEIC, 접두사가
  붙은 DOCTYPE 이름을 가진 SVG가 해당합니다.
- 가이드를 시작하는 답변이 유실된 경우(탭 하나일 때와 두 번째 탭이 있을 때)에 관한
  0.16.21의 알려진 문제와, 여러 탭에서의 가이드에 관한 나머지 두 가지 0.16.20
  알려진 문제는 그대로 남아 있습니다.
- "Retry failed pages"는 가져오지 못한 페이지만 세고 다시 시도합니다. 인덱싱에
  실패한 페이지를 다시 실행하려면 소스를 새로 고치거나 페이지를 편집하세요.
- "Start a new chat"에서는, 사용자가 자리를 비운 동안 열려 있던 채팅이 대화를
  그대로 유지합니다. Moss는 로드될 때와 채팅이 열릴 때만 확인하기 때문입니다.
  시간 초과가 지난 뒤 한 핸들러에서 `openChat()`에 이어 `askMoss()`를 호출하면,
  쓰이지 않는 세션이 하나 더 생깁니다.
- 티켓 카드가 열린 채 가이드 도중 페이지가 새로고침되면, 가이드 바는 숨겨진 채
  단계의 강조 표시가 다시 나타나고, 그 요소를 클릭하면 단계가 완료됩니다. 가이드를
  보여 주기만 하는 탭에서 티켓을 등록하면, 가이드를 실행하는 탭은
  `Moss Plan Finished`를 보고하지만 이후 답변이 지울 때까지 가이드 바를 계속
  보여 줍니다.
- 섀도 루트 안의 플레이스홀더는 감지되지 않습니다. 페이지가 렌더링할 때마다 새로
  만드는 플레이스홀더는 턴마다 다시 기다리므로,
  `stability.placeholderGuard.excludeSelectors`로 제외하세요.
- 가이드 단계가 연 새 탭을 클릭과 연결할 수 없으면 가이드는 첫 탭에 남습니다. 새
  탭이 백그라운드에서 열려 다른 주소에 도착한 경우, 페이지가 단계를 보낸 뒤에야
  탭을 연 경우, 페이지 전체의 `no-referrer` 정책이나
  `window.open(url, '_blank', 'noreferrer')` 때문에 출처를 알 수 없는 경우, 중간
  페이지를 두 번 이상 거쳐 도착한 경우가 해당합니다. Moss가 없는 페이지로 가는

## 0.16.20 — 2026-11-04

### 추가

- **Pinecone 프라이빗 엔드포인트(AWS PrivateLink).**
  `PINECONE_USE_PRIVATE_ENDPOINT=true`(기본값은 꺼짐)로 설정하면 sdk-backend,
  dashboard-backend, 워커는 인덱스 조회는 계속 `api.pinecone.io`에서 하고, 모든
  데이터 플레인 트래픽(검색, fetch, upsert, delete)은 인덱스의 프라이빗 호스트
  `<index>.svc.private.<...>.pinecone.io`로 보냅니다. Moss는 이 호스트를 인덱스
  설명에서 읽어 오므로 따로 설정할 호스트는 없습니다. `api.pinecone.io`는 세 워크로드
  모두에서 계속 접근할 수 있어야 합니다.
  - 퍼블릭 호스트로 대체되지 않습니다. 인덱스의 Pinecone 프로젝트에 프라이빗
    엔드포인트가 없으면 Moss는 인덱스에 연결하지 않습니다. 채팅은 애플리케이션의
    지식 기반 없이 답변하고, 소스 삭제는 실패하며, 청킹 작업은 소스의 페이지나 벡터를
    건드리기 전에 실패합니다. 각각 인덱스와 설정 이름이 담긴 오류를 기록합니다.
  - 세 워크로드 모두에 대문자 이름으로, 같은 값을 설정하세요. `true`, `t`, `yes`,
    `y`, `on`, `1`은 대소문자와 관계없이 설정을 켜고, `false`, `f`, `no`, `n`,
    `off`, `0`은 끈 상태로 둡니다. 빈 값이나 앞뒤에 공백 또는 따옴표가 붙은 값을
    포함해 그 밖의 값은 백엔드 기동을 막고 모든 청킹 작업을 실패시킵니다.
  - 각 프로세스는 인덱스를 처음 열 때 `Pinecone data-plane host: private`(또는
    `public`)를 기록합니다. 이 로그는 Moss가 고른 호스트를 보여 줄 뿐, 그 호스트에
    접근할 수 있다는 뜻은 아닙니다.
  - 프로젝트에 Pinecone의 프라이빗 엔드포인트 전용 제한을 켜기 전에, Pinecone이
    프라이빗 호스트를 통해 응답하는지 확인하세요. DNS 레코드나 보안 그룹이 잘못되어
    있어도 `private`가 기록되기 때문입니다. sdk-backend에서는 지식 기반을 쓰는 채팅
    한 턴이 `private` 로그에 이어 N이 0보다 큰 `results=N/M`의
    `Pinecone multi-namespace search completed`를 기록하고, `search failed`는
    기록하지 않아야 합니다. 워커에서는 지식 소스 하나를 새로 고치면 `private` 로그가
    남고 소스가 청크 1개 이상으로 Ready 상태가 되어야 합니다. dashboard-backend는 한동안
    이 로그를 남기지 않을 수 있으므로, 배포에 변수가 설정되어 있는지 확인하세요. 제한을
    켜면 Pinecone이 엔드포인트를 거치지 않은 데이터 플레인 요청을 거부하므로, 아직
    퍼블릭 호스트를 쓰는 워크로드는 검색이나 인덱싱을 할 수 없게 됩니다.
  - 이 설정은 실제 PrivateLink 엔드포인트가 아니라 모의 Pinecone API로 테스트되었으므로,
    위 확인 절차가 설치 환경에서의 테스트입니다.

- 다른 탭이 Next나 단계 진행으로 가이드를 넘겨받은 경우, 원래 탭의 사용자가 나중에
  무언가를 물어보면 원래 탭이 그 다른 탭에서 진행된 단계에 대해서도
  `Moss Plan Step Completed`를 보고합니다. 원래 탭에서 New chat을 누르면 여전히 기기의
  가이드가 종료되고, 그 탭에서 가이드가 끝난 것으로 보고됩니다.
- 가이드를 실행하는 탭이 페이지를 불러오는 중에, 가이드를 보여 주기만 하는 탭에서
  가이드를 종료하면 어느 탭도 그 `Moss Plan Finished`를 보고하지 않습니다.

### 보안

- **API 액션의 사용자 식별.** 설정된 API 액션은 사용자의 회사와 사용자 ID를 대화가
  아니라 서명된 SDK 토큰에서 가져옵니다. 회사는 JWT `metadata` 클레임의
  `company_id`(또는 `companyId`)에서 가져옵니다. 회사 유형 필드(`company_id`,
  `tenant_id`, `organization_id`, `org_id`와 각각의 `X-` 헤더 형식)는 서버가 채우며,
  토큰에 회사 정보가 없으면 이런 필드가 있는 액션은 거부됩니다. `user_id`는 로그인한
  사용자로 채워지고, 다른 사용자를 지정한 호출은 거부됩니다. API 액션을 쓰지 않는
  애플리케이션은 달라지는 것이 없습니다.
- **역할 제한 프로시저.** `allowed_roles`가 지정된 프로시저는 토큰의 `metadata.role`에
  해당 역할이 서명된 사용자에게만 실행됩니다. 호스트가 `role`을 서명하기 전까지 이런
  프로시저는 모든 사용자에게 숨겨집니다. 형식이 잘못된 `allowed_roles` 값은 아무도
  허용하지 않습니다.
- `APP_ENV`가 없거나 비어 있으면 production으로 간주합니다. 이 값을 설정하지 않은
  워커는 텔레메트리에 `production`을 보고하므로, `local`로 필터링하는 대시보드의
  수치가 달라질 수 있습니다.
- 이미지는 최신 베이스 이미지 패키지로 다시 빌드되었으며, 의존성 변경은 없습니다.

- **업그레이드 전에 각 Zendesk 연결의 Filing 설정을 정하세요.** Off로 표시되는데
  프로시저가 여전히 티켓을 제안하던 연결은 업그레이드 시점부터 제안을 멈춥니다.
  호스트 위임 연결은 업그레이드한 뒤에 Live로 전환하세요. 이전 릴리스에서는 Live가
  사용자의 이메일 주소를 묻는 기본 응답의 티켓 제안도 함께 켜기 때문입니다. 기본
  응답에서 티켓을 제안하지 않게 하려면 애플리케이션 설정에서
  `procedures.default_reply_policy`를 `false`로 설정하세요. 이 경우 기본 응답의
  지원팀 문의 안내도 함께 빠집니다. 직접 등록 연결의 Zendesk 양식이 요청자의 역할을
  필수로 요구한다면, Ticket intake 페이지에서 해당 필드에 고정 값을 지정하거나 티켓
  프로시저가 역할을 묻도록 하세요.
- SDK 0.16.16은 결과의 `ticketId`를 `string | number` 타입으로 받아 텍스트로
  전송합니다.

  `LLM_CLIENT_TYPE`에 지정된 프로바이더 하나만 사용합니다.
- Bearer 로그인에서 발생한 트래픽 로그 감사 이벤트는 `auth_method`를 `clerk_jwt`
  대신 `jwt`로 기록합니다. 기존 이벤트는 `clerk_jwt`로 남아 있으므로, 이 값을 쓰는
  SIEM 필터를 업데이트하세요.
- 워커가 DTD를 선언한 사이트맵을 거부합니다.
- 0.16.7에서 업그레이드하면 0.16.8부터 0.16.15까지가 함께 적용되며, 이 가운데

  모드의 통합 연결은 생성되지 않고 마무리 항목으로 보고됩니다. 가져오기는 하나의
  트랜잭션으로 실행되며, 드라이런 보고서에는 생성될 항목, 재매핑된 식별자,
  번들과 다르게 기록되는 모든 값, 다시 입력해야 할 항목 체크리스트가 표시됩니다.
  대시보드 내보내기는 기본적으로 전체 번들을 생성하며, 설정만 담은 번들도 계속
  사용할 수 있습니다. 가이드 플로우는 번들에 포함되지 않습니다. 엔드포인트는
  `GET /api/v1/applications/{id}/export`와
  `POST /api/v1/applications/import?dry_run=true`입니다.
- **대시보드에서 관리하는 외관 컨트롤(1차).** 새로운 테마 슬라이스와 푸터 배경
  색조를 대시보드에서 편집할 수 있습니다. SDK는 대시보드에 저장된 값을 리프
  단위로 호스트 prop 위에 적용하므로, 우선순위는 프리셋, 호스트 prop, 대시보드
  값 순입니다. 대시보드 테마 값을 보려면 호스트가 SDK를 0.16.6으로 업그레이드해야
  합니다.
- SDK 채팅 창을 헤더 전체와 창 가장자리에서 드래그할 수 있습니다.
- 대시보드 토스트에 닫기 버튼이 추가되었고, 오류 토스트는 닫을 때까지 유지됩니다.

### 변경

- 설정 슬라이스의 마지막 리프를 지우면 빈 객체를 저장하는 대신 슬라이스 자체가
  제거됩니다.
- SDK 패키지 tarball에 더 이상 소스맵이 포함되지 않으며, 공개 README와 패키지
  메타데이터가 추가되었습니다.
- 분리 배포 환경의 업그레이드 순서: 백엔드, 대시보드, SDK 순입니다.
- 애플리케이션 정리(prune) 스크립트가 애플리케이션 소유 테이블 전체를 다루고,
  저장된 DOM 스냅샷 객체를 제거하며, 설정된 데이터베이스 스키마를 통해 테이블을
  찾습니다. 애플리케이션 간 참조가 감지되거나 테이블 수를 셀 수 없으면 실행을
  거부합니다.
- 이번 릴리스에는 데이터베이스 마이그레이션이 없습니다.

### 알려진 문제

- 링크만 저장된 푸터의 경우 공개 설정 엔드포인트가 `enabled: false`를 반환합니다.
- 설치 환경에 같은 이름의 애플리케이션이 이미 있는 조직으로 가져오기하면
  거부됩니다. 현재 애플리케이션 이름은 설치 환경 단위로 고유합니다.
