이 섹션은 보안·개인정보 검토자를 위한 문서입니다. Moss가 SDK 요청과 팀원을 인증하는 방법, 조직 간 데이터를 분리하는 방법, Moss가 기록하는 내용, 그리고 페이지 데이터, 보존, 규정 준수에 관한 문서의 위치를 다룹니다. 아래 표는 검토자가 가장 많이 묻는 질문에 답하고 자세한 내용으로 연결합니다.

### 배포 범위

호스팅 서비스 설명은 Moss가 운영하는 서비스에 적용됩니다. 고객 관리형 배포는
합의된 아키텍처, 데이터 흐름 및 접근 제한을 따릅니다. Moss는 소프트웨어 공급망과
빌드·릴리스 보안에 계속 책임을 집니다.

## 한눈에 보는 답변

| 질문 | 짧은 답변 | 자세히 |
|------|-----------|--------|
| SDK는 어떻게 인증하나요? | 서버가 사용자마다 서명한 JWT로 인증하며, 요청마다 확인합니다. SDK용 API 키는 없습니다. | [SDK 인증](/ko/sdk/authentication) |
| 허용 도메인 목록이 보안 경계인가요? | 아니요. 다른 웹사이트가 브라우저에서 어시스턴트를 쓰지 못하게 막을 뿐입니다. 요청을 인증하는 것은 서명된 토큰이며, 목록이 비어 있으면 모든 페이지를 허용합니다. | [허용 도메인](/ko/sdk/authentication#허용-도메인) |
| 팀원은 어떻게 로그인하고, 어떤 역할이 있나요? | Moss 호스팅 서비스에서는 Clerk로, 자체 호스팅 설치에서는 고객사의 ID 공급자(OIDC)로 로그인합니다. 역할은 조직 전체에 적용되는 관리자와 멤버 두 가지입니다. | [인증](/ko/security/authentication) |
| 우리 회사에서 누가 최종 사용자의 대화를 읽을 수 있나요? | 조직의 모든 멤버와 관리자가 모든 애플리케이션의 대화를 읽을 수 있습니다. | [대화를 볼 수 있는 사람](/ko/security/authentication#최종-사용자의-대화를-볼-수-있는-사람) |
| 감사 로그는 무엇을, 얼마나 오래 기록하나요? | 변경, 멤버에게 거부된 관리자 전용 작업, API 로그 읽기, AI 어시스턴트의 도구 호출을 기록합니다. 기본 365일 동안 보관합니다. | [감사 로깅](/ko/security/audit-logging) |
| 자동으로 삭제되는 데이터가 있나요? | 관리자가 **구성 > 데이터 및 개인정보**에서 애플리케이션의 **자동 삭제**를 켜기 전에는 없습니다. 감사 이벤트에는 별도의 보관 기간이 있습니다. | [데이터 및 개인정보](/ko/dashboard/data-privacy) |
| 한 사람의 데이터는 어떻게 삭제하나요? | **구성 > 데이터 및 개인정보 > 사용자 데이터 삭제**에서 삭제합니다. | [데이터 및 개인정보](/ko/dashboard/data-privacy) |
| AI 어시스턴트가 우리 Moss 데이터를 읽을 수 있나요? | 배포에서 제공하고 관리자가 켠 경우에만 가능합니다. 어시스턴트는 연결한 사람으로서 동작합니다. | [AI 어시스턴트](/ko/dashboard/ai-assistants) |

Moss가 페이지에서 읽는 내용과 이를 제한하는 방법은 [Moss가 페이지에서 읽는 내용](/ko/sdk/page-data)에 있습니다. 데이터를 저장하는 곳과 보호하는 방법은 [데이터 보호](/ko/security/data-protection)에, 인증 제도와 법적 기준은 [규정 준수](/ko/security/compliance)에 있습니다.

## 보안 아키텍처

### 심층 방어

Moss는 여러 계층의 보안 제어를 사용합니다:

| 계층 | 보호 |
|------|------|
| **인증** | SDK 요청에는 서명된 JWT, 대시보드 로그인에는 Clerk(Moss 호스팅) 또는 고객사의 ID 공급자(자체 호스팅) |
| **권한 부여** | 조직 역할(관리자와 멤버), 채팅마다 해당 애플리케이션과 사용자에 묶임 |
| **데이터 보호** | 전송 중 암호화(TLS), 민감한 데이터 편집 |
| **감사 로깅** | 감사 이벤트와 선택적 API 로그 |
| **입력 검증** | 요청 스키마 검증 |

### 멀티테넌시 격리

Moss 호스팅 애플리케이션에는 조직 수준의 격리를 적용합니다:

- **데이터베이스 접근** - 조직·애플리케이션·세션 범위에 따른 권한 확인
- **API 격리** - 대시보드 요청은 고객의 조직으로 범위가 정해지고, 각 SDK 토큰은 서명 키를 통해 애플리케이션 하나에 묶임
- **데이터 격리** - 사용자가 다른 조직의 데이터에 접근 불가

다른 조직의 애플리케이션에 대한 대시보드 요청은 거부됩니다. [멀티테넌시 보안](/ko/security/authentication#멀티테넌시-보안)을 참조하세요.

## 규정 준수 약속

Moss는 SOC 2 Type II 감사와 ISO 27001 인증을 진행하고 있습니다:

### 진행 중

| 인증 | 설명 | 상태 |
|------|------|------|
| **SOC 2 Type II** | 보안 제어 (신뢰 서비스 기준: 보안) | 진행 중 |
| **ISO 27001** | 정보 보안 관리 시스템 | 진행 중 |

### 개인정보 보호 및 보안 기능

- **GDPR 지원** - 데이터 삭제 서비스, 감사 로깅
- **TLS 1.2 이상** - 공개 서비스 엔드포인트에 암호화된 HTTPS 연결 적용
- **자격 증명 보호** - API 키 검증용 해시와 재사용 자격 증명 암호화

SDK에는 자체 동의 요청 화면이 없습니다. 고객의 동의 절차가 허용한 뒤에만 SDK를 불러오려면 [Moss가 페이지에서 읽는 내용](/ko/sdk/page-data)을 참조하세요.

## 책임 있는 공개

Moss에서 보안 취약점을 발견하면 책임감 있게 보고해 주세요. 대시보드를 통해 보안팀에 문의하거나 [security@viamoss.ai](mailto:security@viamoss.ai)로 이메일을 보내주세요.

모든 Moss 백엔드는 보안 연락처를 `/.well-known/security.txt`의 `security.txt` 파일(RFC 9116)로도 공개합니다.

모두를 위해 Moss를 안전하게 유지하는 데 도움을 주셔서 감사합니다.
