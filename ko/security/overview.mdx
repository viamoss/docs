## 보안 약속

Moss는 보안을 기본 원칙으로 구축되었습니다. 우리 플랫폼이 민감한 사용자 상호작용과 비즈니스 데이터를 처리한다는 것을 이해하고 있으며, 그 책임을 진지하게 받아들입니다.

이 문서는 데이터와 사용자를 보호하기 위해 Moss에 구현된 보안 조치를 설명합니다.

### 배포 범위

호스팅 서비스 설명은 Moss가 운영하는 서비스에 적용됩니다. 고객 관리형 배포는
합의된 아키텍처, 데이터 흐름 및 접근 제한을 따릅니다. Moss는 소프트웨어 공급망과
빌드·릴리스 보안에 계속 책임을 집니다. 고객별 요건에는 해당 DPA와 보안 부속합의가
적용됩니다.

## 보안 아키텍처

### 심층 방어

Moss는 여러 계층의 보안 제어를 사용합니다:

| 계층 | 보호 |
|------|------|
| **인증** | JWT 토큰, API 키 및 Clerk를 통한 SSO |
| **권한 부여** | 조직 기반 접근 제어, 세션 검증 |
| **데이터 보호** | 전송 중 암호화(TLS), 민감한 데이터 편집 |
| **감사 로깅** | 감사 이벤트 및 선택적 상세 요청 로깅 |
| **입력 검증** | 요청 스키마 검증 |

### 멀티테넌시 격리

Moss 호스팅 애플리케이션에는 조직 수준의 격리를 적용합니다:

- **데이터베이스 접근** - 조직·애플리케이션·세션 범위에 따른 권한 확인
- **API 격리** - JWT 토큰이 특정 조직으로 접근 범위 지정
- **데이터 격리** - 사용자가 다른 조직의 데이터에 접근 불가

## 규정 준수 약속

Moss는 SOC 2 Type II 감사와 ISO 27001 인증을 진행하고 있습니다:

### 진행 중

| 인증 | 설명 | 상태 |
|------|------|------|
| **SOC 2 Type II** | 보안, 가용성 및 기밀성 제어 | 진행 중 |
| **ISO 27001** | 정보 보안 관리 시스템 | 진행 중 |

### 개인정보 보호 및 보안 기능

- **GDPR 지원** - 데이터 삭제 서비스, 감사 로깅, 사용자 동의 메커니즘
- **TLS 1.2 이상** - 공개 서비스 엔드포인트에 암호화된 HTTPS 연결 적용
- **자격 증명 보호** - API 키 검증용 해시와 재사용 자격 증명 암호화
