## 개요

Moss는 규정 준수와 보안 사고 조사를 위해 감사 이벤트를 기록하고, 선택적으로 상세 요청 로그를 수집합니다.

---

## 로깅되는 내용

아래 표는 상세 요청 로깅을 켰을 때의 기록입니다.

### 인바운드 요청 (SDK에서 백엔드로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 수신된 시간 |
| 애플리케이션 ID | 요청을 보낸 애플리케이션 |
| 사용자 ID | 인증된 사용자 |
| 세션 ID | 연결된 채팅 세션 |
| 엔드포인트 | 호출된 API 엔드포인트 |
| 요청 페이로드 | 자격증명 필드를 가린 요청 본문 |
| 응답 상태 | HTTP 상태 코드 |
| 기간 | 요청 처리 시간 |

### 아웃바운드 요청 (백엔드에서 외부 서비스로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 이루어진 시간 |
| 대상 서비스 | LLM 제공자, 임베딩 API, 스토리지 |
| 제공자 | 특정 제공자 (OpenAI, Google 등) |
| 모델 | 요청에 사용된 모델 |
| 요청 요약 | 자격증명 필드를 가린 요청 세부 정보 |
| 응답 상태 | 성공/실패 |
| 토큰 수 | LLM 요청용 |

## 민감한 데이터 편집

요청 로그의 정제기는 저장 전에 아래 자격 증명 필드를 가립니다:

### 편집되는 필드

다음 필드는 자동으로 편집됩니다:

- `api_key`, `apiKey`
- `authorization`
- `password`
- `secret`
- `token`
- `x-api-key`

### 편집 예시

```json
// 원본 요청
{
  "headers": {
    "authorization": "Bearer eyJhbG...",
    "x-api-key": "app_abc123"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}

// 로깅됨 (정제됨)
{
  "headers": {
    "authorization": "[REDACTED]",
    "x-api-key": "[REDACTED]"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}
```

<Info>
    자격증명 필드는 중첩된 객체와 배열에서도 가립니다. 상세 요청 로깅은 계측된
    경로를 대상으로 합니다.
</Info>

## 애플리케이션별 제어

상세 요청 로깅은 애플리케이션별로 활성화 또는 비활성화할 수 있습니다:

이 설정은 상세 요청 로그에 적용되며, 관리 작업의 감사 이벤트 기록과는 별개입니다.

### 대시보드 설정

**설정 > 개발자 옵션 > 감사 로깅**으로 이동하여 애플리케이션의 로깅을 활성화하거나 비활성화합니다.

### 고려 사항

| 상세 요청 로깅 | 사용 사례 |
|----------|----------|
| **활성화됨** | 허용된 범위 안에서 요청 단위 문제 분석이 필요한 경우 |
| **비활성화됨** | 저장 비용이 우려되는 대용량 애플리케이션 |

<Tip>
    필요한 경우에 상세 요청 로깅을 켜세요.
</Tip>

## 감사 로그 접근

### 대시보드 접근

**구성 > 감사 로그**에서 대시보드의 감사 로그를 봅니다.

기능:
- 날짜 범위별 필터
- 사용자 또는 세션별 필터
- 엔드포인트 또는 상태별 필터
- CSV로 내보내기

### API 접근

감사 API를 사용하여 프로그래밍 방식으로 감사 로그를 쿼리합니다:

```bash
# 애플리케이션의 감사 이벤트 조회
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events?start_date=2024-01-01&end_date=2024-01-31" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"

# 동일한 이벤트를 JSON 또는 CSV로 내보내기
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events/export?format=csv" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"
```

결과는 `page`와 `page_size`로 페이지네이션되며, `actor_id`, `action`, `target_type`, `outcome`, `start_date`, `end_date`로 범위를 좁힐 수 있습니다.

### 감사 API 키

감사 로그 접근에는 별도의 API 키가 사용됩니다:

- **격리된 접근** - 감사 키는 SDK API 키와 별도
- **읽기 전용** - 로그나 다른 데이터 수정 불가
- **폐기 가능** - 독립적으로 폐기 가능

## 로그 보존

| 기록 종류 | 백엔드 기본값 | 기간 적용 방식 |
|-----------|---------------|----------------|
| 선택적 상세 API 요청 로그 | 90일 | 앱별 기간 적용. 수집을 꺼도 기존 기록은 삭제되지 않음 |
| 관리·보안 감사 이벤트 | 365일 | 운영자가 관리하며, 고객 지시 대상 기록에는 문서화된 고객 지시 적용 |

실제 적용 기간은 계약, 문서화된 고객 지시 및 적법한 보존 의무에 따라 결정됩니다.
최소 보존 의무가 있으면 삭제 시점과 충돌하지 않도록 먼저 맞춰야 합니다.
해당 배포의 활성화된 삭제 일정은 Moss에 확인하세요.

## 사용 사례

### 규정 준수 보고

감사자를 위한 보고서 생성:

1. 날짜 범위별 로그 필터
2. CSV로 내보내기
3. 규정 준수 문서에 포함

### 보안 조사

의심스러운 활동 조사:

1. 사용자 또는 세션 식별
2. 모든 관련 요청 검토
3. 비정상적인 패턴 확인
4. 사고 대응을 위한 증거 내보내기

### 성능 분석

API 사용 패턴 분석:

1. 요청 기간 검토
2. 느린 엔드포인트 식별
3. LLM 토큰 사용량 추적
4. 데이터 기반 최적화

### 비용 분석

LLM 사용 비용 추적:

1. 모델별 토큰 수 검토
2. 높은 사용량 세션 식별
3. 프롬프트 및 컨텍스트 최적화

## 로그 무결성

### 감사 이벤트의 수정·삭제 제한

- 애플리케이션 사용자는 대시보드나 감사 API에서 기존 감사 이벤트를 수정하거나 삭제할 수 없습니다.
- 보존 기간이 지난 감사 이벤트는 보존 정책에 따른 정리 작업으로 삭제합니다.

### 타임스탬프

감사 이벤트 시각은 서버에서 UTC로 생성합니다.

---

## 모범 사례

### 프로덕션에 활성화

다음 목적에 맞게 운영 감사·요청 로깅을 설정하세요:

- 규정 준수 요구 사항 충족
- 사고 조사 가능
- 사용 패턴 추적

### 정기적 검토

다음을 위해 감사 로그를 주기적으로 검토하세요:

- 비정상적인 접근 패턴
- 접근 권한 변경과 기록된 보안 이벤트
- 예기치 않은 API 사용

### API 키 보안

감사 API 키 보호:

- 안전하게 저장 (코드에 포함하지 않음)
- 주기적으로 로테이션
- 무단 사용 모니터링
