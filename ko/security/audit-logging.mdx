## 개요

Moss는 주요 감사 이벤트를 기록하고 선택적으로 상세 요청 로그를 수집합니다. 인프라 로그는 별도로 관리합니다.

---

## 로깅되는 내용

아래 표는 상세 요청 로깅을 켰을 때의 기록입니다. 감사 이벤트에는 별도 이벤트 형식이 적용됩니다.

### 인바운드 요청 (SDK에서 백엔드로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 수신된 시간 |
| 애플리케이션 ID | 요청을 보낸 애플리케이션 |
| 사용자 ID | 인증된 사용자 |
| 세션 ID | 연결된 채팅 세션 |
| 엔드포인트 | 호출된 API 엔드포인트 |
| 요청 페이로드 | 정제된 요청 본문 |
| 응답 상태 | HTTP 상태 코드 |
| 기간 | 요청 처리 시간 |

### 아웃바운드 요청 (백엔드에서 외부 서비스로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 이루어진 시간 |
| 대상 서비스 | LLM 제공자, 임베딩 API, 스토리지 |
| 제공자 | 특정 제공자 (OpenAI, Google 등) |
| 모델 | 요청에 사용된 모델 |
| 요청 요약 | 정제된 요청 세부 정보 |
| 응답 상태 | 성공/실패 |
| 토큰 수 | LLM 요청용 |

## 민감한 데이터 편집

요청 로그의 정제기는 저장 전에 아래 자격 증명 필드를 가립니다:

### 편집되는 필드

다음 필드는 자동으로 편집됩니다:

- `api_key`, `apiKey`
- `authorization`
- `password`
- `secret`
- `token`
- `x-api-key`

### 편집 예시

```json
// 원본 요청
{
  "headers": {
    "authorization": "Bearer eyJhbG...",
    "x-api-key": "app_abc123"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}

// 로깅됨 (정제됨)
{
  "headers": {
    "authorization": "[REDACTED]",
    "x-api-key": "[REDACTED]"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}
```

<Info>
    재귀 정제기는 중첩된 객체와 배열도 처리합니다. 자유 형식의 본문에는 개인정보가 남을 수 있습니다.
</Info>

## 애플리케이션별 제어

상세 요청 로깅은 애플리케이션별로 켜거나 끌 수 있습니다. 감사 이벤트는 별도로 기록됩니다:

### 대시보드 설정

**설정 > 개발자 옵션 > 감사 로깅**으로 이동하여 애플리케이션의 로깅을 활성화하거나 비활성화합니다.

### 고려 사항

| 상세 요청 로깅 | 사용 사례 |
|----------|----------|
| **활성화됨** | 규정 준수 요구 사항, 보안에 민감한 애플리케이션 |
| **비활성화됨** | 저장 비용이 우려되는 대용량 애플리케이션 |

<Tip>
    필요한 경우에 상세 요청 로깅을 켜고, 접근권한과 보존 기간을 정하세요.
</Tip>

## 감사 로그 접근

### 대시보드 접근

**구성 > 감사 로그**에서 대시보드의 감사 로그를 봅니다.

기능:
- 날짜 범위별 필터
- 사용자 또는 세션별 필터
- 엔드포인트 또는 상태별 필터
- CSV로 내보내기

### API 접근

감사 API를 사용하여 프로그래밍 방식으로 감사 로그를 쿼리합니다:

```bash
# 애플리케이션의 감사 이벤트 조회
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events?start_date=2024-01-01&end_date=2024-01-31" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"

# 동일한 이벤트를 JSON 또는 CSV로 내보내기
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events/export?format=csv" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"
```

결과는 `page`와 `page_size`로 페이지네이션되며, `actor_id`, `action`, `target_type`, `outcome`, `start_date`, `end_date`로 범위를 좁힐 수 있습니다.

### 감사 API 키

감사 로그 접근에는 별도의 API 키가 사용됩니다:

- **격리된 접근** - 감사 키는 SDK API 키와 별도
- **읽기 전용** - 로그나 다른 데이터 수정 불가
- **폐기 가능** - 독립적으로 폐기 가능

## 로그 보존

보존 기간은 기록 종류와 저장소에 따라 다릅니다. 감사 이벤트·상세 요청 로그·인프라 로그에 적용되는 기간은 문의해 주세요.

## 사용 사례

### 규정 준수 보고

감사자를 위한 보고서 생성:

1. 날짜 범위별 로그 필터
2. CSV로 내보내기
3. 규정 준수 문서에 포함

### 보안 조사

의심스러운 활동 조사:

1. 사용자 또는 세션 식별
2. 기록된 관련 이벤트와 요청 확인
3. 비정상적인 패턴 확인
4. 사고 대응을 위한 증거 내보내기

### 성능 분석

API 사용 패턴 분석:

1. 요청 기간 검토
2. 느린 엔드포인트 식별
3. LLM 토큰 사용량 추적
4. 데이터 기반 최적화

### 비용 분석

LLM 사용 비용 추적:

1. 모델별 토큰 수 검토
2. 높은 사용량 세션 식별
3. 프롬프트 및 컨텍스트 최적화

---

## 로그 무결성

### 읽기 전용 API 접근

감사 API는 읽기 전용입니다. 데이터베이스 관리자와 보존 작업에는 별도 접근·삭제 통제가 적용됩니다.

### 타임스탬프

이벤트 시각은 서버에서 UTC로 기록합니다. 요청 본문에는 클라이언트가 보낸 시각도 포함될 수 있습니다.

---

## 모범 사례

### 프로덕션에 활성화

다음 목적에 필요한 운영 이벤트와 요청 로그 범위를 정하세요:

- 규정 준수 요구 사항 충족
- 사고 조사 가능
- 사용 패턴 추적

### 정기적 검토

다음을 위해 감사 로그를 주기적으로 검토하세요:

- 비정상적인 접근 패턴
- 실패한 인증 시도
- 예기치 않은 API 사용

### API 키 보안

감사 API 키 보호:

- 안전하게 저장 (코드에 포함하지 않음)
- 주기적으로 로테이션
- 무단 사용 모니터링
