## 개요

Moss는 선정된 감사 이벤트를 기록하고 선택적인 상세 요청 로깅을 지원합니다. 이 기록은 활동 조사에 활용할 수 있지만 모든 API 요청이나 AI 상호작용을 수집한다는 의미는 아닙니다. 인프라 운영 로그는 별도로 관리됩니다.

---

## 선택적 상세 요청 로그

아래 표는 해당 수집 경로가 켜져 있을 때 지원하는 요청 로그의 필드입니다. 실제 수집 범위는 연동과 배포에 따라 다릅니다. 감사 이벤트는 별도의 이벤트 형식을 사용합니다.

### 인바운드 요청 (SDK에서 백엔드로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 수신된 시간 |
| 애플리케이션 ID | 요청을 보낸 애플리케이션 |
| 사용자 ID | 인증된 사용자 |
| 세션 ID | 연결된 채팅 세션 |
| 엔드포인트 | 호출된 API 엔드포인트 |
| 요청 페이로드 | 정제된 요청 본문 |
| 응답 상태 | HTTP 상태 코드 |
| 기간 | 요청 처리 시간 |

### 아웃바운드 요청 (백엔드에서 외부 서비스로)

| 필드 | 설명 |
|------|------|
| 타임스탬프 | 요청이 이루어진 시간 |
| 대상 서비스 | LLM 제공자, 임베딩 API, 스토리지 |
| 제공자 | 특정 제공자 (OpenAI, Google 등) |
| 모델 | 요청에 사용된 모델 |
| 요청 요약 | 정제된 요청 세부 정보 |
| 응답 상태 | 성공/실패 |
| 토큰 수 | LLM 요청용 |

## 민감한 데이터 편집

지원되는 로그 경로에서는 알려진 자격 증명 필드 이름을 기준으로 값을 가립니다. 모든 개인정보나 기밀 내용을 제거한다는 의미는 아닙니다:

### 편집되는 필드

알려진 자격 증명 이름에는 다음이 포함됩니다:

- `api_key`, `apiKey`
- `authorization`
- `password`
- `secret`
- `token`
- `x-api-key`

### 편집 예시

```json
// 원본 요청
{
  "headers": {
    "authorization": "Bearer eyJhbG...",
    "x-api-key": "app_abc123"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}

// 로깅됨 (정제됨)
{
  "headers": {
    "authorization": "[REDACTED]",
    "x-api-key": "[REDACTED]"
  },
  "body": {
    "query": "비밀번호를 어떻게 재설정하나요?"
  }
}
```

<Info>
    예시는 알려진 키 이름을 가리는 방법을 보여줍니다. 중첩 처리 여부는 로거에 따라 다릅니다. 자유 입력·이미지·DOM·녹화의 수집과 마스킹은 별도로 확인해야 합니다.
</Info>

## 애플리케이션별 제어

상세 요청 로깅은 애플리케이션별로 켜거나 끌 수 있습니다. 이 설정이 모든 보안 감사 이벤트나 인프라 운영 로그를 제어하는 것은 아닙니다:

### 대시보드 설정

**설정 > 개발자 옵션 > 감사 로깅**으로 이동하여 애플리케이션의 로깅을 활성화하거나 비활성화합니다.

### 고려 사항

| 감사 로깅 | 사용 사례 |
|----------|----------|
| **활성화됨** | 승인된 조사·진단 목적에 맞춰 내용을 최소화하고 접근·보존을 정한 경우 |
| **비활성화됨** | 해당 경로의 상세 요청을 보관하지 않음. 조사에 필요한 기록을 먼저 확인 |

<Tip>
    보안과 책임 추적에 필요한 감사 이벤트를 정하세요. 상세 본문·트래픽 로깅은 승인된 목적에 한해 최소 수집, 접근 제한과 적절한 보존 기간을 정한 뒤 사용하세요.
</Tip>

## 감사 로그 접근

### 대시보드 접근

**구성 > 감사 로그**에서 대시보드의 감사 로그를 봅니다.

기능:
- 날짜 범위별 필터
- 사용자 또는 세션별 필터
- 엔드포인트 또는 상태별 필터
- CSV로 내보내기

### API 접근

감사 API를 사용하여 프로그래밍 방식으로 감사 로그를 쿼리합니다:

```bash
# 애플리케이션의 감사 이벤트 조회
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events?start_date=2024-01-01&end_date=2024-01-31" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"

# 동일한 이벤트를 JSON 또는 CSV로 내보내기
curl -X GET "https://moss-api.viamoss.ai/api/v1/applications/YOUR_APP_ID/audit-events/export?format=csv" \
  -H "X-Audit-API-Key: YOUR_AUDIT_API_KEY"
```

결과는 `page`와 `page_size`로 페이지네이션되며, `actor_id`, `action`, `target_type`, `outcome`, `start_date`, `end_date`로 범위를 좁힐 수 있습니다.

### 감사 API 키

감사 로그 접근에는 별도의 API 키가 사용됩니다:

- **격리된 접근** - 감사 키는 SDK API 키와 별도
- **읽기 전용** - 로그나 다른 데이터 수정 불가
- **폐기 가능** - 독립적으로 폐기 가능

## 로그 보존

보존 기간은 기록 종류, 저장소와 배포 설정에 따라 다릅니다. 감사 이벤트·상세 요청·인프라 로그의 보존 및 삭제 방식이 서로 다를 수 있습니다. 실제 배포에 적용되는 기간은 Moss에 확인해 주세요. 이 페이지는 플랜 전체에 적용되는 보존 설정을 보장하지 않습니다.

## 사용 사례

### 규정 준수 보고

감사자를 위한 보고서 생성:

1. 날짜 범위별 로그 필터
2. CSV로 내보내기
3. 규정 준수 문서에 포함

### 보안 조사

의심스러운 활동 조사:

1. 사용자 또는 세션 식별
2. 남아 있는 관련 이벤트와 요청 기록 검토
3. 비정상적인 패턴 확인
4. 사고 대응을 위한 증거 내보내기

### 성능 분석

API 사용 패턴 분석:

1. 요청 기간 검토
2. 느린 엔드포인트 식별
3. LLM 토큰 사용량 추적
4. 데이터 기반 최적화

### 비용 분석

LLM 사용 비용 추적:

1. 모델별 토큰 수 검토
2. 높은 사용량 세션 식별
3. 프롬프트 및 컨텍스트 최적화

## 로그 무결성

### 접근과 삭제

감사 API 키는 읽기 전용입니다. 이 접근 제한만으로 저장소의 불변성이 보장되지는 않습니다. 관리자 접근, DB 작업, 보존·삭제 작업은 별도로 고려해야 합니다.

### 타임스탬프

서버에 기록된 이벤트 시간으로 활동의 순서를 확인할 수 있습니다. 데이터 본문에는 클라이언트가 제공한 시간도 포함될 수 있으므로, 조사할 때 서버 기록 시간과 구분하세요.

---

## 모범 사례

### 프로덕션에 활성화

다음 목적에 필요한 운영 이벤트와 상세 요청의 수집 범위를 정하세요:

- 규정 준수 요구 사항 충족
- 사고 조사 가능
- 사용 패턴 추적

### 정기적 검토

다음을 위해 감사 로그를 주기적으로 검토하세요:

- 비정상적인 접근 패턴
- 실패한 인증 시도
- 예기치 않은 API 사용

### API 키 보안

감사 API 키 보호:

- 안전하게 저장 (코드에 포함하지 않음)
- 주기적으로 로테이션
- 무단 사용 모니터링
