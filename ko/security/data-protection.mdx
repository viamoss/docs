이 페이지는 Moss가 애플리케이션을 위해 다루는 데이터를 종류별로 정리합니다. 언제 수집되고 무엇으로 켜고 끄는지, 어디에 저장되는지, 모델 제공업체로 전달되는지, 어떻게 마스킹하는지, 얼마나 보관되는지를 설명합니다. Moss 0.17.0 기준이며, 0.16.x에서 바뀐 점은 따로 표시합니다.

- 페이지가 보내는 데이터를 바꾸려면 [페이지 데이터](/ko/sdk/page-data)를 참고하세요.
- 데이터 보관 기간을 정하거나 사용자 한 명의 데이터를 삭제하려면 [데이터 및 개인정보](/ko/dashboard/data-privacy)를 참고하세요.

고객 관리형 배포는 [배포 범위](/ko/security/overview#배포-범위)를 참고하세요.

## Moss가 수집하는 데이터

| 데이터 | 수집 시점 | 저장 위치 | 모델 제공업체로 전달 |
| --- | --- | --- | --- |
| [채팅 메시지](#채팅-메시지) | 모든 질문과 답변 | 데이터베이스 | 예: 질문과 그 채팅의 이전 메시지 |
| [페이지 URL과 제목](#페이지-텍스트-url-제목) | 질문할 때마다. 단, 페이지 컨텍스트가 `none`이면 제외 | 데이터베이스 | 예 |
| [페이지 텍스트](#페이지-텍스트-url-제목) | 페이지 컨텍스트가 `full`일 때 질문할 때마다. **화면 가이드**가 켜져 있으면 기본으로 `full`입니다 | 데이터베이스 | 예 |
| [스크린샷](#스크린샷) | 기본값은 꺼짐. 비전이 켜져 있고, 페이지 컨텍스트가 `full`이며, 사용자가 화면 공유를 허용했을 때 질문과 함께 | 파일 저장소 | 예. 이미지를 받는 모델일 때 |
| [화면 기록](#화면-기록) | 기본값은 꺼짐 | 데이터베이스 | 예 |
| [세션 녹화](#세션-녹화) | 기본값은 꺼짐. **세션 리플레이 활성화**가 켜져 있을 때, 채팅이 열려 있는 동안 | 파일 저장소 | 아니요 |
| [페이지 스냅샷](#페이지-스냅샷) | 기본값은 꺼짐. 프로덕션으로 실행 중인 서버는 받지 않음 | 파일 저장소 | 아니요 |
| [업로드한 파일](#업로드한-파일) | 베타, 기본값은 꺼짐. 사용자가 파일을 첨부할 때 | 파일 저장소 | 파일 이름만 |
| [API 로그](#api-로그) | 기본값은 꺼짐. **API 로그 기록**이 켜져 있을 때 | 데이터베이스 | 아니요 |
| [사용자 ID와 메타데이터](#사용자-id와-메타데이터) | 세션을 시작할 때마다 | 데이터베이스 | 메타데이터는 예 |
| [상호작용 보고](#상호작용-보고) | 가이드 단계가 가리키는 요소를 사용자가 조작할 때 | 데이터베이스 | 예: 요소에 대한 짧은 설명과, 질문할 때와 같은 페이지 컨텍스트 |
| [피드백](#피드백) | 사용자가 답변이나 세션을 평가할 때 | 데이터베이스 | 질문과 함께 보내지는 않음. 일부 대시보드 기능이 읽음 |
| [브라우저의 사본](#데이터-저장-위치) | 사용자가 채팅을 쓰는 동안 | 사용자 브라우저 | 아니요 |

대화의 데이터베이스 레코드와 파일은 삭제할 때까지 보관됩니다. 자동 삭제는 관리자가 켜기 전까지 꺼져 있습니다. [데이터 보관 기간](#데이터-보관-기간)을 참고하세요.

## 데이터 종류별 수집 방식

### 채팅 메시지

사용자가 입력한 모든 질문과 Moss의 모든 답변은 대화와 함께 저장됩니다. 모델은 질문과 함께 그 대화의 이전 메시지를 받습니다. 새 채팅은 빈 상태로 시작하며, Moss는 이전 대화를 모델에 보내지 않습니다.

### 페이지 텍스트, URL, 제목

질문할 때마다 SDK는 페이지를 읽어, 어시스턴트가 페이지에 관해 답하고 요소를 가리킬 수 있게 합니다. 얼마나 읽을지는 페이지 컨텍스트 수준이 정합니다.

| 수준 | SDK가 보내는 데이터 |
| --- | --- |
| `full` | 페이지 텍스트와 구조, URL, 제목. 스크린샷은 이 수준에서만 찍을 수 있습니다. |
| `metadata` | URL과 제목만 |
| `none` | 아무것도 보내지 않음 |

- 애플리케이션은 **화면 가이드**가 켜져 있으면(기본값) `full`을, 꺼져 있으면 `metadata`를 씁니다. 설정 위치는 **구성 > 동작 > 주요 기능**입니다.
- **CDN 스크립트:** 애플리케이션의 수준을 따릅니다. 단, 페이지가 `window.mossSettings`에 `pageContext`를 넣으면 그 값이 어느 쪽으로든 우선합니다.
- **npm 패키지:** 자체 `pageContext` 옵션 값을 따르며, 설정하지 않으면 `full`입니다. 덜 보내려면 설정에 `pageContext: 'metadata'`나 `'none'`을 넣으세요.
- 서버는 수준을 확인하지 않고, 페이지가 보낸 데이터를 그대로 받습니다.

SDK는 보내기 전에 페이지 텍스트의 입력 필드와 표시된 영역을 마스킹합니다([브라우저의 마스킹](#브라우저의-마스킹) 참고). 그 밖에 보이는 텍스트는 페이지에 보이는 그대로 전송됩니다.

Moss는 각 턴에서 모델에 보낸 내용의 기록을 페이지 텍스트를 포함해 대화와 함께 저장합니다. 이 기록은 대화와 함께 삭제됩니다.

### 스크린샷

**스크린샷은 브라우저의 화면 캡처 API로 찍은 브라우저 탭의 원본 화면입니다. 아무것도 마스킹되지 않습니다.** 입력 필드도, `data-moss-redact`로 표시한 영역도 그대로 찍힙니다.

스크린샷은 다음 조건을 모두 만족할 때만 질문과 함께 찍힙니다.

1. **비전이 켜져 있습니다.** **구성 > 동작 > 주요 기능**의 **비전 사용** 설정(기본값은 꺼짐)을 따르지만, 페이지의 SDK 설정에 `useVision`이 있으면 그 값이 어느 쪽으로든 애플리케이션 설정보다 우선합니다. `useVision: false`이면 스크린샷을 찍지 않고, `useVision: true`이면 **비전 사용**이 꺼져 있어도 찍습니다.
2. **페이지 컨텍스트가 `full`입니다.**
3. **사용자가 화면 공유를 허용했습니다.** 스크린샷이 필요한 첫 질문에서 브라우저의 화면 공유 창이 열리고, 사용자는 현재 탭을 공유해야 합니다. 거부하면 스크린샷 없이 채팅이 계속됩니다.

브라우저는 서명된 업로드 링크로 스크린샷을 파일 저장소에 올리고, 질문은 그 스크린샷을 참조합니다. 업로드에 실패하면 이미지를 질문에 담아 보냅니다. 모델이 이미지를 받을 수 있으면 이미지를 받습니다. 0.17.0부터는 10MiB가 넘는 스크린샷은 올리지 않고 스크린샷 없이 답하며, 질문은 자기 채팅에 올린 스크린샷만 쓸 수 있습니다.

### 화면 기록

기본값은 꺼짐입니다. 화면 기록은 사용자가 최근에 한 클릭, 입력, 이동, 페이지 변화를 짧은 텍스트 타임라인으로 정리한 것으로, 질문할 때마다 모델에 함께 전달됩니다.

- **CDN 스크립트:** **구성 > 동작 > 주요 기능**의 **LLM용 화면 기록 활성화** 설정을 따릅니다. 단, 페이지가 `window.mossSettings`에 `enableScreenHistoryRecording`을 넣으면 그 값이 어느 쪽으로든 우선합니다.
- **npm 패키지:** 설정에 `enableScreenHistoryRecording: true`가 있을 때만 보냅니다.
- 서버는 애플리케이션 설정을 확인하지 않고, 페이지가 보낸 화면 기록을 그대로 받습니다.

화면 기록은 세션 녹화와 같은 페이지 내 녹화기로 만들어지며, 이 녹화기는 채팅이 열려 있는 동안 작동합니다. 0.17.0부터는 마스킹도 녹화와 같습니다. `redactAllInputs`가 켜져 있으면(기본값) 사용자가 입력 필드에 입력한 내용이 마스킹됩니다. 0.16.x에서는 화면 기록에 사용자가 입력한 내용이 들어갈 수 있습니다.

화면 기록은 각 턴에서 모델에 보낸 내용의 기록에 저장되며, 대화와 함께 삭제됩니다.

### 세션 녹화

기본값은 꺼짐입니다. 녹화는 채팅이 열려 있는 동안 페이지 구조와 사용자 활동을 담아, 대시보드에서 세션을 다시 볼 수 있게 합니다. 녹화는 모델에 전달되지 않습니다.

- 애플리케이션의 **세션 리플레이 활성화**(**구성 > 동작 > 주요 기능**)가 켜져 있어야 합니다. 꺼져 있으면 서버가 녹화를 받지 않습니다.
- **CDN 스크립트:** 애플리케이션 설정이 켜져 있으면 녹화합니다. 페이지에서 `enableSessionRecording: false`로 끌 수 있습니다.
- **npm 패키지:** 설정에 `enableSessionRecording: true`도 있어야 녹화합니다.
- 캔버스 내용은 녹화되지 않고, 이미지는 녹화에 복사되지 않습니다.
- 0.17.0부터 녹화에서도 입력 필드와 표시된 영역이 마스킹됩니다([브라우저의 마스킹](#브라우저의-마스킹) 참고).
- 0.17.0부터 업로드 한 번은 16MiB, 이벤트 12,000개까지이고, 세션 하나는 64MiB, 이벤트 100,000개, 업로드 720번까지입니다.

<Note>
    0.17.0에서 바뀐 점: 애플리케이션은 **세션 리플레이 활성화**가 켜진 상태로 저장되어 있을 때만 녹화합니다. 0.16.x에서는 이 설정을 한 번도 저장하지 않은 애플리케이션도 세션을 녹화했습니다.
</Note>

### 페이지 스냅샷

페이지 스냅샷은 오프라인 분석을 위해 질문과 함께 저장하는 페이지 HTML 사본입니다. 마스킹되지 않습니다. SDK는 페이지가 `enableRawDomCapture: true`를 설정했을 때만 보내고, 서버는 운영자가 개발 또는 테스트 환경에서 이 수집을 켰을 때만 받습니다. 프로덕션으로 실행 중인 서버는 페이지 스냅샷을 모두 거부합니다.

### 업로드한 파일

베타 기능이며, 페이지가 `appearance.chrome.attachments: true`를 설정하지 않으면 꺼져 있습니다(0.17.0에서 추가). 켜면 사용자가 PDF, PNG, JPEG 파일을 메시지당 5개, 파일당 10MiB까지 첨부할 수 있습니다. 파일은 대화와 함께 파일 저장소에 저장됩니다. 모델에는 파일 이름만 전달되며 모델은 파일을 읽지 않습니다. 파일 자체는 사용자가 확인한 단계에서, 파일을 받는 API 작업이나 MCP 도구에만 전달됩니다.

### API 로그

기본값은 꺼짐입니다. 관리자가 **API 로그 기록**(**분석 > API 로그**, 또는 **구성 > 데이터 및 개인정보**의 **API 상세 로그 수집**)을 켜면, Moss는 애플리케이션의 API 호출 요청과 응답을 저장합니다. 위젯의 요청과, Moss가 AI 모델·파일 저장소·API 작업을 호출한 기록 등이 해당합니다. 본문은 저장하기 전에 마스킹됩니다. [API 로그의 마스킹](#api-로그의-마스킹)을 참고하세요. [API 로그](/ko/dashboard/analytics#api-로그)도 참고하세요.

### 사용자 ID와 메타데이터

- **사용자 ID:** 사용자의 서명된 토큰의 `sub` 클레임에서 가져오며, 요청 본문에서는 가져오지 않습니다. 사용자의 프로필과 대화를 식별합니다.
- **메타데이터:** 페이지가 `userMetadata`와 토큰의 `metadata` 클레임으로 넘기는 속성입니다. 사용자 프로필에 저장되고 모델의 프롬프트에 추가되어, 어시스턴트가 그 사용자에 맞게 답할 수 있게 합니다. 이름, 이메일, 전화번호 같은 개인정보를 그대로 넣지 말고 역할과 분류를 넘기세요.

[인증](/ko/sdk/authentication)을 참고하세요.

### 상호작용 보고

가이드 단계가 가리키는 요소를 사용자가 조작하면, SDK는 이를 Moss에 보고합니다. 그 시점의 페이지 컨텍스트와, 사용자가 조작한 요소의 텍스트·레이블·마크업이 담깁니다. 요소의 마크업은 브라우저에서 페이지 텍스트와 같은 방식으로 마스킹됩니다. 보고는 턴과 함께 저장됩니다. 다음 단계를 정하기 위해 모델은 요소에 대한 짧은 설명과 함께, 질문할 때와 같이 페이지 텍스트, 화면 기록, 스크린샷을 받습니다.

### 피드백

사용자가 답변이나 세션을 평가하면, Moss는 평가와 댓글을 대화와 함께 저장합니다. 0.17.0부터는 페이지에서 켜면, 싫어요를 누를 때 무엇이 문제였는지 묻고 세션 카드에서 1–5점 평가를 받을 수 있습니다. **백엔드 개인정보 필터링**이 켜져 있으면 모든 댓글이 필터링됩니다. 피드백은 사용자의 질문과 함께 모델에 전달되지 않으며, 대시보드의 코파일럿과 셀프 힐링 기능이 읽습니다.

## 데이터 저장 위치

| 저장소 | 보관하는 데이터 |
| --- | --- |
| **데이터베이스** | 대화와 메시지, 각 턴에서 모델에 보낸 내용의 기록(페이지 텍스트, 화면 기록), 사용자 프로필과 메타데이터, API 로그, 감사 이벤트, 삭제 요청, 애플리케이션 설정 |
| **파일 저장소** | 스크린샷과 업로드한 파일은 한 버킷에, 세션 녹화는 두 번째 버킷에, 페이지 스냅샷은 세 번째 버킷에 저장하며, 모두 대화 ID 아래에 둡니다. |
| **지식 베이스 색인** | 검색에 쓰는 도움말 콘텐츠. 최종 사용자의 대화는 들어 있지 않습니다. |
| **사용자 브라우저** | `localStorage`에는 열려 있는 채팅의 ID와 사용자 ID, 그리고 사용자의 최근 채팅 10개가 각각 첫 질문의 처음 100자와 사용자 ID와 함께 저장됩니다. 이 값은 SDK가 바꾸거나 브라우저의 사이트 데이터를 지울 때까지 남습니다. 가이드 단계의 클릭으로 다른 페이지가 열리는 동안에는 그 단계의 제목, 페이지 URL, 클릭한 요소의 마스킹된 마크업도 `localStorage`에 담기며, 새 페이지가 이를 보내거나 제한 시간이 지나면 사라집니다. 탭을 닫으면 브라우저가 지우는 `sessionStorage`에는 열려 있는 채팅과 그 탭에서 끝난 채팅의 메시지, `askMoss()`로 넘긴 질문(보낼 때까지), 제출 응답을 기다리는 지원 티켓의 내용이 담깁니다. CDN 스크립트는 사용자 ID를 `localStorage`의 `moss_user_id`에도 저장하며, 페이지가 사용자 ID를 주지 않으면 익명 ID(`anon_…`)를 만듭니다. 자동 삭제도, 사용자 데이터 삭제도 이 사본에는 미치지 않습니다. |

대시보드는 스크린샷과 녹화를 서명된 링크로 보여 주며, 링크는 기본적으로 7일 동안 유효합니다. 링크가 만료되면 그 링크로는 접근할 수 없지만, 파일이 삭제되지는 않습니다.

자체 호스팅 설치에서는 운영자가 설정한 데이터베이스, 파일 저장소, 모델 제공업체를 씁니다.

### 데이터를 볼 수 있는 사람

관리자뿐 아니라 조직의 모든 멤버가 조직 내 모든 애플리케이션의 세션, 대화 기록, 리플레이를 열고 세션을 내보낼 수 있습니다. API 로그, **데이터 및 개인정보**, 감사 로그는 관리자만 볼 수 있습니다.

**외부 AI 어시스턴트**(0.17.0에서 추가). 배포에서 AI 어시스턴트를 제공하고 관리자가 **AI 어시스턴트 허용**(기본값은 꺼짐)을 켜면, 멤버마다 데스크톱 채팅 앱 같은 자신의 AI 어시스턴트를 Moss에 연결할 수 있습니다. 어시스턴트는 그 멤버가 볼 수 있는 것을 읽습니다. 관리자가 **대화 내용**(기본값은 켜짐)을 끄지 않으면, 최종 사용자가 쓴 내용(대화 기록, 질문, 인용, 피드백 댓글)도 여기에 포함됩니다. 어시스턴트가 읽은 내용은 그 어시스턴트의 제공업체로 전달됩니다. [AI 어시스턴트](/ko/dashboard/ai-assistants#어시스턴트가-읽을-수-있는-것)를 참고하세요.

역할은 [최종 사용자의 대화를 볼 수 있는 사람](/ko/security/authentication#최종-사용자의-대화를-볼-수-있는-사람)과 [대시보드 개요](/ko/dashboard/overview)를 참고하세요.

## 모델 제공업체로 전달되는 데이터

**채팅 모델**은 질문할 때마다 다음을 받습니다.

- 질문과 그 대화의 이전 메시지
- 페이지 URL과 제목, 그리고 `full` 수준에서는 페이지 텍스트
- 스크린샷을 찍었고 모델이 이미지를 받을 수 있으면 스크린샷
- 켜져 있으면 화면 기록
- 사용자의 메타데이터
- 지식 베이스에서 가져온 발췌문과 AI 지침
- API 작업처럼 어시스턴트가 실행한 도구의 결과
- 사용자가 가이드 단계를 조작하면 그 요소에 대한 짧은 설명. 이 턴에도 질문할 때와 같이 페이지 텍스트, 화면 기록, 스크린샷이 전달됩니다.

Moss는 대시보드의 코파일럿, 평가 점수, 대화 인사이트, 모니터, 셀프 힐링에도 대화 내용을 모델에 보냅니다.

0.17.0부터 배포에서 여러 모델을 제공하면, **구성 > 동작 > 모델**에서 애플리케이션에 답하는 모델과 데이터 처리자를 확인할 수 있습니다("이 모델로 보내는 데이터는 …에서 처리됩니다."). 모델을 바꿀 때는 먼저 확인을 받습니다. 선택한 모델을 쓸 수 없는 동안에는 배포의 기본 모델이 대신 답하고 카드에 그렇게 표시됩니다. 단, 대체를 허용하지 않는 것으로 표시된 모델은 예외입니다.

**임베딩 제공업체**는 지식 베이스를 색인할 때 그 콘텐츠를, 질문할 때마다 검색 텍스트를 받습니다.

**선택형 모델**은 두 가지 모두 기본값이 꺼짐입니다. 배포를 운영하는 쪽(Moss 호스팅 서비스는 Moss, 자체 호스팅 설치는 운영자)이 각 모델을 쓸지, 어느 제공업체가 실행할지를 정합니다.

- **스크린샷 분석 모델**
- **요소 지정 모델**: 가이드 단계가 강조할 요소를 고릅니다. 가이드 단계의 텍스트와, 페이지 텍스트에서 뽑은 페이지의 상호작용 요소 목록(요소마다 역할, 속성, 보이는 텍스트)을 받습니다. 운영자가 이 모델을 켜고 제공업체를 허용했을 때, 그리고 그 제공업체를 지정한 애플리케이션에서만 실행되며, 다른 제공업체로 넘어가지 않습니다. 호출이 실패하면 채팅 모델이 고른 요소를 그대로 씁니다.

지식 베이스를 색인할 때 Moss는 지식 베이스의 이미지를 이미지 모델에 보내 설명을 만들 수도 있습니다. 이것은 사용자 데이터가 아니라 도움말 콘텐츠입니다.

자체 호스팅 설치에서는 운영자의 설정이 채팅 모델과 임베딩 제공업체를 정합니다. [모델과 응답 시간](/ko/self-hosting/models-and-response-time)을 참고하세요. 선택형 모델과 이미지 모델도 운영자 설정입니다.

## 마스킹과 필터링

마스킹은 세 곳에서 일어납니다. 사용자 브라우저, 저장하거나 모델에 보내기 전의 서버, 그리고 API 로그입니다.

### 브라우저의 마스킹

SDK는 페이지 데이터가 브라우저를 떠나기 전에 마스킹합니다. 옵션은 페이지 코드에서 설정합니다. [페이지 데이터](/ko/sdk/page-data)를 참고하세요.

| 대상 | 페이지 텍스트 | 세션 녹화(0.17.0부터) | 스크린샷 | 페이지 스냅샷 |
| --- | --- | --- | --- | --- |
| 입력 필드: `input`, `textarea`, `select`, 편집 가능한 영역(`redactAllInputs`, 기본값은 켜짐) | 마스킹됨 | 마스킹됨 | 마스킹 안 됨 | 마스킹 안 됨 |
| `data-moss-unredact`로 표시한 필드 | 마스킹 안 됨 | 그래도 마스킹됨 | 마스킹 안 됨 | 마스킹 안 됨 |
| `data-moss-redact`로 표시했거나 `redactionSelectors`에 맞는 영역 | 마스킹됨 | 마스킹됨 | 마스킹 안 됨 | 마스킹 안 됨 |
| 그 밖에 보이는 텍스트 | 마스킹 안 됨 | 마스킹 안 됨 | 마스킹 안 됨 | 마스킹 안 됨 |

- `redactionSelectors`에 잘못된 항목이 있으면 그 세션의 녹화가 멈추며, 오류는 브라우저 콘솔에만 나옵니다.
- 0.17.0 이전에는 세션 녹화가 마스킹되지 않았습니다.
- 화면 기록은 녹화의 마스킹을 따릅니다([화면 기록](#화면-기록) 참고).

### 백엔드 개인정보 필터링

<Info>
    0.17.0에서 추가되었습니다.
</Info>

**구성 > 보안 > 백엔드 개인정보 필터링**은 Moss가 요청을 저장하거나 모델에 보내기 전에, 서버에서 일반적인 개인정보 패턴을 `[REDACTED]`로 바꿉니다. 대화 기록, 저장된 턴 기록, API 로그, 모델에는 모두 필터링된 같은 텍스트가 전달됩니다. 이미 저장된 데이터는 바뀌지 않습니다. 모든 설치 방식에 적용되며, 관리자만 바꿀 수 있습니다.

**켜기.** **이 애플리케이션의 요청 필터링**으로 애플리케이션의 필터를 켜거나 끕니다. 관리자가 설정하기 전까지 애플리케이션은 배포 기본값을 따르며, 운영자가 설치 전체에 켜지 않았다면 기본값은 꺼짐입니다(자체 호스팅 설치에서는 `PII_FILTER_DEFAULT_ENABLED`). **배포 기본값 사용**을 누르면 애플리케이션 자체 설정이 지워집니다.

**필터링 대상**(하나 이상):

| 대상 | 범위 | 기본값 |
| --- | --- | --- |
| **페이지 컨텍스트** | 페이지 텍스트, 화면 기록 타임라인, 페이지 제목 | 켜짐 |
| **상호작용 보고** | 사용자가 조작한 요소의 텍스트, 레이블, 마크업 | 켜짐 |
| **채팅 메시지** | 사용자가 입력한 내용 | 꺼짐. 사용자가 묻는 값 자체를 지울 수 있기 때문입니다 |

필터가 켜져 있으면 피드백 댓글은 항상 필터링됩니다.

**패턴.**

- 필터가 켜져 있으면 항상: 이메일 주소, 미국 전화번호, 결제 카드 번호, 미국 사회보장번호
- **추가 패턴**(각각 선택): IPv4 주소, IBAN(체크섬 검증), 주민등록번호
- **사용자 지정 패턴**: 최대 25개, RE2 문법, 패턴당 최대 200자. 전방·후방 탐색과 역참조는 지원하지 않습니다. 빈 텍스트에 맞는 패턴은 쓸 수 없습니다. 패턴마다 고유한 이름이 필요하며, 이름은 영문 소문자로 시작하고 영문 소문자, 숫자, 밑줄만 쓸 수 있고 기본 제공 이름과 겹치면 안 됩니다.

적용하려면 **개인정보 설정 저장**을 누르세요.

**검사하지 못하면 막습니다.** 필터가 어떤 필드의 검사를 끝내지 못하면, 필터링하지 않은 채 넘기지 않고 필드 전체를 보내지 않습니다.

**필터링하지 않는 데이터:**

- 페이지 URL, 그리고 페이지 텍스트 안의 링크·이미지 주소(`mailto:`, `tel:`, `sms:` 링크는 필터링됩니다)
- 스크린샷, 세션 녹화, 페이지 스냅샷, 업로드한 파일
- 사용자 메타데이터
- 지식 베이스 콘텐츠, API 작업과 도구의 결과, 모델의 답변

<Warning>
    자체 호스팅 설치를 0.16.25로 롤백하면 필터가 꺼집니다. 0.16.25는 이 설정을 무시하므로, 다시 업그레이드할 때까지 페이지, 상호작용, 채팅 텍스트가 필터링되지 않은 채 저장되고 모델에 전달됩니다.
</Warning>

### API 로그의 마스킹

0.17.0부터 API 로그의 요청과 응답 본문은 저장하기 전에 마스킹됩니다.

- `[REDACTED]`는 토큰, 비밀번호, 시크릿, 쿠키, 인증 헤더, API 키 같은 자격 증명 키의 값을 대신합니다. 키는 대소문자나 구분자와 관계없이 찾습니다.
- `[REDACTED]`는 이메일 주소, 전화번호(미국 형식, 그리고 `+`와 국가 번호로 쓴 국제 번호), 미국 사회보장번호, 카드 번호도 대신하며, 애플리케이션의 **백엔드 개인정보 필터링**이 켜져 있으면 그 패턴에 맞는 값도 대신합니다.
- `[OMITTED]`는 아예 저장하지 않은 항목을 표시합니다. 헤더, URL과 경로, 페이지 텍스트, HTML, 파일, 2KB를 넘는 텍스트, 오류 상세가 해당합니다.

이름, 주소, 그 밖의 자유 텍스트는 마스킹되지 않습니다.

0.16.x에서는 몇 가지 자격 증명 키(API 키, authorization, 비밀번호, 시크릿, 토큰. 이름이 정확히 같을 때만)의 값만 바꾸며, 이메일, 전화번호, 페이지 텍스트를 비롯한 본문의 나머지는 보낸 그대로 저장합니다.

## 페이지 텍스트와 도움말 콘텐츠는 지시가 아닙니다

페이지나 도움말 문서의 텍스트가 어시스턴트에게 무언가를 시키려 할 수 있습니다. 0.17.0부터 Moss는 이런 텍스트를 지시가 아니라 답변에 참고할 내용으로 다룹니다.

- 모델에는 Moss의 프롬프트, 관리자가 정한 AI 지침, 사용자가 직접 보낸 메시지만 지시이며, 페이지 텍스트, 화면 기록, 도움말 문서, 도구 결과, 사용자 메타데이터, 모델 자신의 이전 답변은 내용일 뿐이고, 그 안에 있는 지시는 따르지 말라고 알립니다.
- 페이지 텍스트는 프롬프트에서 자기 블록을 벗어날 수 없게 감싸며, 페이지 텍스트나 도움말 콘텐츠의 줄 가운데 프롬프트 자체의 레이블처럼 보이는 줄에는 페이지나 문서 내용이라는 표시를 붙입니다.
- 답변은 페이지 자체의 사이트, 허용 도메인, 지식 베이스의 호스트, `replyLinks.allowedHosts`로 추가한 호스트에서만 링크를 열고 이미지를 불러옵니다. 그 밖의 링크는 일반 텍스트로, 이미지는 대체 텍스트로 표시되므로, 답변이 외부 주소를 불러오면서 페이지 데이터를 내보낼 수 없습니다.

**안전 필터가 요청을 차단할 때.** Moss는 Google Cloud 프로젝트의 Model Armor 같은 모델 제공업체의 안전 필터를 설정하지 않습니다. 안전 필터는 제공업체에서 설정하세요. Gemini의 안전 필터나 Model Armor가 요청이나 답변을 차단하면, 사용자에게는 "A safety filter blocked this request, so I can't answer it. If it keeps happening on this page, please contact your administrator."라는 답변이 표시됩니다. 다시 시도 버튼은 없습니다. 0.17.0부터 대시보드는 그 턴에 "안전 필터가 요청을 차단했습니다"라고 표시합니다.

## 데이터 보관 기간

0.17.0에서 추가된 자동 삭제는 관리자가 **구성 > 데이터 및 개인정보**에서 켜기 전까지 모든 애플리케이션에서 꺼져 있습니다. 그때까지 Moss는 아래 데이터를 누군가 삭제할 때까지 보관합니다.

| 데이터 | 자동 삭제를 켰을 때의 기간(기본값) |
| --- | --- |
| 대화와 그 메시지, 페이지 텍스트, 화면 기록, 업로드한 파일 | 삭제할 때까지 보관 |
| 스크린샷 | 7일 |
| 세션 녹화 | 삭제할 때까지 보관 |
| 페이지 스냅샷 | 삭제할 때까지 보관 |
| API 로그 | 90일 |
| 사용자 프로필과 메타데이터 | 사용자의 마지막 대화와 함께 삭제 |

- 위의 다섯 종류는 관리자가 1일에서 36,500일 사이의 기간이나 삭제할 때까지 보관을 고를 수 있습니다.
- 대화를 삭제하면 그 대화의 스크린샷, 녹화, 페이지 스냅샷, API 로그도 함께 삭제됩니다.
- 감사 이벤트는 Moss 관리자가 정한 기간(기본값 365일) 동안 보관됩니다. [감사 로깅](/ko/security/audit-logging)을 참고하세요.
- 사용자 한 명의 데이터는 언제든 삭제할 수 있으며, 삭제 증명서가 발급됩니다. [사용자 데이터 삭제](/ko/dashboard/data-privacy#사용자-데이터-삭제)를 참고하세요.
- 자동 삭제는 헬프데스크로 이미 보낸 티켓, 사용자 브라우저에 남은 사본, 고객사 백업에는 미치지 않습니다.

Moss 호스팅 서비스의 보존기간은 계약, 문서화된 고객 지시 및
[개인정보 처리방침](https://viamoss.ai/legal-terms/privacy-policy)에 따라 결정합니다.

법적 보존, 최소 기간, 자체 호스팅 설치에 필요한 설정 등 자세한 내용은 [데이터 및 개인정보](/ko/dashboard/data-privacy)에 있습니다. 위젯에서 채팅 세션이 유지되는 시간은 별도의 설정이며 아무것도 삭제하지 않습니다. [세션](/ko/sdk/api/session)을 참고하세요.

## 암호화

### 전송 중

Moss의 공개 서비스 엔드포인트에는 HTTPS가 적용됩니다:

- **TLS 1.2 이상** - 공개 API 연결 암호화
- **인증서 검증** - 엄격한 인증서 확인

### 저장 시

#### Moss 호스팅 서비스

Moss 데이터베이스에 저장된 데이터는 보호됩니다:

- **데이터베이스 암호화** - Moss가 호스팅하는 데이터베이스에 AES-256 저장 암호화 적용

#### 저장된 자격 증명 (모든 설치 환경)

애플리케이션이 저장하는 자격 증명을 다루는 방식이며, Moss 호스팅 서비스와 자체 호스팅 설치에 똑같이 적용됩니다:

- **자격 증명 보호** - API 키 검증용 해시와 재사용 자격 증명 암호화
- **보안 키 저장** - 암호화 키가 데이터와 별도로 관리

자세한 내용은 [자격 증명 저장](#자격-증명-저장)에 있습니다.

## 자격 증명 저장

### API 키

API 키는 API 로그 접근 키와 감사 API 키 두 가지입니다. SDK용 API 키는 없으며, SDK는 서명된 토큰을 씁니다. API 키는 절대 평문으로 저장되지 않습니다:

| 단계 | 보호 |
|------|------|
| 생성 | 암호학적으로 무작위 (`secrets.token_urlsafe`) |
| 저장 | SHA-256 해시 |
| 검증 | SHA-256 해시로 조회 |
| 표시 | 생성 시 한 번만 표시, 이후 검색 불가 |

### JWT 서명 키

JWT 비밀은 향상된 보호를 받습니다:

| 단계 | 보호 |
|------|------|
| 생성 | 256비트 엔트로피 (`secrets.token_urlsafe(32)`) |
| 저장 | 저장 시 암호화 |
| 로테이션 | 여러 활성 키 지원 |
| 폐기 | 유예 기간이 있는 예정된 폐기 |

대신 공개 키(RS256 또는 ES256)를 등록하면 Moss는 공개 키만 보관하며 서명에 쓰는 비밀은 갖지 않습니다. [인증](/ko/security/authentication)을 참고하세요.

### 암호와 유사한 비밀

최종 사용자 비밀번호와 로그인 비밀정보는 해당 배포의 인증 제공자가 관리하며,
Moss는 이를 수집하거나 저장하지 않습니다. 재사용이 필요한 연동 자격 증명은
암호화하여 저장합니다.

## 도메인 화이트리스트

허용 도메인 목록은 다른 웹사이트가 내 애플리케이션 ID로 Moss를 불러오지 못하게 막습니다.

### 설정

SDK를 실행하는 도메인을 **구성 > 보안 > 도메인 접근 제어 > 허용 도메인**에 모두 추가하세요.

```
app.example.com
*.example.com
localhost:3000
```

- 각 항목은 그 호스트와 정확히 일치해야 합니다. `*.example.com`은 `example.com`의 모든 하위 도메인과 일치하지만, `example.com` 자체와는 일치하지 않습니다.
- 포트를 적은 항목은 그 포트에만 일치하고, 포트가 없으면 모든 포트에 일치합니다. `:443`은 적지 마세요.

### 적용

Moss는 SDK가 설정을 불러올 때와 모든 SDK 요청에서, `Origin` 헤더(없으면 `Referer`)로 페이지 주소를 확인합니다. 목록이 비어 있지 않은데 목록에 없는 페이지는 코드 `DOMAIN_NOT_ALLOWED`와 함께 `403`을 받고, 그 페이지에서는 Moss가 로드되지 않습니다. 목록에 항목이 하나라도 있으면 샌드박스 프레임이나 `file://` 페이지는 거부됩니다.

목록이 비어 있으면 모든 페이지를 허용합니다. 단, 설치 운영자가 허용 도메인을 필수로 설정했다면 예외입니다. SDK 설정을 포함한 같은 규칙이 [SDK 인증](/ko/sdk/authentication#허용-도메인)에도 있습니다.

이 목록은 인증 수단이 아닙니다. 브라우저가 보내는 헤더에 의존하므로, 브라우저 밖의 클라이언트는 막지 못합니다. 모든 SDK 요청에는 유효한 서명된 토큰이 있어야 합니다. [인증](/ko/security/authentication)을 참고하세요.

<Warning>
    화이트리스트에 모든 환경(프로덕션, 스테이징, 개발)을 포함하는 것을
    잊지 마세요.
</Warning>

## 입력 검증

API 요청 본문과 매개변수는 Moss가 처리하기 전에 타입이 정해진 스키마로 검사합니다. 필드가 빠졌거나 잘못된 요청은 `422`로 거부되며, 문제마다 항목이 나옵니다.

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "user_id"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
```

SDK 엔드포인트에서는 본문에 `problem`과 `reference` 필드도 들어 있으며, SDK는 이 필드로 오류를 표시합니다.

## 자주 묻는 질문

**최종 사용자의 브라우저에서 무엇이 나가나요?**
질문, 페이지 URL과 제목, 입력 필드와 표시된 영역을 마스킹한 페이지 텍스트, 사용자가 가이드 단계를 조작할 때의 상호작용 보고, 그리고 피드백입니다. 켜면 스크린샷(마스킹 안 됨), 화면 기록, 세션 녹화(마스킹됨), 업로드한 파일도 나갑니다. SDK는 최근 채팅의 짧은 목록도 브라우저 저장소에 보관합니다. [Moss가 수집하는 데이터](#moss가-수집하는-데이터)를 참고하세요.

**페이지 텍스트와 스크린샷을 보내지 않으려면 어떻게 하나요?**
페이지 컨텍스트를 `metadata`(URL과 제목만)나 `none`으로 쓰세요. CDN 스크립트에서는 **화면 가이드**를 끄면 됩니다. 단, 페이지가 `window.mossSettings`에 `pageContext`를 직접 넣었다면 그 값이 우선합니다. npm에서는 설정에 `pageContext`를 넣으세요. 스크린샷만 막으려면 **비전 사용**을 끈 채로 두고 페이지에 `useVision: true`를 넣지 않거나, `useVision: false`를 넣으세요. [페이지 데이터](/ko/sdk/page-data)를 참고하세요.

**스크린샷은 마스킹되나요?**
아니요. 스크린샷은 브라우저 탭의 원본 화면입니다. 세션 녹화는 0.17.0부터 마스킹되지만 스크린샷은 마스킹되지 않습니다. 모델에 보내면 안 되는 데이터가 보이는 페이지에서는 비전을 켜지 마세요.

**개인정보를 모델에 닿기 전에 지울 수 있나요?**
[백엔드 개인정보 필터링](#백엔드-개인정보-필터링)을 켜고, 자사 식별자에 맞는 패턴을 추가하세요. 스크린샷, 녹화, 업로드한 파일에는 적용되지 않습니다.

**페이지의 텍스트가 어시스턴트에게 다른 일을 시킬 수 있나요?**
0.17.0부터 Moss는 페이지 텍스트, 도움말 문서, 도구 결과를 지시가 아니라 내용으로 다루라고 모델에 알리며, 답변은 허용된 호스트에서만 링크를 열고 이미지를 불러옵니다. [페이지 텍스트와 도움말 콘텐츠는 지시가 아닙니다](#페이지-텍스트와-도움말-콘텐츠는-지시가-아닙니다)를 참고하세요.

**우리 회사에서 누가 최종 사용자의 대화를 읽을 수 있나요?**
조직의 모든 멤버가 조직 내 모든 애플리케이션의 대화를 읽을 수 있으며, 리플레이와 세션 내보내기도 포함됩니다. 관리자가 AI 어시스턴트를 허용하면, **대화 내용**이 꺼져 있지 않은 한 멤버가 연결한 어시스턴트도 대화 내용을 읽을 수 있습니다. [데이터를 볼 수 있는 사람](#데이터를-볼-수-있는-사람)을 참고하세요.

**클라우드 프로젝트에서 Model Armor 같은 안전 필터를 써도 되나요?**
네. Moss는 안전 필터를 설정하거나 바꾸지 않습니다. Gemini의 안전 필터나 Model Armor가 요청을 차단하면 사용자에게 안전 필터가 차단했다는 답변이 표시되고, 대시보드에는 그 턴이 표시됩니다. [안전 필터가 요청을 차단할 때](#페이지-텍스트와-도움말-콘텐츠는-지시가-아닙니다)를 참고하세요.
