## 개요

Moss는 정보가 전체 수명 주기 동안 안전하게 유지되도록 여러 계층의 데이터 보호를 구현합니다.

[보안 개요](/ko/security/overview#배포-범위)의 호스팅·운영 책임 경계가 여기도 적용됩니다.
고객 관리형 인프라·인증·스토리지는 합의된 배포를 따르며, 아래 호스팅 예시가 계약 밖의
데이터 전송이나 지원 접근을 허용하지 않습니다.

---

## 암호화

### 전송 중

Moss의 공개 서비스 엔드포인트에는 HTTPS가 적용됩니다:

- **TLS 1.2 이상** - 공개 API 연결 암호화
- **인증서 검증** - 엄격한 인증서 확인

### 저장 시

Moss 데이터베이스에 저장된 데이터는 보호됩니다:

- **데이터베이스 암호화** - Moss가 호스팅하는 데이터베이스에 AES-256 저장 암호화 적용
- **자격 증명 보호** - API 키 검증용 해시와 재사용 자격 증명 암호화
- **보안 키 저장** - 암호화 키가 데이터와 별도로 관리

## 입력 검증

API 요청 스키마로 처리 전 입력을 검증합니다:

### 스키마 검증

Pydantic 스키마로 요청 필드와 검증 규칙을 정의합니다:

```python
class SessionRequest(BaseModel):
    user_id: str
    application_id: str
    metadata: Optional[dict] = None

    @validator('user_id')
    def validate_user_id(cls, v):
        if len(v) > 256:
            raise ValueError('user_id too long')
        return v
```

### 검증 규칙

| 입력 유형 | 검증 |
|----------|------|
| 문자열 필드 | 길이 제한, 형식 검증 |
| ID | UUID 형식 확인 |
| 열거형 | 허용된 값만 |
| 중첩된 객체 | 재귀적 검증 |

### 거부 동작

유효하지 않은 요청은 명확한 오류 응답을 받습니다:

```json
{
  "detail": [
    {
      "loc": ["body", "user_id"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

## 민감한 데이터 처리

### 자동 편집

요청 로그의 정제기는 저장 전에 알려진 자격 증명 필드를 가립니다:

**편집되는 필드:**
- `api_key`, `apiKey`
- `authorization`
- `password`
- `secret`
- `token`
- `x-api-key`

**작동 방식:**

```python
# 로깅 전
{
    "user_id": "user-123",
    "api_key": "app_abc123xyz..."
}

# 정제 후
{
    "user_id": "user-123",
    "api_key": "[REDACTED]"
}
```

### 재귀적 정제

편집은 중첩된 객체와 배열에도 적용됩니다:

```python
{
    "config": {
        "auth": {
            "token": "[REDACTED]"  # 중첩된 필드도 정제됨
        }
    }
}
```

## 자격 증명 저장

### API 키

API 키는 절대 평문으로 저장되지 않습니다:

| 단계 | 보호 |
|------|------|
| 생성 | 암호학적으로 무작위 (`secrets.token_urlsafe`) |
| 저장 | SHA-256 해시 |
| 비교 | 상수 시간 비교 (타이밍 안전) |
| 표시 | 생성 시 한 번만 표시, 이후 검색 불가 |

### JWT 서명 키

JWT 비밀은 향상된 보호를 받습니다:

| 단계 | 보호 |
|------|------|
| 생성 | 256비트 엔트로피 (`secrets.token_urlsafe(32)`) |
| 저장 | 저장 시 암호화 |
| 로테이션 | 여러 활성 키 지원 |
| 폐기 | 유예 기간이 있는 예정된 폐기 |

### 암호와 유사한 비밀

최종 사용자 인증정보(비밀번호 또는 그 밖의 비밀정보)는 해당 배포의 인증 제공자가 관리하며,
Moss는 이를 수집하거나 저장하지 않습니다. 이는 위에서 설명한 서비스 API 키, JWT 서명 키,
재사용 연동 자격증명과 구분됩니다. 재사용이 필요한 연동 자격증명은 암호화하여 저장합니다.

프로덕션에서는 모든 SDK 요청에 인증이 적용되며, 격리된 개발 환경 외에서는 비활성화할 수 없습니다.

## 도메인 화이트리스트

승인된 도메인으로 SDK 사용 제한:

### 설정

**설정 > 보안**에서 대시보드에 허용된 도메인 설정:

```
app.example.com
staging.example.com
localhost:3000
```

### 적용

| 시나리오 | 동작 |
|----------|------|
| 빈 화이트리스트 | SDK가 모든 도메인에서 작동 |
| 화이트리스트 구성됨 | SDK가 목록의 도메인에서만 작동 |
| 목록에 없는 도메인 | SDK 초기화 실패 |

<Warning>
    화이트리스트에 모든 환경(프로덕션, 스테이징, 개발)을 포함하는 것을
    잊지 마세요.
</Warning>

## 데이터 최소화

Moss는 데이터 최소화 원칙을 따릅니다:

### 수집되는 데이터

| 데이터 유형 | 목적 | 보존 |
|------------|------|------|
| 사용자 ID | 세션 식별 | 해당 보존 정책 적용 |
| 스크린샷 | AI를 위한 시각적 컨텍스트 | 해당 보존 정책 적용 |
| 채팅 메시지 | 대화 히스토리 | 해당 보존 정책 적용 |
| 세션 녹화 | 리플레이 및 디버깅 | 해당 보존 정책 적용 |

Moss 호스팅 서비스의 보존기간은 계약, 문서화된 고객 지시 및
[개인정보 처리방침](https://viamoss.ai/legal-terms/privacy-policy)에 따라 결정합니다.
캡처 설정은 수집을 제어하고, 서명 URL 만료는 접근을 제어하며 객체를 삭제하지 않습니다.
자동 보존기간에 의존하기 전에 해당 앱과 실제 저장소에 삭제 일정이 활성화되어 있는지
확인해야 합니다. 녹화와 지원 과정의 사본은 별도의 범위와 삭제 처리가 필요합니다.

아래 SDK 캡처 옵션이 스크린샷 픽셀의 가림 처리를 보장하지는 않습니다. 페이지 텍스트
가림과 스크린샷 캡처는 별도 제어입니다. 세션·히스토리 녹화 설정만으로 모든 스크린샷
캡처가 꺼졌다고 볼 수 없으므로, 합의된 배포의 별도 캡처 설정을 확인해야 합니다.

### 사용자 제어

사용자는 SDK 설정을 통해 데이터 수집을 제어할 수 있습니다:

```html
<script>
  window.mossSettings = {
    apiUrl: 'https://moss-api.viamoss.ai',
    userId: 'USER_ID',
    enableSessionRecording: false,       // 녹화 비활성화
    enableScreenHistoryRecording: false, // 히스토리 비활성화
  };
</script>
<script src="https://cdn.viamoss.ai/moss-sdk@latest.min.js?applicationId=YOUR_APP_ID"></script>
```

SDK가 로드된 후에 동일한 설정을 적용하려면 `window.MossSDK.boot(...)`에 전달하세요:

```javascript
await window.MossSDK.boot({
    enableSessionRecording: false,
    enableScreenHistoryRecording: false,
})
```
