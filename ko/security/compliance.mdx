## 개요

Moss는 글로벌 규정 준수 표준을 충족하고 사용자 개인정보를 보호하기 위해 최선을 다하고 있습니다. 이 페이지는 규정 요구 사항을 지원하는 규정 준수 상태와 기능을 설명합니다.

---

## GDPR 준수

Moss는 GDPR 준수 의무를 지원하는 기능을 제공합니다.

고객을 대신해 처리하는 데이터에 대해 고객은 개인정보처리자 또는 해당 개인정보처리자를
위해 일하는 주체이며, Moss는 수탁자 또는 재수탁자입니다. 권리 요청은 해당 고객에게
보내세요. Moss가 요청을 받으면 고객에게 신속히 알리고 대응을 지원하며, 문서화된 고객
지시 또는 법률상 의무에 따라 답변합니다. 아래 기능은 권한 있는 고객 운영자를 위한
것으로, 최종 사용자에게 다른 사용자의 기록 접근을 허용하지 않습니다.

### 데이터 주체 권리

#### 접근권 (제15조)

사용자는 자신의 데이터에 대한 접근을 요청할 수 있습니다:

- 대시보드를 통한 채팅 히스토리 내보내기
- 세션 녹화 다운로드
- 활동에 대한 감사 로그 접근

#### 삭제권 (제17조)

Moss는 사용자와 연결된 데이터의 삭제를 지원합니다:

**삭제되는 항목:**
- 채팅 세션 및 메시지
- AI 생성 지침 및 플랜
- 설정된 저장소의 스크린샷 및 녹화
- 사용자 레코드
- 관련 요청 로그

**삭제 프로세스:**

1. API를 통해 삭제를 요청하거나 Moss에 문의
2. Moss가 요청 검증
3. 사용자 레코드와 연결된 애플리케이션 데이터 삭제
4. 검토할 수 있도록 삭제 결과 반환

결과의 확인 범위는 선택한 앱·사용자의 현재 레코드와 설정된 세션 객체 경로입니다.
이 응답만으로 백업, 과거 객체 버전, 외부 처리자 사본, 관리 감사 이벤트 또는 보관 중인
삭제 증빙까지 삭제됐다고 인증하지 않습니다. Moss는 해당 사본을 계약과 고객 지시에
맞춰 별도로 확인합니다. 스토리지 삭제가 실패하면 요청은 미완료로 남고 재시도에 필요한
참조를 유지합니다.

대기열 방식이 활성화된 환경에서는 API가 먼저 영속적인 요청 ID와 상태를 반환합니다.
해당 요청의 완료 상태를 조회하세요. 접수는 삭제 완료 증거가 아닙니다.
고객 관리 인프라와 Moss가 보유한 사본의 운영 책임은 구분됩니다. 계약상 반환·삭제·증명
기한은 정기 보존기간과 별도로 적용됩니다.

종료·만료 시에는 계약상 반환·삭제 선택권, 기존 사본의 삭제 기한 및 서면 증명 요건을
따라야 합니다. 통상적인 백업 만료나 일부 범위의 API 결과로 기한이 연장되지 않습니다.
삭제 예외에는 계약과 적용 법률상 근거가 필요하며, 내부 보존 조치로 고객 약속을
면제할 수 없습니다.

#### 이동권 (제20조)

표준 형식으로 사용자 데이터 내보내기:

- 채팅 히스토리 (JSON)
- 세션 메타데이터 (JSON)
- 감사 로그 (CSV)

### 적법한 근거

개인정보처리자가 자신의 처리에 적용할 적법 근거를 결정하고 문서화합니다. 아래는
가능한 목적과 지원 기능이며, Moss의 독립적인 고객 데이터 재사용 허가가 아닙니다:

| 근거 | 구현 |
|------|------|
| **동의** | SDK가 활성화 전 사용자 동의 요청 가능 |
| **정당한 이익** | 개인정보처리자가 정당성을 확인한 목적과 데이터에 한함 |
| **계약** | AI 어시스턴트 서비스 제공 |

Moss는 계약과 문서화된 지시가 허용한 목적 또는 법률상 요구에 따라서만 고객 데이터를
처리합니다. 이 페이지가 모델 학습·개선을 독립적으로 허용하지 않으며, 해당 콘텐츠를
사용하려면 계약과 문서화된 지시의 명시적 허용이 필요합니다.

### 데이터 처리 계약

요구 사항을 충족하는 데이터 처리 계약(DPA)은 영업팀에 문의하세요.

고객별 보안·사고 통지·하위 처리자 동의·사전 통지 의무에는 해당 DPA와 보안 부속합의가
적용됩니다. 웹사이트 제공자 목록 갱신이나 계속된 서비스 이용이 필요한 서면 통지·동의·
계약 변경 절차를 대체하지 않습니다. 인증이 진행 중이라는 이유로 계약상 통제나 합의된
구현 기한이 면제되지 않습니다.

## SOC 2 Type II

Moss는 SOC 2 Type II 감사를 진행하고 있습니다.

### 신뢰 서비스 기준

| 기준 | 상태 | 설명 |
|------|------|------|
| **보안** | 진행 중 | 무단 접근에 대한 보호 |
| **가용성** | 진행 중 | 운영을 위한 시스템 가용성 |
| **기밀성** | 진행 중 | 기밀 정보 보호 |

### 제어

Moss는 다음 영역에서 제어를 구현합니다:

- **접근 제어** - 역할 기반 접근, MFA, 세션 관리
- **변경 관리** - 코드 검토, 배포 승인, 롤백 기능
- **사고 대응** - 감지, 에스컬레이션, 해결 절차
- **모니터링** - 실시간 알림, 감사 로깅, 이상 감지

### 일정

SOC 2 Type II 감사 준비와 관련 작업이 진행 중입니다. 현재 상태 및 감사 보고서는 영업팀에 문의하세요.

## ISO 27001

Moss는 ISO 27001 인증을 진행하고 있습니다.

### 정보 보안 관리

주요 영역:

- **위험 평가** - 정기적인 보안 위험 평가
- **자산 관리** - 정보 자산의 목록 및 분류
- **접근 제어** - 알아야 할 필요성 및 최소 권한 원칙
- **암호화** - 데이터 보호를 위한 암호화 표준
- **운영 보안** - 안전한 개발 및 배포 관행

### 일정

ISO 27001 인증이 진행 중입니다. 업데이트는 영업팀에 문의하세요.

## EU AI Act

Moss는 AI 기반 어시스턴트 시스템에 적용되는 EU AI Act 준수를 준비하고 있습니다.

### 투명성 요구 사항

Moss는 다음을 통해 투명성을 지원합니다:

- **명확한 AI 식별** - 사용자가 AI와 상호작용하고 있음을 인지
- **기능 공개** - AI 기능 및 제한 사항 문서화
- **결정 설명** - 해당되는 경우 AI 응답에 추론 포함

### 인간 감독

- **사용자 제어** - 사용자가 AI 제안을 무시하거나 재정의 가능
- **관리자 제어** - 애플리케이션 소유자가 AI 동작 사용자 정의 가능
- **감사 추적** - 주요 감사 이벤트와 선택적 상세 요청 로그로 검토 지원

### 위험 분류

적용 요건은 사용 목적과 조직의 역할에 따라 달라집니다:

- 투명성 의무
- 사용자 알림
- 인간 감독 기능

## 도메인 화이트리스트

SDK가 작동할 수 있는 위치 제한:

### 목적

- 애플리케이션 ID의 무단 사용 방지
- Moss에 접근할 수 있는 환경 제어
- API 키 노출 위험 감소

### 설정

**설정 > 보안**에서 대시보드에 허용된 도메인 추가:

```
app.example.com
staging.example.com
localhost:3000
```

### 적용

허용 목록을 설정하면 목록에 없는 도메인의 요청은 SDK 초기화 중 거부됩니다. 목록이 비어 있으면 모든 도메인을 허용합니다.
