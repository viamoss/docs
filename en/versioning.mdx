# Versioning & Compatibility

## One version number

`@viamoss/moss-sdk` and the Moss platform (backend and dashboard) share one version number: SDK 0.17.0 is the client for Moss 0.17.0. This has been the scheme since 0.13.0.

Not every version has both parts:

- **SDK-only releases.** 0.16.26 changed only the SDK. It works with a 0.16.25 server, and there was no 0.16.26 server.
- **Platform-only releases.** 0.16.24 was published for self-hosted installs but not to npm, so the SDK went from 0.16.23 to 0.16.25.

The [changelog](/en/changelog) says which parts each release has.

## Which combinations work

**An older SDK with a newer platform** keeps working. Each SDK request carries the SDK's version, and the backend serves an older SDK the way that version expects. Features and fixes added later are missing from the older SDK.

**A newer SDK with an older platform** works for most features, but features that need the newer backend don't work. Upgrade the backend first, then the SDK. With SDK 0.17.0 and a 0.16.x backend:

- **Links and images in answers.** An older backend sends no list of allowed hosts, so links to your knowledge base and your allowed domains show as plain text, and their images as alt text. Only your page's own origin and the hosts in `replyLinks.allowedHosts` work. See [replyLinks](/en/sdk/configuration#replylinks).
- `appearance.chrome.feedback.sessionRating: 'stars'`: the older backend refuses the star rating, so the session's rating is lost.
- `appearance.chrome.feedback.askWhatWentWrong`: the older backend drops the reason and comment without an error.
- Recent chats need a 0.17.0 backend.
- `streamActivity`: without the newer backend's streaming routes, the SDK falls back to ordinary requests, and the step loader shows its fixed rows.

To see which SDK version a page runs, look for the SDK's startup line in the browser console, written at the default log level: `[MossSDK] v0.17.0 initialized …`.

## What these docs describe

These docs describe the **latest release, 0.17.0**. Where something is new or changed since 0.16.25, the page says so, for example "From 0.17.0, …". If you run an older version, treat anything without such a note as present in 0.16.25, and check the [changelog](/en/changelog) for what arrived after your version.

## Staying current

Upgrade with your package manager:

```bash
npm install @viamoss/moss-sdk@latest
```

Stay on a recent version rather than pinning one indefinitely: fixes land only in the versions that carry them. Self-hosted installs: upgrade the backend before the SDK. Notable customer-visible changes in each release are listed in the [changelog](/en/changelog).

<Info>
    Releases that need action on your side, such as a configuration change or a breaking API change, are raised with you directly. Contact support through the Dashboard if you need to know whether a specific version affects your integration.
</Info>
