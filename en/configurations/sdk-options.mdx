This page groups the SDK's options by what you want to do, and says what each one is for and when to use it. The complete reference, with every option's type and default, is [Configuration](/en/sdk/configuration).

You pass options in the `config` prop of `AgentProvider`. With the CDN script, set the same keys in `window.mossSettings`, except `applicationId`, which goes in the script URL. A `userId` in the script URL and a `data-api-base` attribute on the script tag also win over `window.mossSettings`.

Some settings can also come from the Moss dashboard, and for theme and branding the dashboard wins. [Configuration overview](/en/configurations/overview) shows, for each setting, which side applies.

## Connect Moss to your app and your user

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
}}>
  <AssistantButton />
</AgentProvider>
```

- **`apiUrl`**, **`applicationId`** and **`userId`** are required. `applicationId` is shown under **Configure > General** as **Application ID**. From 0.17.0, a trailing `/` on `apiUrl` is ignored.
- **`getJwt`** returns a signed token for the signed-in user. Use it rather than **`jwt`**, a token you already hold, so the session survives the token expiring. See [Authentication](/en/sdk/authentication).
- **`userMetadata`** carries the user's role, plan and similar attributes, sent when a session starts. Use it so Moss can word answers for the user, and set `role: 'admin'` to show admins their own suggested content. Pass roles and categories, not personal data.
- **`getBridgeCode`** (from 0.17.0) is needed only when your application's MCP server signs users in through your site. See [Integrations](/en/dashboard/integrations).

<Warning>
    Use an opaque, stable `userId`, not an email address or a name. Moss stores it with every chat session.
</Warning>

The SDK reads `apiUrl`, `jwt`, `getJwt`, `getBridgeCode` and `applicationId` once, when `AgentProvider` mounts, and `redactionSelectors` and `redactAllInputs` for the page text likewise. To change them, for example when a different user signs in, remount the provider by giving `AgentProvider` a `key` that changes with the user:

```tsx
<AgentProvider key={currentUser.id} config={mossConfig}>
  <AssistantButton />
</AgentProvider>
```

## Change how the widget looks

- **`appearance`** sets colors, fonts, the chat window's layout and position, the header, footer, guide controls, start screen and fallback messages. See [Appearance](/en/sdk/appearance).
- **`pageKey`** names the current page, such as `'billing-settings'`. Use it to show different suggested questions on different pages; events carry it too. See [Per page and per role](/en/sdk/appearance#per-page-and-per-role).
- **`language`** fixes the widget's language to `'en'` or `'ko'` and hides the language menu. Leave it unset to let Moss detect the language. See [Language](/en/sdk/configuration#language).

## Control sessions and guides

- **`sessionConfig`** sets how long a chat lasts and what a user sees when they come back after a timeout. See [Sessions](/en/sdk/api/session).
- **`closingChatEndsGuide`** ends a running guide when the user closes the chat. Use it when your page shows no guide controls of its own. See [What ends a guide](/en/sdk/guides-and-navigation#what-ends-a-guide).
- **`stability`** sets how long Moss waits for the page to settle before it reads it. Turn on `stability.afterReload` when a guide step's click can load a new page. See [Reloads, redirects and new tabs](/en/sdk/guides-and-navigation#reloads-redirects-and-new-tabs) and [Stability tuning](/en/sdk/advanced#stability-tuning).
- **`streamActivity`** (from 0.17.0) shows the steps Moss's backend takes for a turn as it takes them, with `appearance.chrome.loader: 'steps'`. Proxies between the page and Moss must pass Server-Sent Events.
- **`enableProactiveGuides`**: set it to `false` to turn off announcements and trigger rules set up for the application.

## Limit what Moss reads and records

[Page data and privacy controls](/en/sdk/page-data) explains each of these.

- **`pageContext`** sets how much of the page each turn sends: the page's structure and text (`'full'`), only the URL and title (`'metadata'`), or neither (`'none'`). Use `'metadata'` on pages whose content must not leave the browser, and leave `enableScreenHistoryRecording` off: the action timeline is sent at every level. Moss can't point at elements at `'metadata'`.
- **`redactAllInputs`** and **`redactionSelectors`** hide form values and the elements you name from the page text. Mark elements in your markup with `data-moss-redact` as well.
- **`useVision`** sends a frame of the tab the user shares with each turn, once the user allows the browser's screen-capture prompt and while `pageContext` is `'full'`. Redaction doesn't apply to it. Set it to override the dashboard's **Enable Vision** in either direction; `false` keeps screenshots off.
- **`enableSessionRecording`** records the session for **Session Replay** in the dashboard. The dashboard's **Enable Session Replay** must be on too: from 0.17.0 the server refuses recordings while it is off.
- **`enableScreenHistoryRecording`** sends a timeline of the user's recent actions with each turn.
- **`observeTargetSelector`** limits the part of the page Moss reads to one element.
- **`collectionEnabled`** and **`collectionControl`** (from 0.17.0) let your code keep Moss from mounting, for example until the user consents.
- **`pageSanitizationScript`** is a function Moss runs on your live page each time it starts watching the page: when it mounts, and again when `observeTargetSelector` or the function itself changes. Anything it changes, users see too, so it is not a privacy control. Define the function outside your component, or an inline function runs again on every render.
- **`screenshotMode`** has no effect on chat screenshots in 0.17.0.

## Connect Moss to your own systems

- **`onSupportTicket`** files a support ticket through your backend and reports the outcome. See [Support ticket handoff](/en/sdk/support-ticket-handoff).
- **`onEvent`** receives usage events for your analytics, and **`eventQueryText`** decides whether they carry the question's text. See [Events and errors](/en/sdk/events).
- **`onError`** (from 0.17.0) receives every problem the chat shows the user, with who can fix it. See [onError](/en/sdk/events#onerror).
- **`replyLinks.allowedHosts`** (from 0.17.0) adds hosts that replies may link to and load images from. Use it when answers link to a site that isn't in the application's allowed domains or knowledge base. See [replyLinks](/en/sdk/configuration#replylinks).

## Diagnose problems

- **`logLevel`** sets how much the SDK logs to the console. It takes the `LogLevel` enum the SDK exports, not a string. With the CDN script, pass the enum's number: `1` (debug) to `5` (silent).
- **`debugMode`** shows debug controls inside the chat. Never turn it on in production: every user sees them. It is never taken from the dashboard.

```tsx
import { AgentProvider, AssistantButton, LogLevel } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  logLevel: LogLevel.WARN,
}}>
  <AssistantButton />
</AgentProvider>
```

## Changes in 0.17.0

- **Removed:** `displayMode`, `headless` and `forcedActivationFlow`. TypeScript rejects them; remove them from your config.
- **Changed:** session recording needs **Enable Session Replay** on in the dashboard, and an application that never saved that switch now counts as off (in 0.16.x it counted as on). The npm default of `enableSessionRecording` is still `false`.
- **Changed:** a trailing `/` on `apiUrl` is ignored.
- **New:** `onError`, `replyLinks`, `streamActivity`, `getBridgeCode`, `collectionEnabled` and `collectionControl`. New appearance keys are listed in [What's new in 0.17.0](/en/sdk/appearance#whats-new-in-0170).

## Settings only the dashboard holds

AI instructions, the model, on-screen guidance, allowed domains, the knowledge base, procedures, integrations and data retention have no SDK option. See [Settings only the dashboard holds](/en/configurations/overview#settings-only-the-dashboard-holds).
