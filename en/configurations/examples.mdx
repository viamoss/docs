Copy-ready `AgentProvider` configurations for common cases. Each one is complete for SDK 0.17.0. `currentUser` and `fetchMossToken()` stand for your own user object and token call; see [Authentication](/en/sdk/authentication) for the token endpoint.

[Configuration](/en/sdk/configuration) lists every option with its type and default, and [Configuration overview](/en/configurations/overview) shows which settings the dashboard can also supply.

---

## Minimal setup

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
}}>
  <AssistantButton />
</AgentProvider>
```

Every other option takes the SDK's default. From the dashboard, the widget also gets what arrives with each chat session: theme and branding from **Configure > Appearance**, suggested content from **Content > Suggested Content**, and the **Enable Vision** setting. The widget's language, session timeouts, screen history and log level come from your code; the dashboard's values for those are not applied with the npm package.

## Guides across page loads

For an app where guide steps load new pages, and where users close the chat mid-guide:

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),

  // Hand a guide step to the next page when its click loads one.
  stability: {
    afterReload: { enabled: true },
  },

  // Closing the chat ends the guide, so no highlight is left behind.
  closingChatEndsGuide: true,

  appearance: {
    chrome: {
      // Let users minimize the chat while a guide runs (0.17.0).
      guide: { minimize: true },
    },
  },
}}>
  <App />
  <AssistantButton />
</AgentProvider>
```

Mount `AgentProvider` above your router so client-side navigation doesn't unmount it. See [Guides and navigation](/en/sdk/guides-and-navigation).

## Analytics and error reporting

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';
import { analytics } from './analytics';         // your analytics client
import { errorTracker } from './error-tracker';  // your error tracker

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),

  onEvent: (event) => analytics.track(event.name, event.properties),

  // Question text is left out by default. Include it with emails masked.
  eventQueryText: (text) => text.replace(/[\w.+-]+@[\w-]+\.[\w.]+/g, '[email]'),

  onError: (error) => {
    errorTracker.captureMessage(`Moss: ${error.code}`, { extra: { ...error } });
  },
}}>
  <AssistantButton />
</AgentProvider>
```

See [Events and errors](/en/sdk/events) for the event catalog and the error fields.

## Privacy-focused setup

Moss reads less from the page, sends no screenshots, and makes no session recording or action history. The conversation itself is still stored; see the note after the example.

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),

  // No screenshots go to the model, whatever the dashboard says.
  // Redaction doesn't apply to screenshots, so keep vision off here.
  useVision: false,

  // Input values are hidden (this is the default; keep it on).
  redactAllInputs: true,

  // Hide these elements' content too, as data-moss-redact does.
  redactionSelectors: ['.account-number', '[data-private]'],

  // No session replay and no action history for the model (both off by default).
  enableSessionRecording: false,
  enableScreenHistoryRecording: false,
}}>
  <AssistantButton />
</AgentProvider>
```

Moss still reads the page's structure and text, which it needs to point at elements and run guides. To send no page content at all, set `pageContext: 'metadata'`: Moss then sends only the URL and the page title, so it answers in the chat but can't point at elements on the page. `pageContext: 'none'` also leaves out the URL and title.

Mark sensitive elements in your markup with `data-moss-redact` as well. See [Page data and privacy controls](/en/sdk/page-data). How long Moss keeps conversations is set in the dashboard under **Configure > Data & privacy**, not by the session timeouts.

## Full-featured setup

Vision, session replay and screen history all on:

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),

  useVision: true,                    // even if Enable Vision is off; the user must allow screen sharing
  enableSessionRecording: true,       // also needs Enable Session Replay in the dashboard
  enableScreenHistoryRecording: true,
  language: 'en',

  userMetadata: { role: currentUser.role, plan: currentUser.plan },

  sessionConfig: {
    inactivityTimeout: 60, // minutes
    maxSessionAge: 4,      // hours
  },

  stability: {
    afterReload: { enabled: true },
  },
}}>
  <AssistantButton />
</AgentProvider>
```

## Different settings per plan

```tsx
import { AgentProvider, AssistantButton, type MossSDKConfig } from '@viamoss/moss-sdk';

type Plan = 'free' | 'pro' | 'enterprise';

const planSessions: Record<Plan, MossSDKConfig['sessionConfig']> = {
  free: { inactivityTimeout: 15, maxSessionAge: 1 },
  pro: { inactivityTimeout: 30, maxSessionAge: 2 },
  enterprise: { inactivityTimeout: 60, maxSessionAge: 8 },
};

function MossAssistant({ user }: { user: { id: string; plan: Plan } }) {
  return (
    <AgentProvider config={{
      apiUrl: 'https://moss-api.viamoss.ai',
      applicationId: 'YOUR_APP_ID',
      userId: user.id,
      getJwt: () => fetchMossToken(),
      sessionConfig: planSessions[user.plan],
      userMetadata: { plan: user.plan },
    }}>
      <AssistantButton />
    </AgentProvider>
  );
}
```

`userMetadata` is sent when a session starts, so Moss can word its answers for the user's plan. See [Sessions](/en/sdk/api/session) for the timeouts.

## Next.js App Router

The SDK reads browser globals as it loads, so it must not be imported on the server. Load it with `next/dynamic` and `ssr: false`, inside a client component.

```tsx components/moss-assistant.tsx
'use client';

import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

export default function MossAssistant({ userId }: { userId: string }) {
  return (
    <AgentProvider config={{
      apiUrl: 'https://moss-api.viamoss.ai',
      applicationId: process.env.NEXT_PUBLIC_MOSS_APP_ID!,
      userId,
      getJwt: async () => {
        const res = await fetch('/api/moss-token');
        const data = await res.json();
        return data.token;
      },
    }}>
      <AssistantButton />
    </AgentProvider>
  );
}
```

```tsx components/moss.tsx
'use client';

import dynamic from 'next/dynamic';

// ssr: false keeps the SDK out of the server render.
const Moss = dynamic(() => import('./moss-assistant'), { ssr: false });

export default Moss;
```

```tsx app/layout.tsx
import Moss from '@/components/moss';
import { auth } from '@/lib/auth';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const session = await auth();

  return (
    <html lang="en">
      <body>
        {children}
        {session?.user && <Moss userId={session.user.id} />}
      </body>
    </html>
  );
}
```

```typescript app/api/moss-token/route.ts
import jwt from 'jsonwebtoken';
import { auth } from '@/lib/auth';

export async function GET() {
  const session = await auth();
  if (!session?.user) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  const token = jwt.sign(
    // app must be the same application ID the client passes as applicationId.
    { sub: String(session.user.id), app: process.env.NEXT_PUBLIC_MOSS_APP_ID },
    process.env.MOSS_JWT_SECRET!,
    { algorithm: 'HS256', expiresIn: '15m', keyid: process.env.MOSS_KEY_ID! },
  );

  return Response.json({ token });
}
```

`auth()` stands for your own session helper. The `'use client'` directive is required: Next.js doesn't allow `ssr: false` in a Server Component.

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,

  appearance: {
    colors: {
      primary: '#0F766E',
      primaryLight: '#5EEAD4',
      primaryLighter: '#F0FDFA',
      userMessage: '#0F766E',
      actionButton: '#0F766E',
      actionButtonHover: '#115E59',
```

## Docked side panel

```tsx
import { AgentProvider, AssistantButton } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),
  appearance: {
    layout: { mode: 'docked', anchor: 'right', width: 400 },
  },
}}>
  <AssistantButton />
</AgentProvider>
```

The panel is full height and sits over your page. It can't be moved, resized or minimized, and it ignores `modal` and the position passed to `openChat()`.

## Developer and debug setup

For local development only:

```tsx
import { AgentProvider, AssistantButton, LogLevel } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'http://localhost:8000',
  applicationId: 'YOUR_APP_ID',
  userId: 'dev-user',
  getJwt: () => fetchMossToken(),

  logLevel: LogLevel.DEBUG,
  debugMode: true,
}}>
  <AssistantButton />
</AgentProvider>
```

<Warning>
    `debugMode` shows debug tools inside the widget to every user. Never turn it on in production.
</Warning>

## Shorter page waits

Before it reads the page, Moss waits for it to settle: up to 15 seconds by default, plus up to 4 seconds for loading placeholders to clear. On pages that load fast, you can cap the wait lower:

```tsx
import { AgentProvider, AssistantButton, LogLevel } from '@viamoss/moss-sdk';

<AgentProvider config={{
  apiUrl: 'https://moss-api.viamoss.ai',
  applicationId: 'YOUR_APP_ID',
  userId: currentUser.id,
  getJwt: () => fetchMossToken(),

  stability: {
    maxTotalWaitMs: 5000,
    placeholderGuard: { timeoutMs: 2000 },
  },

  logLevel: LogLevel.WARN,
}}>
  <AssistantButton />
</AgentProvider>
```

A wait that is too short can make Moss read a page before its content has loaded, and miss the element a guide needs. See [Stability settings for guides](/en/sdk/guides-and-navigation#stability-settings-for-guides).

## Choosing between code and the dashboard

**Use the dashboard for:**
- AI instructions, the model, procedures and the knowledge base
- Allowed domains and JWT claim checks
- Theme, branding and suggested content that admins should change without a release
- Turning on vision and session replay for the application

**Use your code for:**
- Everything the npm package reads only from code: language, session timeouts, log level, stability, fallback states and the rest of the appearance
- Settings that differ by user, plan or environment
- Per-page suggested content, with `pageKey`

## Security tips

1. Keep your JWT signing secret on your server. Never put it in client code.
2. List the domains your app runs on under **Configure > Security > Allowed Domains**.
3. Ask for users' consent before you turn on session replay, where your policies require it.
4. Use opaque user IDs, not email addresses or names.
