## Overview

Export sessions from the **Sessions** list as CSV or JSON. There are two export types:

- **Session summary** (the default): one row per session, with its counts and rating.
- **Full transcript**: one row per message, with ratings and feedback on each answer.

Admins and members can both export. To export:

1. Open **Analyze > Sessions** and narrow the list with the search box and **Filters** (see [Sessions](/en/dashboard/sessions#filters)).
2. Select **Export**.
3. Optionally set **User ID**, **Created Date**, **Last Activity**, **Session Rating** and **Message Rating** in the export panel.
4. Choose an **Export type**.
5. Select **Export as CSV** or **Export as JSON**.

The file downloads as `sessions-export-<date>.csv` or `.json`, with the date in UTC (for example `sessions-export-2026-11-24.csv`).

<Warning>
  In 0.17.0, a **Session summary** export as JSON fails with **Export failed**. Export the session summary as CSV, or use **Full transcript** when you need JSON.
</Warning>

## Which sessions are exported

An export includes the sessions that match all of the following:

- **The fields in the export panel**: **User ID** (any ID that contains the text, ignoring case), **Created Date** from and to, **Last Activity** from and to, **Session Rating** (Helpful, Unhelpful, Neutral or Not rated) and **Message Rating** (Helpful or Unhelpful). These are separate from the same-named fields in the **Filters** panel: set them here. When the list was opened with a **Created** filter, for example from a **View sessions** link on the **Analytics** page, **Created Date** starts out with that range.
- **The list's search and outcome filters**, which carry over as they are: the search box, **Topic**, **Answer status**, **Resolution**, **Tool runs**, and the **Article** and **Content-gap window** chips that **Analytics** links add.

The list's **Recording** filter does not carry over, and the export panel has no field for it.

Only sessions with at least one message are exported, as in the list.

## Limits

| Limit | Applies to | What happens |
|---|---|---|
| 5,000 sessions | Both types | The export reads the 5,000 matching sessions that were updated most recently. Any more are left out without a message, so a **Session summary** never has more than 5,000 rows and a **Full transcript** covers at most 5,000 sessions. |
| 10,000 rows | **Full transcript** | If the sessions read hold more than 10,000 messages, nothing is exported and the dashboard shows "Too many rows. Please narrow your filters." The error behind it reads `Export exceeds 10000 rows (<count> found). Please narrow your filters.` |

To export more, split the export by **Created Date** and run it once per period.

## Export Columns

### Session summary

One row per session, the most recently updated first.

| Column | Contents |
|---|---|
| `session_id` | The session ID, starting with `cs_`. |
| `user_id` | The user ID your app passed. |
| `status` | Whether the server considers the session active or closed (see [Active and closed](/en/dashboard/sessions#active-and-closed)). In 0.17.0 the CSV cell reads `ChatSessionStatus.ACTIVE` or `ChatSessionStatus.CLOSED`. |
| `created_at` | When the session started, ISO 8601 in UTC, for example `2026-11-03T11:58:04.987654+00:00`. |
| `last_activity_at` | When the last message was written, in the same format. |
| `message_count` | The **Steps** count from the list: the user's questions, the page actions they took while guided, and the assistant's answers, counting only messages that finished. |
| `tool_run_count` | The **Tool runs** count from the list. |
| `session_rating` | The rating of the whole session: `helpful`, `unhelpful`, `neutral` (a score of 3), or empty. |
| `session_comment` | The comment the user left with that rating, or empty. |
| `first_user_query` | The first question the user typed. |
| `has_recording` | `True` or `False`: whether the session has a recording. |
| `session_score` | The 1 to 5 score, or empty. From 0.17.0. |

```text
session_id,user_id,status,created_at,last_activity_at,message_count,tool_run_count,session_rating,session_comment,first_user_query,has_recording,session_score
```

### Full transcript

One row per message. Rows are grouped by session, and within a session they are in conversation order. Sessions are not sorted by date.

| Column | Contents |
|---|---|
| `session_id` | The session ID. |
| `user_id` | The user ID your app passed. |
| `session_created_at` | When the session started, ISO 8601 in UTC. |
| `message_sequence` | The message's position in its session, counting only the exported rows and starting at 1. |
| `message_type` | `user_query`, `assistant_response` or `system_continuation` (see [Message Type Descriptions](#message-type-descriptions)). |
| `message_content` | The message text. For `assistant_response` rows it is a JSON object as a string (see [`assistant_response` Message Content Schema](#assistant_response-message-content-schema)). |
| `message_created_at` | When the message was written, ISO 8601 in UTC. |
| `message_rating` | The user's thumbs on this answer: `helpful`, `unhelpful`, or empty. |
| `ai_rating` | `unhelpful` when a later answer in the same session corrected this one, otherwise empty. |
| `session_rating` | The rating of the whole session, repeated on every row of the session: `helpful`, `unhelpful`, `neutral`, or empty. |
| `session_comment` | The comment left with the session rating, repeated on every row of the session. |
| `message_feedback_reason` | What the user said went wrong after a thumbs down on this answer, or empty. From 0.17.0. |
| `message_feedback_comment` | The comment the user typed with that reason, or empty. From 0.17.0. |
| `session_score` | The session's 1 to 5 score, repeated on every row of the session, or empty. From 0.17.0. |

```text
session_id,user_id,session_created_at,message_sequence,message_type,message_content,message_created_at,message_rating,ai_rating,session_rating,session_comment,message_feedback_reason,message_feedback_comment,session_score
```

`message_feedback_reason` holds one of these keys; the dashboard and the widget show the words:

| Key | Shown as |
|---|---|
| `steps_mismatch` | Steps didn't match the page |
| `hard_to_follow` | Guide was hard to follow |
| `not_solved` | Didn't solve the problem |
| `wrong_answer` | Answer was wrong |
| `not_answered` | Didn't answer my question |
| `other` | Something else |

Reasons and scores are collected only when the widget asks for them; see [Ratings, scores and reasons](/en/dashboard/sessions#ratings-scores-and-reasons).

## Message Type Descriptions

- `user_query`: a question the user typed.
- `system_continuation`: a turn Moss started after something happened on the page rather than a typed question: the user completed a step Moss was guiding them through, or a support handoff came back with a result. Its content is text Moss wrote for the assistant, not words the user typed.
- `assistant_response`: the assistant's answer.

Only finished messages are exported. A turn that failed without an answer, or one that was replaced, is left out, so a session's transcript export can be shorter than its session page.

## `assistant_response` Message Content Schema

For `assistant_response` rows, `message_content` is a JSON object serialized as a string, with one field:

```json
{"guidance_text": "Click Save in the top-right corner."}
```

`guidance_text` is the answer text as the user saw it. No other fields are exported: the elements the answer pointed to, guide plans and step updates are not in the export. Characters outside ASCII are escaped inside this string (for example `\uc800\uc7a5` for 저장); any JSON parser turns them back.

## Example `assistant_response` in JSON Export

```json
{
  "session_id": "cs_3f1c9a2e-7b4d-4e8a-9c1f-2d6b8e0a5c71",
  "user_id": "user_42",
  "session_created_at": "2026-11-03T11:58:04.987654+00:00",
  "message_sequence": 2,
  "message_type": "assistant_response",
  "message_content": "{\"guidance_text\": \"Click Save in the top-right corner.\"}",
  "message_created_at": "2026-11-03T11:58:07.120000+00:00",
  "message_rating": "unhelpful",
  "ai_rating": "",
  "session_rating": "neutral",
  "session_comment": "",
  "message_feedback_reason": "not_answered",
  "message_feedback_comment": "I asked about bulk export",
  "session_score": 3
}
```

In JSON, `message_sequence` and `session_score` are numbers; an empty `session_score` is `""`. Every other value is a string.

## CSV cells that start with a formula character

To keep a spreadsheet from running a cell as a formula, a CSV cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading `'`. A question such as `-5 is my balance?` is written as `'-5 is my balance?`. JSON exports are not changed.

## Common questions

**Why doesn't my export match the list?**
The export reads at most 5,000 sessions, so it can have fewer than the list. It ignores the list's **Recording** filter, and it uses the export panel's **User ID**, date and rating fields instead of those in **Filters**, so it can also have more. Set those fields in the export panel before exporting.

**Where are the 1 to 5 scores and thumbs-down reasons?**
`session_score` in both types; `message_feedback_reason` and `message_feedback_comment` in **Full transcript**. They are empty unless the widget collects them.

**Can I export the steps of a guide or the tools the assistant ran?**
Not in an export. A **Full transcript** has only the answer text; open the session to see its tool runs and guided steps. The **Session summary** gives the number of tool runs.
