## GDPR Compliance

Moss provides features to support your GDPR compliance obligations.

Moss acts as processor or sub-processor for customer data. Direct data-subject
requests to the relevant customer.

### Data Subject Rights

#### Right to Access (Article 15)

Authorized customer operators can fulfill data access requests using:

- Export chat history via Dashboard
- Download session recordings
- Access audit logs for their activity

#### Right to Erasure (Article 17)

Moss supports deletion of user-linked data:

**What Gets Deleted:**

- Chat sessions and messages
- AI-generated instructions and plans
- Screenshots and recordings in configured storage
- User records
- Associated request logs

**Deletion Process:**

1. Submit a deletion request via API or contact Moss
2. Moss validates the request
3. User records and linked application data are deleted
4. Deletion results are returned for review

The response reports the selected current application/user records and configured
session-object prefixes. It does not by itself certify deletion of backups,
historical object versions, external processor copies, administrative audit
events, or retained deletion evidence. Moss reconciles those copies with the
applicable agreement and customer instructions. A failed storage sweep leaves
the request incomplete and preserves references for retry.

Where queued deletion is enabled, the API first returns a durable request ID and
status. Poll that request for completion; acceptance is not proof of deletion.
Customer-managed infrastructure and copies held by Moss have separate operating
responsibilities. Contractual return, deletion and certification deadlines apply
independently of routine retention periods.

#### Right to Portability (Article 20)

Export user data in standard formats:

- Chat history (JSON)
- Session metadata (JSON)
- Audit logs (CSV)

### Lawful Basis

The controller determines the lawful basis for processing:

| Basis                   | Implementation                                    |
| ----------------------- | ------------------------------------------------- |
| **Consent**             | SDK can prompt for user consent before activation |
| **Legitimate Interest** | Purposes justified by the controller              |
| **Contract**            | Providing the AI assistant service                |

## EU AI Act

Moss is preparing for EU AI Act compliance as it applies to AI-powered assistant systems.

### Transparency Requirements

Moss supports transparency through:

- **Clear AI Identification** - Users know they're interacting with AI
- **Capability Disclosure** - Documentation of AI capabilities and limitations
- **Decision Explanation** - AI responses include reasoning when applicable

### Human Oversight

- **User Control** - Users can dismiss or override AI suggestions
- **Admin Control** - Application owners can customize AI behavior
- **Audit Trail** - Selected audit events and optional detailed request logs support review

### Risk Classification

Applicable requirements depend on the use case and the organization’s role:

- Transparency obligations
- User notification
- Human oversight capabilities

## Domain Whitelisting

Restrict where your SDK can operate:

### Purpose

- Prevent unauthorized use of your application ID
- Control which environments can access Moss
- Reduce risk of API key exposure

### Configuration

Add allowed domains in Dashboard under **Settings \> Security**:

```
app.example.com
staging.example.com
localhost:3000
```

### Enforcement

When an allowlist is configured, requests from unlisted domains are rejected during SDK initialization. An empty allowlist permits any domain.
